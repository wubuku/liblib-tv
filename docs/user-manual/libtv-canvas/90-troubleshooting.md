# 故障排查

按**症状**查。每条都写清楚：现象 → 原因 → 怎么修。

---

## 画布打不开 / 一进去就被弹回来

**症状**：访问 `/canvas` 被弹回首页。

**原因**：`/canvas` 裸路由**不带参数会跳首页**。画布必须带两个 id：

```
https://www.liblib.tv/canvas?spaceId=…&projectId=…
```

**修**：从顶栏「画布 N」下拉里点进去，或从项目页重新进入。别手敲地址。

---

## 打开我的画布，界面显示「会话已过期，请刷新页面以继续编辑」

**症状**：同一张画布在两处打开时，后打开的那处被挡住。

**原因**：LibTV 有**单画布单编辑者保护** —— 同一张画布同一时间只允许一处编辑。

**修**：关掉另一个标签页/窗口后刷新。

> 这是设计如此，不是故障。复制链接给自己另开窗口试也会撞上。

---

## 点「新建项目」以为没反应，又点了一下，结果建了两张

**症状**：画布下拉里多出两张几乎一样的画布。

**原因**：这个按钮**没有确认对话框**，点一次就已经建好并跳转了。

**修**：多出来的那张删掉，见 [10-tasks/manage-canvases.md](10-tasks/manage-canvases.md)。

## 删除键按了没用

**症状**：选中节点，按 `Delete` / `Backspace`，节点还在。

**原因**：节点里有提示词输入框，焦点还在框里 —— 此时 `⌘A` 选中的是**框里的文字**。

**修**（实测有效）：

1. 点一下画布空白处，把焦点交回画布；
2. `⌘A` 全选；
3. `⌫` 删除。

## ⭐ 点一个节点，选中的却是旁边那个 / 怎么都点不到它

**症状**：想编辑 A 节点，点了它却选中了 B 节点；或者 A 节点在画面上明明看得见，
**点哪儿都选不中它**。

**原因**：两个节点**重叠**了。压在上面的那个会把下面的**整个挡住**，
鼠标点到的永远是上面那层。

**实测**（`⌘0` 重置视图后，视口 1440×810）：

| | 视口框 `[x, y, 宽, 高]` | 在 DOM 里的次序 |
|---|---|---|
| 上面那层（点得到） | `[65, 319, 285, 161]` | 靠后 |
| 下面那层（点不到） | `[76, 319, 285, 161]` | 靠前 |

两者的 `z-index` **都是 `0`** ⇒ 靠 DOM 次序决定谁压谁，**后出现的赢**。
在下面那层上打 `7×7` = **49 个采样点**逐个用 `elementFromPoint` 查归属：
**落在上面那层的 37 个，落在任何节点之外的 12 个
（最右一列 7 个 + 最下一行除 1 个外的 5 个），
落在它自己身上的 —— 0 个。**
⇒ 它不是「难点到」，是**一个像素都点不到**。

**修**：

1. 先把上面那层**拖开**（按住拖它，别用框选——框选会把两层一起圈进去）；
2. 或者按 <kbd>⌘F</kbd> 打开「搜索画布元素」，输入节点名直接定位；
3. 实在分不清时，用**整理画布**（<kbd>⌥⇧F</kbd>）把它们按类型分开摆。

> ⛔ 别指望 <kbd>Tab</kbd> —— 它是「**新建节点**」的快捷键，
> 按下去只会弹出「添加节点」面板，**不会在节点之间切换选中**。

> ⭐ 这是**手写取证脚本时最容易踩的坑**：脚本按「取节点中心点点击」来选节点，
> 一旦目标被压住就会**静悄悄地选错对象**，而后面的读数全部作废
> （本项目已经栽过一次：脚本以为在读图片节点，实际读的是盖在它上面的视频节点）。
> ⇒ 自动化操作前**必须**先确认落点归属，见 [20-reference.md](20-reference.md#阴性结论自证三步法)。

## 在资产管理里点了「复制」，画布上一个节点都没多

**症状**：资产管理左抽屉的行尾 `⋯` → `复制`，列表里明明多出了一行「原名 - 副本」，
底部也从「共 1 节点」变成「共 2 节点」，可画布上还是老样子。

**原因**：**副本建出来了，只是没在你眼前。** 副本排在**原节点正下方约一个身位**，
而 LibTV 只渲染视口内的节点。复制之前如果你按过 `⌘0` 把画布放大到「一个节点占满屏」，
那副本就在视口外面。

**修**：按 **`⌘0` 适合屏幕**，副本立刻出现。实测：复制完立刻数 = 1 个，`⌘0` 之后 = 2 个。

> 拿「画布上渲染了几个节点」当「我复制成功了吗」的判据，在这一步上会判错 ——
> **资产管理抽屉底部的「共 N 节点」才是准的。**

## 在资产管理里点了「删除」，想反悔

**症状**：节点没了，想找回。

**实测结论：找不回来。** 逐条核过：

| 检查 | 结果 |
|---|---|
| 二次确认弹窗 | **没有**，点完 200 毫秒全屏扫一遍，除了资产管理抽屉自己没有任何 `role="dialog"` |
| `⌘Z` | 无效 —— 焦点交回画布（`document.activeElement` 变成 `BODY`）后再按，画布仍是 0 个节点 |
| `⌘⇧Z` | 无效 |
| 成功提示 | 无 |

**预防**：

1. 删之前按 `⌘D` 复制一份（副本会落在原节点下方）；
2. 或者用 **`Option` + 拖动节点**复制；
3. 或者**先复制一张画布**再在里面随便删（见 [10-tasks/manage-canvases.md](10-tasks/manage-canvases.md)）。

> ⚠️ 画布**列表**里删整张画布是有二次确认的，删**单个节点**这一步没有。别拿前者的经验套后者。

## 点「添加到Agent」之后，节点挂了两次

**症状**：资产管理里点 `⋯ → 添加到Agent`，TV Director 抽屉的输入框里并排出现**两枚一模一样的附件 chip**。

**实测**：画布上只有 1 个节点、只点了 1 次菜单，输入区里就有 2 枚文字完全相同的 chip。
两枚的 DOM 完全一样（同一个 class、同样的 16px 文字高度、没有任何 `title` / `aria` / `data-*` 能区分），
在两张不同的测试画布上各复现了一次。

**手册判断不了这两个 chip 各自代表什么**，只把现象记在这里。

**修**：发送前把不需要的那枚处理掉 —— chip 上有 `×` 就点 `×`。
（chip 的删除按钮是 hover 才出现的，本手册没去点它。）

> 顺带一提：这个动作**只挂载、不发送**。发不发由你点右下角 `Send` 决定。
> 而只挂附件、没打字时 `Send` **已经可点**了。

## ⭐ 在资产侧栏点「添加到Agent」/「添加到画布」，什么也没发生

**症状**：左下角 `资产管理` → `资产` 标签 → 行末 `•••` → 点 `添加到Agent`（或 `添加到画布`），
菜单「啪」一下关掉了，然后什么都没发生。

**这不是点错了 —— 实测就是空操作。** 四条判据同时为空：

| 判据 | `添加到Agent` | `添加到画布` |
|---|---|---|
| 界面里有没有新东西冒出来 | 0 个 | 0 个 |
| 抽屉里的文字变没变 | 没变 | 没变 |
| 画布上的节点数变没变 | `+0` | `+0` |
| 有没有新的输入框 | 没有 | 没有 |

> ⚠️ **同一个名字，两处行为不一样**：
> **画布节点**侧栏的 `⋯ → 添加到Agent` 是**有效的**（右侧滑出 TV Director 抽屉、节点挂成附件 chip）。
> **资产**侧栏这一条同名项，在没有素材的这个状态下没有反应。
> 别拿前者去推断后者。

**修**：手册**判不了**它需要什么前置条件 📖。
目前能确定的是：它**不是**节点那条路，也不是一个坏掉的按钮。

## 建子文件夹时打出来的是「新建文件夹XXX」

**症状**：点 `新建子文件夹`，输入框里已经有「新建文件夹」了，
你敲上自己的名字，结果变成了 **`新建文件夹我的名字`**。

**原因**：那个输入框**开出来就已经自动聚焦、默认名已经全选好了**，
**直接打字就是改名**。如果你先**点了一下框里**，
光标会从「全选」变成「停在末尾」，于是你打的字变成**追加**。

**修**：⛔ 下次**别点那个框**，看到输入框直接打字，回车提交。
不需要手动删原名，也不需要全选。

## 资产分类建错了，想删掉

**症状**：在 `资产管理 → 资产` 里建错了分类或文件夹，想清理掉。

**做法**：那一行最右边的 `•••` → 最下面那枚 **`删除`**（整份菜单里**唯一的红字**）。

⚠️ 会先弹一道确认框，正文是：

> 确定删除「`{文件夹名}`」吗？删除后不可恢复。

> ⭐ **框里会写你要删的那个名字** —— 不可恢复的删除之前，**先核对一眼框里的字**，
> 那是它插值进去的，不会认错对象。

框里两枚按钮：`取消`（半透明）/ `删除`（**实心红**）。

**注意**：`删除` 删的是**那一个文件夹**。手册实测过完整的
「建子文件夹 → 回车 → 删掉 → 账户回到原样」，删完抽屉里和之前**一个字都没变**。

## 上传资产时，右下角「保存」是灰的

**症状**：点 `上传资产`，面板出来了，但右下角 `保存` 点不动。

**原因**：面板右侧的 **`保存位置 *`** 是**必填项**（标签后面带一颗红星 `*`）。
没填之前 `保存` 就是禁用的 —— 实测它的 `disabled` 属性就是 `true`。

**做法**：先点 `请选择文件夹` 选一个位置，`保存` 才可用。

> 💡 **顺带一提：这个面板不是系统选文件框。**
> 正确顺序是：**先定「保存到哪个文件夹」** → 再在左边虚线框里放文件 → `保存`。
>
> ⭐ **支持哪些格式，界面自己写着**，就在面板左下角：
> `支持的文件格式 🖼 jpg/jpeg/png ▶ mp4 🔊 mp3`，外加 `单个文件大小不超过 20MB`。

## 点「管理」以为没反应，其实弹窗被遮住了

**症状**：在 `资产` 标签点 `管理`，好像什么都没变。

**实测**：它**确实打开了一个弹窗** —— 一整块居中的「资产管理」窗，
上面写着「资产管理」，左侧栏是 `个人资产库` / `可灵主体库`。
**按 `Esc` 能关掉**。

> ⚠️ 这条之所以容易被误判成「没反应」，是因为**抽屉还在原地**，
> 而那块弹窗又是深色的 —— 不留意会以为页面没动。
>
> 💡 顺带记一条：在抽屉里按 `Esc`，**会把整个抽屉一起关掉**，
> 不只是关菜单。所以「按 Esc 收尾」之后通常要重新把抽屉打开。

## 资产管理里搜不到东西，是画布上没有还是搜错了地方

**症状**：在资产管理抽屉里搜一个节点名，列表空掉，出现「当前画布没有相关搜索结果」。

**先确认你搜的是哪个列表。** 这个抽屉有**两个**标签，各带一套独立的搜索：

| 标签 | 搜的东西 | 打开搜索的方式 |
|---|---|---|
| `画布` | **节点名** | 点工具行的 🔍（`aria-label="搜索节点"`） |
| `资产` | **资产名** | 点工具行的 🔍（`aria-label="搜索"`） |

> ⚠️ **工具行平时没有搜索框**，得先点一下 🔍 才会展开。
> 直接往抽屉里打字，打到的是上面那个工作区名称框里去 —— 本手册的取证脚本就踩过这个坑，
> 在「工作区名称」里打了「音频」，列表纹丝不动。

**搜的是节点名，不是节点类型、也不是提示词。** 按类型筛要用旁边那枚 `筛选：…`（十个档位），
按星级筛要用 `所有评级`（六档）—— 三者是分开的。

**两个筛选器会叠在一起。** 类型筛选 + 星级筛选 + 搜索框同时生效时，
列表可能空得莫名其妙 —— 把 `筛选：…` 切回「全部」、`所有评级` 切回「所有评级」再搜一次。

> 底部那个「共 N 节点」**数的是整张画布**，不跟着筛选走。
> 列表被筛到 1 行时它照样写着「共 3 节点」，别拿它当「我筛出来几个」的依据。

## ⭐ 找不到给节点评星级的入口

**症状**：想给节点标个重要程度，翻遍节点卡片、参数条、顶底栏，**一个星星也没找到**。

**本手册的结论：截至最后一次取证，这个入口在界面上确实找不到** 📖。

为了不把「没找到」和「不存在」混为一谈，取证时**穷举了五处**带星级语义的位置，全部 0 命中：

| 找过的地方 | 判据 | 结果 |
|---|---|---|
| 11 个节点的卡片 | 中文关键词 + `★☆` | 0 |
| 五类节点的参数条 | 同上 | 0 |
| 节点右键菜单 | 同上 | 无菜单弹出（无头环境拿不到浏览器菜单）📖 |
| 资产管理列表行内 | 同上 | 0 |
| 顶栏 + 底栏全部可交互元素 | 逐个过一遍，**共 58 个** | 0 |

**别用错判据。** ⭐ 评级档位那一列**不是文字，是图标** —— 每档右侧是一枚 `12×12` 的橙色五角星（`iconify--libtv`）。
所以「找一个带星字的元素」或者用正则 `/\d\s*[★☆]/` 去筛，**必然 0 命中**，
那是判据错了，不是这个 UI 不存在。同理，用这套办法去找「设置星级的按钮」也找不到，结论并不可比。

![评级筛选共六档，每档右侧跟着一枚橙色五角星图标](screenshots/M-198-评级筛选-六档.png)

**现在能用的办法**：只有 `所有评级` 这个**筛选器**。
它能按星级过滤列表，**但没有任何界面能改星级** —— 本账户的 11 个节点全是未评级状态 📖。

## 画布空了，节点全不见了

**症状**：画面上一片空白，底部中央浮出「**当前视窗没有节点**」。

**这多半不是画布被清空了**，只是**视口飘到了所有节点之外**。

**原因**：LibTV 的画布只渲染**落在视口内**的节点。实测按住 `Space` 每轮向右拖 420px，四轮之后页面里渲染的节点数从 `3 → 3 → 2 → 1 → 0`，提示就是在 DOM 节点数归零那一刻出现的。

**修**（按顺序）：

1. 点提示条上的 **`返回节点`** —— 实测点完视口飞回，节点重新出现，提示自动消失；
2. 或者按 `⌘0` 适合屏幕；
3. 还找不到就按 `⌘F` 搜节点名字 —— 搜索面板**不受视口影响**，节点在页面外也照样列得出来（见 [10-tasks/create-nodes.md](10-tasks/create-nodes.md)）。

> ⚠️ **在这个状态下别按 `⌘A` + `⌫`**。你看到的「一个节点都没有」其实是「一个节点都没渲染」，删除操作很可能打空。

**症状**：导演台节点点进去，3D 视窗是空的，中间弹一个框：

> **请开启浏览器硬件加速**

> 至于搭建场景、参考图、多视角截图这些具体操作，**本手册没能进入 3D 视窗验证** —— 取证环境无硬件加速，所以这一段不写。

## 拖动画布拖不动

**症状**：在空白处按住左键拖，画布纹丝不动。

**这在默认状态下是正常的**。实测同一段鼠标位移 `(+220, +120)`，四种操作的结果差得很远：

| 操作 | 视口实际位移 |
|---|---|
| 空白处无修饰键左键拖 | `(+16.3, 0)` —— 基本等于拖不动 |
| `Space` + 左键拖 | `(+220, +120)` ✅ |
| 抓手工具（`H`）+ 左键拖 | `(+220, +120)` ✅ |
| 中键拖 | `(+220, +120)` ✅ |

**修**：按住 `Space` 再拖（最省事），或用中键拖。

> 顺带一提：如果你本来是想**框选**节点，那要按住 **`Shift`** 拖 —— 不按 `Shift` 是拖不动画布的。见 [10-tasks/create-nodes.md](10-tasks/create-nodes.md)。

## ⭐ 节点拖不动，而且空白处一拖就整张画布跑了

**症状**：想去拖一个节点，结果节点纹丝不动，反而整张画布跟着鼠标跑。

**原因**：**你处在「抓手工具」模式下。** 这一模式下拖任何东西都是平移画布，不是拖节点。

**怎么确认自己处在抓手模式**：看**画布空白处的光标**。

| 模式 | 空白处光标 |
|---|---|
| 移动 | 一枚**自定义箭头图标**（内联 SVG 做的 `cursor: url(...)`） |
| **抓手工具** | 标准的 **`grab` 手形** |

> 💡 看光标比看按钮可靠 —— 底栏那枚按钮没有高亮，两种状态下长得几乎一样，
> **只有它的无障碍名会变**（「移动」↔「抓手工具」）。

**修**：按 **`V`** 切回移动。

### ⚠️ `H` 是单向的：进得去，出不来

这是本轮实测中最容易让人卡住的一条：

| 你的动作 | 结果 |
|---|---|
| 按 `H` | ✅ 进了抓手模式 |
| **再按 `H`** | ❌ **还是抓手模式**（连按三次，状态序列 `移动 → 抓手 → 抓手 → 抓手`） |
| 按 `⇧` + `H` | ❌ 还是抓手模式 |
| **点底栏那枚按钮本身** | ❌ 还是抓手模式 |
| 按 **`V`** | ✅ 这才回到移动 |

**进抓手靠 `H` 或点按钮，退出只能靠 `V`。**
如果卡在抓手模式又忘了这件事，表现就是上面那个「节点拖不动」的坑。

## 点「网格吸附」，看不出变化，也不知道它到底管什么

**症状**：点左下角工具条上的「网格吸附」，按钮**看不出任何变化**；
而且**开着关着好像都一样**，拖节点的感觉也差不多。

### ⭐⭐⭐ 先记住一句话：这枚开关的名字和它是**反着**的

| 开关 | 按钮里的图标 | 拖动节点时 |
|---|---|---|
| **关**（默认） | 磁铁 1 枚 | ⭐⭐ **吸附**到 **12 个画布单位**的格点 |
| **开** | 磁铁 + **一道斜杠** | ⭐⭐ **完全不吸附**，想放哪放哪 |

⭐ **那个斜杠是「把磁铁划掉」** —— 划掉的正是**吸附**。
**「开了斜杠」= 关掉吸附。**

### 一、按钮这一侧：它**确实是开关**，只是长得几乎没变

开着时按钮里会多出第二枚 `svg`：

```html
<!-- 关 -->
<button aria-label="网格吸附"><span …><svg class="iconify iconify--lucide …"><path d="m12 15l4 4M2.352…"/></svg></span></button>
<!-- 开：同一枚 path 后面多出第二枚 svg -->
<button aria-label="网格吸附"><span …><svg class="iconify …"><path d="m12 15l4 4M2.352…"/></svg><svg class="absolute inset-0" viewBox="0 0 14 14"><line x1="1" y1="1" x2="13" y2="13" stroke-width="1.5" opacity="0.6"/></svg></span></button>
```

⚠️ **它的无障碍名、class、`aria-pressed`、背景色、透明度全都一模一样** ——
只盯着「按钮长什么样」或「它的名字变没变」，永远看不出它翻没翻。

> ⚠️ 顺带提醒一个容易误判的现象：鼠标点完按钮**还停在按钮上**，
> 这时按钮会因为悬停而变色，看上去「开了」。**那只是悬停。**
> 要判断状态，得**先把鼠标移开，再数里面的 `svg` 有几枚**。

### 二、拖动这一侧：**两态的轨迹长得完全不一样**

同一次拖拽（13 个屏幕像素），**每 2 个像素读一次**落点：

| 开关 | 导演台读到的画布 x |
|---|---|
| **关** | `−47724` → `−47724` → `−47712` → `−47712` → `−47712` → `−47700` |
| **开** | `−47724` → `−47719.9` → `−47715.7` → `−47713.6` → `−47709.5` → `−47705.4` → `−47701.2` |

- **关**态是**阶梯**：中间几帧纹丝不动，到格子边界才「咔」地跳 `12` 个画布单位。
- **开**态是**平滑等差**：一帧一帧匀速推进，**没有任何停顿**。
- ⭐ 开态落点 `−47701.2` **不是 12 的倍数**（`−47701.2 ÷ 12 = −3975.1`）⇒ **确实不吸附**。
- ⭐⭐ 「关」态各测了**两遍，逐字相同** ⇒ 行为稳定，不是偶发。

**绕开的办法**：想要节点精确落位，别指望松手就准 ——
拖完按 [⌥⇧F 整理画布](10-tasks/shortcuts.md) 一次性把所有节点铺整齐。

> ⭐ **一个实用组合**：点开（不吸附）把节点拖到想要的位置，**再点回去**（恢复吸附）。
> 关掉吸附**只影响下一次拖动**，已经放好的节点不会被动。

> ⚠️ **本手册对这一节改过两次，两次都记在这里**：
> ① 「网格的真实步长是 35 个画布单位」**不准确** —— 35 是**背景淡灰小圆点**的间距，
>    而且那个点阵的**相位会随画布平移跳变**，画布里没有固定格线；
> ② 手册一度写成「开着它拖仍然被吸附」—— **也错**，
>    正确的是**关着才吸附**。早先那句「开着它拖是严格 1:1 跟手」当时被当成采样假象划掉了，
>    现在用帧间隔 170ms、两个节点、各测两遍**独立复现，结论是对的**。

> 📖 仍未验：`12` 这个格距在别的缩放级别下会不会变；
> 开着的时候是「完全不吸附」还是「换成另一个格距」（本轮只试了 13 个屏幕像素这一小段）。

## 背景那一片淡灰小点，我以为是网格线

**症状**：以为画布背景上的点是「网格」，于是想把节点对齐到某个「格子」上，
结果怎么拖都对不齐。

**那不是网格线**。把背景的图案整个倒出来，里面画的是**圆点**：

```html
<pattern id="pattern-1" x="1.71" y="-13.26" width="16.0517" height="16.0517"
         patternUnits="userSpaceOnUse" patternTransform="translate(-8.0259,-8.0259)">
  <circle cx="0.2293" cy="0.2293" r="0.2293" class="react-flow__background-pattern dots"></circle>
</pattern>
```

- 点**半径 0.5 个画布单位**、**间距 35 个画布单位**；
- ⭐ `x` / `y` 属性**随画布平移不断变化** ⇒ 这一片点阵**没有固定相位**，
  画布里并不存在「每 35 个单位一条线」。

**那节点到底吸附到哪儿？** 吸到 **12 个画布单位**的格点上，
和背景那一片 35 间距的圆点**没有对应关系**。别拿圆点当格线去对位。

> ⚠️ 这两个数（圆点间距 `35` / 吸附格距 `12`）很容易互相认错：
> 查 DOM 时两处都会冒出 `pattern`，一个画点、一个管吸附，**不是同一个东西**。

**症状**：成组后点组操作条上的「转分镜组」，或者按快捷键 `⌘⌥G` 合并分镜组，画布毫无变化，也没有任何提示。

**这不是你操作错了。** 本手册推测它只在特定条件下（比如故事板模式下）才可用 📖，但**没有在那个条件下试过**，所以无法告诉你怎么触发。

## 连线拖不出来

**症状**：从出口拖到入口，松手后没有连线。

**原因**：三件事之一 ——

1. **两张节点完全重叠**。从「+」建出来的节点一律落在同一个位置，两张卡叠在一起时两个端口坐标几乎重合，拖拽被当成空操作。实测两张叠放的节点端口坐标只差 1 像素。
2. **方向接反了**。必须**右出左进**。
3. ⭐ **你盯着的那条边上根本没画连接口**。那枚 ⊕ 图标**默认 `opacity: 0`**，**鼠标不在它那一带、节点也没被选中时，它就是不显形**的 —— 看上去「这节点没有出口」，其实只是还没点亮。

**修**：

- 先把**鼠标移到那个节点的左右边缘**（不用点，划过就现形）—— 见上面第 3 条；
- 再用**双击画布空白处**把节点建在不同的位置（面板会锚在双击点），避免重叠。

> 💡 显形是**逐节点**的：同一时刻只有光标指着（或已选中）的那一个会亮，其余照旧是空的。
>
> ![九个节点里只有光标正停着的那个亮出两个圆圈，其余边上什么都没有](screenshots/M-201-只点亮光标所在节点.png)
>
> 💡 出来后别去死磕那个小圆点：真正能点的不是它，是**套在里面的一个 `80×80` 透明圆形**。
> 节点左右边缘往外一带的 80 像素内随手拖，都能起线。
>
> ![鼠标悬停在出口上（还没点选），带加号的圆圈已经浮出来了](screenshots/M-200-连接口-悬停未选中.png)

## ⭐ 找不到「删除连线」的按钮

**症状**：想把一根线断开，鼠标在连线上来回划，**什么都没冒出来**。

**原因**：这枚按钮**确实极难被发现**，但不是没有。四条实测：

| 它是什么样 | 所以你才会找不到 |
|---|---|
| 是个 `div`，**不是** `<button>`，也没有 `aria-label` / `title` / `role` | 它不在任何「按钮列表」里 |
| **只在指针悬停时挂载**，指针一移开就卸载 | 不划着它就查不到 |
| 藏在 `foreignObject` 里 | 按标签名或按可见区域找都容易漏 |
| 悬停后线会**亮成浅蓝**，中点浮出一枚**圆形剪刀** | 不盯着线看会以为什么都没变 |

**修**（两条路都实测能断，挑顺手的）：

1. 把鼠标**停在那根线上别动**（不用点选），中点会浮出一枚剪刀，**点它一下就断**；
2. 或者**点一下把线选中**（线会变成选中态），按 `Delete` 或 `Backspace` —— 面板上那个笼统的「删除 ⌫」对连线也生效。

> ⚠️ 两种都**没有确认框**。好在断了之后按 `⌘Z` 能**原样接回来**。
> 断完刷新页面也不会自己回来 —— 那是真断了。

## ⭐ 误删了节点或连线，找不到「回收站」

**症状**：删错了，想去回收站捞回来，翻遍界面找不到垃圾桶。

**原因**：⭐ **LibTV 画布里没有画布级回收站。** 这一条是**逐处查过的阴性结论**，不是「没找到」：

| 底栏那枚**生成历史**按钮 | 全部画布 / 本画布 · 图片 / 视频 / 音频 计数 · 所有评级 · 时间倒序 · 批量操作 | 无（它管的是**生成记录**，不是删除记录）。⚠️ 它底部那个红色的 `删除` 删的是**历史记录**，不是画布上的节点 —— 别混。详见 [生成历史](10-tasks/generate-history.md) |

| 资产管理抽屉 | `画布` / `资产` 两个页签 | 无 |
| 页面资源路径 | 含 `trash` / `recycle` / `bin` / `history` / `undo` 的请求 | **0 条** |

**修**：

1. ⛔ **先分清你删的是「连线」还是「节点」—— 两者的可撤销性完全不同**：

   | 删掉的东西 | 有确认框吗 | `⌘Z` 能撤回来吗 | 证据 |
   |---|---|---|---|
   | **连线** | 没有 | ✅ **能** —— 原样接回来，刷新也不会自己回来 | [connect-nodes.md](10-tasks/connect-nodes.md#断开连线) |
   | **节点** | ⛔ **没有，点完立刻消失** | ⛔ **撤不回来** | 见下方「本轮实测」 |

2. 撤销用完了、或者已经刷新过页面 → **没有别的地方可以捞**，只能重建。
   所以**大动作之前先想清楚**。

> ⭐ **节点删了撤不回来** —— 本轮实测（Batch ED，代价是一个基线节点）

这不再是源码推断，是**真的删掉了一个节点**换来的读数。逐项记下：

| 检查项 | 读到的结果 |
|---|---|
| 二次确认框 | ⛔ **没有**。选中一个普通节点按 `Delete`，`.mantine-Modal-content` **一个都没出现**，节点**当场消失**（画布 11 → 10） |
| `⌘Z` 撤销（第 1 次） | ❌ 无效，节点数仍 10 |
| `⌘Z` 撤销（第 2、3 次） | ❌ 仍无效 |
| 按 `⌘Z` 前焦点在哪 | ⚠️ 开屏时焦点在底栏某枚 `BUTTON` 上；**先点画布空白处把焦点交回 `BODY`**（这一步做了，焦点确实变成 `BODY`）——**焦点不是原因** |
| 刷新后 | 节点数仍是 10，**撤销栈不跨会话** |
| 画布级回收站 | 无（见上表，逐处查过） |

> 之前那轮是从 `⋯ → 删除` 菜单测的，本轮是**选中节点直接按 `Delete`**，
> **两条不同的删除路径，结论相同：都撤不回来。**
>
> ⭐⭐ **但「没有确认框」这句话要加限定条件**（源码 `3-mou5v69wxmq.js` 查清）：
>
> | 你删的是哪类节点 | 有确认框吗 | 框的标题 |
> |---|---|---|

> | 脚本节点（`SCRIPT` / `SCRIPT_V2`） | ✅ 有 | `确认删除` |
> | 视频节点，且它**被「创意片头」用过** | ✅ 有 | `确认删除该节点？` |
> | **分镜组** | ✅ 有 | `删除分镜图组` / `删除分镜视频组` / `删除分镜组` |
>
> ⇒ **正因为「删普通节点不给你任何提示」，它才是真正危险的那一种。**
> 脚本 / 创意片头 / 分镜组至少会弹一次框让你看一眼。
>
> ⭐ **无论哪一类，按钮都是同一对**：`确定删除` / `取消`。
> （文案表里另有 `继续删除` / `放弃` 两个键，但删除节点这条路径**没有用它们**。）
>
> ⚠️ **还有一个反直觉的点**：确认框里**写着「可通过 `⌘Z` 撤销」**
> （脚本节点那套的正文原文：「删除当前节点后，数据可能会丢失，也可通过 `⌘Z` 撤销。确定要删除吗？」）
> —— ⛔ **但本轮实测，删掉之后 `⌘Z` 真的撤不回来。**
> ⇒ **别信这句话**，它是文案，不是承诺。
>
> ⭐ 所以**删节点这件事，在 LibTV 画布里是真正不可逆的**。
> 连线至少还能 `⌘Z`，**节点连这个都没有。**

> 💡 **唯一能救回来的办法是「自己重建」**：底部工具条中央那枚 `+` → 选节点类型。
> 本轮就是这么把误删的音频节点补回来的 —— ⛔ 但**救不回原来那个**：
> 新建的节点是**新的 id**（原 `a-CUfJfmKzUJ` → 新 `a-GgqvrVz0pw`），
> 和它连过的线**不会自动接回来**，节点里的内容也没了。
> ⇒ **能拖到连线的那一步之前，先看一眼要删的是哪一个。**

> 💡 「生成历史」听起来像回收站，但它存的是**你生成过的图片/视频/音频**，
> 和「被你删掉的节点/连线」是两回事。

> ⭐ 顺带更正一个很容易想当然的说法：**面板上写着 `⌫ 删除`，不代表它管所有东西** ——
> 同理，`⌘L` 写着「连线」是**加线**的意思，不是断线。断线在连线上。

## 明明拖出了预览线，松手却没连上

**症状**：从出口拖出去，那条蓝色曲线**跟着光标跑了**，看着完全正常；可一松手，**连线数没变**。

**原因**：**这一对节点已经连过了** —— 同一对之间连不出第二根线。

这一点做过**阳性 + 阴性配对**的对照：两次拖的是**完全相同的动作**（手势、坐标、时长都一样），
只有「这一对已经连过没有」不同：

| | 拖到一半 | 松手之后 |
|---|---|---|
| 第 1 遍（还没连过） | 预览线出现 | 连线数 **+1** |
| 第 2 遍（已经连过） | **预览线照样出现** | 连线数 **不变** |

**分辨办法**：往回退一步，看**拖到一半有没有预览线**。

| 拖到一半 | 含义 |
|---|---|
| 有蓝色曲线跟手 | 手势被识别了，问题在**松手那一下**（多半是重复连） |
| 完全没有曲线 | 手势**没被识别** —— 多半是没对准端口，往[连线拖不出来](#连线拖不出来)那条走 |

> ⚠️ **界面不会给你任何提示**：重复连线时松手既不弹窗，落点也不变色
> （落点处的 `valid` / `connectable` 类名两次读到的都是空的）。
> 所以它看起来就像「卡住了」。

## 节点参数条上有按钮点了没反应

**症状**：选中一个节点，底部那排按钮点几枚都没动静 —— 不弹面板、不报错。

**原因**：**三枚按钮都有「前置条件」，行为各不相同**，得先分清是哪一种：

| 按钮 | 什么时候没反应 | 你会看到什么 |
|---|---|---|
| `📄` **提示词优化**（**只有视频节点有**） | 提示词是空的 | 顶部弹一条提示「**提示词为空，请输入内容后点击**」 |
| `文A` **翻译提示词**（四类节点都有） | 提示词为空 | 顶部弹一条提示「**提示词为空，请输入内容后点击**」（与 `提示词优化` **逐字相同**） |
| 最右白圆按钮（**生成**） | 条件没满足 | 按钮**变灰**，`cursor` 变 `not-allowed` |

**修**：

1. **先写点提示词** —— 三枚里有两枚都是这个前置条件；
2. **分不清是哪一枚就把鼠标停在上面等一秒** —— 悬停提示会直接写出它的名字
   （`提示词优化` / `翻译提示词`），不用猜图标；
3. **生成按钮灰着时，悬停它会告诉你缺什么**：
   - 音频节点写「请输入提示词**或添加参考素材**」——
     意思是**光有文字还不够，加个参考音频也能生成**；
   - 文本节点写「请输入提示词」。

> 💡 「点了没反应」和「它本来就点不动」在界面上长得一模一样。
> 区别只有一个：**灰的那枚会告诉你缺什么** —— 先读这句，比反复点省事。
>
> ⭐ `提示词优化` 和 `翻译提示词` 是**一对孪生按钮**：提示词为空时，
> **两者弹出的是同一条提示、同一句话**，都写「提示词为空，请输入内容后点击」。
> 也就是说 —— 弹了这条提示，就说明你缺的是提示词，**跟按的是哪一枚无关**。
>
> ⭐⭐ **注意：这两枚在提示词为空时并没有变灰**（实测 `disabled` 仍是关的），
> 所以「它亮着」**不能**推出「它现在就能干活」。
> 真正会变灰的是**生成按钮** —— 那是唯一一枚**用灰度告诉你条件没满足**的。
>
> ⚠️ 反过来，**亮着的不代表随便点**：
> 生成按钮一旦点亮，点下去就**真的会扣积分**（视频 135 / 图片 15 / 音频 1）。

## 「提示词框打不进字」/「打完字刷新就没了」

**症状**：想在节点的提示词框里写点什么，结果敲了半天没反应；或者写了、刷新一下内容不见了。

**原因**：四条实测出来的规矩，每一条都对应一个真实的坑。

| 现象 | 实测 |
|---|---|
| ⭐ **它不是多行输入框** | 提示词框**不是 `textarea`**，是一块 `contenteditable="true"` 的 `div`。用「页面上有没有 `<textarea>`」去找它，**必然找不到** —— 本手册前几轮就是这么把「找不到」写成了 📖 |
| ⭐ **不选中就没有** | 提示词框**只在节点被选中时**才渲染。没选中时扫全页，读到的就是「0 个」 —— 那是**没选中**，不是**不存在** |
| ⭐ **它常常在画面外** | 选中之后，它常常落在**视口下沿之外**（读到的坐标是 `y≈803~842`，而画面高只有 810）。这时你**看得见节点、看不见输入框**，点不到也正常 |
| ⭐⭐ **打字是立刻存盘的** | 往框里打字之后**刷新，内容还在** —— 也就是说它**每敲一下就在存**。没有「保存」按钮，也没有「确定」 |

![文本节点的提示词框里已经写进了一句话：节点下方那块圆角输入区域里逐字显示着刚输入的英文句子，左上角是模型名 `GVLM 3.1`，右侧是参数条上的一排小按钮，最右那枚白色圆形按钮此刻是灰的](screenshots/M-300-文本节点-提示词框写进内容之后.png)

> ⭐⭐ **最后这一条对用户最要紧**：因为打字即存盘，
> **「先随便打点字看看」这种习惯会真的改掉你的画布**。
> 本手册自己就踩了 —— 测试文本落进了一个节点，**只能靠事后逐字删掉才能还原**。

![清空之后重新刷新复核：同一个文本节点的提示词框重新变成空白，节点本身和其它节点的位置都没动](screenshots/M-301-文本节点-提示词已清空-刷新后复核.png)

**怎么把框挪进画面里**：

1. 选中那个节点；
2. 按 `⌘0`（**适合屏幕**）把整张画布收进画面；
3. 还够不着就用**中键拖拽**平移画布 —— 提示词框在节点的**正下方**，所以要**往下**拖；
4. ⛔ 缩放菜单里**没有 35% 这一档** —— 只有 `缩放至50%` / `缩放至100%` / `缩放至800%`。
   想要更小就**连按 `⌘-`**。

> ⚠️ 本手册早期有一处写着「缩到 35% 后就能读到」—— **这个说法要改**：
> 菜单里根本没有 35% 这一档，35% 是**连按 `⌘-`** 缩出来的，不是从菜单里选的。

> ✅ **这一条已经测到了**（后来换了认按钮的办法：按**图标形状**认，不按坐标认）。
> 「翻译提示词」**有内容时会把整句翻译成中文并原地替换** —— 详见下一节。
> 本手册早期写的「测不到」是因为**没把点击落到那枚按钮上**，
> 不是因为这枚按钮没用 —— 这两件事完全不同。

## ⭐⭐ 「翻译提示词」到底会把提示词改成什么

**答案：整句翻译成中文，然后原地替换掉你写的原文。**

![点完「翻译提示词」之后：节点的提示词框里原本那句英文已经变成「一只猫坐在温暖的窗台上，迎接日出。」，框的右上角多出一枚斜向双箭头的展开图标，节点名「文本节点 1」还在上方](screenshots/M-306-翻译提示词-点之后变成中文.png)

![点「翻译提示词」之前：节点的提示词框里逐字显示着刚输入的英文句子 a cat sitting on a warm windowsill at sunrise，框右上角还没有展开图标](screenshots/M-305-翻译提示词-点之前是英文.png)

实测（`GVLM 3.1` 的文本节点）：

| | 读数 |
|---|---|
| 点之前 | `a cat sitting on a warm windowsill at sunrise` |
| 点之后 | **`一只猫坐在温暖的窗台上，迎接日出。`** |
| 要等多久 | ⭐ **约 5–6 秒**。连着采样 9 次：前 7 次**原文一字未动**，第 8 次才变成中文 |
| 有没有提示 | **没有**。不弹浮层、不弹 toast、不给「翻译中」 |
| 扣不扣积分 | ⭐ **不扣**。顶栏余额点前 `20`、点后 `20` |
| 原文还在不在 | ⛔ **没了**。它是被**替换**掉的，不是追加在后面 |

> ⭐⭐ **同一句话翻两次，措辞不一样** ——
> 第一次得到 `一只猫在日出时坐在温暖的窗台上`，
> 第二次得到 `一只猫坐在温暖的窗台上，迎接日出。`。
> 所以它**不是固定词表查表**，是**模型意译** ——
> 想要某个特定说法，翻译完**自己再改**，别指望每次都一样。

> ⛔ **因为「打字立刻存盘」，翻译结果也是立刻存盘的。**
> 而且原文被替换后**没有地方可以找回** ——
> 想保留英文原文，**先把原文复制到别处**再点这枚按钮。

> 💡 也就是说：**这枚按钮「没反应」不是坏了，是它在干活。**

但它做的**不是收起** —— ⭐⭐ 它是**弹出了一个居中的大编辑器**：
一块 `800×600` 的浮层盖在屏幕正中，后面还压着一层把画布变暗的黑色遮罩。
**节点里那张卡片是被这个浮层顶掉的，不是被折起来的。**

![点开参数卡片右上角的 `⤢` 之后：整块画布被压暗，正中浮出 800×600 的大编辑器](screenshots/M-332-点⤢打开节点大编辑器.png)

**修**：✅ **点大编辑器外面那层压暗的黑色遮罩**（屏幕四角任意一处），
或者点它**右上角那枚收拢箭头**（`28×28`）。节点那张卡片就回来了。

> ⛔ **`ESC` 关不掉它。** 实测按下 `ESC` 浮层纹丝不动。
>
> ⛔ **点大编辑器以内关不掉。** 屏幕正中那块 `800×600` 里的任何点击都会被浮层吃掉。

> ⚠️ **「点一下节点标题」有时管用、有时不管用 —— 这不是玄学。**
> 标题栏只要**落在那块 `800×600` 之外**，点它就等于点遮罩，浮层会关；
> 一旦**被浮层盖住**，点它就是点进浮层里，什么都不会发生。三条实测：
>
> | 节点 | 标题位置 | 在浮层内？ | 点标题 |
> |---|---|---|---|
> | 视频 `智能剪辑 4` | `(1018, 22)` | ⛔ 浮层外 | ✅ 关掉了（`45 → 104`） |
> | 文本 `文本节点 1` | `(263, 596)` | ⛔ 浮层外 | ✅ 关掉了（`46 → 83`） |
> | 图片 `图片节点 2` | `(877, 304)` | ✅ **浮层内** | ⛔ 没反应（`39 → 39`） |
>
> 👉 **别赌这一招，直接点屏幕角落的遮罩。**

> ⭐ 三件让你放心的事：
> ① **它不扣积分**（实测顶栏 `20 → 20`）；
> ② **它不存盘** —— 刷新页面后遮罩和浮层都会消失，节点回到**未选中**状态；
> ③ 你的提示词、参考图、模型、规格**一个都没丢**，关掉浮层就全回来了。
>
> ⚠️ **别把刷新后的样子误当成「还收着」**：刷新后节点确实也没有卡片，
> 但那是因为**节点取消了选中**（实测 `选中: false`），不是卡片被收起来了 ——
> 再点一下节点，卡片照常出现。

> ⚠️⚠️ **如果 `⤢` 点了根本没反应**（不是打开浮层，而是毫无动静），
> 十有八九是**被别的东西盖住了**。三种都实测过：
>
> | 原因 | 读数 | 怎么办 |
> |---|---|---|
> | TV Director 抽屉开着 | 抽屉占 `[1024, 154, 400×640]`，`⤢` 正好落在 `[1022, 217]` | 先把抽屉收起来（点它右上角的「—」或无障碍名 `关闭` 的按钮） |
> | 画布底栏压住按钮下半截 | 底栏是一枚 `fixed`、压在 `z-index: 20` 上的 `[571, 748, 299×50]` 工具条 | ⭐ 点的时候**往上偏 8px**（实测：点 `(708, 748)` 没反应，点 `(708, 740)` 正常） |
> | 节点太靠右，`⤢` 跑出视口 | 那个文本节点的 `⤢` 在 `x=1566`，而视口只有 `1440` 宽 | ⭐ **先把节点拖到画布中间再点** |

> ⭐⭐ **这一节此前写的是「`⤢` 把卡片收起来」，还派生出一串「点标题恢复 / 收起用不回来 /
> 文本节点不工作 / 刷新不管用」的结论 —— 全部撤回。** 真实机制是上面那一条。
> 一连错这么多轮，是因为只量了「卡片在不在」，而「卡片不在」有**两个成因**
> （浮层开着、节点没选中），只量它必然读出假的稳定值。

## ⭐⭐⭐ 空画布上最右边那枚「生成芯片」点了没反应

**症状**：新画布一打开，中间横着一排五张卡片（图片生成 / 视频生成 / 音频生成 / 剧本生成 / 智能剪辑）。前四张点了都建出节点，**唯独最右边那张「智能剪辑」点了毫无动静** —— 有时还像是什么都没点。

**原因**：⭐⭐ **这不是你点歪了，是它被 TV Director 对话抽屉压住了。**

- 抽屉固定贴在视口**右侧**，宽度恒定 **398px**；
- 芯片那一排在画布**正中央**，视口越窄它越往左挪；
- 两者一重叠，抽屉的层级更高，**点击就落到了抽屉上**。

实测各视口宽下被压住的情况（视口高固定 810）：

| 窗口宽度 | 抽屉左边缘 | 芯片排最左一枚 | **点不到的几枚** |
|---|---|---|---|
| 1440 | 1025 | 204 | 第 ⑤ 枚「智能剪辑」 |
| 1280 | 865 | 124 | 第 ⑤ 枚「智能剪辑」 |
| 1100 | 685 | 34 | ⭐ 第 ④「剧本生成」+ 第 ⑤「智能剪辑」 |

⇒ ⭐ **窗口越窄，被压住的越多。** 1440 宽只坏一枚，1100 宽就坏两枚。

**修**：⭐ **点那几枚之前，先把右侧的 TV Director 抽屉关掉**：

- 按 `Esc`；
- 或点抽屉右上角那枚「✕」关闭键。

实测关掉之后，同一枚芯片立刻恢复可点（按下去时命中的是卡片本身而不是抽屉）。

> 💡 **认自己是不是被挡了**：点之前把鼠标移过去，被压住的那张**不会有任何悬停反馈**，而能点的四张会变色。
>
> ⛔ 更省事的办法：**用双击画布或底部「+」打开添加节点面板**建智能剪辑节点 —— 那条路完全不受抽屉影响（见 [10-tasks/create-nodes.md](10-tasks/create-nodes.md)）。

## ⭐⭐ 故事板里右下角那枚「剪辑」按钮点不到

> ✅ 「剪辑」点开是什么，已验：它会就地变成一整块内嵌的**时间轴剪辑器**，

## ⭐⭐ 故事板里点开一张卡之后，再点下一张没反应

**症状**：切到故事板，点了一张卡，卡片撑开变成编辑态（顶栏变成「‹ 节点名」，
底下出现提示框和一枚白色 ↑ 键）。你关掉提示框，改点旁边另一列的卡片 —— **什么都不会发生**。

**原因**：⭐⭐ **编辑态的面板会盖住旁边的列。**

三块面板的实测框分别是 `[512, 609, 903, 188]`（音频）、
`[512, 605, 903, 192]`（图片）、`[512, 549, 903, 248]`（视频）——
**宽都是 903，左边缘都是 `x = 512`**，而图片列的左边缘正好也是 `495`。
⇒ 面板**一律向左溢出，把图片列整块盖在下面**。

你想点的下一张卡如果落在图片列，它此刻在面板底下，
那一点击被面板自己吃掉了。

**修**：

1. ⭐ **先按 `Esc`**（或点面板右上角的 `✕`）关掉当前编辑态。
2. 等面板消失再点下一张。
3. 💡 想同时看两张卡，只能**切回工作流态**去点节点，
   或者在故事板里点**同一列**的另一张（同一列的其它卡在面板右边，没被盖住）。

> ⚠️ 别被「点了没反应」骗了以为那张卡坏了。**先 `Esc`，再重试一次。**

## ⭐⭐⭐ 点了列头的「放大」，另一列整个不见了

**症状**：切到故事板，最右边并排着「图片」和「视频」两列。你点视频列头右上角那枚
放大镜（`放大视频`），想着把视频看大一点 —— 结果**半张屏幕只剩「视频」一列，
两个图片节点一张都看不见了**。你在空白处怎么滚都翻不出来。

**原因**：⭐⭐⭐ **这个功能是坏的，不管点哪一枚都一样。**

放大时**两列被拉到完全相同的框** `[495, 48, 937, 762]`，后渲染的那列盖住前一个：

| 你点的 | 活下来的是 | 消失的是 |
|---|---|---|
| `放大视频` | 视频列 | ⛔ 整列图片节点 |
| `放大图片` | 图片列 | ⛔ 整列视频节点 |

而且放大态下两枚收起键的**框也变成完全相同的 `[1387,57,28,28]`**，重叠在一起 ——
**只有活下来那列的收起键点得到**，另一枚点下去什么都不会发生。

**修**：

1. ⭐ **直接按 `Esc`** 还原。实测三种状态来回切，四列的框逐字相同，**一定能还原干净**。
2. ⛔ **别去点收起键** —— 两枚重叠，你分不清点到的会是谁，
   运气不好会「关掉」你以为在放大的那一列。
3. ⭐⭐ **不要用 `Esc` 去关「全部 ▾」筛选菜单** ——
   实测在放大态里按 `Esc` 关菜单，会**把放大态一起关掉**。
   想关菜单，**点菜单外面**。

> 📖 这个「放大」在源代码里本来的设计是只放大一列、另一列缩窄
> （`StoryboardBoard.tsx:173-175`），但那个文件自己标了 `CLONE_DECISION`，
> 线上 DOM 里连 `data-storyboard-expand` 属性都没有 ⇒ **线上跑的确实不是这份代码**。

## ⭐⭐ 剪辑器里的「导出」按钮明明能点，点它却说合不成

**症状**：在故事板视频列点右下角那枚 `剪辑`，打开时间轴剪辑器，
右上角有一枚白底 **`导出 ▾`**。它看着完全正常 —— 不灰、鼠标是手型 —— 你点它。

**原因**：⭐⭐ **按钮没有被禁用**（实测 `disabled = false`、`cursor: pointer`），
但它的悬停提示已经写明了：**`时间轴上暂无片段，无法合成`**。

⇒ **时间轴是空的**。视频列里那些卡片都还写着「待确认后生成」，
**没有真实视频文件，时间轴上就没有片段**，自然合不成。

**修**：

1. 👉 **先让视频列里出现真实产物**，时间轴上才会有片段。
   这一步要真的跑生成 —— ⛔ 本手册没有跑过，所以「有片段之后导出是什么样」**没有验证** 📖。
2. ⛔ **在视频产物出来之前，不要点「导出」**。
3. ⭐ 想知道能不能点，**把鼠标悬停在按钮上读那行提示**就行，
   不必真的按下去。

> 💡 同一块工具条里，**前五枚（撤销 / 重做 / 分割 / 向左裁剪 / 向右裁剪）
> 全都是灰的**，原因一样：时间轴为空。
> 真正亮着的编辑类按钮只有三枚：`添加文字` / `添加字幕` / `添加转场`。

## ⭐ 「剧本生成」芯片点开的是一块题材抽屉，不是节点

**症状**：空画布上点第 ④ 枚「剧本生成」，**画布上什么都没多出来**，右边倒是滑出一块面板。

**原因**：⭐ **这是对的，不是 bug。** 五枚芯片里只有它是这个行为 —— 另外四枚（图片 / 视频 / 音频 / 智能剪辑）都是直接建出对应类型的节点，唯独「剧本生成」是**开抽屉让你挑题材**的。

抽屉里逐字是：

- 标题 `新对话`，副标题 `从爆款题材开始`；
- **八个题材，每个带一个热度名次徽标**：`#1` 玄幻修仙逆袭 · `#5` 古代女频甜宠 · `#2` 现实职场成长 · `#6` 规则怪谈悬疑 · `#3` 末世生存基建 · `#7` 重生复仇爽剧 · `#4` 非遗国潮视觉 · `#8` 仙门团宠日常；
- 底部标着 `剧本设定器` / `剧本创编 · 原创` / 模型 `Doubao Seed Evolving`。

⚠️ **徽标上的数字是热度名次，不是排列顺序**（屏幕上从左到右是 1、5、2、6、3、7、4、8）。别当成「第一行就是第一名」来读。

**修**：

- 想**从题材起步** ⇒ 在这块抽屉里挑一个继续；
- 想要**一个空的脚本节点** ⇒ 这枚芯片给不了，改用**双击画布**或底部「**+**」打开添加节点面板。

> 📌 附带一条：芯片**一被点就没了** —— 点掉第一枚之后，剩下四枚在页面上直接消失（不是变灰，是整个元素没了）。所以五枚只能选一个；想建别的类型就删掉刚才那个再回来看。

|---|---|---|
| **「此协作画布已在其他标签页打开」** | `collabSessionExpiredDescription` | ⭐⭐⭐ **同一张画布不能在两个标签页同时编辑。** 你多半是把同一张画布在两个标签/两个窗口都打开了 |
| 「协作会话已过期」 | `collabSessionExpiredTitle` | 上面那句的标题 |
| 「会话已过期」 | `sessionExpiredTitle` | 单画布的编辑会话断了 |
| 「请刷新页面以继续编辑」 | `sessionExpiredHelper` | 上面那句的副标题 |
| ⭐ **「您的修改已被撤回（节点正在被他人编辑）」** | `lockPendingDenied` | **别人正在编辑同一个节点**，你那边的改动被系统退回来了 |
| ⭐ 「其他成员正在编辑该节点，无法复制」 | `nodeLockedCannotCopy` | ⭐ **节点级锁**：有人正在改这个节点，你连复制都不行 |
| 「其他成员正在编辑该节点，无法复制图片」 | `nodeLockedCannotCopyImage` | 同上，图片版 |
| ⭐ 「该节点已被其他成员更新，已为你重新加载最新内容」 | `v4AbortHandlerLoadingNode` | 别人先改完了，**系统自动帮你把节点刷新成最新的** |
| 「节点已同步，正在重新加载…」 | `v4AbortHandlerLoadingNodeProcessing` | 正在刷 |
| ⭐ 「画布版本已更新，请刷新页面以继续编辑」 | `v4AbortHandlerEditRefreshCanvasResume` | ⭐ **整张画布的版本被推进了**，要刷新才能接着改 |
| 「收到来自更新版本的协作消息，请刷新页面」 | `v4AbortHandlerRefreshCollabPlease` | 同上 |
| ⭐ 「对方正在跟随你，无需再跟随 TA」 | `useCollabPresenceProcessing2` | **「跟随」是双向的** —— 你在跟随别人时，对方也能跟随你 |

### ⭐ 怎么应付

| 症状 | 怎么办 |
|---|---|
| ⛔ 「此协作画布已在其他标签页打开」 | **把另一个标签页/窗口关掉**（或那边先退出版本），再刷新这一页。⭐ 这不是「画布坏了」，也不用新建画布 |
| 「画布版本已更新，请刷新页面」 | 刷新。⭐ 刷新**不会**丢你的节点（节点坐标是落盘的），但**没提交的生成任务可能会中断** |
| 「您的修改已被撤回」 | ⭐ 等对方松开那个节点，或者换个节点改。**这不是 bug，是节点级锁** |
| 「其他成员正在编辑该节点，无法复制」 | 同上，只能等 |

> ⚠️ **一个必须说清的边界**：
> 上表是**从真实生产 bundle 的文案表里读出来的**，
> ⛔ **本手册没有在界面上实测过**其中任何一条（要复现必须真的开两个会话抢同一个节点，
> 属于会影响别人的操作）。
> ⭐ 所以这些只能说明**产品有这些提示、且文案是这样写的**，
> ⛔ **不等于**「每一条的触发条件都和文案暗示的一样」。
> 需要确认触发条件时，**看源码**（`docs/research/` 下抓下来的真实 bundle）比看界面可靠。

> ⭐⭐ 反过来，这条对**自动化脚本**是个大坑：
> ⭐ **`lib.mjs` 里那个 `isEditorLocked` 名字起错了** —— 它检测的是
> 「会话已过期」+「请刷新页面以继续编辑」，而这两句**不是**画布锁，是**协作会话过期**。
> ⭐ 真正的「画布被占了」是另一句：**「此协作画布已在其他标签页打开」**。
> ⭐ 反复用无头浏览器打开同一张画布时，前一个会话没关干净就会被这句挡下来 ——
> **这正是它容易「莫名其妙打不开」的原因。**
