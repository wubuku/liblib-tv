# 创建节点：九类节点与它们各自能调什么

> 目标：知道该建哪种节点，建完之后每个旋钮是干什么的。
> 适用角色：普通创作者 · 验证状态：✅ 九类节点全部实跑建出；⚠️ **一次都没有提交过生成**

## 两种建节点的入口

| 入口 | 操作 | 节点落点 |
|---|---|---|
| 添加节点面板 | 点底部工具条最左的「+」 | 固定落在同一个位置 |
| 双击画布 | 在空白处**双击**，再选类型 | **锚在双击点** |

两种入口弹出的是**同一个面板**（下方那张图就是双击弹出的），只是锚点不同。想把节点摆到画布某个特定位置，用双击。

![我的工具箱：标题旁有一枚 ? 说明图标，右上角 ×，下面是三列卡片网格，每张是预览图加名称（【预设】左弧滑行 / 【预设】电商手机弹出效果 / 【预设】咖啡杯出场 / 【预设】360旋转展示 / 【预设】机械臂视角 / 【预设】Live 2D …）](../screenshots/M-129-工具箱弹窗.png)

| 观察 | 实测 |
|---|---|
| 卡片数 | 本次读到 **28** 张 |
| 平台预设的命名 | 一律带前缀 **`【预设】`** —— `【预设】左弧滑行`、`【预设】咖啡杯出场`、`【预设】Live 2D`、`【预设】旅拍转场 zoom in`… |
| 自己建的 | **不带**前缀，本账户的是 `手册取证测试箱` |
| 标题旁 | 一枚 `?` 圆形图标（无障碍名「工具箱模板说明」） |
| 关闭 | 右上角 `×`（`24×24`，无文字无无障碍名 —— 第几次了） |

#### 「使用」按钮要悬停才看得见

每张卡片右下角都有一枚 `使用` 按钮（`50×24`），但**平时看不见**：

![悬停到「【预设】左弧滑行」那张卡片之后：图片变暗，中央浮出半透明的「使用」按钮](../screenshots/M-131-工具箱-悬停显示使用.png)

这里有个**容易判错的地方**，本手册专门量过两次：

| 读数 | 未悬停 | 悬停后 |
|---|---|---|
| 按钮 `opacity` | `1` | `1` |
| `display` / `visibility` | `flex` / `visible` | `flex` / `visible` |
| 看得见吗 | **否** | 是 |

也就是说 —— 它**不是**故事板那种「`opacity: 0` 悬停变 1」，
而是**一直实实在在、只是被预览图压在下面**，悬停时才浮到图上面。
所以拿「按钮在不在 DOM 里 / opacity 多少」判断它，**一定会判错**。

> 本手册**没有点过任何一枚「使用」** —— 点了会把工具箱套到画布上，属于写操作。

## 节点里的「高级设置」

先说清楚一件容易误会的事：**参数面板不是节点卡片的一部分，是挂在节点下方的一张独立卡片。**

![视频节点本体在上，整块参数面板挂在它下面，中间有明显间隙](../screenshots/M-20-参数面板挂在节点下方.png)

实测框的位置关系（1440×810 视口）：

| 部分 | 说明 |
|---|---|
| 节点本体 | 视频 `311×175`、音频 `175×175`（50% 缩放下实测） |
| 节点标题浮条 | 节点上方一条 `263×20` 的小条（`⏵ 视频节点 3`），class `node-floating-ui transition-[transform,opacity]` |
| 参数面板 | 节点下方一张约 `660` 宽的独立卡片 |

> ⚠️ **两个 float 的 class 都在 `node-floating-ui` 家族里，但它们不是同一个东西**：
> 那条 20px 高的**标题浮条**才是 `node-floating-ui`；
> 真正的**参数面板**是另一张 660 宽的卡片。找面板时别拿 `node-floating-ui` 当判据 —— 会量到标题条。

所以 `⌘0`（框住所有节点）**只框节点、不框参数面板** —— 面板会挂在框外甚至视口外，
这时候只能靠手动平移把它拉回来。

> **单击节点中央 = 打开/收起参数面板。** 实测图片节点元素数 `42 → 140`（折叠 → 展开）。
>
> ⚠️ **参数面板还有两个前置条件**，本手册花了三轮才摸清：
> 1. **右侧的 TV Director 对话抽屉必须关掉，面板才会渲染。**
>    抽屉开着时，DOM 里照样有完整面板（`innerText` 读得到全文），**画面上一个像素都看不到**。
>    按 `Esc` 能关掉它，**点画布空白关不掉**（实测两次）。
> 2. 面板的**宽度不随画布缩放改变**。缩放 42% 和 50%，`getBoundingClientRect()` 都报 `660` 宽。
>    所以「把画布缩小就能看见面板」这条路不成立。

### 「高级设置」的入口是 `⚙`，不是「高级设置」那四个字

这是最容易走弯路的一处，单独说清楚：

> **入口是参数条右侧那枚 32×32 的滑块图标按钮（`⚙`）。**
> 面板里那行灰色的「高级设置」四个字是**标题**，**点了没有任何反应**。

![视频节点：点开 ⚙ 之后，参数条下方多出「高级设置」分区，里面是 联网搜索 / 自动校验素材 / 智能引用 AutoLink 三个开关，全部处于打开状态；⚙ 本身变成深色高亮态](../screenshots/M-142-视频节点-高级设置展开.png)

上面这张图里能看到三件事：

1. `⚙` 按钮**变成深色高亮态** —— 这是它被打开的视觉信号；
2. 参数条下面出现一条**分隔线**，线下面是灰色的「高级设置」标题；
3. 标题下面就是内容区。视频节点这里是**三个开关，全部默认打开**：
   `联网搜索` · `自动校验素材` · `智能引用 AutoLink`。
   其中 `自动校验素材` 和 `智能引用 AutoLink` **各带一个 `?` 问号图标**（点它有说明），
   `联网搜索` 没有。

音频节点的同一枚 `⚙` 打开的是**三个滑杆**：

![音频节点：点开 ⚙ 之后，「高级设置」分区里是 语速 / 声调 / 音量 三个滑杆，每个滑杆右边跟一个数值框，分别显示 1.00、0、1.0](../screenshots/M-143-音频节点-高级设置展开.png)

| 滑杆 | 当前值 | 取值范围 |
|---|---|---|
| `语速` | `1.00` | `0` – `2` |
| `声调` | `0` | `0` – `12` |
| `音量` | `1.0` | `0` – `10` |

再点一次 `⚙` 就收回去，**是开关（toggle）不是单向展开**。

> ⚠️ **这里更正手册早先的两版说法**：
> ① 「`高级设置` 是可折叠分区、点**那四个字**展开/收起」—— **点它没反应**，
>    正确入口是 `⚙` 那枚图标按钮。
> ② 「音频是 3 个滑杆、**没有**数字输入框」—— **画面上就摆着三个数值框**
>    （`1.00` / `0` / `1.0`）。它们确实不是 `input[type=number]`
>    （实测该选择器恒为 0 个），但**用户是能看见数字的**，
>    手册说「没有数字框」会让人以为看不到数值。
>
> 另外一个小差异：滑杆自己的 `aria-valuenow` 读出来是 `1` / `0` / `1`，
> 而**显示在框里的是 `1.00` / `0` / `1.0`** —— 同一个值，两种写法。

折叠机制本身是在 `grid-template-rows` 的两个值之间切换：

| 状态 | class | `grid-template-rows` 计算值 |
|---|---|---|
| 收起 | `grid-rows-[0fr]` | `0px` |
| 展开 | `grid-rows-[1fr]` | `157px` |

面板高度也跟着变：视频节点 **246px → 411px**。

> 💡 **这一段踩的坑值得记一笔**：我盯着「高级设置」那四个字试了十几轮，
> 每次都点不到（它只是标题），于是先写下「它默认就是展开的」、
> 后来又写下「产品根本没有展开态」—— **两次都是把「我没找到入口」当成了产品事实**。
> 真正的入口一直就在旁边那排图标按钮里，只是没有文字也没有无障碍名，
> 前两轮按文字/aria 找控件时**根本没把它列进候选**。
> **「我点不到」≠「它不存在」**。

## 框选：一次选多个节点

**`Shift` + 在空白处左键拖出一个矩形**，框完整包住的节点会一起被选中。

![按住 Shift 从空白处拖出一个虚线矩形，把两张节点卡都圈进去](../screenshots/K-01-Shift拖动框选.png)

![松开后两张节点卡同时被选中，边框变蓝](../screenshots/K-02-框选结果.png)

> ### ⚠️ 两条最容易踩空的
>
> 1. **在空白处直接左键拖，画布是拖不动的。** 实测鼠标走 220px，视口只挪了 16.3px、纵向一点没动。所以「想框选却拖出一片空白」不是操作错了，是**没按住 `Shift`**。
> 2. **必须框完整包住节点才算选中**，擦着边不算。本手册的验证方式是：先量出两张卡的完整外框，再按外框 +14px 拖，松开后 2 / 2 全中。

框选是成组、解组、批量复制的前置动作 —— 这几个键位只在多选状态下才有意义。

## 成组 / 解组

| 动作 | 键 | 界面上发生了什么 |
|---|---|---|
| 成组 | `⌘G` | 出现一个包住所有成员的框，组名叫 `Group 1` |
| 解组 | `⌘⇧G` | 框消失，成员恢复成独立节点 |

成组后画布上的节点总数会 **+1**（多出来的是组本身），解组后减回去。

### 组操作条

![成组后，组上方浮出一条操作条：颜色圆点、排列、整组执行、添加到工具箱、转分镜组、解组、批量下载](../screenshots/M-08-组操作条全景.png)

**组被选中时**，它上方浮出一条操作条。注意这些按钮**在 DOM 里不是 `<button>`，而是 `div` / `span`**，
所以如果你想用自动化工具按文案找它们，`getByRole('button')` 一律返回空 —— 必须按文字去定位叶子 `div`。

从左到右是 7 个动作，中间夹着 2 条竖分隔线：

| # | 按钮 | 实测结果 |
|---|---|---|
| 1 | 颜色圆点 | ✅ 可用，展开 10 色色板，**选了真的会变色** |
| 2 | `⊞˅` 排列 | ✅ 可用，菜单 3 项，**三种排列都实测生效** |
| — | 竖分隔线 | — |
| 3 | `▶ 整组执行` | ⚠️ **会真的跑生成、扣积分，本手册没点过** |
| 4 | `添加到工具箱` | ✅ 可用，打开「创建/更新工具箱」弹窗 |
| 5 | `转分镜组` | ❌ **灰的**（实测 `opacity: 0.45`），点了什么也不会发生 |
| 6 | `解组` | ✅ 可用 |
| — | 竖分隔线 | — |
| 7 | `⬇ 批量下载` | ❌ 灰的（`opacity: 0.45`，组里还没有生成产物时不可用） |

> `转分镜组` 是灰的，这同时解释了快捷键面板上的 `⌘⌥G 合并分镜组` 为什么按了没反应 ——
> 它对应的是同一个功能，在普通工作流画布上就是不可用的 📖。
> **快捷键面板上的 `⌘⌥G`，本手册实按过，画布毫无变化，也没有任何提示。**

#### 1｜颜色圆点：10 色色板，选了组真的会变色

![点开颜色圆点后浮出的 10 色色板，5 列两行](../screenshots/M-09-组操作条-颜色色板.png)

点最左边那个 20×20 的圆点，浮出一块 **5 列 × 2 行 = 10 个** 圆形色块，每块 36×36：

| 行 | 色板从左到右 |
|---|---|
| 上排 | 灰 `rgb(122,122,122)` · 红 `rgb(231,76,60)` · 橙 `rgb(242,138,46)` · 黄 `rgb(244,183,64)` · 绿 `rgb(46,204,113)` |
| 下排 | 青 `rgb(8,182,221)` · 蓝 `rgb(59,130,246)` · 紫 `rgb(139,92,246)` · 粉 `rgb(246,59,151)` · 白 `rgb(230,230,230)` |

**实测换色**：点第 2 块红色之后，组的框色和底色立刻从 `rgba(255,255,255,0.1)` 变成
`rgba(231,76,60,0.2)` / `rgba(231,76,60,0.1)`，圆点自己也变红，连左上角的 `Group 1` 标签底色一起变红：

![把组改成红色之后：组框、颜色圆点、Group 1 标签都变成红色](../screenshots/M-15-组操作条-选色之后.png)

> **给组上色是最容易被忽略的整理手段。** 一屏里组很多时，先按用途给组分配颜色，
> 后面找东西就不用逐个读组名了。

#### 2｜排列：宫格 / 水平 / 垂直，三种都实测生效

![点开排列按钮后浮出的三项菜单：宫格排列、水平排列、垂直排列](../screenshots/M-14-组操作条-排列菜单.png)

点 `⊞˅` 弹出三个排列方式。**三个都真按过，节点坐标都真的变了**，
节点间距实测 298px = 节点高 270 + 间隙 28。

**水平排列** —— 三个节点排成一行，`y` 全部对齐：

![水平排列后，三个节点在同一行](../screenshots/M-17-排列-水平排列.png)

> 文本 `x=180 → 975`（`+795`）、音频 `x=486 → 677`（`+191`）、图片 `x=792 → 169`（`-623`），
> 三者 `y` 统一到 `273`。

**垂直排列** —— 三个节点排成一列，`x` 全部对齐：

![垂直排列后，三个节点在同一列](../screenshots/M-17-排列-垂直排列.png)

> 图片停在 `x=169, y=273`，音频移到 `x=169, y=571`（`dx=-508, dy=+298`），`x` 统一到 `169`。
> 第三个节点被排到视口外，会从 DOM 里消失（见 [organize-canvas.md](organize-canvas.md) 的虚拟化说明），
> 所以读数只剩两个 —— 这是**读数不全，不是排列出错**。

**宫格排列** —— 排成 2×2 方阵：

![宫格排列后，四个格子里放了三个节点，右下角空着](../screenshots/M-17-排列-宫格排列.png)

> 图片 `(169, 273)` 左上、文本 `(169, 571)` 左下、音频 `(677, 273)` 右上，右下角空着。

排列完之后**组框会跟着变大变小**（水平排列后 `1170 → 1132` 宽；垂直排列后变成 `536 × 945`），
这是正常的：组框本来就是包住成员的动态框。

## 新建节点的另一个入口

焦点在画布上时按 `Tab`，会直接弹出「添加节点」面板，和点 `+` 是同一个面板。

![按 Tab 弹出的「添加节点」面板：文本 / 图片 / 视频 / 智能剪辑 / 导演台 / 逐帧拉片 / 音频 / 脚本 / 素材库 + 添加资源](../screenshots/K-05-Tab新建节点.png)

## 找不到节点时用搜索

按 `⌘F` 打开「搜索画布元素」，输入框边打边筛，底部实时显示「共 N 节点」。

![⌘F 打开的画布节点搜索面板，底部显示「共 4 节点」](../screenshots/K-04-节点搜索.png)

搜索面板**不受视口影响**：即使用 `Space` 把视口拖到离所有节点一万多像素外、画面上一个节点都看不见（见 [organize-canvas.md](organize-canvas.md)），`⌘F` 依然能列出全部节点。**节点很多、又不知道画在哪，这是最可靠的找法。**

## 取消与恢复

- 建错类型：选中节点 → 让焦点回到画布 → `⌘A` 全选 → `⌫` 删除。
  ⚠️ **只选中单个节点时直接按删除键是没用的**，实测 `Delete` 和 `Backspace` 单独按都不生效；必须先点画布空白处让焦点离开输入框，再全选删除。
- 建多了想重来：直接删，不需要「回收站」。
