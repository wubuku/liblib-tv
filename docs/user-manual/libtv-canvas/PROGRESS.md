### M1 已坐实的结论

- **画布下拉**：分区标题 `画布`；行 = `切换到画布 {名称}` + hover 才出现的 `更多操作`；
  活动画布行带 `✓` 勾。`新建画布` 是独立的加号按钮（aria-label），不是行内按钮。
- **新建画布**：新画布命名 `画布 {N}`，插到列表**最前**，并自动切换过去。
- **行级四项**：`在新窗口打开` / `重命名画布` / `复制画布` / `删除画布`。
- **重命名**：点 `重命名画布` 后该行变行内输入框（`aria-label=画布名称`，内容全选），
  回车提交，发出 `POST /api/canvas/project/update`，行名与顶栏标签同时更新。
  **画布改名不影响顶栏「项目名称」输入框**（那层绑的是 spaceId）。
- **复制**：命名规则 `{原名}副本{序号}`，插在**源画布正下方**（不是列表最前），
  并**自动切换到副本**。
- **删除**：二次确认框文案
  `删除画布` / `确定要删除画布「{名称}」吗？此操作不可恢复。` / `取消` `确认`；
  删掉当前活动画布后自动回落到另一张，`projectId` 随之改变。
- **切换画布**：换的是 `projectId`，`spaceId` 不变 → **一张画布 = 一个 projectId**。
- **缩放菜单**：`放大 ⌘+` `缩小 ⌘-` `适合屏幕 ⌘0` + `缩放至50%` `缩放至100%` `缩放至800%`。
- **发布与分享面板**：`发布你的作品和创作过程，让更多创作者看到。` / `分享链接` /
  `拥有此链接的人可以查看并复制你的画布。`（取证只读，未点发布）。
- **故事板模式**：顶部切换后画布换成三列 —— `文本`（暂无文本）/ `图片`（暂无图片）/
  `视频`（暂无视频）；工作流模式下这五列不出现。

### M1 发现的两个「名不副实」点（正文要如实写，不能照着图标猜）

## 5. 已知坑

1. **`.mantine-Modal-root` 可能是空壳节点**，真正的遮罩是 `.mantine-Modal-overlay`；促销弹窗的关闭按钮**不在** `.mantine-Modal-content` 里。按 class 猜选择器会漏——`closePromos()` 因此改成 Escape → 点遮罩 的降级链。
2. **角色造型室是全屏浮层**，Escape 关不掉，会挡住后续所有点击。逐入口探索时必须先显式点它的关闭按钮。
3. 站点所有生成按钮在余额不足/未配置时是 disabled（例如 `Send`），这不是 bug，是取证时应如实记录的状态。

## 6. M2/M3/M4 取证结论摘要

- **九类节点**逐类建出并拍元素特写；`脚本` 与 `素材库` 右侧带 `›`，点击**只展开子菜单不建节点**。
- **连线**：输出 `data-handleid=source`/`right` → 输入 `data-handleid=target`/`left`，
  `edgeCount` 在两次独立运行中都是 1。
- **新增节点一律落在同一锚点**；要定位必须**双击画布**（面板锚在双击点）——这条同时是
  连线失败最常见的原因（两张卡重叠时端口坐标只差 1 像素，拖拽被判空操作）。
- **选中节点按 Delete/Backspace 不删**；必须先点空白把焦点交回画布，再 `⌘A` + `⌫`。
- **整理画布 `⌥⇧F` 会弹确认条**「是否保留此次整理结果？」，不点「保留」不落盘。
- **TV Director 技能卡文案会轮换**（同一账户两次进场所见不同），正文不写成固定清单。
- 底部 `教程` 按钮实为 `data-sidebar-btn="contact"`，点击无面板/无跳转/无新窗口。

## 10. Batch I/J/K/L/M/N/O：组操作条（拖了七轮才拿全）

AUDIT.md 待回走清单第 9 条「组操作条的『添加到工具箱』『布局下拉』」从 Batch F 挂到本轮，
中间失败六次（batchF/F2、batchG2/H6、batchG3/I2/I3、batchH）。**七轮里我犯的错比产品给的谜面还多**，
下面逐条记下来，因为每一条都会让下一个接手的人重蹈覆辙。

### 10.1 反复踩的同一个坑：成组之后按了任何键，选中态就没了

`Esc`、`⌘0`、`⌘-` 都会清掉组的选中态，组操作条**整个从 DOM 消失**，于是后续按文案找
「整组执行」「添加到工具箱」全部落空。batchH 就是这么废掉的：H1 结尾按了 `Esc`，H2 立刻报
`成组后操作条里没有「添加到工具箱」`。

- **能用的只有 `Space`**（按住拖 = 平移画布，**不丢选中态**）。实测 `Space`+拖把组从 `y=77` 平移到 `y=253`（+176），
  `groupSelected` 全程 `true`。
- 关浮层**不要按 `Esc`**，要点**同一个触发按钮**再点一次（toggle 关）。模态框才用右上角 `×`。

### 10.2 我自己写的 `dismissWithoutKey` 把每一轮都废了

```js
// batchK 的写法 —— 错得离谱
if (await overlayUp()) { await page.mouse.click(80, 750); }   // ← 点空白画布
```

`overlayUp()` 判的是「存在 `fixed inset-0` 且 `z-index > 100` 的 div」。
可站点用 Mantine，**`.mantine-Modal-root` 是个永远挂在 DOM 里的空壳**，永远满足这个条件 ——
于是 `dismissWithoutKey()` 每跑一次就去点一次空白画布，**每次都把组的选中态清掉**。
K1/K2/K3 三个步骤一次性全灭，看起来像「按钮根本找不到」，根因是这段清理代码。

**教训：清理浮层的谓词必须同时要求「有可见内容」和「盖住视口」，不能只认 class。**

### 10.3 「测不到」很多时候只是探针太挑

| 轮次 | 现象 | 真因 |
|---|---|---|
| batchH | 点排列按钮，菜单渲染到 `y=-99`（视口外），`innerText` 全空 | 组贴在视口顶部，弹层向上翻转后整体溢出。用 `Space`+拖把组平移到中部就正常了 |
| batchJ | 中间那枚按钮「找不到」 | 我的过滤器写 `w <= 40`，而它是 **52×36**。**尺寸先验是自找的漏** |
| batchL/K | 排列菜单「点了什么都没有」 | `scenario.mjs` 的 `fingerprint()` 有 `width > 120 && height > 60` 尺寸门槛，这个窄菜单**比 120px 还窄，被整块挡在门外**。改用全量 DOM 差集（`document.querySelectorAll('*')` 前后对比）才抓到 11 个新元素 |
| batchN | 「水平排列 (0,0) 没位移」 | 我用 `!!document.querySelector('div.nodrag.nopan.nowheel')` 判断菜单是否开着，**但菜单收起后那个容器还留在 DOM 里**，probe 恒为真，于是后两次点的是**上一轮的旧坐标**（宫格那项的 x 从 527 变成 210 就是铁证）|

**所以 batchM 一度得出「布局按钮点了毫无反应」的结论，是错的。** 改掉探针后菜单清清楚楚：
`宫格排列 / 水平排列 / 垂直排列`。**自动化探针报「无变化」时，先怀疑探针，再怀疑产品。**

### 10.4 菜单收起后容器还在 DOM 里 —— 每次都必须重读实时坐标

## 11. Batch P–P9：节点「高级设置」，连续三轮「点了没反应」全是我自己打歪的

这一节是整个手册里**最贵的一课**：同一个问题我错了三次，每次错得还不一样。

### 11.1 错误一：以为「找不到按钮」=「按钮不存在」

AUDIT 第 12 条写的是「图片/视频节点的『高级设置』**按钮在但没观察到展开**」。
batchP 去验，发现三种节点里都**找不到**「高级设置」，于是差点把它记成「这个功能不存在」。

实际上节点新建出来停在**折叠态**（只显示「尝试：图生图 / 图片高清」），
**单击节点中央 = 打开参数面板**，元素数 `42 → 140`，「高级设置」这时候才出现。
（音频节点比较特殊：它的参数面板默认就是开的，`fitView` 前后元素数都是 141。）

**「找不到」和「不存在」之间隔着「状态」。** 断言一个控件不存在之前，先把能到达它的状态都走一遍。

### 11.2 错误二：把视口当成无限大的

这是最贵的。视口是 **1440×810**，而我点「高级设置」时拿到的坐标是：

| 轮次 | 「高级设置」坐标 | 视口高 | 结果 |
|---|---|---|---|
| batchP2 | `(510, 809)` | 810 | 落在**视口外** = 点了空白画布 → 面板被关掉（元素 140 → 42）|
| batchP3 | `y=830` / `y=803` | 810 | 同样出界，`inViewport: false` |

我看着 `-98` 个元素的变化，得出「布局按钮点了毫无反应」的结论并写进了手册。
**那不是产品的行为，是我点了画布空白处。** 后来 batchM 换全量 DOM 差集才发现菜单其实开得好好的。

**坐标类操作前必须做命中校验：读 `document.elementFromPoint(x, y)`，看最顶层的是不是我要点的东西。**
batchP 已经在 `adv.topAtPoint` 里加了这个校验，只是当时没把它当成硬门槛。

### 11.3 错误三：找错了元素类型，于是「点开」变成了「拖动」

「高级设置」在 DOM 里是 `div` 不是 `button`，所以 `getByRole('button')` 找不到它 —— 这跟组操作条一样。
但更麻烦的是**我最后一次定位到的那个元素 `cursor: grab`**，那是**节点拖拽手柄**，不是标题。
按下去当然不会展开（反而会拖动整个节点）。

### 11.4 最终坐实的东西

| 结论 | 证据 |
|---|---|
| 参数面板**不是节点卡片的一部分**，是挂在节点**下方**的独立卡片 | class `node-floating-ui nodrag nowheel nopan`，框 `[390,471,660,188]` 在节点本体 `[542,119,356,356]` 之下 |
| `⌘0` 只框节点、**框不到参数面板** | 面板挂在节点框外 |
| 单击节点中央 = 打开参数面板 | 元素 `42 → 140` |
| 「高级设置」是**可折叠分区** | 折叠容器 `min-h-0 overflow-hidden`，`clientHeight=0` / `scrollHeight=145`；外层 `grid transition-[grid-template-rows]`（`0fr → 1fr` 折叠）|
| 音频 = **3 个 Mantine 滑杆**（语速/声调/音量） | `mantine-Slider-root` ×3，176×8px，纵向间隔 36；标签取「同一行左侧文本」= 语速/声调/音量 |
| 音频**没有**数字输入框 | `input[type="number"]` 恒为 **0** —— **手册原来说「3 个数字输入框」是错的，已纠正** |
| 图片 = `智能引用` 开关 + `AutoLink` | 开关 `checked: true` |
| 视频 = `联网搜索` / `自动校验素材` / `智能引用` 三个开关 + `AutoLink` | 三个开关全 `checked: true` |
| 文本节点**没有**「高级设置」 | 折叠态卡片里只有「自己编写内容 / 文生视频 / 图片反推提示词 / 文字生音乐」|

**滑杆是 Mantine 组件、不是 `input[type=range]`** —— 查 `input[type=range]` 会永远返回 0，
必须按 `[class*="mantine-Slider"]` 查。这条让我白查了四轮。

### 11.5 仍然没做到的

**把折叠的「高级设置」从 0 展开到 145px，这个动作本手册没成功过，四次尝试全败。**
所以音频那三个滑杆只有 DOM 读数、没有画面佐证，正文已如实标注 ⚠️，
没有配一张「其实什么都没发生」的图充数。

### 11.6 这轮的方法论收获

1. **别用 `getBoundingClientRect()` 找节点内的东西。** 参数面板不在节点框里，
   在节点框里查滑杆当然永远是 0。要么按 class 全页查，要么看祖先链。
2. **先看祖先链再下结论。** batchP8 的祖先链一步就给出了答案
   （`min-h-0 overflow-hidden` + `grid transition-[grid-template-rows]` = 折叠分区），
   比前面五轮的盲点点击都值钱。
3. **重叠的节点不要按坐标点。** batchP3 用 Playwright locator 点被压住的节点，
   它直接抛 `TimeoutError` —— **这正是它该做的事**：宁可报错，也不要静默点歪到邻居身上。
   「按坐标盲点」在这个布局里已经让我读到过两次邻居的数据。
4. **自己写的探针要有自检。** `addNodeAt` 第一版只试一次就超时（双击点了个寂寞）；
   加了「换位重试 + 建完确认节点数真的变了」之后才稳。

### 11.7 补记：第五次尝试（batchR）与它揭示的东西

第五次我改了个思路：不再点「容器中心」，而是量出**文字本身的包围盒**再点。
结果发现**根本没有独立的「文字」元素**：

| 读数 | 值 | 说明 |
|---|---|---|
| `textRect` | `[399, 755, 642, 28]` | 按文案找到的「高级设置」元素**宽 642px** —— 它是**整行**，不是那四个字 |
| `cursorAtText` | `grab` | 整行处在**节点拖拽区**里 |
| `hitTest`（点击点的最顶层） | `BUTTON`，class `relative flex items-center justify-cente`，**文本为空** | 我点的位置上根本没有「高级设置」，是一个无文本的按钮 |
| `mid.hitTest`（点完之后） | `FOOTER`，文本 `创建新角色` | 点完那一瞬间，该位置的元素变成了完全不相干的另一个 UI |

结论：**这一行的可点热区不是「高级设置」四个字，而是别的什么东西**（很可能是行首/行尾的图标按钮）。
纯靠文案和几何坐标定位，到这里已经走到头了 —— 再试下去只是在换一种方式打空气。

所以最终定性（已写进正文）：

> 「高级设置」**是**可折叠分区（机制确凿：`min-h-0 overflow-hidden` + `grid transition-[grid-template-rows]`，0fr→1fr），
> 内容也确凿（语速/声调/音量三个 Mantine 滑杆）。
> **但本手册没能把它点开** —— 五次尝试分别败在：视口外、行中心、行中心、抓到拖拽手柄、整行≠文字且热区在别处。
> 音频那三个滑杆因此**只有 DOM 读数、没有画面**。

这也是本手册里唯一一个「机制清楚、控件清楚、就是点不开」的条目。
与其编一张假图，不如把这句话原样留在正文里。

## 13. Batch V/W/X：资产管理「更多操作」——五轮里最冤的一次

### 13.1 四次失败各自栽在哪

| 轮次 | 我做了什么 | 结果 |
|---|---|---|
| batchS | 抽屉还没开就找按钮 | 抽屉根本没展开 |

### 13.2 真正的判据：`aria-label`，不是 `innerText`

<BUTTON aria-label="定位到节点 图片节点 1"  rect=[34,194,273,36]>图片节点 1</BUTTON>
<BUTTON aria-label="更多操作"                rect=[253,200,24,24]></BUTTON>   ← 纯图标
<BUTTON aria-label="定位到节点 图片节点 1"   rect=[279,200,24,24]></BUTTON>  ← 纯图标

**两枚 24×24 的按钮 `innerText` 是空字符串**（里面只有 `<svg>`）。
而我 batchV/batchU 用的判据全是 `/更多操作/.test(e.innerText)` 和 `txt(e) === '更多操作'` ——
**对着空字符串做子串匹配，永远不可能命中**。

> 这和组操作条那轮是同一类错误的两个变体：
> 组操作条是「不是 `<button>`，得按文案找叶子 `div`」；
> 这里是「**是 `<button>`，但没有文案，只能读 `aria-label`**」。

## 14. Batch Y/Z/AA/AB/AC：四项全部实按 —— 六个教训

第 13 节打开菜单但四项一个没点。这一批在**一次性测试画布**上全按了，
外加三轮补漏。真正值得记下来的是**六次判据翻车**。

### 14.1 「复制」明明成功，脚本却说「没变」

`nodeCount()` 数的是 `.react-flow__node`。点完「复制」，抽屉底部已经从「共 1 节点」
变成「共 2 节点」、多出一行「原名 - 副本」，**而页面里的渲染节点数还是 1**。

我第一反应是「复制没生效」，差点写成「复制失败/无反应」。

**真相**：副本落在原节点**正下方**，而复制之前我按过 `⌘0` —— 画布被放大到
「一个节点占满屏」（`scale(2.10611)`），副本整个在视口外。
LibTV **只渲染视口内的节点**，所以它不在 DOM 里。

三个时点的读数把这件事钉死了：

| 时点 | `.react-flow__node` | 抽屉「共 N 节点」 |
|---|---|---|
| 复制完立刻 | **1** | **2** |
| `⌘0` 之后 | **2** | 2 |
| 刷新页面后 | **2** | 2 |

> **教训一：`.react-flow__node` 是「视口里渲染了几个」，不是「画布上总共有几个」。**
> 任何涉及「建/删/复制节点」的成功判据，都必须用一个**与视口无关**的来源交叉验证。
> 这里那个来源就是资产管理抽屉底部的「共 N 节点」。
> 上一轮写进正文的那句「画布空了 = 节点没了」的教训其实是同一条的另一个方向，
> 那次我判对了一半 —— 症状认出来了，但**这次我差点把结论写反**。

### 14.2 「删除撤不回来」下结论太早

batchY 里我按完 `⌘Z`，节点没回来，就准备写「删除不可撤销」。
**但焦点还在抽屉里** —— 抽屉吞快捷键是常事，这个对照组不成立。

补了 batchAA2：删完 → 点画布空白把焦点交回画布（确认 `document.activeElement` 变成 `BODY`）
→ `⌘Z` → `⌘⇧Z`。两次都没动，节点数纹丝不变，**这才敢写「撤不回来」**。

> **教训二：断言「某操作不可逆」之前，先排除「快捷键被别的东西吃掉了」。**
> 拿一次失败的 ⌘Z 当证据，等于用「焦点不对」去证明「产品没有撤销」。

### 14.3 「没有二次确认」差点被自己的等待时间掩盖

batchY 里我是**点完睡 2400ms** 再数节点数的。如果有确认弹窗，节点数就不会变 ——
所以「没变」其实**不能证明没有弹窗**，除非弹窗正好在这 2400ms 里自己消失。
batchAA2 改成**点完 200ms 就扫全屏**：

```js
[...document.querySelectorAll('.mantine-Modal-overlay,[role="dialog"]')]
  .filter((d) => { const r = d.getBoundingClientRect(); return r.width > 60 && r.height > 40; })
```

结果只有资产管理抽屉自己（它是 `role="dialog"`，得靠 `.Drawer-content` 排除掉）。

> **教训三：判「有没有弹窗」要在弹窗还活着的时候问，不能事后回忆。**
> 这和「Mantine 空壳 `.mantine-Modal-root` 永远满足 `fixed inset-0 + z>100`」是同一个坑的镜像：
> 那次是**空壳骗你说有弹窗**，这次是**等待骗你说没弹窗**。

### 14.4 判据把自己的前提用掉了

batchAA3 报「抽屉打不开」。原因是上一节 AA2 刚把测试画布**删到 0 个节点**，
而 `openDrawer()` 的判据是：

```js
if (await page.evaluate(() => !!document.querySelector('div.group\\/node'))) return true;
```

**「里面有行」才叫「开着」** —— 抽屉明明开着（还写着「画布暂无节点 共 0 节点」），
脚本却判定没开，直接抛错。

> **教训四：判据要问你要问的东西。**
> 「抽屉在不在」要去查抽屉容器（`.mantine-Drawer-content` 的实时坐标），
> 别拿「里面有没有内容」当代理 —— 代理在前一步把内容清空时就会反咬一口。
> 这和第 11 节「祖先链一步给出折叠机制答案」是同一个思路：
> **先确认你测的那个东西还在，再问它的属性。**

### 14.5 查编辑器查到了另一个编辑器

batchAB 报「输入框是空的」，并据此写下「节点是以附件形式进来的，不是正文」。
结论碰巧对，但过程是错的：我用 `.ChatRichInput-editor` 全局选第一个，
命中的是画布上节点参数面板里那个（`x=726`，在右抽屉 `x=1024` **之外**）。

batchAC 改成**先定位右抽屉容器、再在里面查**，读数才对上：
编辑区 `[1042,668,364×64]`，`innerText` = 两个 chip 的名字。

> **教训五：页面上有同类元素时，「取第一个」是随机数。**
> 凡是 `document.querySelector` 取第一个的地方，都问一遍「页面上还有没有别的东西长这样」。

### 14.6 危险字样扫描漏掉了 `Send`

batchY 的危险检查是 `/发送|提交|派发|运行|开始生成|消耗/.test(text)`，
返回「无危险字样」，于是脚本安心地继续。

后来 batchAB 直接 dump 按钮的 `aria-label`，才看见 **`aria-label="Send"`** ——
那**就是**发送按钮，**而且是英文**，正则一个中文词都匹配不到。

更要命的是它的 `disabled=false`：只挂了附件、没打一个字，Send 就已经能按。

> **教训六：安全护栏不能只靠关键词。**
> 「出现中文『发送』两个字就停手」这种规则，在一个按钮文案是英文的产品上等于没有护栏。
> 正确做法是**把该区域所有按钮的 `aria-label` / `title` 全 dump 出来人工过一遍**，
> 并且对「可点态的图标按钮」默认存疑 —— 本轮从头到尾**没有点过 Send**。

### 14.7 一个写进正文的真·产品观察

「添加到Agent」点一次，画布上 1 个节点，输入区里挂上**两个一模一样的 chip**。
两枚的 `innerHTML` 完全一致、class 相同、都没有 `title` / `aria` / `data-*`，
**从 DOM 上分辨不出它们代表什么**。

在两张不同的测试画布上各复现了一次，所以正文写的是**现象**，
不是「这是 bug 抢修」也不是「这是两种引用」——
**证据只够支撑现象，不够支撑解释。**

同时把这条写进了 `90-troubleshooting.md`，因为它是用户真会遇到、
且会困惑「我是不是手滑点了两次」的场景。

## 15. Batch AD/AE/AF/AG/AH/AI：资产管理工具行 —— 连着五次判据翻车

上一节把「更多操作」四项按完了。这一批转向**资产管理抽屉的工具行**，
那行控件从 Batch A 起就只被当成图里的装饰描述过，一个都没点。
结果打了两百多行脚本、跑了六轮，**一半的结论要靠后一轮去修**。

### 15.1 「搜索框是空的」—— 打进了另一个输入框

AD1 报「输入框 placeholder 为 null，打字列表没变 → 不是真过滤」。

打开抽屉里**第一个** `<input>`，拿到的是**顶部的工作区名称框**（`[12,48,78×20]`，值「未命名工作区」）。
**搜索框压根不存在** —— 工具行上那枚 🔍 是**按钮**，点它才展开一个
`input[placeholder="搜索节点"][aria-label="搜索画布元素"]`。

`placeholder: null` 就是征兆：**一个搜索框没有 placeholder，这事本身就不对**。

> 和 §14.5 是同一类错误：**页面上有同类元素时，「取第一个」是随机数。**
> 这次补的不是「改成取最后一个」，是**先确认要找的控件现在在不在**。

### 15.2 「匿名图标」= 底部那枚收起箭头

AE2 想找「工具行里没有 aria-label 的图标」，判据是
`tb.buttons.find(b => !b.t && !known.test(b.aria))`，`known` 里只列了三枚已知控件。
`.find()` 取的是**第一个**匹配 —— 而抽屉底部还有一枚 `收起节点侧栏`（32×32，纯图标），
它排在那儿，于是「匿名图标」问的其实是**收起箭头**，点完抽屉整个收起。

> **排除法比 `.find()` 可靠。** 更好的做法是**按位置取**：工具行控件的 `cy` 都在同一个值上
> （这一行是 `cy=158`），底部的收起箭头 `cy=782`。一行条件就能分开：
>
> ```js
> tb.filter((b) => b.cy > 130 && b.cy < 190)   // 只要工具行这一行
> ```

### 15.3 「找不到筛选按钮」—— 它一直都在，叫 `筛选：全部`

`筛选：全部` 从 Batch AE0 起就出现在读数里，只是**从没被点过** ——
因为每轮的「已知控件」名单里都没有它。第五轮（AI）才按前缀 `/^筛选/` 去捞，一捞一个准。

点开是**按节点类型**筛的 10 档菜单，选「文本」后列表 3 行 → 1 行，
按钮的 `aria-label` 从 `筛选：全部` 变成 `筛选：文本`。

> **档位直接编码在 `aria-label` 里**，这是个很好的设计（对读屏用户友好），
> 但对脚本很不友好：**不能拿固定字符串去 `find`**。
> 凡是 `aria-label` 里带动态值的控件，一律用**前缀匹配**。

### 15.4 连续三轮只建出 1 个节点 —— 候选点集全在同一个矩形里

AD、AE、AF 三轮都只建出一个图片节点，音频/视频/文本全失败。每轮都当成「建不出来」，
前两轮还去改了 `getByText` 的 `exact` 参数（改完还是失败）。

AF 才看明白：图片节点在 100% 缩放下宽 **622px**，挂在它下面的**参数面板**又是一大块，
两者把 `x ∈ [460, 1082]` 这条竖带填满了。而我给的 8 个候选落点
`[520,250] [520,430] [720,250] [720,430] [900,250] [900,430] [520,610] [720,610]`
**全部落在那条带子里**。双击打不开「添加节点」面板 —— 打开的是节点自己的编辑区。

AG 改成「先 `Esc` 收掉参数面板，再量所有节点的包围盒，从**右侧**和**下方**求解空位」，
一次建出 4 个。

> **教训：「连续 N 次失败」时，先怀疑自己的候选点集是不是撞在同一堵墙上。**
> 如果所有候选点都落进同一个矩形，那不叫搜索，那叫撞墙。
> 正确的做法是**从已占用区域的包围盒往外推**，而不是预先写死一串坐标。
>
> 这条和第 11 节「视口当成无限大」是同一个家族：**坐标先验错了，后面全白干。**

### 15.5 Shift+点击选不中 —— Playwright 的两次按键不是一次「按住」

AG 想选中两个节点再 `⌘G`，写法是 `keyboard.down('Shift')` → `page.mouse.click(...)` → `keyboard.up('Shift')`。

结果 `selectedAfterShiftClick: 1` —— 第二次点击只是**把**选中态换成了另一个节点。

Playwright 的 `keyboard.down/up` 和 `mouse.click` 是**两套独立的事件注入**，
中间没有「Shift 此刻处于按下状态」的共享状态。React Flow 读到的是一次普通点击。

> AH 换成 `⌘A` 全选也没成（选中 0 个，那一轮 `⌘A` 前点空白点的位置不对）。
> **最终「展开/收起全部分组」这一项仍然没验证**，正文里如实标了「没测出差别，
> 因为这两轮没建出组」—— **宁可写没验证，也不把「没效果」说成「产品无效」**。

### 15.6 浮层「点开没反应」和「菜单还开着导致下次读不到」是同一件事的两面

AF3 探四枚按钮时，每轮开头都点一次「资产」标签，结果后三轮全部报「按钮不在」。
原因不是按钮消失了，是**上一轮结尾按的 `Esc` 把浮层收掉的同时，把抽屉也收掉了**，
再点「资产」标签时它只是把标签切回去，工具行根本没重新渲染。

AF3 改成**每测一枚就 `page.reload()` 重新进** —— 慢，但彻底干净。
后来 AH 又踩了它的反面：`displaySetting()` 先点一次「展示设置」，如果菜单本来就是开着的，
这一下反而把它关上了，于是「读到 undefined」。
补法是**先探当前状态**：开着就先点一下关掉，再点才是打开。

> **两次都是「toggle 语义」的控件。** 这类控件必须**先读状态再决定点不点**，
> 盲点一次的结果取决于此刻它是什么状态。
> 这也是为什么本手册一直用「再点一次同一触发按钮」来关浮层、而不是按 `Esc`——
> `Esc` 会顺手把别的东西一起收掉。

### 15.7 一个必须写进正文的坑

类型筛选把列表收到 1 行之后，抽屉底部**仍然写着「共 3 节点」**。

数字数的是**整张画布**，不跟着筛选走。加上搜索框、类型筛选、星级筛选**三者可叠加**，
用户很容易「筛出空列表 → 以为是节点没了」。

这条同时进了 `90-troubleshooting.md`，因为它是真会被用户撞上的误解。

## 16. Batch AJ/AK：故事板的两枚控件 —— 一个隐形按钮，一个筛错了对象

### 16.1 自己写的「列检测器」把自己坑了

AJ 想读故事板三列，于是写了个筛选：
「宽度 380~620 + 高度 >300 + 文本以 文本/图片/视频 开头 + 没有同类子元素」。
结果 `colCount: 0`。

三列明明在 —— 同一轮读到的状态条文本里，「文本 图片 视频 全部 对话」全都在。

> **教训：不要用「宽高区间 + 文本前缀」去猜布局容器。**
> 这套判据在「页面恰好长得像我想的那样」时有效，一旦有任何一个约束不成立就整体归零，
> 而且**失败方式是静默的**（返回空数组，不报错）。
>
> AK 换成最笨也最稳的做法：**全页按文字搜按钮**。
> `findBtns('对话')` 一行就捞到了两枚，还顺带拿到了坐标 ——
> 比「先定位容器、再在容器里找」少一层不确定性。

### 16.2 切到故事板时，TV Director 面板正好压住要点的按钮

AJ 那一轮三列全被 TV Director 面板盖住右半边（面板 `[1024,154,400×640]`，
视频列 `x=970~1440`）。这不是新发现（batchT 早就发现「点故事板会把 TV Director 拉出来」），
但那轮没意识到它**挡路**。

AK 想先把面板收掉，结果 `collapse: null` —— 脚本按 `innerText === '—'` 去找那枚收起按钮，
**它是纯图标，`innerText` 是空的**。第 13 节的老教训，第七次栽在同一类问题上。

不过这次**没栽到底**：视频列的「全部」按钮在 `y=57`，落在面板上方（面板从 `y=154` 开始），
所以照样点得到，读数完整。

> 补一句判据：`elementFromPoint` 那一发
> （`covered: top ? !b.contains(top) : false`）就是用来回答
> **「我现在点的这个位置，事件真的会落到它身上吗」** 的。
> 有它，才敢说「按钮没被挡住」。

### 16.3 「对话」按钮：DOM 里有，平时隐形

按文字全页搜到 2 枚「对话」，坐标 `[888,107]` 和 `[1363,107]`，各 `52×20`。
但 `visible: false` —— 因为我的可见性判据里有 `getComputedStyle(b).opacity > 0.05`，它们是 **`opacity: 0`**。

**悬停到节点行上才显形。** 而我那一轮的 hover 探针又写歪了
（用 `/^节点 \d+$|^(文本|图片|视频)节点 \d+$/` 匹配行文字，一个都没命中）。

最后是靠**点完之后截图**才看明白的：M-95 里「对话」按钮清清楚楚挂在「图片节点 2」行尾，
因为鼠标正好停在那一行上。

> **教训：截图是最后的裁判。**
> DOM 读数说「不可见」、hover 探针说「找不到」、而截图里它明明白白在那儿 ——
> 这种时候以截图为准，并且**回头去修判据**，而不是改结论。

顺带纠正正文两处错：
- 「对话」**不是视频列专属**，图片列节点行尾也有一枚；
- 它**不是常驻可见的按钮**，是悬停才出现的。

### 16.4 「全部」筛的是成片/片段，而我一直以为是状态筛选

点开菜单三行：`全部`✓ / `成片` / `片段`。

也就是说这枚筛选**筛的是产物形态**（整段成片 vs 单个片段），不是节点状态、也不是生成进度。
我原本以为它跟资产管理那两枚筛的是一类东西（类型 / 星级），完全不是。

选「成片」之后，视频列的「视频节点 3」整行消失。**但这不能证明筛选有效** ——
这张画布上根本没生成过任何视频，「筛掉了」和「本来就没有」在数据上长得一模一样。

正文如实写了这个边界，没有把「筛完空了」说成「筛选按预期工作」。

### 16.5 「对话」和「添加到Agent」挂的附件数不一样

同一个节点、同一个 TV Director 输入框、同一套按钮 —— 但：

| 入口 | 附件 chip 数 |
|---|---|
| 资产管理 `⋯ → 添加到Agent` | **2 个**（两张画布各复现一次） |
| 故事板节点行尾 `对话` | **1 个** |

所以「挂两个」不是 TV Director 侧的 bug，是**资产管理那个入口多加了一次**。
（成因仍然不明，正文只记现象。）

这条对比让 M13 那条「实测会挂上两个 chip」的记录更精确了 ——
**现在知道要把「从哪个入口点的」一起写上**，否则读者会以为所有入口都挂两个。

## 17. Batch AL/AM/AN/AO：生成历史面板 —— **同一个错犯了两遍才认出来**

Batch G 时代拍过一张 `M-01-生成历史.png`，之后再没打开过这个面板。
这一批想把里面八个控件点开，结果**前两轮全部扑空**，第三轮才拿到数据。

### 17.1 扑空两次的根因是同一个：我在 `page.evaluate` 里手搓「找容器 → 在容器里找控件」

**AL**：`panel()` 要求容器是 `position: fixed`。
可生成历史是**居中大面板**（约 `[72,80,1296×640]`），不是 fixed。
于是返回 `null`，后面八项全报「面板里没有这个控件」。

**AM**：改成「从『暂无历史记录』这份独有文案往上爬」。
结果**爬过头了** —— 取到的是 `relative h-screen w-screen`（整个应用根节点 `[0,0,1440,810]`），
而 `controls()` 取了**最小**那个锚点（只有那六个字的 div），它的父容器里当然没有按钮。

两轮失败方式一模一样：**静默返回空数组，不报错**。

> **教训：能用手搓遍历解决的，别用手搓遍历。**
> Playwright 的 locator 自带三样我反复漏掉的东西：可见性判定、作用域解析、
> 以及「这个点必须真的收到事件」的校验（被盖住会抛错而不是静默点歪）。
> AN 换成 `page.getByText(label, { exact: true })` 之后，
> 八项里立刻拿到了五项的完整读数（标签名、外层可点祖先、尺寸、坐标）。
>
> 这跟 §16.1 是同一条：**猜布局容器要么靠内容锚点，要么干脆别猜，用 locator。**

### 17.2 `getByText(exact: true)` 找不到「图片」—— 是我匹配写错，不是控件不存在

AN0 报「图片 / 视频 / 音频：页面上找不到这个文案」。

AO 换成「按坐标带扫 `<button>`」之后真相大白：
界面上是 **`图片 0`**、`视频 0`、`音频 0` —— **计数徽标把文字撑开了**，
`exact: true` 匹配不到「图片」这两个字。

> **教训：`exact: true` 失败时，先 dump 一下按钮的真实 `innerText`，别急着下结论。**
> 计数、徽标、角标都会让文案和「标签名」对不上。

### 17.3 「时间倒序」不是下拉 —— 是点了就换

AN 点了它之后浮层是空的，而 `getByText('时间倒序')` **找不到了**。
AO 连点三轮把两个态都读出来：

| 文案 | `title` |
|---|---|
| `时间倒序` | `当前：最新优先` |
| `时间正序` | `当前：最早优先` |

**两态循环**，`倒 → 正 → 倒 → 正`，全程无浮层。

> 而原手册把它和 `所有评级 ▾` 一起写在「排序」一行、还带了个下拉箭头，
> 读者会以为它也是弹菜单。**带 `▾` 的和不带 `▾` 的不是一回事**，
> 但「文案里没有箭头」也**不能**当判据 —— 得实点一次看有没有浮层。

### 17.4 扫 `button` 会把面板**背后的**控件一起收进来

AO 的「与标题同一水平带」几何条件，把画布上「添加节点」面板的按钮
（分镜 / 动态 / 音乐 / 图片高清 / 口播视频 / 素材混剪）全收了进去 ——
它们只是**恰好和标题差不多高**，而且在面板后面（`z` 更低）。

真正的目标（右上角两枚 ⊞ 和滑杆）**根本不是 `<button>`**：
它们在一枚 `div.flex.items-center.gap-2.rounded-lg.p-2.bg-white/[0.0…]`（`[1135,105,164×32]`）里。

> **教训：按几何条件选元素时，必须同时问「它有没有被更高层的浮层挡住」。**
> 判断用 `document.elementFromPoint(x, y)` —— 本轮第 16 节已经把这个招写进
> `findBtns()` 的 `covered` 字段，这轮**忘了用**。
>
> 另一个更省事的判据：**先确认目标是不是它宣称的那个标签**。
> 我要找的是「视图切换按钮」，而 `svg` / `div` 本来就不可能是 `<button>`。

### 17.5 「点了没变化」不能当结论 —— 空列表上本来就看不出变化

两枚 ⊞ 点下去 `changed: false`，面板文字一模一样。

但这个账户**从来没有过一条历史记录**。网格 ↔ 瀑布流切换、缩放大小，
**在空列表上本来就看不出差别**。

正文因此写的是「**没验证出效果，不能据此说无效**」，
而不是「这两枚按钮无效」。这条边界和 §16.4 的「筛完空了 ≠ 筛选有效」是同一条。

### 17.6 一个附带结论：它不是全屏遮罩

生成历史是一块**浮在画布上的居中面板**，四周画布露着、右下角 TV Director 面板也露着。
右上角那枚 `×`（`[1315,107,28×28]`，**纯图标、无文字、无 aria** —— 第几次了）
点完就关，关掉之后画布原样回来，不像遮罩那样吞掉后续操作。

这一条对用户有用：**开着生成历史还能看画布、还能操作 TV Director**。

## 18. Batch AP/AQ：缩放菜单逐档实按 + 画布行菜单坐实 —— toggle 坑**本轮又踩了一次**

上一批（AL–AO）收尾时排的候选是「缩放菜单六项 + 画布下拉行菜单」，
理由是这两处**正文已经写了，但当时的证据都只是「菜单打开着」那张截图**——
一个控件「存在」和「点了有效」是两回事（第 14 批的四项就是这么补上的）。

### 18.1 AP 的三档预设挂了两档 —— 因为**点完第一档菜单自己关了**

脚本的形状是「打开菜单 → 依次点三档 → 每点一档读一次 `scale`」。
AP 跑出来的结果：

| 档位 | 结果 |
|---|---|
| 缩放至50% | ❌ `菜单里没有这一项；菜单=undefined` |
| 缩放至100% | ✅ `2.106` → `1` |
| 缩放至800% | ❌ `菜单里没有这一项；菜单=undefined` |

读到这里第一反应是「这两项不存在」。
但 `undefined` 这个词本身就不对 —— 如果菜单**存在**而**没有这一项**，
返回的应该是空数组，不是 `undefined`。`undefined` 说明**菜单整个找不到了**。

原因很直白：**点完一档，菜单自动关闭**。后两档是在一个已经关掉的菜单里找行。
中间那档之所以「成功」，只是因为它是最后跑的、且 AP 在失败分支里顺手又开了一次菜单。

> **这是 §15.6 记过的同一个坑，本轮又踩了一次。**
> 当时的结论是「toggle 类控件（菜单/下拉/抽屉）一律先读状态再决定点不点」，
> 这次写脚本时**根本没想起这条**，因为「逐档点三下」看起来像普通按钮组。

AQ 改成「每一档之前先确认菜单开着，没开就重新点开触发按钮」，三档全中：

| 档位 | 之前 | 之后 | |
|---|---|---|---|
| 缩放至50% | `2.106`（`211%`） | `0.5`（`50%`） | ✅ |
| 缩放至100% | `0.5` | `1` | ✅ |
| 缩放至800% | `1` | `8` | ✅ |

> **教训（补 §15.6）：「逐项点一遍 N 个选项」这种脚本，天生假设了「点完选项菜单还在」。**
> 这个假设**只在**「点完不关」的控件上成立（资产管理的「展示设置」就是这种）。
> 写这种循环之前先问一句：**点完第 1 项，浮层还在不在？**
>
> 另一个更省事的判据：**报错信息里出现 `undefined` 而不是空数组，本身就是「容器找不到了」的信号**，
> 不要读成「这一项不存在」。

### 18.2 「一格 `%`」其实是个能敲数字的输入框

原手册那张 `A6-zoom-menu.png` 里，菜单最上面有一格 `%`，一直当成「单位装饰」，
表格里也只写了三档预设 + 键盘快捷键。

这次读 inputs 才发现它是个 `input[aria-label="缩放比例"]`（`[181,491,146×20]`，`type=text`），
**而且真的能用**：填 `200` + `Enter` → `scale` 1→2，**菜单不关**，
输入框和左下角标签同时变 `200%`，双向同步。

这条对手册的价值是实打实的：在此之前，用户想调到 200% **没有任何办法**——
快捷键只能逐档，三档预设只有 50/100/800。

> **教训：控件「长什么样」和「能干什么」是两次取证。**
> 同一个元素，截图里是一行灰字，读 DOM 是个 input。
> 有 `aria-label` 的输入框在截图上跟普通文本**几乎没法区分**。

### 18.3 `211%` 是个副产品 —— 它暴露了「适合屏幕」到底在算什么

AP 打开菜单时左下角标签是 `211%`，而 `scale` 实测 `2.10611`。
这个数字不是预设档位，是前一轮「适合屏幕」（`⌘0`）算出来的 —— 节点少，它会**放大到 100% 以上**。

原手册第 50 行早就写了「`⌘0` 是适合屏幕，节点少时会放大到 100% 以上」，
但那是个**结论**，读者没法想象放大到多少。`211%` + `2.10611` 是它的具体长相。

### 18.4 画布行菜单：三行连点，内容逐字一致

正文原来只写「行级菜单四项」，证据是一张打开菜单的截图（`A9b`）。
这次连着点了第 1/2/3 行的「更多操作」，三次读出的浮层**完全一样**：
`在新窗口打开 / 重命名画布 / 复制画布 / 删除画布`，无第五项、无图标、无分组线。

值得写下来的**不是**「有四项」（截图早就写了），而是**「不随行变」** ——
活动画布、已改名的画布，读数都相同。这排除了「某些行会多出/少掉某一项」的可能。

### 18.5 审计做减法：15 张 → 4 张

AP/AQ 一共拍了 15 张。逐张看过之后只留 4 张：

| 处置 | 图 | 理由 |
|---|---|---|
| 删 | `M-115` `M-117` | **md5 完全相同**，是同一帧存了两次（`8d542f0c…`） |
| 删 | `M-119-行2菜单` `行3菜单` | 与行 1 内容一致（这正是 §18.4 的结论本身），留一张就够 |

## 19. Batch AR/AR2：「在新窗口打开」实按 + 发布面板逐控件清点 —— **面板自己写的提示是假的**

上一批收尾排的候选里还剩两处「只有结论、没有控件级证据」：
行菜单的第一项从没点过，发布面板只有 Batch 时代的一张截图。

### 19.1 「在新窗口打开」= 真开新标签页，不是当前页跳转

判据不能只挂一个监听器 —— 同一个界面文案可能对应三种完全不同的行为：
真开新窗 / 当前页跳转 / 压根没反应。所以三路同时挂：

| 监听 | 结果 |
|---|---|
| `ctx.on('page')` | 抓到 **1 个 popup** |
| 原页 URL 变化 | `currentUrlChanged: false` |
| `dialog` 事件 | `dialogs: []`（没有弹确认框） |

popup 的 URL `...projectId=1a0e8bb9…` 与原页 `...projectId=34226ef1…` **不同**，
而标签标题是 `画布 63 - LibTV - 专业视频创作工具` —— 两者对得上，
所以它开的确实是**那一行**的画布，不是随便开了个首页。

> **教训：「开了个新窗口」不是一个判据，是三个。**
> 只挂 popup 监听，遇上「当前页跳转」会误报成「没反应」；
> 只看原页 URL，遇上真开新窗会误报成「跳转了」。
> 三路都挂、互相排除，才能落到唯一结论。

顺带一个有用的副产物：那枚菜单项**不是** `<a target="_blank">`（`tagOf: BUTTON`，
`href` 和 `target` 都是 `null`），是 `window.open`。这解释了为什么
「取第一个匹配文案的元素」要按面积排序 —— 外层容器也会命中同一个文案。

### 19.2 发布面板只有 2 枚按钮，且**提示写着能 Esc 退出、实际不能**

面板逐控件清点的结果是：**按钮 2 枚、输入框 0、链接 0、tab 0、开关 0**。
这跟旧手册的印象差得远 —— 旧图看起来像一张表单，实际上**这一层只负责跳转**。

而两枚按钮的 hover 提示都是 **「按 ESC 退出」**。这句话写得很明确，值得实测。

**结果是 `Esc` 没用**，面板纹丝不动。

一开始想直接写「Esc 无效」，但§17 刚记过一条：**一次读数不足以定性**。
于是补了一步：按完 `Esc` 之后**再点一次触发图标**，读 `closedByReclick: true`。

这个结果的推理链是这样的：

- 如果 `Esc` 已经把面板关掉了，那么再点一次触发点会**重新打开**它 → `closedByReclick` 应该是 `false`；
- 实测是 `true` → 再点确实把它关上了 → 说明 `Esc` 那一刻它**还开着**。

顺带量了 `Esc` 的副作用：URL 不变、节点数 `10 → 10` —— **按错无损失**，
这条让正文可以放心地告诉用户「按了也没事」。

> **教训：判「某个操作无效」时，追加一个能自证的旁证。**
> 单次读数只能证明「我没看到变化」，
> `closedByReclick` 这种**间接推论**才能证明「它确实还开着」——
> 而且它天然排除了「是我的检测器瞎了」这种可能。
>
> 这跟 §14「`⌘Z` 撤不回来之前先排除焦点不对」是同一条思路的正面用法：
> 不是排除干扰项，而是构造一个**不可能有歧义的读数**。

## 20. Batch AS/AS2/AS3/AS4/AS5/AS6/AS7/AS8：连着八轮，中间四轮全是**判据自己坏掉**

这一批的目标很普通：补三处正文标着「📖 没验证」的地方（缩放持久化线索、
`TV Director 全局设置`、`LibTV Plugin`）外加工具箱。

结果有价值的东西拿到了，但**过程里有一半的失败不是产品没反应，是我的判据站不住**。
把四轮失败摊开看，比拿到的结论更值得记。

### 20.1 第一处：无区分力的实验会自己给自己发奖状

AS 想验「缩放是不是持久化」，脚本是：读 `z0` → 点「缩放至50%」→ reload → 读。

跑完：`z0 = 0.5`，点完还是 `0.5`，reload 后还是 `0.5` → `persisted: true` ✅

**这个 true 是假的。** 因为 `z0` 本来就是 `0.5`（AR 那轮留下的），
我又去设成 `0.5` —— 设成了它本来的值，**什么都没变**。
`afterReload === afterSet` 于是**必然成立**，跟持久化毫无关系。

AS2 重做，加了一条硬闸：

```js
as2a.meaningful = (await zoom()).scale !== effectiveTarget;   // 起点 ≠ 目标值？
if (!as2a.meaningful) { as2a.verdict = '起点就等于目标值，本轮实验无区分力，不下结论'; }
```

这一轮起点是 `0.5`、目标是 `8`，`meaningful: true`，才拿到真结论：
`0.5 → 8`，**连续两次 reload 都是 `8`**。

> **教训（补 §17.5）：判「我做的改动被记住了」，改动必须**先验出**跟起点不同。**
> 读到「操作后 == 重载后」就宣布成功，是把「没变化」误读成「记住了」——
> 而这两个在**单向操作**里读数一模一样。
> 判据要自带一道闸：*这一步有没有可能失败？* 没可能，就别拿它当证据。

### 20.2 第二处：按 class 白名单筛浮层，会静默漏掉一整类

素材库面板**明明开了**（M-128 截图里 `风格库 NEW / 特效库 NEW / 打开工具箱` 三行清清楚楚），
`diff` 却返回空数组。原因：它 `fixed z-20`，class 不是 `mantine-Menu-dropdown` / `Popover-dropdown`。

这是 §17.4 的老教训第二次撞上来：**DOM 说没有、截图说明明有**。
改用 `fingerprint()` / `diffPanels()`（只看可见 + 面积 + 位置，**不认 class**）之后一次就捞出来了。

> **教训：class 白名单是一份「我以为的面板清单」，不是「所有面板」的判据。**
> 写它的时候你只见过手边那几款，于是新样式一出现就静默漏掉 ——
> 而且**不报错**。面板识别优先用「位置 + 面积 + 有没有文字」这类物理量。

### 20.3 第三处：`rect` 面积是 0，我照着 `(0,0)` 点了屏幕左上角

AS2 找 `LibTV Plugin`，按 aria 找到了元素，就直接拿 `cx, cy` 去点。
结果 `diff: []`、`modals: []`、`urlChanged: false` —— 全空。
按 §19.2 的标准做法，这会写成「点了没反应」。

差别在于：AS3 补了一步**点之前先验 `rect`**。

```js
const vis = plugin.filter((p) => p.visible);   // area > 2
if (!vis.length) as3a.verdict = 'DOM 里有 N 个，但**全部不可见** —— 本轮**没有点到它**。空结果不能读成「点了没反应」。';
```

这次按钮可见（`area: 784`），点了才是真的「点了没反应」——
**画面上也确实只多了一个悬停提示**（M-126），跟资产管理那枚「管理」同一类。

> **教训：空结果有两种读法，「没反应」只是其中一种。**
> 区分它们要问的是「**那个点真的收到了事件吗**」——
> `rect` 面积 / `elementFromPoint` / 命中测试，任何一个都能回答。
> 没有这一问，「我什么都没点到」和「产品什么都没发生」在证据上**完全一样**。

### 20.4 第四处：筛选条件里带 `!aria`，把全页筛空了

找底栏那枚「+」，我写的是：

```js
bar.find((b) => !b.t && !b.aria && !b.title && b.childSvg)
```

结果 `null` —— 一个都没匹配上。原因很蠢：**底栏十三枚按钮全都有 `aria`**。

我以为「图标按钮 = 没 aria」，而这个产品**每一枚图标按钮都带 aria**。
连着三轮（AS3 用几何、AS4 用几何、AS5 用 `!aria`）都失败，
最后 AS5 的做法是对的：**把整排 dump 出来带坐标，看清楚再认**。

> **教训：连续 N 轮筛不到同一个东西，先 dump 全部，别继续调条件。**
> 调条件是在**猜**，dump 是在**看**。AS5 一 dump 出来就发现：
> 「+」的 aria 是 **`添加节点`**、`789` 那枚是 **`快捷键`**。
> 而 AS 早先拿到 `[789,757,32×32]`（= 快捷键）当成「+」点了，
> 于是读到一堆 `成组 G / 解组 / 连线 L / 缩放 / 移动画布` ——
> 我当时误判成「**快捷键面板是常驻 DOM 的**」。
> 那是**被点开的快捷键面板**。§19 差点把这个结论写进去。
>
> 顺带一条：**筛选条件里写 `!aria` / `!title` 这类「否定断言」特别危险** ——
> 它依赖的是「我猜这个产品会给多少元数据」，
> 而这个猜测一旦错了，返回空数组**而不是报错**。

### 20.5 收获：全局设置里有个会免掉确认的开关

`TV Director 全局设置` 这个面板，正文挂了三个批次一直标着「📖 没有验证」。
打开之后第一眼看到的就是它：

> **自动生成图片/视频/音频/剧本**
> 开启后，TV Director 可直接消耗积分，提交生成任务，无需逐次确认

这个开关**本手册一直守着的那条安全边界的来源**。
手册里所有「不发指令、不提交生成」的理由，之前都只能写成一句原则；
现在能写清楚「这个开关管的是什么」了。

同批还发现一处**说明与状态对不上**：`浏览器通知` 开关是**关**，
说明文字却写「**已在设置中开启**」。两句话至少一句不准。
本手册**没点它验证**（账号级设置），正文如实标出这个矛盾。

### 20.6 收获：工具箱的「使用」按钮不是 opacity 0

AS7 读到 28 枚 `使用` 按钮，**但截图里一枚都看不见**。
照例的假设是「hover 才显形」（§16.2 为故事板那枚记过）。
AS8 照着这个假设去量悬停前后的 opacity：

| | 未悬停 | 悬停后 |
|---|---|---|
| `opacity` | `1` | `1` |
| `display` / `visibility` | `flex` / `visible` | `flex` / `visible` |
| 截图里 | **看不见** | 看得见 |

**假设是错的。** 按钮一直在、也一直是可见的 ——
它只是**被预览图压在下面**，悬停才浮上来。

> **教训：「hover 才显形」至少有两种机制，别混。**
> 一种是 `opacity: 0 → 1`（故事板「对话」按钮是这种），
> 一种是**一直在、只是被盖住**（工具箱「使用」是这种）。
> 量 opacity **区分不了** —— 得问「**那个点上现在是谁**」
> （`document.elementFromPoint`），或者干脆看截图。

### 21.1 第一处失败：一块关不掉的遮罩，把后面两步全带崩了

> 这跟 §20.1 的「改动必须先验出跟起点不同」是同一条：
> **能跟「什么都没发生」产生歧义的读数，就不能单独当证据。**

### 21.4 附带纠正一个差点写进文档的错误

AS2 里我记过一个观察：「快捷键面板的内容是**常驻在 DOM** 的」——
依据是整页文本里一直有 `成组 G / 解组 / 连线 L / 缩放 / 移动画布 / 整理画布 …`。

**那是因为我早先把底栏的「快捷键」按钮当成了「+」**（详见 §20.4），
点开的就是快捷键面板。**不是常驻，是被点开的。**

AT2 实测面板原文与正文表格**逐条一致**（四列：`创作` / `缩放` / `移动画布` / `其他`），
只补了三处读数陷阱：「删除」的键帽是 **⌫ 图标**没文字、
「缩放→触控板」是捏合手势图标、「移动画布→触控板/鼠标」是带 ✥ 的图标 ——
读 `innerText` 时这三行会少掉键位。以及**「整理画布 ⌥⇧F」在第三列最后一行**，
不单独成组。

> **教训：观察本身没错，错的是它的归因。**
> 「内容在 DOM 里」这个观察是真的；「所以它常驻」这个解释是假的。
> §15 有一类判据陷阱的根因就在这儿 ——
> 现象和解释是两件事，中间隔着一个「有没有别的成因」。

## 22. Batch AU：节点参数面板 —— **有 rect 不等于被画出来了**

这一批连着 13 轮（AU…AU13），中间有一半的失败**不是产品没反应，是我拿错了判据**。
最要紧的一条：**`getBoundingClientRect()` 返回完整尺寸、`innerText` 读得到内容，
都证明不了它被画在屏幕上。**

### 22.1 我一度写下了一句完全相反的结论

AU5 我读到音频节点的面板全文里有 `语速 声调 音量`，值是 `1.00 / 0 / 1.0`，
滑杆 rect 是 `176×8`（非零）—— 于是在自己的笔记里记了一句「**默认就是展开的**」。

**这句是错的。** 两张实拍图（`M-139` / `M-140`）里，
视频和音频的**参数面板底边就是提交按钮**，从描述框到提交箭头之间
既没有「高级设置」这一行，也没有「联网搜索 / 自动校验素材 / 智能引用」和「语速 / 声调 / 音量」。

最终定案的读数（四条互相独立，全部指向同一结论）：

| 读数 | 值 |
|---|---|
| 「高级设置」那个元素 | `div.pt-3.text-xs.font-bold`，**不是 button**；祖先链一路到 `.react-flow__node` 没有 `button`/`role`/`aria` |
| 它下面的容器 | `grid transition-[grid-template-rows] ease-in-out grid-rows-[0fr] duration-200` |
| `grid-template-rows` **计算值** | `0px`；容器高 `0`；内部 `clientHeight` **`0`** |
| 全页 `grid-rows-[1fr]` 元素数 | **0**（点开前后都是 0） |
| 点它那个位置 `elementFromPoint` 命中 | `DIV.react-flow__pane` —— **画布背景** |

也就是说：**没有展开态，点不开，也看不见。**
手册原来写的「可折叠分区、点它展开/收起」和 AUDIT 里的「点开没成功」**两处都要改** ——
不是「没试成」，是「它不成立」。

> **教训：`rect` 非零 ≠ 被绘制。**
> 我自己写的 `hiddenByClip` 判据在这个案子上返回了 `false`（「没被裁」），
> 元素确实有 `176×8` 的完整 rect，`innerText` 也读得到内容 ——
> **三个读数一致地为真，而结论完全错**。
> 判「用户看得见吗」，只有一个裁判：**截图**。
> 这跟 §21.3 的「观察没错、归因错了」是同一族的坑，但更隐蔽：
> 那次是解释错了，这次**观察本身就是错的**。

### 22.2 面板能不能看见，取决于一个我一开始没当回事的开关

AU10 出现了一个死结：DOM 里面板 rect 是 `660×605`（`innerText` 读得到全文），
但截图里**一个面板都看不见**。当时我怀疑网格吸附、怀疑缩放、怀疑面板 z 序。

真凶是**右侧的 TV Director 对话抽屉**：

- 抽屉开着 → DOM 里有完整面板，**画面上一个像素都没有**；
- 按 `Esc` 关掉 → 面板立刻渲染出来（`M-139` / `M-140` 就是这么拍到的）。

而 `Esc` 是**有时灵有时不灵**的：AU11 成功，AU12「不灵」。
区别不在于 `Esc` 本身，在于**后面紧接着的操作**——
AU12 紧接着就去点音频节点，那个点上还压着正在消失的抽屉，
于是 `elementFromPoint` 全部落空，报「找不到可点的音频节点」。

> **教训：一次实验里，「前一步有没有真的生效」必须自己断言，不能默认。**
> AU12 我用的是「`.copilotKitMessagesContainer` 还在不在 DOM 里」当判据，得到 `false`（还在），
> 于是以为抽屉没关、跳过了下一步 —— 实际上它已经关了，只是元素还留在 DOM 里没被卸载。
> **判「浮层在不在」要问它的实时可见性/坐标，不是问它在不在 DOM 里。**
> 这跟 §17「判『有没有弹窗』要在弹窗还活着时问」是同一条，只是这次问错了对象。

### 22.3 我把「节点子树 union」当成了「面板位置」

为了判断面板有没有出视口，我一直在算「`.react-flow__node` 子树里所有元素的 boundingRect 之并集」。
这个判据是错的：子树里既有节点本体的预览区、又有溢出到各处的挂件，
union 把**别的节点**也算进去 —— 算出的 `y0=301`，而画面上工具条实际在 `y≈504`，**差了 203px**。

连带的两个假象：

- `elementFromPoint` 落在 union 算出的位置上，命中 `.react-flow__pane`，
  我据此写下「面板被节点本体压住了」—— 顺手量了个重叠面积，`overlapRatio: 0`，
  **自己把自己否掉了**（标题 rect 和节点本体在垂直方向一点重叠都没有）。
- 拖拽判据也建立在 union 上，于是「拖不动」这个结论同样不可信。

正确判据其实**正文第 272 行早就写着了**：面板容器的 class 是 `node-floating-ui`。
但我又拿它当了一次，照样错 —— `.node-floating-ui` 命中的是那条
`263×20` 的**节点标题浮条**（`transition-[transform,opacity] duration-150`），
不是参数面板。**同一个 class 家族里住了两个东西。**

> **教训：class 白名单和「子树 union」都是「我以为的判据」，而且失败时都不报错。**
> 要么用 `fingerprint()`/`diffPanels()`，要么量一个**能被独立验证**的锚点
> （比如「宽 > 400 且高 > 100 且 `innerText` 含『参考』」）。
> 另外：**先量一个重叠面积，再写「被挡住了」这种带方向的结论** ——
> 这一次是那个 `overlapRatio: 0` 救了我。

### 22.4 附一条低级但贵的：按编号前缀删图会误伤

做截图减法时我用 `f.startswith(('M-13','M-14','M-15','M-16'))` 当白名单的反面，
结果把 **AT 批次已提交的 `M-131` / `M-133` / `M-134` / `M-135` / `M-137`** 一起删了
（`M-13` 是 `M-131` 的前缀）。靠 `git checkout -- screenshots/` 全量救回。

> **教训：编号不是前缀安全的。** 涉及批量删除时，**只用完整文件名白名单**，
> 永远不要用「前缀 + 后缀」去构造要删的集合。

## 23. Batch AV：「高级设置」的入口 —— **同一个错误，我犯了两次**

§22 结尾我写下一句自以为很清醒的话：「`rect` 非零不等于被绘制，判『用户看得见吗』只有截图说了算」。
写完当场就**又犯了同一个错**。

### 23.1 我把「我没找到入口」升级成了「产品没有这个功能」

AU 十三轮的结论写进了手册和 AUDIT：「**『高级设置』没有展开态，点不开，也看不见**」，
并附了四条看起来很硬的证据（`grid-rows-[0fr]` 计算值 `0px`、全页 `grid-rows-[1fr]` 为 0、
标题不是 button、点它命中 `.react-flow__pane`）。

**那四条证据全都为真，而且全都只支撑一件事：这四个字点不动。**
我从中读出的是「这个功能不存在」。

真相是：**入口一直就在它右边 60px 的位置** —— 参数条上有一枚 32×32 的滑块图标按钮
（SVG path `M14 17H5M19 7h-9`），**无文字、无 aria**。点它：

| 状态 | class | `grid-template-rows` 计算值 | 面板高度 |
|---|---|---|---|
| 收起 | `grid-rows-[0fr]` | `0px` | 246px |
| 展开 | `grid-rows-[1fr]` | `157px` | **411px** |
| 再点 | 回到 `[0fr]` | `0px` | 246px |

**是 toggle。** 展开后视频出三个开关（默认全开）、音频出三个滑杆（每条右侧带数值框）。

> **这已经是同一个错误的第二次了**：第一次是 AU5 的「它默认就是展开的、一直可见」，
> 第二次是 AU 末尾的「它没有展开态」。两次方向相反，**错的是同一个动作** ——
> 拿「我盯着的那一个入口点不动」当成「功能不存在」的证据。
>
> 根因是**候选集**。前十几轮我按「文字」和「aria」找控件（§15 的经验），
> 于是 `⚙` **从头到尾没被列进候选** —— 它两样都没有。
> **「按已有经验找控件」这个动作本身，会系统性地漏掉那些没有文字也没有 aria 的控件。**
> 正确做法是**先全量清点再挑**：AV1 把面板里 15 个可点元素连 SVG path 一起倒出来，
> `⚙` 立刻就在里面了 —— 那一刻真相已经摆在纸面上，只是没人往那个方向想。

### 23.2 「点不到」和「不存在」在证据上长得很像，但结论强度差一个量级

「点它没反应」这条观察有**至少五种**解释：

1. 它确实是静态文字（我以为的）；
2. 它是按钮但我点在了被遮挡的位置（AU9 测过：`elementFromPoint` 命中 `cursor: grab` 的节点本体）；
3. 它是按钮但坐标算错、点在视口外（AU3 测过：坐标落在 y=809/y=830）；
4. 它是按钮但事件绑在别处；
5. **它是标题，真正的入口在旁边另一枚按钮上**（真相）。

前四种我全都遇到过，每遇到一次我就更相信第 1 种。
**只有第五种需要「清点全部可点元素」才能发现** ——
而清点是要花一轮的，前面每一轮失败都在「微调点击条件」，那是在第 1、2、3、4 种里打转。

> **判据：连续两轮以上「点了没反应」，不要再调点击条件，去清点候选集。**
> 微调是在猜，清点是在看。这跟「连续 N 次失败时先 dump 全部」是同一条，
> 但这次它救回来的不是**判据**，是一整个**功能**。

### 23.3 附两条更小的

**① 节点拖不动，是因为我漏了「先取消选中」这一步。**
参数面板 658 宽、居中在 263 宽的节点上，**盖住节点上半部分**；
面板开着的时候从节点中心抓，抓到的是面板不是节点。
先点空白取消选中、面板收起，再拖，一次就成（`dy: -173`）。

**② 音频节点连三轮点不中，最后是 dump 出来的。**
原因不在控件逻辑，在**几何重叠**：`图片节点 2 [604,339,263×148]`
把两个音频节点整个压在下面 —— 音频节点 1 的 x 范围 `624..772`
**完全落在**图片节点 2 的 `604..867` 之内，**可见区 0 像素**；
音频节点 6 也只露出 5px。把它拖到别处，`selfHit` 立刻从 `N` 变 `Y`。
这三轮我一直在改「选节点的算法」，而算法没问题，**是靶子没了**。

> 通用版：**「点不中」先量重叠面积，别先改算法。**
> `elementFromPoint` 落在谁身上，比「我调用时传了什么」更可信。

## 24. Batch AW：顶部工具条五枚 —— 又一次「我以为的 API」

手册里这五枚**只有名字，从来没被点开过**。这一批逐枚实按，五枚**行为完全不同**：

| 工具 | 点开之后 | 形态 |
|---|---|---|
| `参考` | 进入点选模式，顶部蓝条「从画布或资产管理选择参考」 | 顶部横条 + 画布高亮 |
| `标记` | 进入点选模式，顶部「元素选择模式 / 点击图片选择局部元素」 | 顶部横条 + 画布变暗 |
| `特效` | 特效广场 | 全屏 `mantine-Modal-inner` z=701 |
| `角色库` | **先弹《Seedance模型使用承诺书》**（z=801），需勾选才能「同意并使用」 | 全屏模态框 × 2 层 |
| `运镜` | 运镜广场，22 个内置预设 | 全屏 `fixed inset-0 z-[calc(var(--z-overlay)+2)]` z=602 |

**前两枚根本不是「弹列表」，是把你切进一个交互模式** —— 顶部挂一条蓝条，
右边有 `返回节点` 和 `×`；不点它们就一直停在那个模式里。
这一条正文里一个字都没有，而它是新手最容易懵的地方。

### 24.1 AW1 的「三枚都没反应」是我把公共库 API 用错了

AW1 用 `diffPanels(before, after)` 判「新浮层」，三枚全报 `nNew: 0`。
按平时的习惯，我几乎就要写下「这三枚点了没反应」。

实际上 **`diffPanels()` 返回的是数组**（`after.filter(a => !seen.has(a.sig))`），
不是 `{ added: [...] }` 对象。我写 `d.added || []` → 恒为 `undefined` → 恒报 0。

翻记录发现，**我在 AV2 里写的是 `d.added || d.new || d`** ——
那个 fallback 恰好蒙对了，把这个误用**掩盖了整整一个批次**。

> **教训：「我以为的 API」和「我以为的 class 清单」是同一族错误（§15）。**
> `diffPanels` 叫「diff」，我就以为它返回一个「差异对象」；
> 实际上它返回的就是差异本身。**调公共库之前先读实现，或者 `console.log` 一次。**
>
> 更值得记的是第二层：**一个碰巧蒙对的 fallback 会掩盖误用**。
> 写 `d.added || d.new || d` 的时候「多写几个 key」是保险，
> 但它同时把「我其实不知道这个函数返回什么」这件事藏了起来 ——
> 藏到下一次我严格按猜测写 `d.added` 时才爆。**fallback 不是豁免，是延期。**

### 24.2 浮层的 class 不可靠：同一个功能两种实现

`特效广场` 是 `mantine-Modal-inner`（z=701），
`运镜广场` 是 `fixed inset-0 z-[calc(var(--z-overlay)+2)] flex items-center`（z=602）——
**两个都是「全屏浮层」，实现却完全不同**。按 Mantine class 白名单去认浮层，
**运镜广场会被整块漏掉**。

这跟 §15 记的「素材库面板不是 Mantine class，按白名单筛会漏」是同一类，
只不过这次**漏的是两个功能里更常用的那个**。

> 所以这批一路都用**无 class 白名单的判据**：
> 「全页所有 `position` 为 fixed/absolute/sticky、可见、尺寸 ≥ 8×8、
> 且 `innerText` 非空」的元素做**签名前后差集**。
> 这套判据 AW1 漏的、AW3 全抓到了。

### 24.3 角色库：没勾选，就没资格说它长什么样

点「角色库」先弹《Seedance模型使用承诺书》，要**勾选同意**才能「同意并使用」。
我**没有勾、也没有点同意** —— 那是替用户签协议。

于是「角色库里有多少角色、怎么挑」这一项**只能标 📖 没验**。
能写进手册的只有：它有两个标签 `公共角色库` 和 `Seedance、Seedance 2.5 合规素材库`
（这是从承诺书背后透出来的画面里读到的），以及承诺书的三条正文。

> 这也顺带解释了 AS 批次记的那条黄色提示「**未签署人像安全协议…去签署**」——
> 当时只当成一条提示条记下来，没想到它就是这道承诺书的入口。
> **提示条上的链接往往通向一处此前完全没进过手册的流程。**

### 25.1 「点偏了」和「没反应」在读数上完全一样

AX1 里图片的 `参考` / `标记` 两枚都读到 `nAdded: 0`。
差一步我就写下「图片节点上这两枚点了没反应」。

而参数面板是**以节点为中心居中、宽 660**，节点一偏左整块面板跟着左移 ——
AX1 实测面板 rect 是 `[-127,306,660,192]`，`参考` 那枚在 **x = -114**。
同一次里 `风格` 在 x=2 勉强进屏，就点成了、读到了风格广场。

AX2 把节点**同时**拖到 `(720, 150)`，面板变成 `[380,301,660,192]`，两枚都点成了，
读数是「新增 13 个元素」—— 全是画布节点重排（z 从 0 跳到 1000），
**这正是「切模式」的指纹**：画布上的节点整体进入可选状态。

> **教训：`nAdded: 0` 这种「什么都没发生」的读数，先怀疑自己的坐标。**
> 判据要问的是「我点的地方有没有那个东西」——
> AX2 因此在点击前加了一条硬闸：`rect` 出视口就**不点**，并把原因记成
> 「按钮仍在视口外」而不是「没反应」。
> **让判据能说出「我为什么没测」，比让它多报一个数字有用得多。**

### 25.2 「我以为的 API」，第三次

**以为 `pick` 收整个 `panelState` 对象，实际只收到 `st.btns` 那个数组**。

加上 §24 的 `diffPanels` 那次，这是**同一个批次族里第三次**把公共库/自写辅助函数的
签名想当然。三次的共同点都一样：**我按名字猜了参数，没读实现。**
代价是三轮脚本白跑。

> 收口成一条：**自己写的回调、工具库的返回值，用之前先 `console.log` 一次。**
> 名字是最不可靠的文档。

## 26. Batch AY1/AY2/AY3：悬停读 Tooltip —— 一个比「点开看」便宜得多的手段

这一批最值钱的发现不是某个功能，而是**一个手段**：
> **无文字、无 `aria-label` 的按钮，悬停一秒就能拿到官方名字，
> 而且悬停不触发任何操作。**

### 26.1 挖出来的东西

| 按钮 | 此前手册的状态 | 现在 |
|---|---|---|
| `📄`（SVG `M10.26 1.67c.32 0 .57.25.57.57v.35`） | **完全没记**。AW2 点过一次读到 `newPanels: []` | **提示词优化**。点下去不弹面板，弹顶部提示「**提示词为空，请输入内容后点击**」 |
| `文A`（SVG `M15.52 7.2c.16 0 .31.1.37.26l3.8 1`） | 「📖 没点，**八成**是翻译提示词，可能扣积分」 | **翻译提示词**，四类节点都有 |
| 参数条最右那枚白圆上箭头 | 只知道「有它，不知道是什么」 | **生成按钮**（见 26.3） |
| 抽屉工作区栏 | 没记 | `未命名工作区` 是**可编辑 input**、`画布 2` 是画布切换按钮 |

顺带纠正一处旧误读：`AUDIT.md` 那条「资产管理工具行是「🔍 / 筛选 / 管理」三枚」不完整 ——
**「画布」页是四枚、「资产」页是五枚**，两页位置对齐但内容不同。

### 26.2 为什么早没发现：我在用最贵的方式认按钮

前几批认无文字按钮的路子只有两条：
**读 SVG path 的 `d` 猜语义**，或**直接点开看**。
前者慢且容易错（`📄` 反推了三轮），后者贵 —— 点开可能触发生成、弹协议、上传文件。

悬停读 Tooltip 两条都不沾：**只读、不触发**。
而且 Mantine Tooltip 在 `[class*="Tooltip-tooltip"]` 上，坐标一给就能读到。

> 噪声要剔：`按 ESC 退出` 是 Mantine 的默认尾巴，
> `新功能：支持真人` 是一次性引导气泡（第一次读会盖住真提示，第二次读就没了）。
> 过滤掉这两条，剩下的才是按钮自己的名字。

### 26.3 认「会花钱的按钮」：借同类节点的禁用态

最右那枚白圆按钮 `disabled: false`、`cursor: pointer`、
悬停**也没有提示** —— 本手册**不能点**（真扣 135 积分）。

办法是**去同类节点上找同一枚的禁用态**：
音频节点参数条同位置那枚，提示词为空时
`disabled: true` + `cursor: not-allowed`，
tooltip 写着「**请输入提示词或添加参考素材**」；
文本节点写「**请输入提示词**」。
一比就知道**它是生成按钮**。

> **「什么都不能点」不等于「只能不测」。**
> 找到一个**同构但更安全的读数**（禁用态文案），照样能把功能坐实。

### 26.4 抽屉容器判据：这个批次族连翻三次车

三次都是「用几何条件挑容器」，三次都挑错：

| 判据 | 挑中了什么 | 后果 |
|---|---|---|
| 宽≥280 且 x<400，取面积最小 | `react-flow__viewport` | **画布变换容器**。里面是节点自己的按钮（音频生视频 / 分镜 / 打开导演台…）+ 3 个 rect `[0,0,0,0]` 的 `input[type=file]`。抽屉控件一个没读到 |
| 取最内层 | `ScrollArea-content`（33 个按钮） | 比抽屉本体窄一层，**顶部那层又没进来** |
| 取最外层 | `h-screen w-screen` | 铺满整屏，含画布和底栏 |

收口成两条：

1. **用文案锚点反查** —— 「含『所有评级』且靠左、不在 `.react-flow` 内」。

### 27.6 顺带记一次共享仓库的插曲

Batch AZ 提交时撞上并发提交：`git commit` 报「no changes added」，
另一条提交把我的暂存内容一并带走了（挂在那条 message 下），
而我的两张新截图没被带上。

处置办法：
1. 先 `git fetch`，用 `git ls-tree` 逐个比对**远端和本地在这个目录上的 blob**；
2. 确认**逐字节一致**（说明我的内容已经在远端，本地那条提交是冗余的）；
3. `git reset --mixed origin/master` —— **只动索引、不动工作区**；
4. 提交前后各存一份 `git diff` 做字节比对，确认**他人的未提交修改一处未动**
   （3838150 字节，diff 为空）。

> ✅ **不要用 `git stash`** —— 那会把别人的修改一起卷进去。
> `--mixed` 是这个场景下的正确工具：**移动 HEAD，不碰工作区**。
> 无论怎么动，**动之前先存一份 `git diff` 留证**。

## 30. Batch BD —「点了没反应」的第三种成因：判据自己错了

这一批的起因是一句不起眼的话：手册里有 **71 行**「📖 / 没验 / 没点过」的声明。
按「只读就能验 / 会写数据需授权 / 环境不可能」分诊之后，挑了四个不需要授权的目标：
**网格吸附**、**移动/抓手工具**、**`⌘Option` 拖动**、**预设工作流蓝点**。

计划了 5 个脚本（BD1–BD5），实际跑下来**最有价值的产出不是这四件事的答案**，
而是两条方法论上的翻车。两条都写进了 `AUDIT.md` 和 `90-troubleshooting.md`。

### 30.1 假结论一：我用悬停色当成了「开关已开启」

BD3 的结论是「**网格吸附点开了就关不掉**，连点 8 次纹丝不动」。
听起来像个产品 bug。BD4 拿同一排另外两枚开关做对照，露了底：

| 观察 | 真实含义 |
|---|---|
| `rgba(0, 0, 0, 0)` | 关着 |
| `rgba(255, 255, 255, 0.15)` + class `bg-canvas-controls-active` | **开着** |
| `rgba(255, 255, 255, 0.1)` | **鼠标还悬在上面** |

`mouse.click` 完**鼠标不会离开按钮**，悬停样式立刻生效。
`0.1` 和 `0.15` 只差 0.05 透明度 —— **肉眼、正则、脚本都分不开**。

> ⚠️ 所以「点了没反应」有**三种**成因，不是两种：
> (a) 产品真的没反应；(b) 落点不归我；(c) **判据本身读错了**。
> 第三种最贵，因为会把手册写成「产品在骗你」。
> ✅ 固定判据：**class 里的 `bg-canvas-controls-active`**，回读前**先把鼠标移开**。

### 30.2 假结论二：下标取按钮，把邻居当成了目标

BD4 改用正确判据之后，仍然漏测了「网格吸附」——
因为我用的是**工具条里的第 N 个按钮**，而那一排是：

```
0 整理画布  1 切换小地图  2 隐藏节点连线  3 网格吸附  4 缩放选项
```

BD4 测了 `0/1/2` 就以为测完了三枚开关；后面想补测网格吸附时写的又是 `tap(2)`，
**点到的还是「隐藏节点连线」**。BD5 全部改成 **aria 全等**才真正点到。

> ⚠️ 同一族错误还有两处，都是这批踩到的：
> - BD1 用 `/网格吸附|隐藏节点连线|切换小地图/` 这种 **alternation** 找按钮，
>   结果抓到 DOM 里排更靠前的 `切换小地图` —— **找谁取决于谁在前面，不取决于谁在正则里**。
> - BD4 的 `bar()` 过滤 `r.x > 100`，把 `x=61` 的 `资产管理` 漏在了外面。
>
> ✅ 同一个概念**只写一遍判据**（共用常量/共用函数），
> 并且**一律用 aria 全等，不用下标、不用 alternation**。

### 30.3 坐实的四件事

| 事项 | 结论 |
|---|---|
| `网格吸附` | **点了没有任何可观察变化**：aria 不换、class 不亮、背景不变；三种触发方式（坐标点击 / DOM `el.click()` / 派发完整五事件）全无效；拖节点请求 `(+37,+28)` 实际 `(+34,+25)`，**不是任何网格倍数**。对照组 `切换小地图` 相同代码一点就开 |

| `H` / `V` | ⭐ **不对称**。连按三次 `H` = `移动 → 抓手 → 抓手 → 抓手`；`Shift`+`H` 无效；**点按钮本身也退不出来**；只有 `V` 能退。三轮复现 |
| 预设蓝点 | ⭐ **`pointer-events: none`** —— 它**收不到悬停，所以不可能有 tooltip**。全画面 5 个，预设里**正好 3 个**（`调度故事板`/`故事板`/`人像质感调节`），另两个在模型下拉和 `TV Director` 上 |

## 31. Batch BE — 画布坐标：唯一不受缩放影响的判据

BE 的起因是 BD5 亲手留下的两个 📖（网格吸附是否只在特定缩放下有效、`⌥⇧F` 在弄乱后铺不铺）。
计划 3 个脚本，实际跑了 5 个（BE1–BE5），**因为我自己制造的两次假绿灯不得不回头收拾**。
最有价值的产出仍然不是那两个 📖 的答案，而是**一条判据**和**两次自我打脸**。

### 31.1 两个 📖 的答案

- **网格吸附**：把画布从 48% 放大到 **83%**（行内相邻节点间距从 226px 变成 **640px**），
  再点开关 —— aria 不换、class 不亮、背景不变；拖动请求 `(+37,+29)`、落点 `(+34,+27)`，
  **对 640 取模仍是 (34,27)**。**「格子太小看不出来」这个解释被排除。**
- **`⌥⇧F` 整理画布**：⭐ **按钮有效、键盘无效**（见 §31.3）。

### 31.2 ⭐ 画布坐标：唯一不受缩放影响的判据

本轮学的最重要的一课。节点位置有两种读法：

| 读法 | 从哪来 | 能不能当判据 |
|---|---|---|
| **屏幕坐标** | `getBoundingClientRect()` | ❌ 屏幕坐标 = 画布坐标 × scale + 视口平移。**一次 `⌘0` 就让所有目标失效** |
| **画布坐标** | 节点自己的 `transform: translate(Xpx, Ypx)` | ✅ 与视口缩放、平移无关，跨缩放跨会话都稳定 |

BE2 的复原失败就是这么来的：它拿 BE1 进场的**屏幕坐标**当拖动目标，
而中间 `⌘0` 改过缩放 —— 拖回去的位移量在画布空间里根本不对应。
**目视反推是对的**：拖完节点落到了「原点 − 位移」，两处都不对。

> ⭐ 从这以后，**判位置一律读 `transform` 的 matrix**。
> BE4 之后所有脚本都改成了 `flowPos()`，不再读屏幕坐标。

### 31.3 两条路径分诊：整理画布的按钮有效、键盘无效

在**一张确实乱的画布**上（先拖乱、再用画布坐标确认「7 行、间距 3 种取值」）各试两次：

| 做法 | 画布坐标变化 | 确认条 |
|---|---|---|
| 键盘 `⌥` `⇧` `F` | **0 个** | 不弹 |
| 底栏「整理画布，Option+Shift+F」按钮 | **11 个（全部）** | 弹「是否保留此次整理结果？」 |

⭐ 整理后的布局也一并坐实：**3 行，行内 4/4/3，行内间距 4 种取值**。
**间距不一致是正常的** —— 节点卡片宽度不同，间距 = 卡片宽 + 固定间隙。

> ⚠️ **没有**写成「`⌥⇧F` 快捷键坏了」。macOS 上 `⌥`+字母可能被输入法/系统层吃掉，
> 自动化分不清这一层和产品层。手册只写「按钮一定管用，键盘不一定」。

### 31.4 两次假绿灯，都是同一个形状

**第一次（BE4）**：复原循环报「1 轮之后仍有偏差：0 个」，
但同一段输出里紧跟着「复原后布局：**0 行**，间距 `[]`」——
`flowPos` 返回的是**空数组**，空数组 `.filter()` 当然过。

> ⭐ **空读数会替你撒谎。** 「全部通过」的空结果和「真的全部通过」在数值上无法区分。
> ✅ 铁律：**每一次读数都要配一条「读到了几条」的断言**，空读数显式判为失败。
> BE5 之后每一步都打了 `读到 N 个节点`。

**第二次（BE3）**：`Object.keys(节点数组).slice(0,2)` 拿到的是**下标字符串 `"0"` `"1"`**，
所以「把画布弄乱」这一步**根本没执行**（两行都报「无可拖点」），
而脚本照常往下打出了「画布**确实是乱的**」。

> ⚠️ **动作失败却在报告里被写成了前置条件成立** ——
> 这是比「读错数」更隐蔽的一类错误：判据在替失败背书。
> ✅ 数组用 `.slice()`，别用 `Object.keys()`；每个动作都要单独判成败。

### 31.5 新的判据陷阱：`<script>` 里的 RSC payload

BE3 用 `[...document.querySelectorAll('body *')]` + `innerText` 搜「是否保留此次整理结果？」，
结果 `barTexts` 吐了 **65 KB**，内容全是 Next.js 的 JS chunk 名和转义引号 ——
因为 LibTV 是 Next.js 站点，`<script>` 的 `innerText` 是整份 **RSC flight payload**，
**任何文案在里面都搜得到**。那次调用直接把后续所有输出冲掉了。

> ✅ 两条规矩：
> 1. 判可见文案**必须先排掉 `SCRIPT` / `STYLE` / `NOSCRIPT` / `TEMPLATE`**；
> 2. 自检：**单次读数超过几百字、且全是 chunk 名和转义引号，
>    那不是读到了界面，是读到了 payload。**
>
> ⚠️ 这是 §22「class 白名单不可信」、§29.4「宽松匹配截进别人的内容」的**第三种**：
> 匹配范围包含了**根本不该参与匹配的节点**。

### 31.6 画布收尾

BD1–BE4 全在做拖动实验，画布布局被反复改动。
最终**没有手动把节点拖回去**，而是用产品自己的路径收尾：
点整理按钮 → 点「**保留**」→ **刷新一次**验证落盘。
刷新后读到 11 个节点、3 行、4/4/3 —— **与最初的行分布一致**。
节点内容一个没少、没多、没改名；**只有位置变了**。

### 31.7 这批没解决的

- `⌥⇧F` 到底是没绑键位还是被 macOS 吃掉 —— 自动化分不清 📖；
- 网格吸附是否在别的画布 / 别的项目设置里才生效 📖；
- 整理的排版规则（为什么是 4/4/3 而不是别的分布）只观察了**一个样本** 📖。
