### 已知误读风险（留给 Gate B）

| 风险 | 说明 |
|---|---|
| 下拉列表动画期读数 | 打开画布下拉后立刻读行列表，会读到**过渡中的瞬态**（曾把 2 行读成 1 行，误判成「画布被删了」）。必须等读数连续两次一致 |
| 清理画布不可靠 | 焦点在节点输入框里时 `⌘A` 选的是文字，连点四次都没清干净；一度让截图堆着上一轮残留节点 |
| `hasText` 子串误匹配 | `filter({hasText:'视频节点'})` 会命中「请连接**视频节点**后操作」的智能剪辑节点。必须按标题前缀精确匹配 |
| `input[type="text"]` 选不中 | React 只设了 `type` **属性**没设 attribute，得用 `aria-label="画布名称"` |
| 「看着像空白的地方」可能压在节点上 | 图片节点卡片宽 615px，一直铺到 x=1312。想在右上角起手拖，结果**把图片节点拖走了**，后面按旧坐标算的框选矩形全部错位 |
| 视口内读不到节点 ≠ 节点不存在 | 节点被虚拟化了，移出视口就从 DOM 消失。判断「画布上有没有节点」不能只看 `.react-flow__node` 计数，要用 `⌘F` 搜索面板交叉验证 |
| 组操作条不是 `<button>` | 成组后的六个动作全是 `div` / `span`，按 `getByRole('button')` 找永远返回空 |
| 自己写的 helper 会咬人 | `nodeCount(page)` 少传一个参数就是 `undefined.locator`，7 个步骤一路崩到底 —— 报出来的是**脚本崩了**，不是产品没反应 |
| 「页面上最大的元素」当面板 | **别这么判**。React Flow 的 `.react-flow__viewport` 带 transform，`getBoundingClientRect()` 永远巨大，于是每一次读到的都是画布本身。batchG 三个面板全部「读成画布」，而截图是对的 —— **只看截图会以为没问题**。必须用 DOM 差集法（`fingerprint` + `diffPanels`） |
| 写死坐标建节点 | 图片节点宽 622px 铺到 `x=1022`，把第二个节点写在 `x=1000` 就会落在它身上，双击打开的是编辑区不是「添加节点」面板。起手点要**程序化求解** |
| `querySelector('.selected')` 取第一个 | 画布上可能残留别的选中态，会把参数**读串到别的节点上**。要按节点标题精确定位 |
