### 📏 节点 canvas 尺寸速查（2026-10-02 批次 79 实测，**在 100% 缩放下读**）

> **怎么量才不用换算**：屏上读数 = canvas 尺寸 × 当前缩放，所以
> **把缩放设成 100% 再读，屏上数字就是 canvas 数字**。批次 79 的整张表就是这么量的。
> 🔴 **订正**：本表此前混入了「某个缩放下的屏上读数」，本轮已逐个反查并改正：
>
> ✅ **2026-10-02 批次 103 补：这条等式本身在三个缩放下都成立**（此前只在 100% 量过一次）。
> 同一个文本节点逐档量，每档的除数**当场连读两次确认相同**（绝不写死 `0.6`）：
>
> | 缩放档 | 屏上读数 | ÷ 当时读到的 scale | 推出的 canvas |
> |---|---|---|---|
> | **40%** | `128×128` | ÷ `0.4` | **`320×320`** |
> | **60%** | `192×192` | ÷ `0.6` | **`320×320`** |
> | **100%** | `320×320` | ÷ `1` | **`320×320`** |
>
> ⇒ 三档极差 **0.00 / 0.00**，等式成立。顺带两次确认：
> ① **节点跑出视口也照样量得到**（60% 档 `@(-318,-189)`、100% 档 `@(-957,-556)`）——
>    「量尺寸不需要节点在视口内」这条已**第五次**得到独立确认；
> ② 节点本体与它内部那个满铺的层（`text-flow-node-full`）**三档都同尺寸**。

### 🎬 视频节点播放控件速查（2026-10-02 批次 101 实测，此前全册缺失）

🔑 **控件是「条件存在」的** —— 静止时卡片上其实什么都没有：

| 阶段 | 有 | 没有 |
|---|---|---|
| 未选中 | 封面 `video-passive-preview`（**一个 `<img>`**） | 播放键、时间、进度条、控件行、**`<video>`** |
| 已选中未播 | 封面 + 正中 **`44×44`** 大播放键 `video-simple-player`（aria `Play <名>`） | 时间、进度条、控件行、**`<video>`** |
| 播放中 / 播完 | `video-node-player-bar` 整条 + **`<video>`**（aria `<名> player`） | 大播放键 |

📌 **「没有 `<video>` 元素」只对静止态成立** ⇒ **不能用「有没有 `<video>`」代替「在不在播」**。

**控件行五件套**（canvas 像素）：

| 控件 | testid | 尺寸 | 读法 |
|---|---|---|---|
| 播放/暂停 | `video-node-playback-toggle` | **`16×16`**（屏上仅 10×10） | aria **`Play <名>` ⇄ `Pause <名>` 会翻转** |
| 时间 | `video-node-player-clock` | `50×12` | 卡片内 `00:03 / 00:06`（**有前导零**） |
| 静音 | `video-node-mute-toggle` | `36×36` | `Unmute video` ⇄ `Mute video`；**默认静音** |
| 全屏 | `video-node-fullscreen-toggle` | `36×36` | `Enter browser full screen` |
| 进度 | `slider-track` | `568×5`（屏上 `341×3`） | aria `Seek <名>`；**点击跳转误差 < 0.03s** |

**全屏播放器**（testid 全新，此前全册一个都没有）：

| 元素 | 几何 |
|---|---|
| `video-fullscreen-player-bar` | `1280×88`（铺满底部） |
| 顶部整宽进度条 `slider-track` | `1248×2`，thumb `8×8`，`aria-valuemax` = **素材总时长** |
| `video-fullscreen-playback-toggle` | `20×32` |

🔴 **不是「建任何节点都会改」** —— 实测**只有「空的」媒体节点会**。
🔑 **2026-10-01 批次 53 实测：触发条件与「内容变大 / 装不下视口」无关。**
两轮都先把内容包围盒撑大、且**建完都装不进视口**，只有左栏新建的空媒体节点那轮改了视口：

| | 包围盒横向 | 建完装得下吗 | 视口 transform |
|---|---|---|---|
| 左栏「图片」→ 空图片节点 | 1200 → 1820（+620） | ❌ 装不下（左侧出视口 584） | 🔴 `scale 0.6` → `0.568085` |
| 左栏「上传」→ 带内容图片节点 | 1200 → 1945（+745） | ❌ 装不下 | ❌ **逐字不变** |

⚠️ **自动适配 ≠「适配画布 ⇧1 / ⌘0」**：实测触发后内容包围盒（1820）**比视口（2253）还窄**、
只要重新居中就装得下，可自动适配后的视口是**偏右**的，左侧仍有 **584 画布像素**在视野外。
**前者是「建完节点后的视口调整」，后者才是「把全部内容收进画面内」。**
🔧 **2026-10-01 批次 51 推翻旧机制假设**：早前推测「媒体节点更大/落点更远把**包围盒撑大**」。
但经左栏「上传」得到的**带内容图片节点画布尺寸同样是 569×320**（与空视频节点一致），
缩放却**一点没变** ⇒ **「包围盒变大」不是触发条件**。
🔧 **2026-10-01 批次 54 把这个边界关上了**：用「**复制副本**」这条第三路径判别 —

| 创建入口 | 节点本身 | 缩放 |
|---|---|---|
| 左栏「图片」/「视频」新建 | **空**媒体节点 | 🔴 **触发** |
| 左栏「上传」 | **带内容**图片节点 | ❌ 不触发 |
| **右键「复制副本」** | **空**视频节点 | ❌ **不触发**（transform 逐字不变） |
| **右键「复制副本」** | **带内容**图片节点 | ❌ 不触发（副本 img 元素 1 个，**内容一并复制**） |

⇒ **与「节点是否为空」无关**：空节点经「复制」出来照样不触发。
现有全部读数一致指向：**自动适配是「从左栏新建节点」这个动作的副作用**。
📌 顺带：右键菜单里的「下载」是**禁用态**（`aria-disabled="true"`），
与工具条上那个**不是同一个按钮** —— 别把菜单的禁用态套到工具条上。

⚠️ **「适配画布」只重新居中、不会把倍数拉回原值**（内容装得下就保留当前倍数）。
**要精确还原缩放，必须在底部缩放输入框里填数字。**

### 🔑 节点自报资源账：`X resource(s): Y ready, Z processing, W failed`（2026-10-02 批次 105 首测，此前全册缺失）

**节点的 `innerText` 里始终带一串资源账**。它是判断「素材走到哪一步了」最省事的判据 ——
比「有没有 `<video>` 元素」更早一步，因为后者的出现还取决于选中态与播放态。

| 节点此刻 | 资源账（逐字） |
|---|---|
| 还没放素材 | `No resources: 0 ready, 0 processing, 0 failed.` |
| 素材处理完 | `1 resource: 1 ready, 0 processing, 0 failed.` |
| 素材收下了、还在处理 | `1 resource: 0 ready, 1 processing, 0 failed.` |
| 素材处理失败 | `2 resources: 1 ready, 0 processing, 1 failed.` ← ⚠️ **批次 112 仍未能造出** |

- 资源账后面跟 `Selected.` 或 `Not selected.`
- 节点类型不同，措辞也不同：时间线节点写
  `时间线: 1 visual track, 0 audio tracks, 0 clips.`
- 🔴 **这是「上传期」的账，播放期失败不会改它**
  （批次 105 实测：注入播放期加载失败后，账本仍是 `1 ready, 0 processing, 0 failed`）。
- 🔴 **账在哪个属性里，因节点类型而异**（批次 112 实测）：
  **视频 / 音频节点在 `innerText` 里；图片节点在 `aria-label` 里。**
  一张「预览不可用」的图片节点 `innerText` 逐字是 `预览不可用 重试 jimeng-b1...truncated`，
  **账不在里面**；它在 aria 上：`1 resource: 1 ready, 0 processing, 0 failed. Selected.`
  ⇒ 读账**两个都要读**（aria 优先，回落 `innerText`）。
- 🔴 **`failed` 这一档至今没能自然造出**（批次 105 两次 mp4、批次 112 四种坏图片全部落空）：
  - **0 字节**与**纯文本改扩展名** ⇒ **连节点都不建**（客户端就拒了）
  - 能建出节点的三种损坏（截断 PNG / IDAT 垃圾 / 伪随机 mp4）⇒ 资源账**要么 `1 ready`、要么永远 `processing`**
  ⇒ 结论按三态记「**无法验证**」：`2 resources: 1 ready, 0 processing, 1 failed.`
  **仍然只是抄写**，请以遇到时的实际读数为准。
- 🆕 **找「媒体渲染失败」最快的判据**（批次 112）：
  扫 **`data-canvas-content-state="media_error"`** ——
  它写的就是「这是一个媒体错误」这层语义，比「某个 testid 在不在」可靠。
  图片节点上它出现在
  `<div data-canvas-content-evidence="element" data-canvas-content-state="media_error"
  elementtiming="canvas-initial-content">预览不可用</div>` 里，
  外层 testid **`image-preview-unavailable`**（`192×192` 铺满整卡）。
- 「处理中」这一档的卡片特征：testid **`video-node-uploading`**、
  aria `<素材名>.mp4: 正在处理上传内容…`、卡片里**只有一个** `Rename <名>` 按钮、
  `<video>` 与 `<img>` **各 0 个**。详见[预览与播放视频节点](10-tasks/media-playback.md#媒体异常)。
- 🔑 **`<类型>-node-uploading` 是一族，不止视频一个**（2026-10-03 批次 109 实测）：
  音频传上去时是 **`audio-node-uploading`**，文字**逐字两段**
  `正在上传音频 0%` → `正在处理上传内容…`；
  图片传上去时是 **`image-node-uploading`**，文字 `正在上传图片 0%`。
  这三个都带 **`role="status"`** ⇒ 它们是**页面里第三个、第四个** `[role=status]`，
  且**在节点内部**（下面这条要注意）。

### 播放取流与上传存储不是同一个 key

（2026-10-03 批次 110 实测）

要复现「资源失效」或做故障注入，**必须知道拦哪条 URL**。而画布上有两个长得像、其实不同的 key：

| 环节 | 出现在 | 逐字样例（同一个 4 秒 WAV） |
|---|---|---|
| **上传存储 key** | 上传 POST 的路径里（`tos-d-ct-lf.snssdk.com/upload/v1/tos-cn-v-148450/<key>`） | `ooHx1IfRMfIKm8GlcVBdIOFE9UxdJqfdDnCfEL` |
| **播放取流 key** | `<audio>` / `<video>` 的 `src` 里 | **`oERcOtFfdQDiV1DIHmFBfRExqfYiGndCM8df8E`** |

🔴 **两者不是同一个值。** 拿上传日志里的 key 去拦播放，会得到
「**拦截报了命中、媒体却完好无损**」的假注入（`readyState 4`、`error null`、`duration 4.032`）——
本轮 b 轮就是这么白跑的。**正确做法：从 `<audio>` / `<video>` 的 `src` 里取 key。**

**取流 URL 的形状**（逐字，注意**没有扩展名**）：

```text
https://v3-dreamina-de.jianying.com/<hash>/6ac00098/video/tos/cn/tos-cn-v-148450/<key>/?a=513695&ch=0&…
```

- 同一素材的请求会在**多个 CDN 节点**之间跳（`v3-dreamina-de` / `v26-dreamina-de`），
  换节点时前一个请求会 `net::ERR_ABORTED` —— **那是正常的，别当成失败**
- 🔑 **服务端会转码**：源文件是 **WAV**，取流 URL 上却带 **`mime_type=audio_mpeg`**
  （时长 `4.032` 与源文件一致）⇒ 播的**不是**你上传的那个字节流
- `<audio>` 元素带 **`preload="none"`**，且**未播时它根本不在节点 DOM 里**
  （`audio: null`）⇒ 要读 `src` 得先点一次播放
- 资源账**不会**因为取流失败而变（批次 105 首测、批次 110 复测，两次独立）

画布上时间线节点的标尺（`timeline-ruler`）逐字是
`00:00 00:05 00:10 00:15 00:20 00:25 00:30`（每 5 秒一格）。

### 🔴 「全部清空」是坏的（两种节点类型上都是）

受控对照（同一基线、同一动作序列、**只换节点类型**）：

| 源节点 | 初始 | 打 1 个 | 打 2 个 | 点「全部清空」后 +600 / +1500 / +3000ms |
|---|---|---|---|---|
| **文本节点** | `Add tags` | `Edit tags: 青绿色` | `Edit tags: 青绿色, 紫色` | **三次都不变，面板一直开着** |
| **导演台节点** | `Add tags` | `Edit tags: 青绿色` | `Edit tags: 青绿色, 紫色` | **三次都不变，面板一直开着** |

⇒ **这是全局行为，不是某个节点类型的怪癖。**
💡 目前**唯一可靠的清法是删掉整个节点**（标签随节点一起消失，实测无遗留）。
⚠️ 顺带一句：**`Edit tags: …` 这个 aria 是判断「这个节点有没有标签」最快的办法**，
比看颜色点、比读 `innerText` 都稳。
