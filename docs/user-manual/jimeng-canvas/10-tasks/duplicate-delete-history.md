# 复制、删除与撤销

## 适用角色

已登录的即梦画布创作者。

## 目标

复制节点（含副本命名规则）、删除节点与连线，并用撤销/重做恢复误操作。

## 前置条件

画布中已有至少一个节点。

## 入口

- 节点右键菜单。
- 键盘：**⌘C**（复制）、**⌘D**（复制副本）、**⌘V**（粘贴）、**⌫**（删除）、
  **⌘Z**（撤销）、**⌘⇧Z / ⌘Y**（重做，两者均已实测可用）。

## 节点右键菜单（实测逐字）

容器统一是 `role="menu"`、aria 逐字 **`Canvas context menu`**、DOM 为
`[data-testid="canvas-context-menu"]`，**宽恒为 200**，每项 192×36。
**高度与条目数随节点类型变化**（2026-10-01 逐类型实测）：

| 节点类型 | 条目数 | 容器尺寸 | 与「空视频」基线的差异 |
|---|---|---|---|
| 空视频 | 7 | 200×292 | —— 基线 |
| 文本 | 7 | 200×292 | **「下载」可用**（不附原因文案） |
| 时间线 | 7 | 200×292 | 「下载」禁用，原因文案不同（见下） |
| 导演台 | 7 | 200×292 | 同时间线 |
| 图片 | 8 | **200×332** | 多出 **「复制为图片 ⌘⇧C」**（禁用，附「无法复制或剪切此选区。」） |
| 主体 | 8 | **200×332** | 多出 **「保存到主体库」**（**可用**，无快捷键、无原因文案） |

### 七个共有项（以空视频节点为基线，2026-10-01 复测逐字）

| 逐字 | 快捷键 | 状态 |
|---|---|---|
| 复制 | ⌘C | 可用 |
| 复制副本 | ⌘D | 可用 |
| 粘贴 | ⌘V | 可用 |
| **下载** | — | **禁用**，附逐字原因「**没有可用的就绪资源**」 |
| 重做 | ⌘⇧Z | 禁用时附「无需重做操作」 |
| 撤销 | ⌘Z | 禁用时附「无需撤销操作」 |
| 删除 | ⌫ | 可用 |

- **禁用项不是灰着就算**，而是在条目下方附一句**原因文案**
  （「没有可用的就绪资源」/「无需重做操作」/「无需撤销操作」）——
  这是判断「为什么不能点」的第一手信息，比猜要准。
- 禁用态同时有三种可脚本化判据：`aria-disabled="true"`、文字色
  `rgba(255,255,255,0.2)`（可用态是 `rgb(255,255,255)`）、**没有右侧快捷键字样**。

### 「下载」的禁用原因分两种（2026-10-01 新发现）

| 节点类型 | 「下载」逐字原因 |
|---|---|
| 空视频 / 图片 | **没有可用的就绪资源** |
| 主体 / 时间线 / 导演台 | **请选择至少一个组、文本、图片或视频项** |
| 文本 | 不禁用，直接可用 |

第二种原因说的是「这类节点根本不在可下载的范围内」，第一种说的是
「在范围内但还没有就绪资源」——**两句话含义不同，不要当成同一条**。

> ✅ **已关闭一个旧疑问**：本手册早前写「早前记『媒体节点的菜单可能多出
> 『保存到主体库』等项』—— 实测空视频节点没有这一项；『保存到主体库』是否出现在
> **有资源的媒体节点**上，**仍未验证**」。
> **2026-10-01 实测关闭**：**「保存到主体库」出现在「主体」节点上**（可用态），
> 与「有没有资源」无关；空视频与图片节点都没有这一项。
> 图片节点另有一项独有的 **「复制为图片 ⌘⇧C」**（空态时禁用）。

> 🔧 **订正一条旧结论**：批次 5 曾记录「节点右键菜单在自动化下不弹出，脚本场景不可依赖」。
> **该结论错误。** 批次 11 用 `mouse.down({button:'right'})` + 150ms 停顿稳定复现，
> 批次 30 进一步用**在选中节点上直接派发 `contextmenu` 事件**复现（更稳，
> 不受节点互相遮挡的命中测试影响）。**右键菜单是可靠的删除路径之一**
> （与「单击选中 + Backspace」并列）。

## 原子步骤

### 复制副本（实测）

1. 右键节点 → 点击 **复制副本 ⌘D**（或选中后直接按 **⌘D**）。
2. 结果：副本出现在原节点右侧相邻位置，自动选中，命名追加序号
   （「文本 1」→「文本 1 (2)」）。
   - 成功判据：节点计数加一，副本呈选中态。
   - 注意：今日命名后缀为 ` (2)`；连按多次 ⌘D 生成 (3)、(4)…
   - **2026-10-01 精确复测**（569×320 的视频节点）：⌘D 后状态行
     `1 node, 0 edges, 1 selected` → `2 nodes, 0 edges, 1 selected`；
     副本 aria 逐字 **`视频 node: 视频 1 (2)`**，尺寸与原节点**完全相同**
     （569×320），位置在原节点**正右方、同一水平线**（实测偏移
     **`dx=648 dy=0`**），且**副本自动成为选中态**。
   - **⌘Z 可撤销副本**：实测按一次 ⌘Z 回到 `1 node, 0 edges, 0 selected`，
     副本消失、原节点保留。
   - ⚠️ **必须先真正选中节点**才有效果。（本批曾因缩放后坐标变化、单击落空
     导致 `0 selected`，此时按 ⌘D 毫无反应——先看状态行再按。）

### 删除（实测）

1. 选中节点（或连线）。
2. 按 **⌫（Backspace）**，或右键 → **删除 ⌫**。
   - 成功判据：目标消失、计数减一；被删节点上的连线一并移除。
   - 注意：焦点在输入框（如生成面板提示词）内时 **⌫** 只删文字；先点空白
     取消焦点再删。

> ⚠️ **文本节点在「编辑态」时 ⌫ 只删文字、不删节点**（2026-10-01 实测踩坑）：
> 症状是「节点明明选中了，按 ⌫ 毫无反应，节点数不变」。
> 原因是点**卡片主体**会进入编辑态，焦点落在 `.ProseMirror` 编辑器里。
> **两种正解**（均实测有效）：
> - 点节点的**标题行**（那一行文字）来选中它 —— 焦点落在 `.react-flow` 而不是
>   编辑器里，此时 ⌫ 正常删除；
> - 或先按一次 **Esc** 退出编辑态，再选中并按 ⌫。

> ⚠️ **请按 Backspace，不要按 Delete**（2026-10-01 实测对照）：
> 同一个已选中的节点，按 **Backspace** 立刻删除（5→4→3→2→1 连续生效）；
> 按 **Delete**（数字小键盘右侧那颗）**没有任何反应**，节点数不变。
> 快捷键面板与右键菜单标注的都是 **⌫**，那就是 Backspace。
>
> 删除脚本化时也要注意：**Delete 与 Backspace 不可互换**，
> 只发 Delete 会得到「看似选中成功、实则什么都没删」的假象。

> ⚠️ **从「搜索」面板选中的节点，按 ⌫ 删不掉**（2026-10-01 实测）：
> 用顶栏 **搜索** 面板点结果行，节点**确实被选中了**（状态行变成
> `1 selected`、浮动工具条也出现了），但按 **⌫** 节点数**完全不变**。
> 原因是**焦点没落到画布上**——点结果行时 `document.activeElement` 是 `body`
> 或搜索按钮，React Flow 的画布容器收不到按键。
> **两种正解**（均实测有效）：
> - 点一下节点本体把焦点交回画布，再按 ⌫；
> - 或直接用**右键 → 删除 ⌫**（本手册推荐的脚本化路径，见上文）。
>
> 这和「文本节点编辑态下 ⌫ 只删文字」是两回事：症状都是「按 ⌫ 没反应」，
> 但前者焦点在编辑器里、后者焦点在面板里，**根因不同，别混着记**。

### 撤销 / 重做（实测 ⌘Z）

1. 误删后立即按 **⌘Z** → 被删节点/连线恢复（多次实测，包括恢复整条连线）。
2. **2026-10-01 对照实测**：建 2 个文本节点（3 节点）→ 右键删除其中一个 →
   2 节点；按 ⌘Z 第 1 次恢复到 3 节点，第 2 次再删回去，第 3 次退回到建节点前。
   结论：⌘Z 对**删除**有效，且能连续回退多步。
3. **重做 ⌘⇧Z（2026-10-01 已单独实测，确认可用）**：
   - 实测链：选中「视频 2」→ **⌫** 删除（`2 nodes` → `1 node`）→ **⌘Z** 撤销（回到
     `2 nodes`）→ **⌘⇧Z** 重做（又回到 `1 node`）。三步读数连续可核。
   - **菜单里的状态提示就是判据**：⌘Z 之后右键，**「重做 ⌘⇧Z」不再带
     「无需重做操作」副文案** → 说明此时重做可用；一旦重做完，它会重新变灰。
   - ✅ **⌘Y 也已单独实测确认可用（2026-10-01 批次 21，关闭多批以来的长期缺口）**。
     早前几批一直标「单独未验证」，原因是**试按 ⌘Y 时恰好已无可重做内容**，读数自然
     不变 —— 那是**测试条件不成立**，不是功能不可用。批次 21 用
     **⌘D → ⌘Z** 主动造出「有可重做历史」的状态再按 ⌘Y：
     `1 node` →（⌘D）`2 nodes` →（⌘Z）`1 node` →（**⌘Y**）**`2 nodes`** ✅。
     复现两轮，读数连续可核。
4. **撤销历史不跨会话**：刷新页面后 ⌘Z 不再回退任何内容（2026-09-23 实测；
   2026-10-01 复现——删除后先刷新，再连按 10 次 ⌘Z 仍为删除后状态，无任何恢复）。

> ⚠️ 两条实测合起来才是完整结论：**⌘Z 能撤销删除，但只在同一个页面会话内。**
> 误删后先按 ⌘Z 再去干别的；一旦刷新，删除就找不回来了。

### 粘贴（2026-10-01 复测：可用）

- 2026-09-23 曾以真实键盘事件发送 **⌘V** 未产生新节点，记为「不可用」。
- **2026-10-01 复测推翻**：先 ⌘C 再 ⌘V，节点数 5 → 6，**粘贴确实生效**，
  粘贴出的是选中节点的副本（内容与被复制节点一致）。
- 结论：⌘V 可用，但它是**面板未声明**的快捷键，稳定性没有保证。
  关键操作仍建议用 **复制副本 ⌘D**（声明在右键菜单里，行为可预期）。

## 常见错误与恢复

| 现象 | 处理 |
|---|---|
| 按 ⌫ 没删掉节点 | 焦点在输入框里；点空白后重新选中再按 |
| 删错了 | **立刻按 ⌘Z**；刷新过页面就撤不回来了 |
| ⌘Z 连按没反应 | 检查是不是刷新过页面——撤销栈已清空 |
| 重做菜单是灰的（无需重做操作） | 当前没有可重做的历史，属正常 |
