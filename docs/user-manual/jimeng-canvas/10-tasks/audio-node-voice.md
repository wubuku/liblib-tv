# 配置音频节点（配音、声音库与音乐模式）

## 适用角色

已登录的即梦画布创作者。

## 目标

创建音频节点，了解配音/音频生成的面板参数、音色库与价格显示，为台词配音做准备
（执行生成会消耗积分）。

## 前置条件

已打开画布；建议先想好台词文本。

## 入口

左栏 **音频**（点击即在画布中央新建「音频 N」空节点，自动选中并弹出音频生成面板）。

### 连接手柄：音频节点**能**当连线的起点

音频节点**左右两侧的手柄都在**（`source` 31/31、`target` 31/31）——
这与**时间线节点形成对照**（时间线**没有**出边手柄，见[时间线节点](timeline-node.md)）。

⚠️ **有手柄 ≠ 能拖**。真正的可拖热区在**伪元素**上：

| 部位 | 读数 |
|---|---|
| 手柄元素本体 | `pointer-events: none`、`opacity: 0`、屏上 `14×28` |
| **`::before`** | **`pointer-events: auto`、`40px×80px`** ← **这才是热区** |
| `::after` | `20×20`，`opacity: 0`（圆形字形，**鼠标悬停或选中时**才显形） |

⇒ 想判断「这个节点能不能发起连线」，**要读 `getComputedStyle(手柄, '::before').pointerEvents`，
不是看元素本体在不在、看不看得到。**

### 🔑 有资源的音频节点，工具条**不是**生成面板（全册此前没有这一档）

2026-10-03 批次 114 实测：**同一个音频节点，「空」和「有资源」是两种形态**，
连工具条里装的东西都不一样：

| | **空**音频节点 | **有资源**的音频节点（上传 wav） |
|---|---|---|
| 工具条里是什么 | **生成面板**（说明文案、创作类型、模型、模式、音色、价格、生成钮） | **`165×40`，逐字只有「音频修剪」**，一个 `下载` 钮 |
| 有 `generation-prompt-editor` 吗 | ✅ 有 | ❌ **0 个** |
| 能打 `@` 引用素材吗 | ✅ 能 | ❌ **不能** |
| 有音色库吗 | ✅ 有 | ❌ 没有 |
| 卡片内 testid | `audio-node-empty`、`audio-node-status-icon`（6 个） | `audio-node-result`、`audio-result-gallery`、播放器与波形家族、`audio-duration` × 2（18 个） |

⚠️ **这条有实际后果**：`@` 面板（引用素材）**只在空节点上能用**。
想让「用 `@` 引用某个音频」，得在**空节点**的提示词里引用它 ——
在那个音频自己的节点上是打不了 `@` 的。

📌 也因此：「`@` 二级子菜单里能不能看到自己」这个问题**在产品里不可判定** ——
宿主必须空才能打开生成面板，而空宿主必然没有资源。详见[参考页](../20-reference.md#二级子菜单)。

### 选中态 vs 未选中态：差的**不只是那一句 aria`（2026-10-03 批次 113 补上）

上面「节点结构」记的是**未选中**态。同一个空音频节点，切到选中态，内部结构**多出 3 个 testid**：

| | 未选中 | **选中** |
|---|---|---|
| 内部 testid | 6 | **9** |
| 按钮数 | 1 | **4** |
| 多出的 testid | — | `flow-node-media-stroke`、`flow-node-target-connection-menu-button`、`flow-node-source-connection-menu-button` |
| DOM 变化 | — | `node-toolbar` / `selection-context-toolbar-popup-host` / `node-feature-chrome-host` **从无到有** |
| `aria-node-empty` 末句 | `… Not selected.` | `… Selected.` |

🔑 **`audio-node-empty` 元素本身两种态下都在**，变的只有它的 `aria-label`
（详见下方「批次 113 也结清了另一处 VOID」）。

### 有媒体的音频节点：结构见下节，这里只补**时长读数的双形态`

完整的 testid 清单见下方「[结构（canvas 尺寸 `320×320`）](#结构canvas-尺寸-320320与空节点一致)」。
批次 113 补了一条此前没记的读数：

> 🔑 **`audio-duration` 里有**两个**时长形态**：
> 它的可见文字逐字是 **`00:00:04 00 : 00 : 04`** ——
> 紧凑的 `HH:MM:SS` 后面**跟一个带空格的 `HH : MM : SS`**（屏上 `62×15`）。
> 另一个宿主 `audio-duration-accessible` 只有紧凑形态，且屏上 **`1×1`**（`sr-only`）。
> ⇒ 判「时长显示在哪」**两个宿主都要读**：
> 只看 `innerText` 会以为有两个时长；只看 `aria-label` 又只会看到一个。

### 试听 `Play`（2026-10-01 批次 32 首次实测，2026-10-03 批次 113 补齐时序）

- 按钮 aria 逐字 `Play 生动解说`（24×24）；**播放中 aria 变成 `Pause 生动解说`**——
  同一个按钮就地翻转，可再次点击停止。**`aria-pressed` 也跟着翻**（`Play` 时该属性不出现）。
  🔴 **订正（批次 113）**：这一条曾因批次 97「30 秒未翻转」而被标为**待复核**；
  2026-10-03 已用**同轮阳性对照**重新**证实**（下面那张时序表），
  并撤掉那处 VOID —— 但**批次 97 为什么记到 0 条至今查不出**。
- **精确时序（批次 113 实测，同轮带阳性对照）**：

| 时刻 | 按钮 aria | 其它同步变化 |
|---|---|---|
| **+0.02s** | 仍是 `Play 生动解说` | `aria-busy` 出现、`disabled` 出现、class 变 —— **准备态** |
| **+1.68s** | → **`Pause 生动解说`** | `aria-pressed` 出现、`aria-busy` 撤销、`disabled` 撤销 |
| **+5.71s** | → 翻回 **`Play 生动解说`** | 同上反向 |

  ⇒ **样音播放段 ≈ 4.0 秒**（1.68s → 5.71s），前后各有准备/收尾。
  💡 这解释了批次 32 记的「**0.9s 仍是 `Play`、3.4s 已变成 `Pause`**」——
  两条读数**都是真的**：0.9s 落在那段 **1.68 秒的准备态**里，3.4s 已经过了准备态。
  当时把「慢」误读成了「翻转要 3 秒」。
- 页面上**没有 `<audio>` 元素**：30 秒连采 120 次，`document.querySelectorAll('audio').length`
  **全程为 0**（播放中也没有）⇒ 音色库样音**不放 `<audio>` 进 DOM**。
- **不扣积分**：操作前后顶栏积分读数均为 **805**。
- **音色库不会因试听而关闭**。

> 🔑 **想判断样音在不在播，看 `aria-label`（`Play` ↔ `Pause`）或 `aria-pressed`**，
> 这两个都实测到过。**不要用「页面上有没有 `<audio>`」判** —— 它压根不在 DOM 里。

### 时间读数是 `HH:MM:SS`，而且和视频节点**写法不同**

`00:00:04` 这种写法容易被误读成「4 小时 0 分」。它其实是
**`时:分:秒`，且按秒向下取整**：

| `currentTime` | 读数 |
|---|---|
| `0.995` | `00:00:00` |
| `1.682685` | `00:00:01` |
| `2` | `00:00:02` |
| `3.005` | `00:00:03` |

（4 个样本与 `floor(currentTime)` 的差**全部为 0**。可见读数由三个 SPAN 拼成
`00` ＋ `:00` ＋ `:03`；另有一份 `sr-only` 同值副本。）

🔴 **全册三处时间格式各不相同**，别拿错：

| 位置 | 格式 | 例 |
|---|---|---|
| **音频节点** | `HH:MM:SS`，秒向下取整 | `00:00:04` |
| 视频卡片内 | `MM:SS`，有前导零 | `00:06 / 00:06` |
| 视频全屏 | `M:SS`，无前导零 | `0:06 / 0:06` |

### ⚠️ 一个会让人误判的读数

节点里的 `<audio>` 是 **`preload="none"`**，所以**在你真的播之前**，
它的 `readyState` 恒为 **`0`（HAVE_NOTHING）**、`duration` 是 **`null`** ——
**这是正常的，不是「音频加载失败」**。我为此连采 6 次全部读到 `readyState 0`，
差点记成「上传的音频播不了」。

📌 判断「能不能播」要看**有没有点播放**、以及播放后 `readyState` 有没有变成 ≥ 1，
**不能拿 `readyState` 当加载成功的判据**。

### 🔴 取流失败时，卡片长什么样（2026-10-03 批次 110 实测，本页新增一档）

此前本页只分「空节点」和「有资源」两档。批次 110 在**有资源**那一档下面
又分出第三档：**素材在、但这一次取流失败**。

| 观测量 | 逐字 |
|---|---|
| 节点 `innerText` | `<名> 音频播放失败 重试播放音频 1 resource: 1 ready, 0 processing, 0 failed. Selected.` |
| 卡片中央 | **红色** `音频播放失败`，外面是 `<div aria-atomic="true" role="alert">` |
| 按钮 | **`重试播放音频`**（`66×19 @607,383`）—— 顶替了 `Play <名>`（`22×22 @701,446`） |
| 关键 testid | **`audio-playback-error`**，`192×192`（**铺满整张卡**） |
| `<audio>` 元素 | **整个从 DOM 里消失** |
| 一起消失的 testid | `audio-simple-player` / `audio-playback-waveform` / `audio-duration` / `audio-duration-accessible` |
| **时间读数** | **完全没有**（`[data-testid^="audio-duration"]` 读出 **0 个**） |
| **资源账** | ⚠️ **纹丝不动**：仍是 `1 resource: 1 ready, 0 processing, 0 failed.` |

⚠️ **三处容易踩**：

1. 🔴 **资源账不能用来判「是不是坏了」** ——
   卡片已经写着「音频播放失败」，账本**仍然**是 `1 ready, 0 processing, 0 failed.`
   （批次 105 首测、批次 110 复测，**两次独立**）。判据是**卡片中央那行红字**。
2. 🔧 **订正一处旧写法**：此前本页与视频页都写「失效态时间显示 00:00 / 00:00」——
   **不成立**。实测失效态的时间那一行**根本不渲染**（`audio-duration` 与
   `audio-duration-accessible` 两个元素都不在 DOM 里，读出 **0 个**）。
   `00:00 / 00:00` 那个样子是**时间线节点**的播放条。
3. ✅ **「重试播放音频」只重新取一次流**：
   取到了就**直接开始播**（按钮变 `Pause <名>`，实测 **1.2 秒内**）；
   取不到就**连文案都不换**（连采 12 次 / 14.4 秒逐字不动）。

复现手法与「上传存储 key ≠ 播放取流 key」见
[预览与播放视频节点 · 重试播放两分支](media-playback.md#重试播放的两个分支)
与[参照页 · 播放取流与上传存储不是同一个 key](../20-reference.md#播放取流与上传存储不是同一个-key)。
