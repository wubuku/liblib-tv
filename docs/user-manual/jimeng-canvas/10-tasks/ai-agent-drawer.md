# 使用「与 AI 对话」智能体抽屉

## 适用角色

已登录的即梦画布创作者。

## 目标

打开画布右侧的 Agent 对话抽屉，了解技能入口与输入方式（发送消息可能触发
生成并消耗积分，本手册只讲到发送前）。

## 前置条件

已打开画布。

## 入口

画布右下角 **与 AI 对话** 按钮，或按 **⌘/**（**2026-10-01 实测两按两态**：
`关闭 → 打开 → 关闭`，确认可开关）。

> 🔴 **2026-10-02 批次 84 补一条本页此前没写的**：
> **⌘/ 同时也是「让画布快捷键全部失效」的那一下。**
> 抽屉一开，键盘焦点就进了抽屉，你按的 G / F / ⌘Z **全都不会到达画布**。
> 而且**两种失效的表现完全一样：屏幕上什么都不发生**。
> 详见下面「抽屉开着，画布快捷键全部失效」一节——**这是本任务最容易被误判成「快捷键坏了」的地方**。

## 🔴 抽屉开着，画布快捷键**全部失效**（2026-10-02 批次 84 四格实测）

本批把「选中」和「焦点」两个因子交叉，各测一格，**每格都断言两个因子各自的值**。
四个格子里只有**焦点**在变：

| 格 | 有节点选中 | 键盘焦点落在 | 按 **G** 的结果 |
|---|---|---|---|
| **A** | ✅ 1 个 | `DIV[rf__wrapper] aria="Canvas"` | ✅ **300ms** 弹「此快捷键当前不可用」**`360×44@460,32`** |
| **B** | ✅ 1 个 | **抽屉输入框**（`aria` 逐字「说说你的想法或任务，上传参考、输入文字或」） | 🔴 字母 **`g` 被输入框吃掉**，画布无提示 |
| **C** | ✅ 1 个 | **抽屉侧栏容器**（`ASIDE[canvas-feature-sidecar] aria="Agent"`，点标题处） | 🔴 字母**完全消失**，画布无提示 |
| **D** | ✅ 1 个 | 收起抽屉后重新框选 → 回到画布 | ✅ **恢复**，同样 300ms 弹同样的提示 |

- 🔑 **A 与 B/C 的唯一差别就是焦点。** 选中数四格全是 1，变量只有焦点。
- 🔴 **B 和 C 又是两种不同的失效**：
  **B** 的字母进了输入框（最容易误判——看起来像「快捷键坏了」，其实字打进去了）；
  **C** 的字母**凭空消失**（输入框没变、画布也没反应）。
- ✅ **D 排除了「开一次就把快捷键弄坏了」**：关掉抽屉、重新在画布上操作，**完全恢复**。

### 💡 怎么看出来「这次是焦点跑了」

按 G 之后**看 Agent 输入框**：

- 输入框里**多了字母** ⇒ 焦点在输入框（格 B）。
- 输入框**没变**、画布**也没反应** ⇒ 焦点在抽屉别处（格 C）。
- 画布**弹了提示** ⇒ 焦点在画布，一切正常（格 A / D）。

### ⚠️ 点「收起」之后焦点也**不在画布上**

| 怎么关的 | 关完焦点落在 | 画布快捷键能用吗 |
|---|---|---|
| 点头部 **收起** 钮 | `BUTTON[canvas-sidecar-launcher] aria="与 AI 对话"`（右下角启动钮） | ❌ **仍然不能用** |
| 按 **⌘/** | `SECTION[canvas-main-region] aria="Canvas editing area"`（批次 82 实测） | ✅ 可以 |

⇒ **「收起」只是把画布还给鼠标，键盘焦点还留在界面按钮上。**
想立刻用画布快捷键，**再点一下画布空白处**（落点要在画布网格上，不是节点），
或者用 **⌘/** 而不是「收起」钮来关。

## ⚠️ 抽屉会盖住画布右侧的节点

**这是本任务最需要先知道的一件事。** 抽屉不是把画布挤窄，而是**覆盖在画布之上**：
实测宽 **400**、从屏幕 **x=868** 起铺满右侧，与画布重叠。

后果是**画布右侧约三分之一被挡住，落在那一带的节点点不中**：

| 状态 | 同一坐标的命中 | 点下去的结果 |
|---|---|---|
| 抽屉展开 | 落到抽屉内部（标题、技能 chips 等） | **节点选不中**，选中数不变 |
| 抽屉收起 | 落到节点卡片 | **正常选中** |

2026-10-01 对照实测：把「视频 1」拖到右侧使其与抽屉重叠，点节点上 `(957, 218)`
这个位置 —— 抽屉打开时命中 `H2`（抽屉标题）且选中数仍为 0；点抽屉头部 **收起** 后，
同一坐标命中节点卡片、选中数变 1。**节点位置没变，变的只是抽屉开合。**

> 💡 **要么先把节点拖出来，要么点「收起」/ 按 ⌘/**，再操作节点。
> 被盖住的节点**可以用左侧露出的一条点中**（实测节点左侧 111px 仍可正常点选），
> 但看不到全貌时很容易以为节点「失灵了」。

- ✅ **不再遮挡画布** —— 但机制**不是**「它消失了」，而是**它不接收点击**。
  零成本对照实测：取侧栏内 5 个坐标，`elementFromPoint` 在展开态 **5/5** 命中侧栏内，
  折叠态 **0/5**。
- ⚠️ **别把「画布上什么都没有」当成「元素不存在」** —— 它一直在 DOM 里。
- ⌘/ 是**切换**：折叠态按 ⌘/ **直接重新展开**（不是先「打开」再「打开」）。

### 🔑 2026-10-02：这层 `prompt-composer` 就是「污染全文档判据」的那个元素

批次 82 在别处撞见过一个**来历不明的** `.ProseMirror[contenteditable="true"]`，
恒定停在 `357×84@890,554`、坐标与画布节点完全无关，一度不知道它是谁。
批次 84 查实了归属：

| 读数 | 值 |
|---|---|
| 在侧栏内？ | ✅ **是**（`canvas-feature-sidecar .ProseMirror` 命中） |
| 在任何画布节点内？ | ❌ **否**（`.react-flow__node .ProseMirror` 命中 **0**） |
| 几何 | **`357×84@890,554`** —— 与上表 `prompt-composer` **逐字相同** |

⇒ **它就是 Agent 抽屉的输入框。** 抽屉一开它就在、抽屉一收它就消失
（实测 `pmAnywhere`：折叠态 **0** / 展开态 **1**）。

🔑 **对读者有什么用**：如果你（或任何一个自动化脚本）用
「页面上有没有 `contenteditable`」来判断「画布节点是不是在编辑态」，
**只要 Agent 抽屉开着，这个判断就永远为真**。
⇒ 判断画布节点是否在编辑，要**限定在该节点内部**去找，不能搜整个页面。

### ⚠️ 输入框里有**两层**同尺寸的 DIV，`elementFromPoint` 命中的不是编辑器

```
prompt-composer 357×84@890,554
└ DIV (relative w-full …) 357×84@890,554
  └ DIV.contents 0×0@0,0
    ├ DIV.tiptap.ProseMirror              357×84@890,554   ← contenteditable=true，能打字的那层
    └ DIV.relative.col-start-1.row-start-1 357×84@890,554 ← 占位符层，叠在它**上面**
```

输入框内**任意**坐标，`elementFromPoint` 命中的都是**占位符层**。
⇒ 想确认「点到了输入框」，判据是**落点在 `canvas-agent-session-composer` 之内**，
**不是**「落点在 `[contenteditable]` 之内」—— 那是**兄弟关系**，永远不成立。

## 原子步骤

**已实测**：打开与折叠抽屉。

1. 点击画布右下 **与 AI 对话** → 右侧全高抽屉展开（实测）。
2. 浏览空态技能 chips（**/视频反解**、**/创作分镜** 等）与底部输入卡的占位文案
   （实测逐项读过结构）。
3. 点击头部 **收起** → 抽屉**折叠**成看不见的空壳，画布右侧恢复可点（见上）。

**已实测（批次 62，全程未发送、积分 805 → 805 不变）**：

4. **点空态的技能 chip** —— 不是「展开引导」，而是**把该技能插成输入框里的一个 chip**。
   点 `/ 视频反解` 后输入框内容变成 `视频反解`，编辑器 HTML 是
   `<p><span class="react-renderer node-composerChip …">`，可见 chip **84×20 @ (890,556)**。

## 取消 / 恢复

- **折叠**抽屉不影响画布内容；「新会话」仅新建空会话。
- **折叠同时解除对画布右侧的遮挡** —— 机制是 `pointer-events: none`
  让点击穿透，**不是**因为它被关掉了（见「只有两态」一节）。
- 技能 chip 是插在输入框里的，**删掉它即可撤销**（清空输入卡）。
