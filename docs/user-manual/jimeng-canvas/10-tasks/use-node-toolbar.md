# 使用节点工具条

## 适用角色

已登录的即梦画布创作者。

## 目标

选中节点后使用上方浮动工具条：查看/播放媒体、使用截取帧、视频修剪等加工能力，
并清楚哪些是付费（✦/VIP）功能。

## 前置条件

- 画布中有可选中节点。
- 工具条内容按**节点状态与媒体类型**共同变化：
  - **带媒体的视频节点** → 视频加工工具条（局部重拍/智能超清/视频编辑/截取帧/
    视频修剪/工具）；
  - **带内容的图片节点** → 图片加工工具条（**实测 12 项**：智能改图✦/720 全景✦/扩图/
    智能超清/抠图/预设∨/多角度/智能打光✦/工具∨/AI 助手∨/全屏/下载）——
    **与视频不是同一套**，见下方两节；
  - **空节点** → 工具条位置改放**生成面板**（2026-10-01 实测：容器仍是
    `node-toolbar`，但内容换成生成面板，**680×208**，逐字含「展开视频生成器／
    添加参考／引用参考／选择模型: 即梦 Seedance 2.0 VIP／视频尺寸选项: 16:9 · 720P · 1／
    生成模式: 全能参考／选择视频生成时长: 4s／生成」。见 [准备生成](prepare-generation.md)）；
  - **文本节点** → 背景色/全屏/下载 小工具条（**选中态与编辑态是两套不同工具条**，
    见下方「文本节点的两套工具条」）；
  - **多选** → N 节点/编组/布局/下载 工具条（实测 511×40，**无 Add tags**；见
    [编组与整理](organize-group-layout.md)）；
  - **编组** → 解除编组/布局/背景色/**下载** 工具条，**固定四项**。
    2026-10-01 批次 50 做了控制变量：纯文本组与含空视频节点的组逐字相同，
    与缩放也无关；**只有 0 成员空组**才只剩「解除编组/背景色」两项。
    详见[编组与整理](organize-group-layout.md)。

## 入口

单击选中任意节点，工具条自动出现在节点上方。

> **重要区分**：文本节点有**两套**工具条，容易混淆：
> - **选中态**（单击选中、未进入编辑）：三项 —— `背景色` ｜ `全屏` ｜ `下载`
>   🔴 **批次 93 订正**：`185×40` **三档都没复现**。2026-10-02 实测屏上 **40%→`160×40`、60%→`192×40`、100%→`320×40`**，
>   **高度屏上恒 `40`、宽度三档不同**；按钮本身**屏上恒定**（`背景色 75×32`／`全屏 32×32`／`下载 32×32`）。
>   🔑 **批次 144 补上公式**（三档不够，七档密布实测 30/40/45/50/55/60/100%，
>   锁 `data-id`、每档等实测 `scale()` 追平）：
>   **屏上宽 = `max(320 × 当前缩放, 160)`，高度恒 `40`，交叉点 `160÷320 = 50%`**。
>   ≤50% 的四档（`30/40/45/50%`）读数**逐字恒 `160`**，
>   ≥50% 读 `176 / 192 / 320`（= `320 × scale`）。`320` 就是**文本节点的 canvas 宽** ——
>   高缩放时工具条与节点等宽，低缩放时停在 `160` 的下限（不然三个按钮挤不下）。
>   📌 与组工具条是**同模板、不同内层**：组是 `max(卡片canvas宽×scale, 296)` +
>   **整块** `selection-context-toolbar` 恒定；节点这个是**三个按钮各自**屏上恒定、
>   外层只当容器。详见 [编组与布局](organize-group-layout.md) 与 SOURCE_OBSERVATIONS §4.67。
> - **编辑态**（双击进入）：316×40，八项 —— `Text style` ｜ `无序列表` ｜ `有序列表` ｜
>   `加粗` ｜ `删除线` ｜ `倾斜` ｜ `下划线` ｜ `全屏`
>
> 两者都用 `.react-flow__node-toolbar` 作为外层类名，**只能靠按钮 aria 区分**。
> 详见 [创建与编辑文本节点](edit-text-node.md)。

## 文本节点的「背景色」色板（2026-10-01 实测逐字）

选中态工具条点 **背景色** → 下方展开 **214×40** 色板浮层（容器背景 `rgb(38,38,38)`，
圆角 12px），内含 **6 枚** 28×28 色块：

| 色板逐字文案 | 色块 computed backgroundColor |
|---|---|
| 无颜色（默认，带白环表示已选） | `rgb(61, 61, 61)` |
| 青绿色 | `rgb(0, 202, 224)` |
| 靛蓝色 | `rgb(109, 124, 255)` |
| 紫色 | `rgb(190, 104, 255)` |
| 橙色 | `rgb(255, 146, 48)` |
| 黄色 | `rgb(255, 214, 0)` |

- 点击色块 → 卡片底色**即时变更**，工具条「背景色」按钮图标同步变为该色。
- 选 **无颜色** 恢复默认。
- **与节点颜色标记是同一套色值**，但**文案不同**：节点标记的 aria 用「青绿色 / 蓝 /
  紫色 / 橙色 / 黄色」，背景色色板把蓝色正式命名为 **「靛蓝色」**。
  两种叫法指向同一个 `rgb(109,124,255)`。

## 带媒体视频节点的工具条（2026-09-23 实测逐字）

**局部重拍✦ ｜ 智能超清✦ ｜ 视频编辑✦ ｜ 截取帧∨ ｜ 视频修剪 ｜ 工具∨ ｜（分隔）｜
全屏 ｜ 下载**

- ✦ 为 VIP/付费标记。**这些按钮会提交按积分计费的任务**：本手册只说明入口与
  位置，是否执行由你决定；执行前请确认积分余额。
- **截取帧∨**：下拉含 首帧/尾帧/自定义，用于从视频截取静态帧生成图片节点。
- **视频修剪**：打开修剪条（帧条 + 两端拖拽把手 + 确认），用于裁剪片段。
- **工具∨**：分两组——「编辑」：补帧（VIP 标）、深度动作捕捉；「预设」：提示词反推。

> **注意「工具」下拉里两类条目的差别**：「编辑」组的 补帧 带 VIP 菱标，属计费任务；
> 而「预设」组的 **提示词反推 不带菱标**，点击后**不会**直接提交付费任务——它会在
> 右侧打开「与 AI 对话」抽屉并**预填**一条指令（例如「用 视频反解 反推出 {视频标题}
> 的提示词，并创建文本节点，方便我拉片复刻」），节点同时放大并暂停。
> 抽屉里的消息**发不发由你决定**，关掉抽屉即无消耗。

## 主体节点：**没有**浮动工具条（2026-10-03 批次 118 补上，全册此前缺这一档）

本页此前覆盖了**六种**工具条（文本选中态/编辑态、图片、视频、空节点=生成面板、
多选、编组），**唯独没有「主体节点」这一档**。批次 118 补上，结论是**没有**。

| 宿主（扫了 7 种） | 主体节点 | **文本节点（阳性对照）** |
|---|---|---|
| **`[data-testid="node-toolbar"]`** | **0 个可见** | **1 个可见** |
| **`.react-flow__node-toolbar`**（class） | **0 个可见** | **1 个可见** |
| `[data-testid*="toolbar"]` | 4 个可见 | 7 个可见 |
| `[role="toolbar"]` | 1 个可见 | 2 个可见 |
| `[class*="node-toolbar"]` | 18 个可见 | 19 个可见 |
| `[class*="floating"]` | 147 | 148 |

⚠️ **只有前两行是决定性的**。后四行在主体节点上「命中」的**全是别人的东西**：
两个**时间线**节点各带一套**节点内部**工具条（`00:00 / 00:00 全屏编辑` ＋ 按钮
`导出时间线` / `全屏编辑`），加上左栏那个 `role="toolbar"`（文本/图片/视频/音频/时间线/主体/导演台/资产库/上传）。
⇒ 它们**随画布上别的节点而变，与「谁被选中」无关**。

🔴 **订正（批次 119）**：上面把时间线节点那套说成「**浮动**工具条」**是错的** ——
它是**节点内部**的工具条（testid **`timeline-toolbar`**）。
它之所以被 `[class*="node-toolbar"]` 这种**宽泛**扫命中，
是因为它的 class 里含 `node-toolbar` 子串，**不是**因为它是浮动工具条。
**本页的结论不受影响**（用的是**精确 class `.react-flow__node-toolbar`**），
但**判据必须写清**：

| 要判的东西 | 该用哪个宿主 |
|---|---|
| **浮动**工具条 | **精确** class `.react-flow__node-toolbar` ＋ 高度 > 1 ＋ 在节点**外** |
| **节点内部**工具条 | `n.contains(元素)` 为真（如 `timeline-toolbar`） |

📌 **宽泛 class 扫会把两者混在一起** ⇒ 它的命中数**不能**用来判「有没有浮动工具条」。
（批次 119 已实测：**时间线节点也没有浮动工具条**，见
[时间线节点](timeline-node.md)。）

🔑 **判据有效性的证明**：同一套判据在**文本节点**上命中 1 个
（`320×40@368,204`，`class` 与 testid **两个宿主都指向它**）
⇒ 「主体节点 0 个」是**读数**，不是判据坏了。

### 🔴 主体节点只留下**两个零高度占位元素**

`[data-testid="node-toolbar"]` 在主体节点上有 **2 个**元素，**高度都是 0**：

| 缩放 | 占位元素宽度 |
|---|---|
| 40% | **141** |
| 60% | **211** |
| 100% | **352** |

⇒ **宽度 = 节点的 canvas 宽度**（主体节点 canvas `352×352`：
`352×0.4 = 140.8 ≈ 141`、`×0.6 = 211.2 ≈ 211`、`×1 = 352`），
**高度恒 0** —— 与批次 85 在**视频节点**上记的「宽度等于节点屏上宽、高度恒 0」**同构**。
⚠️ 这两个占位元素是 `querySelector('[data-testid="node-toolbar"]')` 会**先命中**的
（批次 85 已警告过「单数 `querySelector` 会命中它」），自动化必须按高度筛。

## 原子步骤（不产生费用的部分）

1. 选中带媒体的视频节点 → 核对工具条逐字标签（上方列表）。
2. 点击 **截取帧∨** → 确认下拉出现（首帧/尾帧/自定义）后按 **Esc** 关闭，不执行。
3. 点击 **工具∨** → 确认菜单出现（编辑：补帧/深度动作捕捉；预设：提示词反推），
   按 **Esc** 关闭。
4. 播放预览：卡片底部有 播放/暂停、时间（00:00 / 00:06）、静音、全屏控件；
   点击 **Unmute video / Mute video** 可切换静音（实测翻转）。
5. 点击尾部 **下载** → 保存媒体文件（本地行为，不耗积分）。

### 视频修剪（不产生费用）

裁剪只改本地片段，不提交生成任务，因此可以放心操作：

1. 选中带媒体的视频节点 → 点击 **视频修剪**。
2. 节点下方出现**修剪条**（内联展开，不是弹窗）：一条胶片帧条，两端各有一个
   白色拖拽把手；把手之间是当前选中的片段。
3. 拖动任一把手调整入点/出点：
   - 拖**起点**把手向右 → 左侧时间读数前进，选中段变短；
   - 条内右侧有**选区时长**标签（如 `6.1s`），随拖动实时变化。
4. 条下方是播放走表（`▶ 00:00 / 00:06`，current/total 走表），播放可试听选区。
5. 点击右端白色 **确认** 胶囊钮 → 修剪生效，节点回到常规工具条。
   - 成功判据：确认后修剪条收起，播放区间已缩短。
6. **Esc** 或再次点击 **视频修剪** 可退出修剪态而不保存。
   - 确认后想反悔：**⌘Z** 撤销（见
     [复制、删除与撤销](duplicate-delete-history.md)）。
- 修剪态下工具条暂时隐藏，标题行保持可见——这是正常的中间态，不是卡死。

### 截取帧：把视频变成图片节点（不产生费用）

1. 选中带媒体的视频节点 → 点击 **截取帧∨** → 下拉三项：
   **首帧** ｜ **尾帧** ｜ **自定义**。
2. 选 **首帧 / 尾帧**：**不打开选择条**，直接异步产出一个图片节点
   （新节点标题形如 `…_首帧`），落到画布上。
   - 成功判据：画布新增图片节点。
3. 选 **自定义**：节点下方出现**帧选择条**——胶片帧条（左侧有一根播放头竖线），
   底部一行 `▶ 00:00 / 00:06 ｜ 📷 截取帧 ｜ 确认`。
   - 先在帧条上点选目标帧 → **📷 截取帧** 截取 → **确认** 变为可用 → 点击
     **确认** 生成图片节点。
   - 注意：**未截取时「确认」是置灰的**，必须先截一帧才能确认。
4. 截取帧得到的是普通图片节点，可继续用图片工具条加工或接到生成节点上。

### 两种会「进入编辑模式」的付费功能（局部重拍✦ / 视频编辑✦）

这两个 ✦ 按钮与上面的修剪/截帧不同：点下去不是弹一个面板，而是**把节点切换成
独立的编辑模式**——画布自动放大聚焦该节点，工具条收起，节点下方换成该模式专属的
工具条与提示条。**进入模式本身不会提交生成**；生成发生在最后的发送钮，而发送
按积分计费（见下方各模式的发送钮说明）。

> 本节两段均来自**复刻研究源站采样**（batch 5/6/214/215/373/374），非当日实测。
> 采样之间存在差异（放大比例、标题行是否可见、图标命名），因此下面只写**稳定可复现
> 的结构**，不把某次采样的具体数值当作恒定事实。

**局部重拍✦**（重拍视频中的某一段）

1. 选中带媒体的视频节点 → 点击 **局部重拍**。
2. 画布自动放大聚焦该节点，节点下方出现两样东西：
   - **修剪条**（与「视频修剪」同族）：胶片条 + 两端拖拽把手，选区右端有
     `4.0s` 这样的时长徽章。先在这里圈定要重拍的片段。
   - **重拍提示面板**：参考缩略图（带时长角标）+ **+** 添加参考 + 蓝色描边芯片
     标出当前选中的片段（形如 `00:00–00:04 重拍片段`）+ 输入框占位
     「描述你如何调整这一片段」。
3. 底部参数行：模型（即梦 Seedance 2.5 ✦）、时长（6s）、@ 引用、发送钮。
4. **发送是扣费边界**：发送钮在提示词为空时禁用（面板会提示
   `Prompt is required`），写好描述后才可用。**本手册不代替你点击发送。**
5. 按 **Esc** 退出重拍模式回到画布。

**视频编辑✦**（对整段视频做局部编辑）

1. 选中带媒体的视频节点 → 点击 **视频编辑**。
2. 画布自动放大聚焦该节点，视频开始播放，工具条收起。
3. 节点下方出现 8 个图标按钮的编辑工具药丸，用两条分隔线分成三组：
   区域选择类（矩形 / 画笔 / 箭头）｜ 文字与擦除类（文字 / 橡皮擦 / 标记）｜
   撤销类（撤销 / 重做）。先选区，再描述要怎么改。
4. 下方是编辑提示条：上传参考内容、输入框占位「描述你如何调整视频」、
   引用参考、@ 引用，以及一枚**价格签**（形如 `✦ 144 分/次`，随配置变化）。
5. **发送是扣费边界**：提示词为空时发送钮禁用。价格签上的数字就是本次预计
   消耗的积分，确认后再决定是否发送。
6. 按 **Esc** 退出编辑模式（退出不产生历史，**⌘Z 无法撤销进入/退出编辑模式**）。

**两种模式的共同点**（这几点最容易误判）：

- 进入后**工具条消失、画布被放大**是正常的中间态，不是卡死；
- 放大比例每次可能不同（采样中出现过 122%、145%、176% 等），**不要依赖具体数值**；
- 退出用 **Esc**，不要用 ⌘Z——编辑模式的进入/退出不入撤销栈；
- 两者的**发送**都按积分计费；只想看看界面的话，进入模式后按 **Esc** 即可退出，
  不产生费用。

- 误触付费按钮时，立即 **Esc**；若已弹出任务面板，**不要点确认/生成**，关闭面板即可。

## 🔑 文本节点工具条的机械契约（2026-10-02 批次 93 三档实测）

本页第 38 行原写「选中态 **185×40**」，批次 85 原写「canvas 恒 `320×67`」——
🔴 **这两个数本轮都被推翻**，三档实测见下。
本轮在**自建文本节点**上逐档实测（**每档都断言 `sel === 1` 且节点完全在视口内**），
两个数都对不上。

### 三档读数

| 缩放 | scale | 工具条（屏上） | 反推 canvas | 视口内 | `sel` |
|---|---|---|---|---|---|
| 40% | 0.4 | **`160×40`** | 400×100 | ✅ | 1 |
| 60% | 0.6 | **`192×40`** | 320×67 | ✅ | 1 |
| 100% | 1.0 | **`320×40`** | 320×40 | ✅ | 1 |

🔴 **两条订正**：
1. **`185×40` 三档都没复现** ⇒ 旧读数未复现，作废。
2. **「canvas 恒 `320×67`」不成立** ——
   **高度是屏上恒 `40`**（canvas 100/67/40 随缩放走），
   那个 `67` 正是**把屏上恒值除以 scale** 得来的；
   容器宽度 canvas 是 400/320/320，**也不恒**。

### 真正稳定的是**按钮**，而且它们**屏上恒定**

| 按钮 | 40% | 60% | 100% | 备注 |
|---|---|---|---|---|
| `背景色` | `75×32` | `75×32` | `75×32` | ⚠️ **`aria` 为 `null`**，只能按文字认 |
| `全屏` | `32×32` | `32×32` | `32×32` | aria 逐字 `全屏` |
| `下载` | `32×32` | `32×32` | `32×32` | aria 逐字 `下载` |

🔑 **三个按钮的屏上 x 坐标三档完全相同**（`565` / `649` / `683`），
而容器左边缘在动（`560` / `544` / `480`）——
**内容是屏上锚定的，变宽的是外层容器**。
这和 ⊕ 按钮「屏上恒 `36×36`」、手柄热区「canvas 恒 `60×120`」是同一族机制：
**有的元素跟随画布缩放，有的刻意抵消缩放**。**给一个元素写契约前，
必须先测三档，看它跟的是哪一个。**

### ⚠️ 一个 testid 陷阱：按 class 找会多数一个

| 选择器 | 命中 | 逐字 |
|---|---|---|
| `.react-flow__node-toolbar` | **3** | `selection-context-toolbar-popup-host`（`0×0`、0 按钮、**在节点外**）／`node-toolbar` ×2（1 真身 + 1 `0×0` 占位） |
| `[data-testid="node-toolbar"]` | **2** | 1 真身（3 按钮）+ 1 `0×0` 占位 |

⇒ 🔴 **class 比 testid 宽**：多出来的那个是**多选工具条的弹层宿主**，
它只是**借用了同一个 class**。本页第 44 行称「两者都用 `.react-flow__node-toolbar`
作为外层类名」——**字面没错，但用 class 计数会多数一个**。
⇒ **稳定定位器是 `[data-testid="node-toolbar"]`；且必须再按「有没有子按钮」筛出真身。**

#### 🆕 2026-10-05 批次 162 补一个**同时在场**的组合（前面两张表都没记这一种）

上面两张表各记了一种情形：**主体节点 → 两个 0 高占位**、**多选态 → 1 真身 + 1 `0×0` 占位**。
本轮实测到第三种：**选中一个普通节点（如图片节点）时，两个「不同用途」的盒子会在同一次渲染里同时在场**：

| 实例 | 屏上盒 | 按钮数 | 它到底是什么 | 在节点外？ |
|---|---|---|---|---|
| A | `680×208 @241,456` | **7** | **底部生成面板的外壳**（内含同盒的 `node-toolbar-feature-host` ＋ `generation-form`） | ✅ 是 |
| B | **`171×0 @495,229`** | **0** | 多选工具条占位（与 `selection-context-toolbar-surface` 同盒），**高 0** | ✅ 是 |

🔴 **而 `querySelector` 命中哪一个，会随上下文变**：
本项目同一条查询，批次 162（有生成面板时）取到 **A `680×208`**，

④ 用 `closest('.react-flow__node')` 确认它**挂在目标节点上**。
**四步缺任何一步，都可能读到别人的东西** —— 本项目已经因此读错两次

### 🔴 订正（2026-10-02 批次 95）：这条提醒的前提测错了，双击**确实**进编辑态

**原结论已作废**。批次 93 当时的测法是「**先单击选中** → **再双击**」，
而这两次点击加起来是**三次**点击，中间那一次**本身就足以改变状态**。
批次 95 用受控复测把序列拆开量，得到的读数与当时完全不同：

| 序列 | `contenteditable` / `.ProseMirror` | 工具条 |
|---|---|---|
| 未选中 + **单击** | `0` / `0` | 选中态工具条（`node-toolbar` **2** 个） |
| 未选中 + **纯双击**（无任何前置单击） | **`1` / `1`** | **一个都没有** |
| **已选中** + 单击 | **`1` / `1`** | **一个都没有** |
| 未选中 + 单击后 120ms 再双击（即批次 93 的序列） | **`1` / `1`** | **一个都没有** |

⇒ **双击文本节点进编辑态，成立。** 批次 93 读到的 0 **不是三击造成的** ——
同一个三击序列这次也读到 1，所以当时的 0 另有原因（那次量的落点很可能不在文本节点上）。
**这说明「测法错了」与「结论错了」是两件事：把测法改对之后，结论照样得推翻。**

### 🔴 真正的机制：编辑态**根本没有**节点工具条

批次 93 留下一个悬案「编辑态工具条的真实 testid 是什么」——
**这个问题问错了**。受控复测的读数是：**编辑态下整副节点外框全部消失**。

| 状态 | `selected` | `contenteditable` | `text-node-resize-controls` | `text-node-selection-outline` | `node-feature-chrome-host` | `node-toolbar` | `selection-context-toolbar` | 右键菜单 |
|---|---|---|---|---|---|---|---|---|
| **未选中** | `false` | `0` | 0 | 0 | 0 | **0** | 0 | 弹得出 |
| **选中** | `true` | `0` | **1** | **1** | **1** | **2** | **1** | 弹得出 |
| **编辑** | `true` | **`1`** | **0** | **0** | **0** | **0** | **0** | **弹不出来** |

两条推论：

1. 🔴 **编辑态里画布上只剩一个裸文本框** —— 没有工具条、没有缩放把手、没有选中描边。
   此刻**右键菜单也弹不出来**（菜单在文本编辑器的右键语境下不触发）。
   ⇒ 想知道「选中态工具条有哪些」时，**必须先确认 `contenteditable` 为 0**，否则量到的是 0 个元素。
2. ⚠️ 顺带解掉一个「看起来像编辑态工具条」的误认：
   `[data-testid="canvas-editor-menu"]` **恒为 1 个、`36×36@1061,12`**，
   位置在**顶栏右侧**而非节点附近，**三种状态下逐字相同** ⇒ 它属于**顶栏**、**与节点无关**。
   🔧 **批次 122 订正后半句**：它**不是那个按钮本身**，而是「更多」按钮的 **36×36 外壳**
   （`display:flex`、只有一个孩子 = `<BUTTON aria="更多" data-testid="null"> 28×28@1065,16`）。
   ⇒ 「位置在顶栏、状态不变」这两条读数仍然成立；
     但**「所以它是顶栏按钮」这一步推错了** —— 它是**顶栏那个按钮的壳**。
   顺带一个读数陷阱：菜单打开时这个 testid **仍然是 1 个**（不会变成 2 个），
   但按钮的 **`data-state` 恒为 `closed`**、只有 `aria-expanded` 会 `false`→`true`。

### 📌 Esc 是**逐级**回退，不是一次回到头

- **编辑态 → Esc 一次 → 选中态**（`editable` 0，但 `resize`/`node-toolbar` 回到 1/2）
- **选中态 → Esc 一次 → 未选中态**（全 0）
⇒ 要回到「完全没碰过」的状态需要**连按两次** Esc。
收尾脚本（删自己建的节点）若只按一次就右键，会打在编辑态上、菜单弹不出来。
