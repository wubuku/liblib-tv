# 概念：BeefTV 是怎么工作的

> 解释性内容，不包含操作步骤。

## 双轨视口：为什么画布这么顺滑

画布把「你正在拖动」和「系统已确认」分成两条轨道：拖动时只直接改写屏幕上的图层（每帧），界面状态按更低的频率（64ms 虚拟化刷新、120ms 提交）批量确认。React 界面在你拖动时保持静止，因此大画布也不卡。

## 任务对账：刷新页面为什么不怕丢

生成任务提交后，任务身份写在节点上。刷新页面后系统用任务列表与画布节点**对账**：仍在运行的任务继续跟踪；没有任务身份的「加载中」节点标记为本地中断，不会覆盖已完成的结果。

## 三层历史

| 层 | 记录什么 | 特点 |
|---|---|---|
| 用户撤销栈 | 每个节点/连线的改动前后像 | 180ms 合并、上限 50 层 |
| Agent 批次 | 整批操作前的完整快照 | 用户一旦接手编辑即整批失效 |
| 项目版本 | 服务端定期与恢复前快照 | 恢复会生成新版本，可再撤销 |

## 生成落账事务

生成结果写回画布是「两阶段」的：提交时登记意图，持久化时只认已确认的标记；失败按四种情形推导回滚目标——避免「半截结果」污染画布。

## 云端 Agent 的封闭指令集

Agent 不能为所欲为：它只能使用 8 种画布操作（增删节点/连线、选区、视口、发起生成等），每次执行后系统按事实复核（比如「资源真的生成了吗」）；与你本地编辑冲突时宁可中断、保留你的编辑。

## 三层能力分布

BeefTV 把「能力」分在三层，各司其职：

| 层 | 承担什么 | 特点 |
|---|---|---|
| 前端内置插件 | 审美批改、提示词优化、Eagle 接入等界面能力 | 编译期打包，**不执行第三方代码** |
| Go 后端协议引擎 | 生成渠道适配（声明式 JSON 模板） | 上传插件只能走声明式路径 |
| 本地伴随进程 | 深度/线稿/姿态等本机推理 | 精确回环地址 + 挑战签名会话 |

安全姿态：上传的插件永远是纯数据，执行永远在可信引擎内。

## 多选与编组

框选 ≥2 个节点后可**成组**：分组盒自动包住成员（外扩 28px）、标签显示「组 N」、支持切换背景色与三种排列方式；组内节点拖拽时整组跟随，**双击标签可重命名**，也可解组恢复独立。分组让「先摆好布局再连线」的工作流成为可能。
