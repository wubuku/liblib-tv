# 故障排查

> 症状 → 原因 → 处理。按真实源码行为整理。

## 先看这一节：看着像坏了，其实不是

下面这些**不是故障**，是产品的既定行为。遇到时先在这里对一遍，能省掉一次误操作和一笔冤枉钱。

| 你看到的 | 真实情况 | 详见 |

| 视频生成模式不是你选的那个 | 它**主要由连线素材推算**。先选模式再连素材，可能被自动纠正 | [generate-video.md](10-tasks/generate-video.md) |

## 打开与加载

### 画布一直显示「正在打开画布...」

原因：新建画布需要后端接口；Web 前端把 `/api` 代理到 `127.0.0.1:8080`，后端未启动时代理连接被拒。
处理：启动后端（仓库 `backend` 目录执行 `go run ./cmd/server`，默认 SQLite、监听 :8080），刷新页面即可。

## 生成类

### 提交时报素材/参数不被接受

界面文案不是一句固定的话，而是按原因分类给的（v1.6.16 源码逐条核对）。常见几类：

| 你会看到 | 含义 | 怎么办 |
|---|---|---|
| 参考素材过大 / 无权访问参考素材 / 参考素材无法读取 | 素材本身的问题 | 换小一点的素材，或检查访问权限 |
| 参考素材时长不符合模型要求 / 视频时长不符合模型要求 | 时长超范围（提示会给出允许的秒数区间） | 按提示把素材调整到区间内 |
| 参考素材高度不符合模型要求 | 尺寸超范围（提示会给出实际值与上限） | 裁剪到允许尺寸 |
| 整次请求的数据量超过接口上限 | 总量超限 | 减少参考数量或体积 |
| 模型不接受当前参数 | 参数组合不被支持 | 核对比例、时长、素材角色 |
| 当前模型或接口不可用 | 模型名或渠道配置有问题 | 检查模型名称与渠道配置 |

处理方向一致：更换或裁剪素材；或在渠道设置里切换能力匹配的模型。

### 审核失败：先分清「内容违规」还是「版权/真人限制」

审核错误要对照官方错误码区分输入与输出、文字与媒体：

- `SensitiveContentDetected` 本身**不代表真人**；同错误族的 `PolicyViolation` 表示**版权限制**；
- 只有输入图片/视频的 `PrivacyInformation` 才提示真人形象，`DeepFake` 提示伪造内容审核；
- `ContentSecurityDetectionError` 表示**审核服务内部失败**，不能当成你的内容违规；
- 调整提示词或更换参考素材后可新建任务（原任务不受影响）。

### 额度与频控：不要一律「稍后再试」

| 错误 | 含义 | 处理 |
|---|---|---|
| `SetLimitExceeded` | 渠道配置的用量上限 | 检查并调整渠道用量/预算 |
| `AccountOverdueError` / `ServiceOverdue` | 供应商**欠费**（不是你的权限问题） | 联系渠道方处理欠费 |
| `InflightBatchsizeExceeded` | 并发数限制 | 降低同时提交的任务数 |
| 模型路由临时不可用 | 可操作的服务端错误（v1.6.5 起） | 稍后重试或换模型，提示会给出方向 |

### Seedance 报 TaskTypeConstraint

参数与任务模式不兼容：核对最终发送的 `ratio`、`duration` 与每个素材的 role（详见 [generate-video.md](10-tasks/generate-video.md) 的任务模式表）。任务 ID 只证明创建成功。

### 提交后一直转圈 / 结果未知（524 等）

原因：网关超时属于「提交不确定」——服务端可能仍在执行。
处理：**不要立刻重发**（可能重复扣费）。先看**画布上那个节点的状态徽章**——徽章会从「运行中/排队」变成「已完成 / 失败 / 已取消」或直接显示结果；确认它确实没有产出，再决定是否重发。

::: warning 没有「任务中心」这个页面
`/tasks` 路由已经退场（访问会被重定向回首页），「生成历史」弹窗也**只列出已成功的结果**（内部按 `status === "succeeded"` 过滤），不是完整任务列表。判断某个任务到底成没成，**唯一可靠的地方是画布上那个节点本身的状态徽章**。
:::

### 视频任务失败：用「取回结果」拿回原结果，不重新生成（v1.6.16 起）

视频任务失败时，任务详情里会出现说明「**查询原任务并取回视频，不会重新生成。**」和「**取回结果**」按钮（仅在任务支持向上游查询时出现）。点它会拿原任务去上游查结果并下载：

| 情况 | 你会看到 |
|---|---|
| 取回成功且画布上还有对应节点 | 「视频已取回并放回画布，未重新生成」 |
| 在任务历史里取回成功 | 「视频已取回，未重新生成」 |
| 节点已不在画布 | 「视频已取回，请在生成历史中查看」 |
| 上游还在跑 | 「原任务仍在处理中，请稍后再取回结果」 |
| 查不到 | 「查询上游任务失败」/「暂时无法取回结果，请稍后再试」/「任务详情加载失败」 |

**为什么重要**：这条路径复用原任务 ID 取结果，**不会再触发一次计费生成**。下载环节断线导致的任务失败也会在后台做有界恢复。

同类入口：画布上失败节点的**「查看原任务」**按钮、批量子节点的同名按钮，都会打开任务详情。

### 反馈问题前先「复制排查信息」

生成失败提示里有「**复制排查信息**」按钮（成功后显示「已复制」，失败显示「复制失败」）。点它会复制一段结构化文本，**报障时把它整段贴出来，比截图有用得多**：

```
原因：<失败原因>
下一步：<建议动作>
类别：<错误分类>
上游代码：<渠道返回码，可缺>
任务 ID：<任务 ID，可缺>
请求 ID：<请求 ID，可缺>
模型：<模型代号，可缺>
时间：<任务创建时间，可缺>
```

v1.6.15 起这份排查信息升级到**版本 2**：新增「请求 ID」与「上游代码」，并保留错误来源与请求证据（上游 HTTP 响应 / 上游业务响应 / HTTP 错误 / 传输或读取失败），用于回查到底是谁拒绝了请求；所有文本都经过脱敏（含含空格的目录名）。另外**丢失提交回执会被记为「未确认」而不是静默重发**——所以你不会再看到系统偷偷替你重复提交。

#### 排查信息里有什么、没有什么

贴排查信息不等于把你的创作内容交出去，系统会主动剔除敏感部分：

**会被剔除 / 截断的**

- **提示词正文**（`prompt`、`input` 等字段的值）→ 替换为「已隐藏」；
- **凭据**：`authorization`、`cookie`、`api_key`、`secret_key`、`access_token`、`refresh_token`、`password` 等键值 → 替换为「已隐藏」；
- **媒体地址与带签名的 URL** → 整段移除；
- 单条文本超过 **240 字** → 截断；以 `{` 或 `<` 开头的整段 → 判定为原始报文，直接丢弃；
- 代码类字段若以 `sk-`/`eyJ` 开头或含 `secret`/`password`/`bearer` → 视为敏感，**不输出**。

**会保留的**

- 任务的**图像设置、参考数量与各项限制**（这些用于判断「是不是素材超限」，不含创作内容）；
- 请求证据与**有界的请求历史**、各阶段耗时——用于回查请求链路；后台轮询期间持续保留，**重试时清空**。

> 换句话说：你可以放心把整段排查信息贴给客服或发到反馈渠道——提示词、密钥和素材地址不会跟着走。

### 相同参数再次提交被要求确认

这是防重复扣费保护：「可能再次消耗积分」确认框出现说明你提交过完全相同的任务。确认继续才会新建任务。

类似的还有**画幅比风险确认**（v1.6.7 起）：受影响渠道上 Seedance 2.0 标准版 / 2.5 参考视频生成在请求画幅比可能不被遵守时先弹确认；生成后实测画幅比与请求不符时视频保留并附提示。

### 提交前被拒：参考视频读不出来 / 帧率不支持

- **尺寸读不出或超范围**（v1.6.8 起）：时长正常也会再读实际尺寸，本地/内联视频以文件为准而非旧元数据——重新导出或转码素材；
- **帧率不支持 / 编码不支持 / 素材访问失败**（v1.6.10 起）：错误提示给出可操作指引，且**任务历史重新加载后仍在**——按提示转码或恢复素材访问；
- **像素超限**（v1.6.8 起）：错误会指明是哪个参考、实际尺寸与允许范围——按指明的目标值裁剪。

### 报「当前模型或接口不可用」但插件明明装了

界面给出的分类文案是「**当前模型或接口不可用**」，建议动作是「请检查模型名称和渠道配置」。

v1.6.9 前企业 Seedance 配置可能存了包名而非已安装的视频提供方 ID，导致这类误报。v1.6.9 起会**自动修复已有配置**并对旧别名做兼容校验——升级后重试即可；仍报错时在渠道设置里重新选择提供方并保存。

### 生成失败但旧结果消失了？

不会发生：失败时旧结果保留。若看到旧结果丢失，请检查是否切换了版本族主版本。

## 恢复与保存

### 打开画布弹出「恢复草稿」

说明存在未同步的本地草稿。文案两种：「远端失败本地草稿已保留」（可放心恢复）与「远端和本地都未保存，请不要关闭」（先别关窗口）。恢复前系统会自动备份当前云端内容。

### localStorage 不可用

导演台等依赖本地草稿的功能会**显式报错而不是静默丢失**：请检查浏览器隐私模式/站点数据设置。

## 连接与会话

### 本地推理（深度/线稿/姿态）报「本机深度运行时不可用」

伴随进程未启动或地址不对：确认进程运行在 `http://127.0.0.1:17371`（其他地址会被拒绝）。

桌面端（v1.6.12 起，Windows）首次使用深度处理会**自动下载签名组件**：CPU 推理已测试可用，NVIDIA CUDA 为社区测试预览（设备故障会自动回退 CPU 一次）；CPU 处理可能较慢且占用内存，下载支持断点续传、取消即停。Apple Silicon Mac 处理不变。

下载失败且本机走代理时：组件下载与桌面更新共用代理规则（显式环境代理优先，否则读系统代理，含排除地址）；**改好系统代理后直接重试**即可，无需在应用里重复配置。

### 云 Agent 连接反复重连

> 云 Agent 界面入口当前未开放（见 [cloud-agent.md](10-tasks/cloud-agent.md)），这一条留作接口层说明。

连接由控制器托管：断流后会**被动恢复**，若期间执行权被切换，需要**显式重连**重试。真实存在的界面/接口提示是「**当前创作连接已切换，请点击重试连接继续。**」——遇到它说明另一次连接接管了这次运行，点「重试连接」即可。

机制上有一条重要约束：**恢复只续租，绝不覆盖本地编辑，也不覆盖未知的提交结果**——所以重连不会毁掉你画布上已有的东西。

4xx（除 408/429）或重试间隔超 5 分钟会停止并报告。仍请先检查登录状态与网络。

### 点「转写自动字幕」报「本地转写服务未配置」

时间线编辑器的转写走**本机 whisper.cpp**，不是云端能力。后端没读到 `CANVAS_WHISPER_BASE_URL` 时，任务在进入转写前就会失败并给出这句提示。

按顺序检查：

1. whisper.cpp 服务是否已启动（`whisper-server` 进程在不在，默认端口 8082）；
2. 后端进程的环境变量 `CANVAS_WHISPER_BASE_URL` 是否指向该服务（含 `/inference` 的基址，如 `http://127.0.0.1:8082`）——**改完要重启后端**；
3. 仓库自带的 `scripts/start-whisper-local.sh` 会检查 `whisper-server` 是否在 PATH、模型文件是否已下载到 `.local/whisper-models/`，缺哪项会直接告诉你。

细节见 [20-reference.md](20-reference.md) 的「本地转写服务」节。

### 转写完成却提示「没有识别出可用字幕」

音视频里没有人声、或语音过短时会出现——空文本与零时长片段会被过滤掉，不写入字幕轨道。换一段有清晰人声的素材再试；视频素材**带静音轨**时后端会明确报错。

## 诊断与反馈

- 客户端诊断只上报 **11 个白名单稳定码**（如 DIRECTOR_VIEWPORT_CONTEXT_LOST、DIRECTOR_SAVE_FLUSH_FAILED），不含你的输入内容；
- 导演台问题可用内置**确定性复现场景 + 15 条手工复现矩阵**协助定位；失败模型会退化为占位人偶而非崩溃，其余面板不受影响。
