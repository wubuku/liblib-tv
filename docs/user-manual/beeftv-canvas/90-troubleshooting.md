# 故障排查

> 症状 → 原因 → 处理。按真实源码行为整理。

## 先看这一节：看着像坏了，其实不是

下面这些**不是故障**，是产品的既定行为。遇到时先在这里对一遍，能省掉一次误操作和一笔冤枉钱。

| 你看到的 | 真实情况 | 详见 |

| 视频生成模式不是你选的那个 | 它**主要由连线素材推算**。先选模式再连素材，可能被自动纠正 | [generate-video.md](10-tasks/generate-video.md) |

## 打开与加载

### 画布一直显示「正在打开画布...」

原因：新建画布需要后端接口；Web 前端把 `/api` 代理到 `127.0.0.1:8080`，后端未启动时代理连接被拒。
处理：启动后端（仓库 `backend` 目录执行 `go run ./cmd/server`，默认 SQLite、监听 :8080），刷新页面即可。

## 生成类

### 提交时报素材/参数不被接受

界面文案不是一句固定的话，而是按原因分类给的（v1.6.16 源码逐条核对）。常见几类：

| 你会看到 | 含义 | 怎么办 |
|---|---|---|
| 参考素材过大 / 无权访问参考素材 / 参考素材无法读取 | 素材本身的问题 | 换小一点的素材，或检查访问权限 |
| 参考素材时长不符合模型要求 / 视频时长不符合模型要求 | 时长超范围（提示会给出允许的秒数区间） | 按提示把素材调整到区间内 |
| 参考素材高度不符合模型要求 | 尺寸超范围（提示会给出实际值与上限） | 裁剪到允许尺寸 |
| 整次请求的数据量超过接口上限 | 总量超限 | 减少参考数量或体积 |
| 模型不接受当前参数 | 参数组合不被支持 | 核对比例、时长、素材角色 |
| 当前模型或接口不可用 | 模型名或渠道配置有问题 | 检查模型名称与渠道配置 |

处理方向一致：更换或裁剪素材；或在渠道设置里切换能力匹配的模型。

### 提交前就失败：本地保存没成功（v1.6.17 起）

界面会写「**本地任务保存失败，尚未提交生成**」。**这句话的重点在后半句**：

- **没有提交**，所以**没有扣费**，也没有在供应商那边留下一个在跑的任务；
- 失败发生在把任务写进本地数据库那一步，**不是模型或参数的问题**——所以去改提示词、改参数都没用；
- 按提示做：**先重启 BeefTV 再重试**；仍然失败就更新应用并联系支持。

> **它替代了旧的一句话**：v1.6.16 及更早版本里，这类情况有时被显示成「模型不接受当前参数」，
> **方向完全指错**——你会去反复调参数，而真正的原因是本地存储写不进去。

### 视频已经生成好了，但暂时拿不回来（v1.6.19 起）

界面会写「**视频已生成，但暂时无法取回**」。这一句刻意把两件事分开：

| | 状态 |
|---|---|
| 生成 | **已完成，费用已发生** |
| 取回 | **暂时失败**（网络、上传、或投递环节） |

**不要重新生成**——按提示**联系支持恢复成片**，恢复后回到任务详情点「**取回结果**」即可，
**无需再次付费**。这与 [generate-video.md](10-tasks/generate-video.md) 里「取回结果」的机制是同一条。

> 早先版本的对应提示是「查询上游任务失败 / 暂时无法取回结果，请稍后再试」，
> **看不出钱已经花了**——那句话容易让人以为失败＝没扣费，从而既不去取回、又重新提交一次。

### 审核失败：先看提示里说的是哪一类

界面提示会写清是哪一类，不必猜。**提示由两部分拼成**：「**对象**」+「**原因**」——
所以同一句「未通过版权审核」，可能出现在 8 种不同的对象上。

**对象（第一段，共 8 种）**：`输入文本` / `参考图片` / `参考视频` / `参考音频`
/ `生成文字` / `生成图片` / `生成视频` / `生成音频`

**原因（第二段，共 4 种）**：

| 提示里的说法 | 对应错误码 | 含义 |
|---|---|---|
| 未通过内容安全审核 | `SensitiveContentDetected` | 泛化的一条，**不告诉你具体原因** |
| 未通过上游版权审核 | `PolicyViolation` | 版权方限制 |
| 未通过隐私审核 / 疑似包含真人形象，该模型拒绝生成 | `PrivacyInformation` | 前者是通用说法；**输入图片/视频**才会换成「真人形象」那句 |
| 未通过伪造内容审核 | `DeepFake` | 伪造内容 |

另外 `ContentSecurityDetectionError` 表示**审核服务内部失败**，不能当成你的内容违规。

**为什么对象这一维值得单列**：处置方向**取决于对象，不取决于原因**。

- 对象是**输入文本** → 改提示词（音频另有一条「请调整音乐或音频相关提示词」）。
- 对象是**参考素材**（图片/视频/音频）→ **换掉那一份素材**，改提示词没用。
- 对象是**生成结果**（文字/图片/视频/音频）→ 你的输入过了审核，是**产出**被拦。
  **这时最该做的是调整输入**（提示词或参考素材）再重做，而不是反复重试同一个输入。
  注意这一类在旧版本里**没有单独提示**，容易和输入侧混淆。

四类原因的处理方向一致：调整提示词，或更换/裁剪受质疑的那份参考素材，然后**新建一个任务**（原任务不受影响，也不会自动重试）。

### 额度与频控：不要一律「稍后再试」

**先分清是谁的额度**——「额度不足」至少有五种，处置完全不同（v1.6.22 源码逐条核对）：

| 你会看到 | 是谁的额度 | 处理 |
|---|---|---|
| **当前账号可用额度不足** | **你自己的**账号余额 | 检查账号余额，补充额度，**或调整令牌/套餐额度**后重试 |
| 模型供应商拒绝了计费或额度相关请求 | **供应商那边** | 到供应商核对账单与额度，**再决定是否重试** |
| 模型服务拒绝了计费或额度相关请求 | 说不清是渠道还是模型 | 到当前渠道或模型供应商核对账单与额度，再决定是否重试 |
| `SetLimitExceeded` | 你给**渠道**配的用量上限 | 检查并调整渠道用量/预算 |
| 模型调用已达到设置的用量上限 | 渠道的用量或预算限制 | 调整限制后再试 |
| `AccountOverdueError` / `ServiceOverdue` | 供应商**欠费**（不是你的权限问题） | 联系渠道方处理欠费 |
| `InflightBatchsizeExceeded` | 并发数限制 | 降低同时提交的任务数 |
| 模型路由临时不可用 | 可操作的服务端错误（v1.6.5 起） | 稍后重试或换模型，提示会给出方向 |

> **v1.6.19 把「当前账号额度不足」改成了「当前账号可用额度不足」**，并补上了处置方向
> （补充额度 / 调整令牌与套餐额度）。**加了「可用」两个字，是为了把它和下面几种"别人家的额度"区分开**——
> 旧文案容易被理解成「这个模型你用不了」，而它其实说的是**你账上的钱不够了**。

### 其余失败提示：先看「是不是已经扣费了」

上面几节讲的是有专门处理办法的。这一类是**没有特定解法、但处置方向一致的**，
按上游的分类文案（v1.6.22 逐条核对）归成五组。**每组第一列都是你在界面上会看到的字**：

**第一组 · 服务端或网络问题，可以直接重试**

| 你会看到 | 说明 |
|---|---|
| 模型服务暂时不可用 | 稍后重试 |
| 网络连接失败 | 检查网络；**先核对原任务状态**，再决定是否重新生成 |
| 请求过于频繁 | 稍后再试 |
| 同时进行的生成过多 | 等已有任务完成后再试（不是额度问题） |

**第二组 · 状态不明，**不要**立刻重新提交**

这三条最容易让人误操作——**重新提交很可能重复扣费**：

| 你会看到 | 说明 |
|---|---|
| 模型服务响应超时 | 稍后**查询原任务**，不要立即重新提交 |
| 提交结果尚未确认，上游任务可能仍在执行 | **先查询原任务状态**，不要立即重新提交 |
| 生成结果下载失败 | 稍后重新加载，**不要立即重新提交** |
| 模型服务返回了无法解析的内容 | 查看详情并核对原任务状态后，再决定是否重新生成 |

**第三组 · 钱已经花了，但结果没到手**

| 你会看到 | 说明 |
|---|---|
| 视频已生成，但暂时无法取回 | 联系支持恢复成片，恢复后点「取回结果」，**无需重新付费** |
| 部分结果已生成，其余失败 | 先看已有结果，再决定要不要补做 |
| 任务结束但没有可用结果 | 查看详情后再决定是否重试 |

**第四组 · 配置或鉴权问题，重试没用**

| 你会看到 | 说明 |
|---|---|
| 模型服务鉴权失败 | 检查 API Key 后重试 |
| 当前渠道没有使用该模型的权限 | 更换模型或检查渠道权限 |
| 输入内容超出模型长度限制 | 缩短提示词或减少参考内容 |

**第五组 · 状态类，不是「失败」**

| 你会看到 | 说明 |
|---|---|
| 任务已取消 | 可以按原输入重新提交 |
| 生成任务没有完成 | 查看详情后决定是否重试 |
| 生成失败（没有更具体的原因） | 查看详情后再决定是否重试 |

> **为什么按组写而不是把 29 条全列出来**：上游 `generation-error.ts` 里的分类表
> 有 29 条，逐条抄进手册既难读也难维护——**而同一组里各条的处置方向本来就一样**。
> 分组后**每组一个处置方向**，读者扫一眼就能定位。
> 抄全表这件事交给构建时的检查（见本页末尾的取证说明）。

### Seedance 报 TaskTypeConstraint

参数与任务模式不兼容：核对最终发送的 `ratio`、`duration` 与每个素材的 role（详见 [generate-video.md](10-tasks/generate-video.md) 的任务模式表）。任务 ID 只证明创建成功。

### 提交后一直转圈 / 结果未知（524 等）

原因：网关超时属于「提交不确定」——服务端可能仍在执行。
处理：**不要立刻重发**（可能重复扣费）。先看**画布上那个节点的状态徽章**——徽章会从「运行中/排队」变成「已完成 / 失败 / 已取消」或直接显示结果；确认它确实没有产出，再决定是否重发。

::: warning 没有「任务中心」这个页面
`/tasks` 路由已经退场（访问会被重定向回首页），「生成历史」弹窗也**只列出已成功的结果**（内部按 `status === "succeeded"` 过滤），不是完整任务列表。判断某个任务到底成没成，**唯一可靠的地方是画布上那个节点本身的状态徽章**。
:::

### 视频任务失败：用「取回结果」拿回原结果，不重新生成（v1.6.16 起）

视频任务失败时，任务详情里会出现说明「**查询原任务并取回视频，不会重新生成。**」和「**取回结果**」按钮（仅在任务支持向上游查询时出现）。点它会拿原任务去上游查结果并下载：

| 情况 | 你会看到 |
|---|---|
| 取回成功且画布上还有对应节点 | 「视频已取回并放回画布，未重新生成」 |
| 在任务历史里取回成功 | 「视频已取回，未重新生成」 |
| 节点已不在画布 | 「视频已取回，请在生成历史中查看」 |
| 上游还在跑 | 「原任务仍在处理中，请稍后再取回结果」 |
| 查不到 | 「查询上游任务失败」/「暂时无法取回结果，请稍后再试」/「任务详情加载失败」 |

**为什么重要**：这条路径复用原任务 ID 取结果，**不会再触发一次计费生成**。下载环节断线导致的任务失败也会在后台做有界恢复。

同类入口：画布上失败节点的**「查看原任务」**按钮、批量子节点的同名按钮，都会打开任务详情。

### 反馈问题前先「复制排查信息」

生成失败提示里有「**复制排查信息**」按钮（成功后显示「已复制」，失败显示「复制失败」）。点它会复制一段结构化文本，**报障时把它整段贴出来，比截图有用得多**：

```
原因：<失败原因>
下一步：<建议动作>
类别：<错误分类>
上游代码：<渠道返回码，可缺>
任务 ID：<任务 ID，可缺>
请求 ID：<请求 ID，可缺>
模型：<模型代号，可缺>
时间：<任务创建时间，可缺>
```

v1.6.15 起这份排查信息升级到**版本 2**：新增「请求 ID」与「上游代码」，并保留错误来源与请求证据（上游 HTTP 响应 / 上游业务响应 / HTTP 错误 / 传输或读取失败），用于回查到底是谁拒绝了请求；所有文本都经过脱敏（含含空格的目录名）。另外**丢失提交回执会被记为「未确认」而不是静默重发**——所以你不会再看到系统偷偷替你重复提交。

#### 排查信息里有什么、没有什么

贴排查信息不等于把你的创作内容交出去，系统会主动剔除敏感部分：

**会被剔除 / 截断的**

- **提示词正文**（`prompt`、`input` 等字段的值）→ 替换为「已隐藏」；
- **凭据**：`authorization`、`cookie`、`api_key`、`secret_key`、`access_token`、`refresh_token`、`password` 等键值 → 替换为「已隐藏」；
- **媒体地址与带签名的 URL** → 整段移除；
- 单条文本超过 **240 字** → 截断；以 `{` 或 `<` 开头的整段 → 判定为原始报文，直接丢弃；
- 代码类字段若以 `sk-`/`eyJ` 开头或含 `secret`/`password`/`bearer` → 视为敏感，**不输出**。

**会保留的**

- 任务的**图像设置、参考数量与各项限制**（这些用于判断「是不是素材超限」，不含创作内容）；
- 请求证据与**有界的请求历史**、各阶段耗时——用于回查请求链路；后台轮询期间持续保留，**重试时清空**。

> 换句话说：你可以放心把整段排查信息贴给客服或发到反馈渠道——提示词、密钥和素材地址不会跟着走。

### 相同参数再次提交被要求确认

这是防重复扣费保护：「可能再次消耗积分」确认框出现说明你提交过完全相同的任务。确认继续才会新建任务。

类似的还有**画幅比风险确认**（v1.6.7 起）：受影响渠道上 Seedance 2.0 标准版 / 2.5 参考视频生成在请求画幅比可能不被遵守时先弹确认；生成后实测画幅比与请求不符时视频保留并附提示。

### 提交前被拒：参考视频读不出来 / 帧率不支持

- **尺寸读不出或超范围**（v1.6.8 起）：时长正常也会再读实际尺寸，本地/内联视频以文件为准而非旧元数据——重新导出或转码素材；
- **帧率不支持 / 编码不支持 / 素材访问失败**（v1.6.10 起）：错误提示给出可操作指引，且**任务历史重新加载后仍在**——按提示转码或恢复素材访问；
- **像素超限**（v1.6.8 起）：错误会指明是哪个参考、实际尺寸与允许范围——按指明的目标值裁剪。

### 报「当前模型或接口不可用」但插件明明装了

界面给出的分类文案是「**当前模型或接口不可用**」，建议动作是「请检查模型名称和渠道配置」。

v1.6.9 前企业 Seedance 配置可能存了包名而非已安装的视频提供方 ID，导致这类误报。v1.6.9 起会**自动修复已有配置**并对旧别名做兼容校验——升级后重试即可；仍报错时在渠道设置里重新选择提供方并保存。

### 生成失败但旧结果消失了？

不会发生：失败时旧结果保留。若看到旧结果丢失，请检查是否切换了版本族主版本。

## 恢复与保存

### 导演台提示「本地草稿已保留 / 请不要关闭导演台」

这是**导演台**里的提示，不是画布打开时弹的。说明这次保存没能落到服务端，但改动还在本机。

- **「远端保存失败，本地草稿已保留，可稍后重试」**——草稿确实存下来了，**重试保存一般能成**；
- **「远端和本地都未保存，请不要关闭导演台并继续重试」**——两边都没写成，**先别关窗口**。

两个提示下面还有一个「发现未保存的本地草稿」的确认框，标题写明这份草稿比项目新、恢复后会写回项目，按钮是「**恢复草稿**」（另一个是「放弃本地草稿」）。恢复前系统会自动备份当前云端内容。

### 报「已达上限 / 必须小于 N」

这不是模型或渠道的问题，是**账号配额**。服务端强制九项配额（存储总量 20GB、结构化数据 256MB、单传 50MB、单生成 64MB、日传 2GB、素材 2000、画布 1000、任务 20000、请求日志 100000），撞哪条报哪条。**按报错里的数字处理**——部署方可以改这些值，你看到的数字可能与文档默认值不同。

最容易被误判的是「账号画布和素材数据已达到 256MB 上限」：它统计的是**节点、连线、提示词这些结构化数据**，不是你上传的大图。**这时候删大图没用，得删画布或节点。** 完整对照表见 [storage-quota.md](10-tasks/storage-quota.md)。

### 报「同时排队或运行的任务最多 5 个」

**只在默认部署出现**：本地部署（`localMode`）把这个上限放宽到 **999**，所以你看到这条说明**不是本地部署**——多半是你连的托管服务。

账号级硬上限。批量创作表会自己排队所以通常撞不到，**单张卡片点「生成」**才会。等着，或者先把批量表的并发调低——见 [generate-images.md](10-tasks/generate-images.md) 与 [storage-quota.md](10-tasks/storage-quota.md)。

### localStorage 不可用

导演台等依赖本地草稿的功能会**显式报错而不是静默丢失**：请检查浏览器隐私模式/站点数据设置。

### 复制了画布，提示「画布副本已创建」，但换个地方就没了

**不是错觉，也不是操作错了。** 画布顶栏菜单的「复制画布」和只读横幅的「复制项目」都走同一条路径，它**只把副本写进当前浏览器的本地存储，从不上传服务器**——所以清掉站点数据、换浏览器或换电脑，副本就消失了。实测：点完后对后端接口的写请求数为 0，服务端画布列表条数不变。

**处理办法**：要可靠副本，去**画布库**里用卡片菜单的「创建副本」——那条路径会把副本真正存到服务端（实测服务端列表会新增一项）。若只是想让人看看、不打算改，用截图或导出更省事。

完整机制与只读模式的进入方式见 [readonly-canvas.md](10-tasks/readonly-canvas.md) 与 [30-concepts.md](30-concepts.md)。

### 画布的文件夹、归类、封面换台电脑就没了

**当前版本服务端没有这些概念，不是你操作错。** 实测：新建文件夹、把画布移进去，对后端接口的写请求数都是 **0**；而且**在画布里反复编辑内容也不会把归类带上去**。

原因：**服务端确实有文件夹，但那是「素材文件夹」，和画布库的文件夹是两套互不相干的东西**。后端画布记录里根本没有归属字段（只有素材才有），画布库也从不调用素材那套接口。画布封面则直接存在浏览器本地，导演台场景同理。

顺带一提：**素材库那套文件夹在当前版本也换不了设备**（接口在、但页面调不到），所以「两套文件夹」其实是「两套都在本机」——见 [asset-library.md](10-tasks/asset-library.md)。

**哪些能留住、哪些留不住**：

| 东西 | 换设备后 |
|---|---|
| 画布内容（节点、连线、生成结果） | **在**——只要之后在画布里编辑过一次 |
| 画布库里的**名字** | 在**画布库**改的那个才在 |
| 画布库里的**文件夹与归类** | **没** |
| **画布封面** | **没** |
| **导演台场景** | **没** |

**要留底就导出 ZIP**（见 [manage-canvases.md](10-tasks/manage-canvases.md)），完整的两张对照表在 [30-concepts.md](30-concepts.md)。

### 改了画布的名字，另一个地方还是旧名
**当前版本有两套互不相通的名字，这是既定行为，不是你记错了。**

- 在**画布库**改的名 → 画布库显示新名，**画布顶栏仍是旧名**（或回落成「画布 1」）；
- 在**画布顶栏**改的名 → 顶栏显示新名，**画布库仍是旧名**。

顶栏那一栏其实同时摆着两个名字：左边是画布标题，右边是画布切换器的名字（读的是另一个字段，为空就显示「画布 N」）。**两个名字的改名都不会立刻上传到服务器**（实测写请求数为 0）。

**该在哪改**：在**画布库**改。改完如果马上要关电脑，**顺手在画布里做一次任意编辑**（加个节点、拖动一下位置都行）——实测只有画布库改的名会跟着这次编辑一起存到服务器；顶栏改的名**无论之后编辑多少次都存不上去**。

同名不同物、两个「回收站」、三条「复制画布」都属于同一族，详见 [manage-canvases.md](10-tasks/manage-canvases.md) 与 [30-concepts.md](30-concepts.md)。

### 画布是只读的，但界面上找不到切换按钮

**当前版本确实没有这个按钮。** 只读模式只能手动改网址：在画布地址后加 `?readonly=1`（或等价的 `?mode=readonly`）。进去后底部编辑坞、滚轮缩放、拖拽平移和画布快捷键都会失效，右上角只留一个「复制项目」。详见 [readonly-canvas.md](10-tasks/readonly-canvas.md)。

### 多标签同时编辑：5 条并发相关文案

同一个账号开两个标签改的是同一份画布数据。系统把并发相关的提示分成下面几类：

| 你会看到 | 发生在哪一层 | 怎么办 |
|---|---|---|
| 画布生成副作用与并发修改冲突 | **本地**写回生成结果时，发现你改的字段被另一个标签改过 | 关掉其他标签，**刷新页面**让画布回到盘上真实的样子，再重试 |
| 画布生成副作用与已删除内容冲突 | 同上，但你改的东西在另一个标签已被删除 | 刷新后确认该节点是否还需要；需要就重新建一个 |
| 当前浏览器不支持跨标签存储锁，已停止画布生成持久化 | 浏览器没有 Web Locks API，**生成结果一律不落盘**（普通编辑不受影响，仍照常保存） | 换用支持 Web Locks 的现代浏览器（Chrome / Edge / Firefox / Safari 新版） |
| 云端画布已有更新，已停止覆盖；请保留本地草稿并加载最新版本 | **后端**发现你带来的版本号不是最新的 | 按提示**先保留本地草稿**，再加载最新版本，手工把你要的内容并回去 |
| 画布引用的素材已变化，当前内容未被覆盖，请保留草稿并重新加载 | 后端发现画布引用的素材被换掉了 | 同上，重新挂载正确的参考素材 |

共同的处理顺序：**别关窗口 → 刷新 → 确认画布现状 → 再决定重试还是重做**。这几条都是「宁可什么都不写也不写错」，刷新后画布就是可信的。

::: warning 两种情况不会有任何提示
- **普通编辑撞车**：两个标签改到同一个字段时，先落盘的赢，**后改的那个静默丢失且不提示**；
- **本地或后端同步失败**：只在浏览器控制台留一行日志，界面上什么都不显示。

真正稳妥的做法是**同一时间只开一个标签页编辑同一张画布**。合并规则见 [30-concepts.md](30-concepts.md) 的「多标签同时编辑」节。
:::

## 连接与会话

### 本地推理（深度/线稿/姿态）报「本机深度运行时不可用」

伴随进程未启动或地址不对：确认进程运行在 `http://127.0.0.1:17371`（其他地址会被拒绝）。

桌面端（v1.6.12 起，Windows）首次使用深度处理会**自动下载签名组件**：CPU 推理已测试可用，NVIDIA CUDA 为社区测试预览（设备故障会自动回退 CPU 一次）；CPU 处理可能较慢且占用内存，下载支持断点续传、取消即停。Apple Silicon Mac 处理不变。

下载失败且本机走代理时：组件下载与桌面更新共用代理规则（显式环境代理优先，否则读系统代理，含排除地址）；**改好系统代理后直接重试**即可，无需在应用里重复配置。

### 云 Agent 连接反复重连

> 云 Agent 界面入口当前未开放（见 [cloud-agent.md](10-tasks/cloud-agent.md)），这一条留作接口层说明。

连接由控制器托管：断流后会**被动恢复**，若期间执行权被切换，需要**显式重连**重试。真实存在的界面/接口提示是「**当前创作连接已切换，请点击重试连接继续。**」——遇到它说明另一次连接接管了这次运行，点「重试连接」即可。

机制上有一条重要约束：**恢复只续租，绝不覆盖本地编辑，也不覆盖未知的提交结果**——所以重连不会毁掉你画布上已有的东西。

4xx（除 408/429）或重试间隔超 5 分钟会停止并报告。仍请先检查登录状态与网络。

### 点「转写自动字幕」报「本地转写服务未配置」

时间线编辑器的转写走**本机 whisper.cpp**，不是云端能力。后端没读到 `CANVAS_WHISPER_BASE_URL` 时，任务在进入转写前就会失败并给出这句提示。

按顺序检查：

1. whisper.cpp 服务是否已启动（`whisper-server` 进程在不在，默认端口 8082）；
2. 后端进程的环境变量 `CANVAS_WHISPER_BASE_URL` 是否指向该服务（含 `/inference` 的基址，如 `http://127.0.0.1:8082`）——**改完要重启后端**；
3. 仓库自带的 `scripts/start-whisper-local.sh` 会检查 `whisper-server` 是否在 PATH、模型文件是否已下载到 `.local/whisper-models/`，缺哪项会直接告诉你。

细节见 [20-reference.md](20-reference.md) 的「本地转写服务」节。

### 转写完成却提示「没有识别出可用字幕」

音视频里没有人声、或语音过短时会出现——空文本与零时长片段会被过滤掉，不写入字幕轨道。换一段有清晰人声的素材再试；视频素材**带静音轨**时后端会明确报错。

## 诊断与反馈

- 客户端诊断只上报 **11 个白名单稳定码**（如 DIRECTOR_VIEWPORT_CONTEXT_LOST、DIRECTOR_SAVE_FLUSH_FAILED），不含你的输入内容；
- 导演台问题可用内置**确定性复现场景 + 15 条手工复现矩阵**协助定位；失败模型会退化为占位人偶而非崩溃，其余面板不受影响。
