# 发起图片生成：任务状态、批量与重试

> 适用角色：所有用户 ｜ **本页操作涉及按量计费**，请先确认渠道配置与额度。

## 目标

从一个图片节点发起生成，看懂任务状态徽章，掌握批量出图与失败重试。

## 前置条件

- 图片节点已连线上游参考（或提示词中已 @mention）；
- 管理员已配置可用的生成渠道（见 [plugins-management.md](plugins-management.md)）。

## 发起生成

1. 选中图片节点，在提示词面板填写提示词（参考 [prompts-and-mentions.md](prompts-and-mentions.md)）；
2. 设置份数（count>1 时自动创建 root + N 个子节点，首张成功后回填为主图）；
3. 点击生成。**同一节点用完全相同的提示词、模型、参数和参考再次提交时，会弹出「可能再次消耗积分」的确认**——这是防重复扣费的保护，确认才会继续。

## 任务状态

进行中的节点显示徽章、spinner、阶段文案与**已耗时**；右上角任务浮层列出当前活跃任务（最多 5 条），2 秒/10 秒自适应轮询，窗口聚焦即时刷新。

| 状态 | 含义 |
|---|---|
| 排队/运行中 | 任务已提交，等待或生成中 |
| succeeded / failed / cancelled | 终态 |
| 提交不确定（如 524 网关超时） | 结果未知，系统**不会自动重试**——请先到任务中心确认结果再手动操作，避免重复扣费 |

## 刷新与恢复

页面刷新后，系统按 taskId 与服务端任务列表**对账恢复**：仍在运行的任务继续跟踪；没有任务身份的孤立「加载中」节点会被标记为本地中断，不会覆盖已完成结果。

## 失败与重试

- 失败时**旧结果不会被清空**；
- 因「输入未变」被审核类规则拒绝的任务不会自动重试；
- 手动重试会重建上下文：从最初生成的节点恢复引用；引用已丢失时会拒绝并提示；重试使用幂等 id，不会重复扣费。
