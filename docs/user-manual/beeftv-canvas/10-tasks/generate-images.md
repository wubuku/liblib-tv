# 发起图片生成：任务状态、批量与重试

> 适用角色：所有用户 ｜ **本页操作涉及按量计费**，请先确认渠道配置与额度。

## 目标

从一个图片节点发起生成，看懂任务状态徽章，掌握批量出图与失败重试。

## 前置条件

- 图片节点已连线上游参考（或提示词中已 @mention）；
- 管理员已配置可用的生成渠道（见 [插件管理](plugins-management.md)）。

## 发起生成

1. 选中图片节点，在提示词面板填写提示词（参考 [提示词与 @mention](prompts-and-mentions.md)）；
2. 设置份数（count>1 时自动创建 root + N 个子节点，首张成功后回填为主图）；
3. 点击生成。**同一节点用完全相同的提示词、模型、参数和参考再次提交时，会弹出「可能再次消耗积分」的确认**——这是防重复扣费的保护，确认才会继续。

### 可选参数（随模型能力档案变化）

和视频一样，图片参数也是**跟着模型走**的，不同模型给的档位不一样。

| 项 | 可选值 |
|---|---|
| 质量档 | **1K / 2K / 4K** |
| 比例 | 1:1 · 16:9 · 9:16 · 4:3 · 3:4 · 3:2 · 2:3 · 4:5 · 5:4 · 21:9（**10 档**，比视频多 2:3、4:5、5:4） |
| 实际像素 | 每个比例在每个质量档下都有对应像素，例如 1:1 依次是 1024×1024 / 2048×2048 / 2880×2880 |
| 透明背景 | 开关，请求模型输出**保留 Alpha 通道的 PNG** |
| 张数 | 快捷按钮 1/2/3 + 数字输入。上限取**内置的 15** 与**该模型的「单次生成张数」**中较小的一个——部分模型会被压到 4 甚至 1 |

::: warning 「质量档」有两套词汇，取决于模型
| 档位词汇 | 含义 |
|---|---|
| **自动 / 高 / 中 / 低** | 传统的画质档位 |
| **1K / 2K / 4K** | 分辨率档位 |

面板**只显示当前模型档案里声明的那一套**。所以有人看到「自动/高/中/低」，有人看到「1K/2K/4K」——**不是版本不一样**。

还有个容易懵的细节：当模型用「宽高比」参数表达尺寸、且分辨率已由质量档决定时，**质量那一组会整个消失**（分辨率改在尺寸选择器里设）。这时面板上就找不到质量档了。

「张数」也是同理：在**蒙版编辑**弹窗里整行不显示（一次只改一张），别以为控件坏了。
:::

::: tip 同一组控件，名字会变
如果模型的质量档就是 1K/2K/4K 这类分辨率档位，这组的标题会显示成「**分辨率**」；否则显示「**质量**」。同一个开关，两种叫法。
:::

::: tip 记不住也没关系
面板里**只显示你当前模型支持的那些档**，不会把全部选项都摆出来。换个模型，比例与质量档会跟着变——**以面板里实际出现的为准**。
:::

> 想看某个模型到底支持什么：先在「模型配置」接入渠道，模型芯片才会展开可选项。视频侧的参数清单见 [发起视频生成与素材限制](generate-video.md)。

## 图片节点工具条：七个按钮，里面装了什么

图片节点被选中后，工具条上是一排**分组按钮**而不是逐个动作。要用某个功能，得先知道它在哪个按钮里：

| 按钮 | 里面有哪些 |
|---|---|
| （直出的主按钮） | **局部重绘** |
| **人像调整** | **表情调整** |
| **视角调整** | **多角度**、**打光** |
| **图片工具** | **裁切**、**宫格切分**、**标注** |
| **图片设置** | **替换图片**、**锁定宽高比** |
| **预览** | 直接打开大图 |
| （另有两个通用项） | 放大、下载 |

### 多角度：换个机位再出一张

「多角度」弹出一个参数面板，确认后按当前角度**生成一张新图**：

| 项 | 说明 |
|---|---|
| 六个预设 | **正面 / 左侧 / 右侧 / 背面 / 俯拍 / 仰拍** |
| 水平角度 | 环绕角度，滑杆可自由拖 |
| 垂直俯仰 | **−60° ~ 60°** |
| 景别缩放 | **1 ~ 10**，步长 0.1（数值越小越近） |
| 镜头 | **标准 / 广角** 两档 |
| 环境 | **天空盒 / 摄像头** 两档 |

初值是水平 **45°**、俯仰 0°、景别 **4.8**、标准镜头。

::: warning 「俯拍」和「仰拍」别选反
两个预设的内部标识是 `top` / `bottom`，但界面上写的是**俯拍 / 仰拍**——**标识名和界面名是反的**。记住界面上的字就行：俯拍是从上往下看，仰拍是从下往上托。
:::

### 打光

「打光」调整光线后生成新图。面板提供：

| 项 | 说明 |
|---|---|
| 方向预设 | **前方 / 右侧 / 后方 / 左侧 / 顶部 / 底部** 六个 |
| 角度 | 可自由设方位角与高度角，不走预设时按角度打 |
| 光线颜色 | 取色器 |
| 亮度 | 数值调节 |
| 关闭打光效果 | 开关——可以只保留原图光线 |

::: tip 找不到的三个功能，不是你漏看了
「质感调整」「全景图」「复制提示词」「反推提示词」这四项在当前版本的图片节点工具条上**不会出现**：
- **质感调整**与「表情调整」同属人像分组，但工具条只渲染了后者；
- **全景图**只在**非图片**节点上提供；
- **复制提示词 / 反推提示词**属于「更多」分组，而图片节点工具条**完全不渲染该分组**——这两项目前在任何地方都点不到。
:::

## 批量创作表：一次排一批

批量创作表是一个**独立节点**（默认尺寸 **1280 × 560**）。它不是「把提示词写长一点」，而是把**一批同类任务排成表**，逐行生成、各自落成结果节点。

### 两种模式

| 模式 | 用途 | 输入怎么排成行 |
|---|---|---|
| **批量换装** | 把同一件衣服/造型换到不同人身上 | **至少要连 2 个**：**最后一个当服装**，前面每一个当人，**每行 = 一个人 + 那件衣服** |
| **创意生图** | 一批各自不同的创意 | **每个输入各占一行** |

两种模式预填的默认提示词不同，也可以自己改。

::: tip 换装模式只连了 1 个会怎样
不会生成任何行——它需要**至少两个输入**才能分出「谁穿什么」。只连一张衣服图是看不出效果的，得再连至少一个人物图。
:::

### 表头设置

| 项 | 可选值 |
|---|---|
| **并发** | **1 / 5 / 10**，默认 **10** |
| **全局提示词** | 填了就**覆盖每一行自己的提示词**；留空则各行用各行的 |
| **参考图列** | 默认给 3 列（参考图 1/2/3），**最多加到 6 列**；每列可以放参考图，也能上下调换顺序 |

::: warning 并发不是「同时提交多少个」的装饰，但**也铺不满 10**
并发决定**同时在跑几个任务**。服务端对每个账号另有硬上限——**默认部署是「同时排队或运行的任务最多 5 个」**（**本地部署这个上限被放宽到 999，你基本撞不到**），所以：

- 选 10 **不会**同时跑 10 个，多出来的行停在「等待中」，前面有任务完成就自动补位；
- 选 5 就够用，选 10 不会更快，只会让更多行提前进入「等待中」；
- 批量链路会自己排队，所以你通常**看不到**那条上限报错；**单张卡片点「生成」**才是硬撞，账号已有 5 个在跑时直接报「同时排队或运行的任务最多 5 个，请等待已有任务完成」（**本地部署不会报这条**——上限是 999，见 [账号存储、容量与配额](storage-quota.md)）。

上游有频控时并发越高越容易被限流，**报「额度/频控」类错误就把它调低**（见 [故障排查](../90-troubleshooting.md)）。完整的账号配额见 [账号存储、容量与配额](storage-quota.md)。
:::

### 每一行的状态

每一行有独立的开关（`enabled`）、输入、提示词和结果节点，状态互不影响：

| 状态 | 含义 | 能重试吗 |
|---|---|---|
| **待生成** | 还没开始 | — |
| **等待中 / 排队 / 生成中** | 已提交，在跑 | — |
| **生成完成** | 结果节点已出图 | — |
| **生成失败** | 失败；标签上会直接显示**失败原因** | ✅ **可以** |
| **已停止** | 被取消 | ❌ 不行 |
| **已停用** | **这一行的开关被你关掉了**——不是出错 | — |

::: warning 「已停用」不是失败
它只表示该行的启用开关是关的。重新打开开关即可，**不会**重新扣费；只有你再点生成才会提交。
:::

**整批**的层面还有「部分失败」这一档——一批里几行成功几行失败是正常状态，不会因为一行失败就整批作废。**成功的那些行照样出结果节点。**

## 任务状态

进行中的节点显示徽章、spinner、阶段文案与**已耗时**；右上角任务浮层列出当前活跃任务（最多 5 条），2 秒/10 秒自适应轮询，窗口聚焦即时刷新。

> 任务详情实时刷新（v1.6.14 起）：打开任务详情后，**进度、日志与开始/完成时间**在任务运行期间持续同步；任务完成后自动停止详情轮询，关闭或切换任务会取消未完成的读取；详情暂时刷不出来时会显示重试提示。

| 状态 | 含义 |
|---|---|
| 排队/运行中 | 任务已提交，等待或生成中 |
| succeeded / failed / cancelled | 终态 |
| 提交不确定（如 524 网关超时） | 结果未知，系统**不会自动重试**——先看该节点的状态徽章确认结果再手动操作，避免重复扣费（没有「任务中心」页面，`/tasks` 已退场） |

## 刷新与恢复

页面刷新后，系统按 taskId 与服务端任务列表**对账恢复**：仍在运行的任务继续跟踪；没有任务身份的孤立「加载中」节点会被标记为本地中断，不会覆盖已完成结果。

## 失败与重试

- 失败时**旧结果不会被清空**；
- 因「输入未变」被审核类规则拒绝的任务不会自动重试；
- 手动重试会重建上下文：从最初生成的节点恢复引用；引用已丢失时会拒绝并提示；重试使用幂等 id，不会重复扣费。

## 失败提示里的三个按钮

生成失败时，提示条上会按情况给出：

| 按钮 | 何时出现 | 作用 |
|---|---|---|
| 查看详情 / **查看原任务** | 状态不确定（如 524）时显示「查看原任务」 | 打开任务详情，看真实进度与日志 |
| **复制排查信息** | 有可复制的诊断内容时 | 复制结构化排查文本（原因/下一步/类别/上游代码/任务 ID/请求 ID/模型/时间），报障时整段贴出即可 |
| 重试 | 该失败允许重试时 | 走上面的重试流程 |

「复制排查信息」自 **v1.6.15** 起升级到版本 2：新增**请求 ID** 与**上游代码**，并保留错误来源与请求证据（上游 HTTP 响应 / 上游业务响应 / HTTP 错误 / 传输或读取失败），所有文本经脱敏。同一时期，**丢失提交回执会被记为「未确认」而不是静默重发**，所以不会再出现系统替你重复提交的情况。

视频任务还有一条专用的「取回结果」恢复路径，见 [发起视频生成与素材限制](generate-video.md)。
