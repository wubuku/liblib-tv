# 本地伴随进程（深度/线稿/姿态）

> 适用角色：需要本地 AI 推理的进阶用户 ｜ 自托管运营者。

> **当前状态（v1.6.16 源码核查）**：本页的「智能剪辑（媒体转换）」路径**当前不可用**——该节点类型在 `canvas-feature-availability.ts` 的 `developingNodeTypes` 集合里，添加节点菜单中显示为「**正在开发**」且**无法创建**。所以下面「媒体转换」一节写的是机制，不是你现在能点到的操作。**可用的本地推理入口是「深度动作捕捉」**，见下文。

## 目标

理解 BeefTV 的本地推理体系，知道哪些能力现在能用、哪些还没开放，以及自托管时后端要准备什么。

## 什么是 framefield-local-runtime

一个运行在你自己电脑上的独立进程（`http://127.0.0.1:17371`），为媒体转换节点提供本地推理：Depth Anything V2 Small 深度图、ControlNet Aux 线稿与 OpenPose 姿态估计。**这些操作不加载 Stable Diffusion 重绘管线，也不经云端**。

它的二进制**不在 BeefTV 仓库里**（属独立发行包），所以本手册无法在本机起服验证——这是本页未能走查的根本原因。

## 安全机制（系统自动执行）

- 只接受**精确回环地址** `http://127.0.0.1:17371`——配置其他地址会直接报错；
- 会话经**挑战-签名**交换建立（浏览器生成密钥对，向进程注册公钥）；挑战过期自动重建；
- 所有请求不带凭据、禁止重定向、禁用缓存；
- 响应体有大小上限（普通 64KB、深度 32MB），超限即失败。

## 现在能用：深度动作捕捉

视频节点的节点工具条里有「**深度动作捕捉**」工具（分区「视频处理」）：**本地生成深度参考视频**，无需云端。

- 仅对**视频节点**可见（且非简洁模式）；
- 说明文案明确提示：**首次需下载组件，CPU 处理可能较慢**；
- 正在修剪视频时该按钮禁用。

![视频节点工具条「视频处理」分区中的深度动作捕捉入口](../screenshots/24-video-process-menu.png)

## Windows 深度视频运行时（v1.6.12/13 新增）

桌面端在 Windows x64 上可**免手动装进程**：首次使用深度处理时自动下载官方签名的可选组件（可续传、校验，取消即停）——

- 固定 Small 模型；**CPU 推理已测试可用**（2 秒与 15 秒片段实测），但可能较慢且占用内存；
- NVIDIA CUDA 为**社区测试预览**：安装前用真实模型探针校验，设备故障自动回退 CPU 一次；
- 进程树级取消：取消任务会终止整棵处理进程；
- Apple Silicon Mac 的本地处理方式不变。

> 代理环境（v1.6.13 后新增）：组件下载与桌面更新共用同一代理选择规则——显式环境代理优先，否则读取 Windows/macOS 当前用户的**系统代理**（含排除地址规则）；修改系统代理后直接重试即可读到新配置，无需在 BeefTV 里重复填写。

Web 自托管模式仍走本机伴随进程 / 服务端 `depthruntime` 域，行为不变。

## 媒体转换（机制说明，当前未开放）

计划中的完整流程是这样，但如上所述，入口节点当前创建不了：

1. 启动本地伴随进程；
2. 画布中创建「智能剪辑（媒体转换）」节点并连接图片/视频；
3. 选择转换类型（灰度 / Canny / AI 线稿 / 深度 / 姿态）执行；
4. 结果保存回当前节点的本地素材存储。

视频输入会先提取首帧再处理；姿态未检测到人物时会跳过并提示。

节点开放后本页会补上真实界面取证。

## 自托管部署注意（v1.6.x 起）

后端新增 `depthruntime` 域：深度素材的服务端拉取与哈希校验由后端完成——自托管运营者在部署后端时需一并确认该域的**网络出口与存储配置**。

## 现在能做什么

本地推理整体受限，但这些**都已在 v1.6.14 上走查过**：

| 你想做的事 | 用这个（已验证） |
|---|---|
| 本地/离线一点的处理 | 视频节点的「**深度动作捕捉**」——本地生成深度参考视频 |
| 提取视频素材 | 「**关键帧截取**」（当前帧 / 首帧 / 尾帧）、「**音视频分离**」，见 [发起视频生成与素材限制](generate-video.md) |
| 修剪视频 | 视频节点的「**视频剪辑**」内联时间轴 |
| 配乐 | 上传音频后进入时间线剪辑，见 [时间线剪辑器](timeline-editing.md) |
