# 管理画布项目

- **适用角色**：所有 TDCanvas 用户。
- **目标**：在首页管理画布项目——打开、重命名、导出、删除。
- **前置条件**：已创建至少一个画布项目。
- **入口**：顶栏「主页」或导航「我的画布」。

## 项目列表与打开

首页「最近画布」按**最近修改时间**倒序排列，每张卡片显示：

- 封面预览（取项目中最新生成的素材）；
- 项目标题与序号徽标；
- 节点数与连线数、更新时间。

点击卡片进入画布；右上角实时预览窗展示当前最新项目。

![首页项目卡与悬停操作](../screenshots/13-project-card-hover-actions.png)

![首页全景：项目卡 TDCanvas 1 与 1 个节点 0 条连线](../screenshots/13-project-management-home-with-card.png)

**按最近修改排序**意味着：今天改过的项目一定在最上面，不用在一堆卡片里找。如果你习惯同时开好几个项目，回到首页扫一眼顶部的几张卡片，通常就是刚在做的那些。

卡片上的「N 个节点 · M 条连线」是判断项目状态的最快信息：连线数远大于节点数，说明这是一个引用关系复杂的项目，**打开时加载可能稍慢**。

## 重命名

两种方式：

- **画布内**：双击顶栏项目标题，输入新名称后 `Enter`。
- **首页**：鼠标悬停项目卡，点击铅笔（重命名）按钮。

项目标题最长 64 字符。建议起名时带上用途或日期（例如「角色设定-1001」），项目多了以后光看标题就能分辨。

## 删除项目

- 悬停项目卡点击垃圾桶图标，或首页「删除全部」批量删除。
- 删除有**确认弹窗**，确认后项目及其内容不可恢复（素材文件由系统统一回收）。

![首页删除画布的确认弹窗：标题「删除画布？」，正文说明节点和连线会一起移除，底部是取消与删除](../screenshots/13-project-management-delete-confirm.png)

> 删除**没有回收站也没有撤销**——这是画布里最不可逆的操作。养成两个习惯：动手删之前先看一眼卡片标题确认没删错；重要项目先导出 zip 再删（见下节，注意 zip 只能保住素材、救不回画布）。

### ⚠️ 删画布有两条路径，行为不一致

同一个「删除画布」，从两个地方进，结果完全不同（2026-10-01 实测 + 源码核对）：

| 路径 | 有确认弹窗吗 | 后果 |
|---|---|---|
| **首页项目卡**垃圾桶图标 / 「删除全部」 | ✅ 有：「删除画布？」+「将删除 N 个画布，里面的节点和连线也会一起移除。」+ 取消 / 删除 | 点「删除」才真正删 |
| **画布内**顶栏汉堡菜单 →「删除当前画布」 | ❌ **没有**，一点即删 | 画布立即消失并跳回首页 |

源码上这是两条独立实现：首页走 `canvas-project-card.tsx` → `setDeleteIds` → `CanvasDeleteProjectsDialog` 确认弹窗；画布内走 `project.tsx:1264` 的 `deleteCurrentProject`，**直接** `deleteProjects()` + `navigate("/canvas")`，中间没有任何确认环节。

> **给用户的实际操作建议**：要删画布，**一律回首页从项目卡删**。画布内那个红色菜单项没有确认框，误触的代价是整个项目瞬间消失，而自动保存和撤销都救不回来——**撤销历史只存在于画布内，画布本身被删掉后就无处可撤了**。养成「删除只在首页做」的习惯，能避开这个版本里最贵的一个坑。

## 导出项目

- 首页勾选项目卡左上角复选框（可多选）→ 使用批量导出。
- 项目卡悬停时也可以单独导出这一个项目。
- 画布内选中若干节点后，工具栏「导出选中」把节点连同素材单独打一个 zip。
- 导出为 zip 包，里面是 `projects.json`（version 3）+ `projects/<项目id>/files/` 下的素材文件。

> **⚠️ 这个 zip 导得出、导不回。TDCanvas 目前没有「导入画布」功能。** 把导出的 zip 拷到另一台机器，TDCanvas 里**没有任何入口**能把它读回去。下面三条证据来自 2026-10-01 的实测与源码核对：
>
> 1. **文案写了，实现没有**：i18n 的 `canvas` 命名空间下有 `canvas.import`「导入画布」、`canvas.imported`「已导入 {{count}} 个画布」、`canvas.importFailed`「导入失败，请选择有效的画布压缩包」三条文案，但全仓 `.tsx` 对这三条键的引用数**都是 0**（源码 grep）。
> 2. **运行时确实没有入口**：实测首页「我的画布」页面里 `input[type=file]` 元素数量为 **0**，整页可见文本不含「导入」二字。
> 3. **换个入口变通也不行**：把画布 zip 丢给「我的资产 → 导入资产」同样失败——`readAssetPackage` 硬要求包内存在 `assets.json`，而画布包里是 `projects.json`，实测弹出「导入失败，请选择有效的资产压缩包」。
>
> **所以请把这句记牢：导出 zip 能保住素材文件，救不回画布结构。**

### 能带走的和带不走的

| 内容 | 换台电脑能带走吗 | 怎么做 |
|---|---|---|
| 画布结构（节点、连线、视口、外观） | ❌ **不能** | 没有导入功能，只能在新机器上重搭；同一台机器内可用「复制所有节点」+「粘贴」快速复刻 |
| 素材文件（上传的图片、视频、音频） | ✅ 能 | 画布 zip 里的 `projects/<id>/files/` 可以手动解压取回；更省事的是走下面的资产导出 |
| 「我的资产」里的提示词与参考图 | ✅ 能 | 「我的资产」工具栏「导出资产」/「导入资产」是一对完整闭环，见 [manage-assets.md](manage-assets.md) |

![我的资产页：工具栏上「导出资产」与「导入资产」成对出现（图中高亮「导入资产」）——资产是可以整体搬走的，画布没有这一对](../screenshots/14-manage-assets-import.png)

> **为什么同一套代码里，资产能往返、画布只能单向？** 两种 zip 的"回读"代码是一对：`exportAssets` 写出 `assets.json`，`readAssetPackage` 读回 `assets.json`；而画布侧只实现了写出的 `exportCanvasProjects`，**读回来的那半截从未被写**。这不是"功能藏得深"，是读回的那一半确实不存在——所以导出的画布 zip 对 TDCanvas 而言是一个**只写不读的死文件**。
>
> **给换机用户的实话**：换电脑、重装系统前，先去「我的资产」把资产导出来（新机器上导入），画布 zip 也存一份——它至少能让你在解压后把图片、视频捞回来重新上传。**但节点和连线必须重搭**，请按"这个项目要重新做一遍"来安排时间。

## 画布项目和「我的资产」是两回事

两者都是本机存储，但用途不同：

| | 画布项目 | 我的资产 |
|---|---|---|
| 存什么 | 节点、连线、视口、外观 | 提示词文本、参考图片 |
| 入口 | 首页「我的画布」 | 顶部导航「我的资产」 |
| 导出 | 首页勾选后批量导出 | 工具栏「导出资产」 |
| 导入 | ❌ **没有导入功能** | ✅ 工具栏「导入资产」 |
| 换机能带走 | 只能取回素材文件，结构要重搭 | ✅ 整个资产库 |
| 详见 | 本页 | [manage-assets.md](manage-assets.md) |

删除画布项目**不会**删除「我的资产」里的内容，反之亦然——两套数据互不影响。
