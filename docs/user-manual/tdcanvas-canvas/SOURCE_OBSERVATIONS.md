## 3. 画布视口与手势（与常见画布不同的语义）

- wheel 永远缩放（5%–500%，鼠标锚）；缩放滑杆 5–500%（视口中心锚）。[运行时+静态]
- 空白左键拖拽 = 平移；**Space+拖拽被禁用**（只 preventDefault）。[运行时+静态]
- Ctrl/Cmd+拖空白 = 框选（Shift 加选）。[静态；运行时部分]
- 重置视图：fit 动画，缩放 clamp ≤100%（运行时实测 100%→77%）。[运行时+静态]
- 小地图（纯 div，240×160，点击/拖拽导航）开关在缩放 Dock。[静态]
- **网格线绘制会随缩小而「变粗」**：可见网格的世界尺寸是 `let worldGridSize = 16; while (worldGridSize * viewport.k < 8) worldGridSize *= 2`（`td-canvas-surface.tsx:267-269`）——屏幕间距恒 ≥ 8px，世界尺寸在 k<0.5 时跳到 32、k<0.25 时跳到 64。实测 k=1.000/0.796/0.633/0.503 世界尺寸均为 16，k=0.401 为 32，过渡点恰在 k=0.5；密度档 `far`/`standard`/`near` 由 `data-grid-density` 暴露。[运行时+静态]
- **吸附步长与可见网格线不是同一个量**：吸附固定用 `CANVAS_GRID_STEP = 16`（`project.tsx:149`，`canvas-alignment-guides.ts:31-32` 取整），**不随缩放改变**。因此 k<0.5 时二者脱钩——实测 k=1.000/0.796/0.633/0.503 四档共 **27/27 次落点精确落在线上（偏移 0.00）**，k=0.401（世界网格 32）**7 次里 3 次正好偏半格**（6.41px / 12.82px 间距 = 精确的二分之一）。[运行时+静态]
- 对齐辅助线阈值是 `thresholdPx = 7` 再除以 `scale` 换算成世界单位（`canvas-alignment-guides.ts:27,34`），**即恒为 7 屏幕像素**，不随缩放漂移——与网格不同，手册对此的措辞是准确的。[静态]
- **滚轮压在节点上不会缩放画布**（被节点自身的文本区消费）。**这会让自动化探针误判「缩放没生效」**——M108 第一版探针把滚轮点定在节点上，六级扫描全程 k=1.000，差点得出「网格不变粗」的结论；换到画布空白处后同一套滚轮立刻生效。[运行时]

### 4.1 组节点（M101–M104 集中取证，此前本账本完全没有这一节）

组的**归属语义**由 `metadata.groupId` 单一字段决定，而 `groupChildCountById`（`project.tsx:656`）对每个节点的 `groupId` **逐个累加**——所以右上角徽标 `{{count}} 个节点`（`canvas.node.nodeCount`）天然是**真计数**而非布尔。[运行时+静态]

| 行为 | 实测结论 | 判据 |
|---|---|---|
| 徽标计数 | 空组 `0` → 拖入 `1` → 再拖入 **`2`** → 拖出 `1` → 拖出 `0` | 第 43 次否证前只有 `0 → 1` 一个数据点，**1 条数据无法区分「计数」与「有无成员」** |
| **入组判据** | 只在**节点拖拽的 mouseup** 里判定，且要求 `dragRef.current.hasMoved`；判据是**中心点**落在组框内 | `findContainingGroupId` **仅被 `project.tsx:1407` 调用**。**新建出来就落在框内的节点不是成员**——对照实验：几何完全相同、只差拖没拖过，`0` vs `1` |
| 拖组联动 | 组位移 `[+200,-90]`，两个成员**逐像素同位移**；组外节点 `[0,0]` | 先断言源位移非零，否则「位移一致」在**全 0 时恒真** |
| 删除 | **删组不删成员**（2 成员全存活、位置不变，撤销后徽标恢复 2）；**删成员不删组** | `project.tsx:855` 只清空存活节点的 `groupId` |
| 嵌套 | **组进不了组**（两处显式排除），但**成员会改投**：两框重叠时中心点同时落在两框内的成员改投到另一组 | 起点 A2/B0 → 拖后 A1/B1，**合计守恒且减的是 A**，据此排除「组被套进去」 |
| 复制粘贴 | 复制的**只是选中的节点**：只选组 → 粘出**徽标 0 的空壳组**；全选 → 新组徽标 `2`、归属保留；只选成员 → 副本**即使落在原组框内也不属于任何组** | `copySelectedNodes`（`project.tsx:1047`）只按 `selectedIds` 过滤；粘贴用 `idMap` 重映射 `groupId`，**组不在剪贴板里则该字段置空** |
| 连线 | **组框不挡端口**；同组成员双向互连均成功（`0→1`、`1→2`）；组内连组外成功；**连线不影响归属** | 成员在组内时两个端口几何上都落在组框内，但 `elementFromPoint` 均命中本节点 |

> **组默认 760×480、文本节点 520×300——两个文本节点塞不进默认大小的组**（并排 1040、竖排 600 都超），必然重叠导致端口互相遮挡。音频 540×160 竖排刚好放得下。**这个坑极易被误记成「组不让连线」。**[运行时+静态]

### 5.1 「我的资产」页计数语义（M100 三条资产下复测）

斜杠读数是 **`当前筛选结果 / 全部资产数`**：**分母恒为全部资产数，不随筛选或搜索变化**；搜索与筛选叠加时分母也不变。六种读数钉死这一条：全部 `3 / 3`、文本 `3 / 3`、图片 `0 / 3`+空态、视频 `0 / 3`+空态、搜索命中 `1 / 3`、搜索无果 `0 / 3`+空态，每页 10 条不变。[运行时]

> **为什么必须用 3 条而不是 1 条**：只有 1 条资产时 `1 / 1` 同时符合好几种解释，**证明不了分母语义**——这正是 M99 那次"陈旧读数"事故的同源问题，只是这次发生在**数据量维度**上。

### 10.1 antd v6 的判据备忘（M81 实测，踩坑三次才攒出来）

本应用锁的是 **antd `^6.4.2`**。**不要照抄旧版 antd 的类名**——以下是实测结论，每一条都曾造成"实测没查到"的假阴性：

| 想找什么 | ❌ 常见写法（此处取不到） | ✅ 本应用实际可用 |
|---|---|---|
| 下拉框触发器 | `.ant-select-selector` | **`.ant-select-content`**（`title` 属性是当前值） |
| 下拉弹层选项 | — | `.ant-select-item-option`（注意用 `ant-select-content` 点开，别用旧类名） |
| 弹窗容器 | — | `.ant-modal` / `.ant-modal-wrap` **仍然有效** |
| 弹窗语义 | — | antd v6 的 Modal **带 `role="dialog"` + `aria-modal="true"` + `aria-labelledby`**，实测打开「新增资产」`roleDialogCount=1` |
| 标签页 | `.ant-tabs-tab` | **实测为 0**——配置页根本没用 antd Tabs；全页那 4 个 `role="tab"` 属**右侧 Agent 面板**（手写 `role="tab"`，非 antd） |

> **因此「某处 `role="dialog"` 数量为 0 ⇒ 这里没有弹窗」这个判据在本应用有效**，手册里"画布内删除画布无确认弹窗"那条 Major 结论正是靠它立住的（见 `90-troubleshooting.md`）。

### 10.2 三个反直觉的 UI 事实（实测，判据已固化）

- **双字中文按钮中间有空格**：`Modal` 的默认按钮渲染为「保 存」「取 消」。写 `/保存/` 或 `getByRole(name:"保存")` **全部匹配不到**。**能用 `button.ant-btn-primary` 就别用中文文本做判据**。
- **中央芯片只在空画布出现**：建完第一个节点即消失，第二个节点必须改走左侧 Dock「+」菜单。脚本里"找不到就跳过"会**静默造出假数据**。
- **节点默认全部叠在画布中心**：按 `.node-element` 索引取中心点逐个点选，**每次命中的都是最上层那一个**。要测某个特定节点，两个可靠办法：① **走左侧面板的节点列表逐行点击**（列表项有独立文本与行坐标，不受遮挡影响）；② **先「清空画布」只留目标节点一个**。这个坑在 M78 与 M80 各栽了一次。


## 11. i18n 文案的三种状态（M85/M86 确立的取证纪律）

**「i18n 里有这个键」≠「界面上有这个词」。** M71 曾把 `canvas.aitudou.status.*` 的八个中文状态名当成「界面原文」写进状态表并据此"订正"过手册，M85 证明这八个词**一个都不在界面上**——它们整组零引用。所以引用 i18n 文案时，**必须先判引用关系，再判字面**：

| 状态 | 判据 | 能不能写进「界面原文」 |
|---|---|---|
| ① 活键 | 存在 `t("该键")` 调用点，且该调用点确实会渲染 | **可以**，但要标注是否已实测 |
| ② 条件渲染 | 有调用点，但只在特定状态出现（如 `canvas.node.generating` 只在跑任务时） | **可以，但必须写明触发条件**，并说明未实测 |
| ③ 死文案 | **全仓零引用** | **绝对不可以** |

**一条命令的判据**（排除 locales 自身与测试）：

```
grep -rn "<键名片段>" web/src --include="*.tsx" --include="*.ts" \
  | grep -v "i18n/locales" | grep -v "\.test\." | grep "t("
```

### 11.1 全量普查结果（2026-10-01，zh-CN.ts 1814 个叶子键）

| 状态 | 数量 |
|---|---|
| 静态引用 `t("…")` 命中 | **1184** |
| 仅动态前缀 `t(\`a.b.${x}\`)` 可能覆盖 | 343（动态前缀 57 条） |
| **零引用（死文案候选）** | **287** |

死文案按命名空间：`agent` 101 / `canvas` 68 / `config` 68 / `workbench` 27 / `comfyuiLocal` 20 / 其余 3。

### 11.2 写普查脚本时踩的三个判据坑（都是"探针没打中"）

- **单行内联对象**：`status: { idle: "待配置", queued: "已排队", … },` 这种写法，若按"以 `{` 开头就是多行块"处理，**整棵子树一个键都进不了清单**。第一版就是这么漏的——**连 M85 刚查出的那八个死键，在普查脚本里都"不存在"**。修法：判断内联对象前**先 `rstrip(",")`**，行尾那个逗号会让 `endswith("}")` 判否。
- **动态前缀的尾点**：`t(\`agent.composer.effort.${effort}\`)` 抽出的前缀**自带尾点**。若按"前缀后必须紧跟 `.`"做边界判断，**永远不成立**，动态引用数恒为 0，于是 467 个 `agent` 键被误判成死文案。修法：抽出来就 `rstrip(".")`。
- **三元表达式里的键（影响面最大的一处）**：`t(!connected ? "agent.skillManager.connectToView" : skills.length ? "…noMatch" : "…none")`——**参数不是字符串字面量，是条件表达式**。只匹配 `t("字面量")` 的判据会把它整条漏掉，`agent.skillManager.connectToView` 因此被判成死文案，**而它在 `agent-skills-view.tsx:352` 明明被引用**。修法：从 `t(` 起做**括号配平扫描**，把该调用范围内的**所有字符串字面量**收进来。**这一处若不发现，后果比 M85 更严重**——M85 是"把死的写成活的"，这一处会让人**把一条真实存在的界面文案当成死文案删掉**。

**教训**：判据写完必须**带自检探针**跑一遍——本脚本开头就断言"八个 M85 死键必须出现在清单里"，第一次跑直接打出 `0/8`，当场暴露了第一个坑。**但自检只能覆盖你写进去的那一条**，第三个坑是**换一个用法**（拿它去查 `use-agent.md`）才暴露的。**没有自检的普查脚本，"跑完了"和"查对了"是两件事；而自检探针本身也需要"换个用法再验一次"。**

### 11.3 这条路走不通的方向（别重复）

**"死文案的中文值出现在手册里"不能当门禁。** 把 407 条死键的中文值拿去撞手册正文，命中 102 条——但绝大多数是**假阳性**：「参数」「提示词」「模型」「上传」「删除」「查看」这类常用词本来就在手册里大量出现，且**往往有活键同名**。命中率看着高、可用信息为零。

**可行的做法是把范围收窄到"手册显式声称取自某个 i18n 键"的地方**——按这个口径复查，手册里的 i18n 引用**只有一条是正向断言**（就是 M71 那条，已订正），其余全是**否定式断言**（"这几条文案零引用"），逐条验下来**全部成立**。

## 12. 「源文件正常、产物坏了」缺陷家族（M84 / M90 / M91 / M92）

**这一族已经出现四次，每次都是同一个形态**：markdown 源文件读起来完全正常——
`**` 成对、表格列数对、锚点写法像样——**但渲染之后内容变了或没了**。而当时的
**全部源码层门禁都报 ok**。所以本手册把"打开产物看一眼"变成了**常设门禁**
（`check-render.py`），并把下面这张表当作排查新写法时的检查清单。

| # | 触发写法 | 产物里变成 | 只能在哪判 | 门禁 |
|---|---|---|---|---|
| 1 | 表格单元格里写**未转义的竖线**（哪怕在行内代码段里） | 该行被撑成多格，**多出的格连同内容一起消失** | 源码（列数仍对）+ 产物（列数不一致） | `check-tables` + `check-render` |
| 2 | 加粗定界符**紧邻标点**且另一侧是实义字 | 字面量 `**`，加粗失效 | 源码（flanking 规则） | `check-emphasis` |
| 3 | **同页锚点**少写 slugify 生成的连字符 | 链接点不动 | 源码 | `check-anchors` |
| 4 | 正文里裸写 `{{ }}` | **整段消失**（代码段里成空 `<code>`，正文里少一句） | 只能源侧 | `check-emphasis` |
| 5 | 行内代码段里想用「反斜杠 + 反引号」显示反引号 | 代码段**提前截断**，后半截漏成正文 | 只能产物侧 | `check-render` |

### 三条必须记住的结论

- **源码层判据有形态上限**。第 1 条的判据数列数，而故障恰恰是"列数对但内容丢"；
  第 5 条的判据数反引号奇偶，而嵌套反引号**总数是偶数**——**判据形态上就抓不到**。
  这类只能从产物侧判。**"我加了判据"不等于"这类故障被覆盖了"**。
- **行内代码段内部不处理反斜杠转义**。CommonMark 的反斜杠转义只在代码段**外面**
  生效；想在代码段里显示反引号，要用双反引号包裹或另选符号。
  **注意这条同样约束本手册自己**——`SOURCE_OBSERVATIONS` 与 `PROGRESS` 里描述这些
  写法时，只能用文字说明、不能把危险序列原样写进表格单元格里（`check-tables.py`
  会把表格里真实的反引号奇偶算进去）。
- **表格单元格里的写法与正文不同**。单元格两侧总有空格，flanking 的 2b 豁免自动
  成立，所以第 2 条**在表格里永远不会中招**，在散文里才会。写判据时若按"首尾是
  标点就错"来判，会得到 146 条假阳性（M90 第一版的教训）。

### 排查新写法时的顺序

1. 先想"这个写法在源码层能看出问题吗"——看不出就**必须**进产物侧判据；
2. 判据写完**做阳性对照**：造一个只含该故障的最小产物，确认抓得住；
3. 再扫真实产物，**把"扫描器有效"和"产物干净"分成两句话说**——没做过第 2 步的
   "0 命中"不能当"没问题"的证据。
