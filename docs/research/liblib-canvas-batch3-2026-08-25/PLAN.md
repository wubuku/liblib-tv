# LibTV 画布 Batch 3 计划：命令基础

> 建档日期：2026-08-25  
> 决策原则：高频、低认知负担、能覆盖多个节点类型、已有原站证据、适合前端原型验证。

## 1. 缺口盘点

| 候选缺口 | 当前克隆 | 原站/既有证据 | 价值 | 本批决策 |
|---|---|---|---:|---|
| 撤销/重做 | `canvasStore` 没有通用 history | 快捷键面板展示“撤销/重做” | 5 | 实现 |
| 节点复制 | 只有画布级复制；节点没有复制命令 | 快捷键面板展示“复制节点和连线”“节点复制” | 5 | 实现 |
| 节点右键菜单 | LibTV 路由没有上下文菜单 | 这是画布编辑器的高频命令入口；FrameOS 克隆已有可复用交互证据，但不把它写成 LibTV 原站实时事实 | 4 | 实现为原型增强 |
| 空白处右键添加 | 只能从底部添加面板按视口中心添加 | 画布工作流需要把新节点放在指针附近 | 4 | 实现为原型增强 |
| 快捷键闭环 | `Delete`、`Escape`、`V/H`、缩放已实现；撤销/重做、复制、`Tab`、整理未实现 | 原站快捷键面板已抽取 | 5 | 实现 |
| 多选/成组 | React Flow 可选区但 store 只有单一 `selectedNodeId` | 原站面板展示成组/解组，但当前 LibTV 证据与数据契约不足 | 4 | 留待下一批 |
| 对齐辅助线 | 当前没有 | FrameOS 有证据，LibTV 本轮没有足够证据 | 3 | 留待下一批 |
| 节点锁定/隐藏 | 当前没有 | 当前 LibTV 证据不足 | 2 | 不做 |

## 2. 本批目标

### P0：必须完成

1. 每个画布独立维护最多 50 步节点/连线 history；
2. `Cmd/Ctrl+Z` 撤销、`Cmd/Ctrl+Shift+Z` 和 `Cmd/Ctrl+Y` 重做；
3. `Cmd/Ctrl+D` 复制选中节点及其关联连线；
4. `Tab` 打开添加节点面板；
5. `Option/Alt+Shift+F` 触发整理；
6. 快捷键面板只展示当前真实可用的命令；
7. 节点右键菜单提供复制、创建副本、删除；
8. 空白处右键菜单提供添加文本/图片/视频和适应画布。

### P1：在同一批闭环

1. 右键添加节点使用指针对应的画布坐标，而不是固定放到视口中心；
2. 节点复制偏移 `40x40`，新节点自动选中；
3. “复制节点和连线”复制被复制节点的入边和出边，并把端点映射到副本；
4. 文本节点编辑结束时写回 store，使其可被撤销；
5. 整理、拖动、派生节点、删除边等已有命令进入同一 history 模型。

## 3. 明确不做

- 不做真实系统剪贴板格式和跨浏览器粘贴；
- 不做多选成组/解组，因为当前 LibTV store 仍以单选为主；
- 不把图片/视频面板内部的“撤销”按钮误接到画布 history；这些按钮属于局部工具状态，后续单独定义；
- 不把浏览器刷新后的 history 伪装成持久化数据；
- 不声称右键菜单是本轮新实测到的 LibTV 原站行为；它是基于画布命令价值和已有 FrameOS 交互证据的克隆原型增强。

## 4. 验收标准

### Store

- 新增、删除、复制节点；
- 新增、删除连线；
- 节点拖动结束；
- 文本/节点数据更新；
- 整理画布；

以上操作都可以撤销，撤销后可以重做；新命令会清空 redo 栈。

### UI

- 右键节点和空白处菜单不超出当前视口；
- 右键添加的节点出现在菜单指针附近；
- 复制后副本可见、被选中，原节点仍保留；
- 快捷键面板文案与行为一致；
- `390px` 宽视口中菜单文本、按钮和快捷键不横向溢出。

### 验证

- `npm run check`；
- Playwright 本地桌面与 `390px` 截图；
- 浏览器控制台无新增运行时错误；
- `/frameos/canvas/demo` 不因 LibTV store 改造而回归。

## 5. 后续候选批次

1. 多选、框选、成组/解组；
2. 节点对齐和吸附辅助线；
3. 画布视口历史、最近操作提示和命令 toast；
4. 真实的系统复制/粘贴协议；
5. 节点锁定、隐藏和批量删除。
