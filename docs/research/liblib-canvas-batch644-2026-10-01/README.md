# batch 644 —— 643 那 14 枚有闭式，而且**闭式被我的前两版各推翻一次**

日期 2026-10-01 · 验收器 `scripts/verify-liblib-batch644.py` · **11 checks / 0 failures**

## 一句话

643 给出的是一张**表**（14 枚、五个邻居表面、每宽度一个读数），
本批把它收成一条**律**，并在 16 个宽度（**含窄族与桌面族两族**）上逐格验证：

> **联合 ⟺ `cx > 它自己最内层裁剪祖先的右沿` ∧ `0 ≤ cx ≤ W` ∧ `0 ≤ cy ≤ H`**

**16 格里观察集合与预测集合逐格相同，分歧 0。**

---

## 1. 闭式的三段各对应一件独立的事

| 条件 | 对应什么 | 少了它会怎样 |
|---|---|---|
| `cx > 自己那层的右沿` | 它**被自己的滚动盒裁掉**了 —— 这正是 `clipped` | 把「点得到」也算成联合 |
| `0 ≤ cx ≤ W` | 它**横向还在窗口里** | 把出屏控件算成被盖 |
| `0 ≤ cy ≤ H` | 它**纵向还在窗口里** | 同样：`跳过` 在 339 的 `cy = 1464` |

后两段合起来就是 643 那 363 枚虚胖的教训，写进闭式是为了不让它再犯 ——
**出屏时中心探针被跳过、`hit` 是 `null`，没有任何东西压住它。**

## 2. 「自己那一层」是关键，不是随便哪一行

第一版闭式写成「`cx > 底部条行右沿 = W − 293`」，**红**了，红得对。
底部条那一层外面还套着**视口工具条自己**（桌面族里右沿恒为 **1004**）和
**时间轴控件行**；哪一层先裁到它，取决于 `cx` 落在哪 ——
**问「哪一行的右沿」是错的，该问「它自己被哪一层裁到」。**

于是验收器给普查标记的每一枚控件单独量它**自己最内层裁剪祖先的右沿**，
闭式拿这个量来比。逐格零分歧。

## 3. 那 12px 缝

属性列左沿恒为 `W − 281`，底部条那一层的右沿恒比它**再左 12**：

```
bandRowRight  = W − 293      （桌面族）        10 个宽度全部读出 12
inspectorLeft = bandRowRight + 12
```

于是同一个 `cx` 随宽度穿过三段：

| 区间 | 邻居 |
|---|---|
| `cx ≤ bandRowRight` | 不是联合（在行里露着） |
| `bandRowRight < cx ≤ inspectorLeft` | 联合，邻居是 **3D 画布**（行已放弃该像素，列还没到） |
| `cx > inspectorLeft` | 联合，邻居是 **属性列** |

## 4. 列的规则要**两个**条件，不是一个

第二版闭式只判 `cx > inspectorLeft`，**又红**了。
时间轴那两枚（`添加关键帧` cx 703 / `删除关键帧` cx 761）在 899 时
`cx` 早已越过列左沿 618，可列底沿是 **718** 而它们的 `cy = 736.5` ——
**在列底之下 18.5px，列根本够不着它们**，实际邻居是时间轴自己的缩放簇与最小化按钮。

> **列覆盖一个点 ⟺ 该点在列的右沿之外 ∧ 在列的上沿之内。**

实测 **21 例**满足两条件、**2 例**满足其一（正是那两枚），**矛盾 0**。

## 5. 分族：底部条那一层的右沿偏移**两个值**

第一版的线性检查把两族池在一起，也**红**了：

```
窄族    bandRowRight = W − 12      （339/480/620/780/898 五点全中）
桌面族  bandRowRight = W − 293     （11 点全中）
```

**两者相差 281 —— 正好是属性列的宽度。** 这是 636–639 那条
「凡与横向行有关的一切都是分族的」的翻版：那条讲时间轴高度，这条讲横向行右沿。

## 6. 余量轨迹：律在量什么

`past = cx − 自己那层的右沿`，律说它在联合宽度上恒为正：

```
发送               1280:229  1366:143  1440:69  1470:39  1500:9
模型库             899:268   1024:143   1152:15
虚拟相机           899:188   1024:63
添加群众阵列        899:228   1024:103
开启九宫格辅助线      899:135   1024:10
```

* `发送` 的 `cx = 1216` 在桌面族里**恒定**，故 `past = 1509 − W` ——
  **它的边界是 `W = 1509`**，实测 1500 时 `past = 9`、1518 时已非联合。
* **所有读数里最小的余量是 9**（`发送`@1500 与 `上传图片`@339/480/620 各为 9）。
  网格从未逼近到能分辨边界，所以本批**只把边界当夹逼报告、不当测量断言**。
* `上传图片` 的 `cx` **会移动**（336 → 477 → 617 → 1037）：
  提示条用 `mx-auto`，内容宽于行时外边距塌成 0、窄于行时居中。
  **所以「某控件在某个宽度以下是联合的」不是一条能靠单个 `cx` 推出来的律** ——
  我第一版那张表正是冻结了一个 `cx` 再加固定偏移，**是错的**，已换成逐格轨迹。

## 7. 我自己写错的四处

1. **闭式套错了行** —— 用固定的底部条行右沿去套所有控件，
   而每枚控件被裁的是它自己那一层。
2. **闭式少了纵向那一半** —— `跳过` 在 339 的 `cy = 1464`，横向不越界却纵向出屏。
3. **列的规则少了一个条件** —— `cx > 列左沿` 不够，还要 `cy < 列底沿`；
   时间轴那两枚就是被这条逼出来的（越过了左沿，落在底沿之下 18.5px）。
4. **线性检查把两族池在一起** —— 偏移是 `W−12` 与 `W−293` 两个值，不是常量。

另有一处是**工具**的错、我读成了数据：验收器里
`new Set(wanted)` 建的是**对象集合**而不是 key 字符串集合，
于是 89 枚控件的 `clipper` 一个都没查到、`预测集` 全空，
而「观察集 ≠ 空集」照样把检查判成红。**红对了，但红的原因是我查表失败** ——
修法是先加一条「每一枚都被测到了吗」的独立检查，再看主检查。

## 8. 本批**不**主张的事

- **不主张**「邻居是谁」有闭式。闭式只说**什么时候**被盖；
  被谁盖取决于版式（643 记录五种表面），逐枚记录、不预测。
- **不主张**每枚控件有精确边界。网格粗（最大步长约 130px），
  最小余量 9px，边界**只能夹逼**；只有 `cx` 在族内恒定的控件（如 `发送`）才能解出闭式边界。
- **不主张**这 14 枚是缺陷 —— 沿用 643：它们真能滚回来（14/14）。
- **零源站断言**：全部读数都是 clone 的。
