# batch 789 — 「`sIP` 主人 + `sIP` 主人」共活：**从没测过的那一格**

## 承重预测，以及它是怎么被否掉的

前三批各测了 Escape **主人叠加**的一个格子，唯独这个格子空着：

| 批 | 组合 | 测到 |
| --- | --- | --- |
| 783 批 | bubble + bubble | 两个都关（并发） |
| 784 批 | `sIP` + bubble | 一次 Escape **只关 `sIP` 那个** ⟹ 要按第二次（D1i） |
| 785 批 | （复用 782 raw）`sIP` + `sIP`，**纯鼠标** | 同上，纯鼠标路径 |
| ★ 789 批 | ★★ `sIP` + `sIP`，**键盘** | ★ 从来没测过 |

两个主人都长这样（`src/components/director/DirectorViewport.tsx`）：

| 主人 | 门（effect 第一条语句） | `sIP` | 注册 |
| --- | --- | --- | --- |
| 运镜草稿 | `:2698` `if (!timeline.motionPathDraft) return;` | `:2702` | `:2711` `window.addEventListener("keydown", handleKeyDown, **true**)` |
| 模型库 | `:2734` `if (!modelLibraryOpen) return;` | `:2744` | `:2748` `window.addEventListener("keydown", closeOnEscape, **true**)` |

★ 两个都是 **window 捕获相位 + `sIP`** ⟹ 同一 target 同一相位下浏览器按
**注册顺序**依次调用 ⟹ **先注册的那个 `sIP` 会把后注册的整个截断**。

### 我写进探针的预测（可 falsify）

★ 两个 effect 都是「**状态非空才注册**」⟹ 我据此推出：

> **谁后被打开，谁的监听器就后注册、谁就赢。**

所以 `draftThenLib`（先造草稿、再开模型库）的预测是：第 1 次按 Escape
关掉的是**模型库**、草稿留着。

### ★ 实测把方向否掉了

| 臂 | 第 1 次按 Escape 实际关掉谁 | 与预测 |
| --- | --- | --- |
| ★★ `draftThenLib` | **草稿**（`draft=false, lib=true`） | ★ **被否** |

⟹ 实测是**先打开的赢**，不是后打开的赢。我把方向想反了。

## ★★ 但本批**分不开**「打开顺序」和「源码顺序」——这是必须写下来的限制

把观测到的规律说成「先打开的赢」是**超出了证据**。原因：

- 唯一**可达**的共活臂 `draftThenLib` 里，草稿既**先打开**、effect 又
  **写在前面**（`:2697` 早于 `:2733`）
- ⟹ 「注册顺序 = 打开顺序」和「源码顺序决定谁赢」**给出同一个预测**
- ⟹ 本批**不能**区分

⭐ 所以报告只准说「**先注册的赢**」。「注册顺序 = 打开顺序」这句话的支撑
**不来自**本臂的胜负，而来自**机制**（S2：两个 effect 体第一条语句都是
「状态为空就 return」⟹ 监听器只在状态变成非空那一刻注册）。这个区别被
写成了验收器里的 `S3`，作为**混淆项**钉在产物里。

**能分开这两个解释的实验**：造出「库先开、草稿后开」且**不触发**外点关闭
的路径（纯键盘造草稿，或让草稿由非 pointer 事件创建）。本批做不到，
因为下一节。

## ★ P789-2 成立：`libThenDraft` **结构上不可达**

预测：先开模型库、再造草稿 —— 造草稿必须点时间轴上的
`[data-director-track-draw-trail]` / `[data-director-motion-path-draw-tool="pencil"]`，
那是**鼠标点击** ⟹ 产生 `pointerdown` ⟹ 模型库的
`document.addEventListener("pointerdown", closeOnOutsidePointerDown)`（`:2747`）
**先把模型库关掉**。

两轮都撞上这个结构。★ 而且 raw 里有一处比「不可达」更强的证据：

| 阶段 | `lib` | `draft` |
| --- | --- | --- |
| 造草稿**之前** | `true` | `false` |
| 造草稿**之后** | `false` | ★ `true` |

⟹ **草稿造出来了**，是模型库被**顺手续掉**的。**不是**「造草稿失败」。
所以这件事的形态和 C787-2（788 测的那个「加条目顺手续掉草稿」）是
**同一个家族的另一半**：那边是操作顺手续掉**后来者**，这边是 pointer
事件顺手续掉**先来者**。

★ 这正是 **C785-2**（「4 个外点关闭**全是 pointer 类** ⟹ 键盘一律绕过」）
的直接推论。

## ★★ 本批真正的 UX 结论：要按的次数

★ 「全清」指什么会改变数字，所以**两个端点分开记**：

| 臂 | 面板全清（草稿与库都不再开着） | 桌关掉（阶梯最后一档） | 逐次读数 |
| --- | --- | --- | --- |
| `draftOnly` | 第 1 次 | 第 **3** 次 | P1 草稿关/导出面板在 → P2 导出面板关 → P3 **桌关** |
| `libOnly` | 第 1 次 | 第 **3** 次 | P1 模型库关/导出面板在 → P2 导出面板关 → P3 **桌关** |
| ★★ `draftThenLib` | ★★ 第 **2** 次 | ★★ **3 次里没发生** | P1 **草稿关、模型库仍在** → P2 模型库关 → P3 导出面板关、**桌还在** |

⟹ **两个 `sIP` 主人共活 ⟹ 多按一次**。784 已证明「一个 `sIP` + 一个 bubble
共活」要多按一次 ⟹ 本批是**同一条成本线的延伸**，而且是这条线上的
**第二个格子**（784 测的是 sIP+bubble，本批是 sIP+sIP）。

★ **诚实标注**：本批只按了 **3 次**，所以共活臂那一格写的是「3 次里没发生」
而**不是**「要按 4 次」—— 第 4 次是**外推**，不是测出来的。要断言得再跑
一格 4 次按压。

## 读数

| 读什么 | 怎么读 |
| --- | --- |
| 草稿活着？ | `[data-director-viewport-gizmo-disabled]`（788 已验证它就是 `motionPathDraft !== null`） |
| 模型库开着？ | `[data-director-model-library-trigger]` 的 `aria-expanded` |
| 阶梯跑到没有？ | `[data-director-export-panel]` 在不在（梯次第 2 档就是关它） |
| ★ 桌还在？ | `[role="dialog"][aria-modal="true"]` 存在与否 |

★ 最后一行是本批**加**上去的。第一版把「桌还在」从「草稿与库两个读数都变
`null`」**推断**出来 —— 那是**推断**，任何一个读数因为别的原因消失就会误判。
`aria-modal="true"` 在整个 `src/components/director/` 里**只有**
`DirectorDesk.tsx:902` 一处（验收器 `S10` 会数），其余 `role="dialog"`
（导出面板等）**没有** `aria-modal` ⟹ 不会被冒充。
