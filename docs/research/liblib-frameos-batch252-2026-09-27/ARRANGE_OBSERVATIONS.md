## 事实 (source fact)

### 宫格排列 (4 成员)
- 2×2 网格: 列 x = {originX, originX+340}, 行 y = {originY, originY+340}
  (origin = 分组盒左上 + 28; 间距 40; 行距按行内最高成员 300+40)。
- 成员排序 = 按原 Y 升序 (并列按 X), 行优先填充 → 与克隆 arrangeGroup 实现完全一致
  (此前标注的"克隆决策"升级为源站确认)。
- 分组盒重算 = 2×300+40+56 = 696 见方 ✓ (bbox+28 规则再次确认)。

### 垂直排列 (4 成员)
- **按原 Y 升序排序** (与水平相同), 单列, y 间距 = 前成员高+40。
- **推翻克隆推断**: 此前垂直按 X 排序是错的, 已修正 frameosStore.arrangeGroup。
- 盒宽 = 最高成员宽+56 (356); 盒高实测 1276 比理论 1176 多 100 — 与下述同步 bug
  同期出现, 疑为服务端用陈旧高度计算, 不作为布局规则 (克隆保持 bbox+28)。

### 添加参考素材 (素材库选择弹层)
- 勾选卡片 → 添加参考素材 → **在画布新建内容节点** (图片→内容图, 音频→内容音频,
  标题=资产名), 节点出现在视口中部附近。Batch 224 的克隆实现方向正确。
- 弹层是 iframe 嵌入 (DOM 不可达), 全程需真实坐标点击; 左侧目录树可进入
  测试项目/画布素材 目录 (本次上传的资产都在「画布素材」)。

## 事件: 源站同步 bug 丢节点 (已修复)
连续两次排列操作 (宫格→垂直, 间隔 <10s) 后, 4 成员中 2 个 (一张内容图 + 视频剪辑台)
从 DOM 消失且**刷新后服务端也不再返回** (撤销按钮 disabled 无法找回)。修复过程:
1. 视频剪辑台: 左栏 + 菜单 → 视频剪辑台 (新建空工作台节点)。
2. 内容图: 素材库「画布素材」→ 勾选 生成蓝色手机图片-2 → 添加参考素材 (新建内容图)。
3. 合成 pointer 拖拽逐节点拖回基准位 (最终误差 ≤9px, 多数 ≤2px), 刷新确认持久化。
- 教训: **不要在源站对同一分组连续快速触发多次排列 ops**; 采样后立即解组复原。
- 节点 id 无法恢复原值 (新建节点 id 不同), 内容/类型/位置已对齐。

## 补充 (Batch 258, 2026-09-28): 分组角点手柄为装饰性

在源站重新成组 (4 成员) 后, 对 NW 角点手柄分别用真实 cua.drag 与合成 pointer
事件 (事件直接派发到手柄与 pane) 向内拖 30px: 分组盒 (left/top/w/h) 与全部成员
位置**零变化**。结论: `.canvas-group__handle--*` 是纯视觉装饰 (疑似未完成的
缩放功能), 无行为语义。克隆当前的装饰性手柄实现即为正确对齐, 无需改动。
采样后已解组复原, 画布 5 节点基准位完好。
