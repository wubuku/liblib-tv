# Batch 13 计划：分镜模式数据绑定与故事板结构

## 1. 缺口与价值

| 缺口 | 当前状态 | 原站证据 | 价值 | 决策 |
|---|---|---|---:|---|
| 分镜主体是固定数组 | `StoryboardBoard` 不读取 active canvas | 原站故事板展示当前项目素材 | 5 | 实现 |
| 关键元素栏缺失 | clone 只有四个静态列 | 原站左侧有“关键元素·全部”，含图片和文本 | 5 | 实现 |
| 故事板列语义不一致 | clone 将脚本、角色、分镜、视频平铺 | 原站主体按“图片 / 视频”分列 | 5 | 实现 |
| 卡片无法反映节点选中 | 点击没有 store 行为 | 原站卡片是画布素材的继续操作入口 | 4 | 实现本地选择 |
| 移动端主体边界不明确 | 静态内容可能撑开页面 | 原站为窄宽度可滚动的画布模式 | 3 | 实现内部横向滚动 |

## 2. 实施步骤

1. 读取 `canvasStore` 当前画布、选中节点和选择 action。
2. 将图片、视频、脚本节点投影为：
   - 左侧“关键元素”资源组；
   - 中间“图片”故事板列；
   - 中间“视频”故事板列。
3. 为卡片增加稳定 `data-storyboard-*` 选择器、`aria-pressed` 和选中视觉。
4. 保留来源节点 ID，卡片点击调用 `selectNode`；提供“返回工作台”命令验证选中节点仍存在。
5. 处理空画布和无媒体列的明确空态。
6. 添加 Batch 13 Playwright，覆盖桌面、移动端、卡片选择、模式往返、画布切换和 console/page error。

## 3. 原站事实与 clone-only decision

### 原站直接事实

- 分镜模式包含左侧关键元素栏、中间故事板主体、右侧 Agent。
- 关键元素栏按图片与文本分组，存在“关键元素·全部”筛选入口。
- 故事板主体至少包含“图片”和“视频”两列。
- 分镜截图中的图片卡展示缩略图、标题、尺寸/来源信息和参考缩略图。

### Clone-only decision

- 当前画布节点直接作为本地原型数据源，不引入服务端故事板对象。
- 卡片点击更新 `canvasStore.selectedNodeId`；原站卡片点击后的更深层动作未在本轮重新采样，因此不声称完全复刻。
- 过滤下拉保留为静态“全部”显示，不新增未经证据支持的过滤选项。
- 不实现拖拽排序、卡片删除、故事板发布或真实 Agent 任务。

## 4. 验收标准

- 初始 `画布 2` 在分镜模式显示 5 个图片卡、1 个视频卡、1 个脚本关键元素。
- 关键元素栏存在“图片”和“文本”分组；图片卡数量与当前画布图片节点一致。
- 点击任一故事板卡或关键元素卡后，该卡 `aria-pressed="true"`，store 选中节点保持可见。
- 切回工作台后 React Flow 仍保留 10 个节点、11 条边和对应选中态。
- 切换到空的 `画布 1` 后，分镜主体显示明确空态，不残留画布 2 内容。
- `390x844` 不产生页面级横向溢出；故事板内部可滚动。
- 无 console error 或 page error。
