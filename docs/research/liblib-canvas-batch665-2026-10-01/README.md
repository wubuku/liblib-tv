# batch 665 —— 四路判据交叉表，以及 617 普查的 6 道静默 `continue`

## 一句话

639 挂了两年的下一批候选第 1 条是「绘制类读数与命中类读数的一致率表」。
本批把那张表做出来了 —— **而做的过程中发现盲区的位置不在「测量」里，在「纳入」里**：
共享判据 `verify-liblib-batch617.py:282` 有一句
`if (s.pointerEvents === 'none') continue;`，**普查连 `pe:none` 的控件都不枚举**。

## 1. 盲区的位置：664 找到仪器端，本批找到纳入端

664 普查的是**测量调用**（`elementFromPoint` / `elementsFromPoint`），
结论是 26 个调用点、只有 1 台能拒绝。
**它没有普查纳入过滤** —— 而第三态塌缩在共享判据里正是**那一行**：

```js
// scripts/verify-liblib-batch617.py:282
if (s.pointerEvents === 'none') continue;
```

那不是「仪器答错」，是**「这个控件在我们的账本上不存在」**。

> 664 与本批合起来才把这条路径找全。**一个普查只数调用点，就会漏掉「谁被纳入了」。**

## 2. 六道门逐条归因

抄 617 的 `inScope` / `isFlow` / `isScrim` 与 6 道 `continue`（逐行号），
对**每一个**控件记录它被哪一道拦下 —— 而不是让它静默消失：

| 门 | 行 | 判据 | 每窗高拦下 |
|---|---|---|---|
| L276 | 276 | `!inScope(el) \|\| isFlow(el)` | **60**（画布页顶栏：项目菜单 / 工作区名称 / 画布 2 / 工作流 / 故事板） |
| L278 | 278 | `b[2] <= 0 \|\| b[3] <= 0` | **4**（623 在案的零尺寸族） |
| L280 | 280 | `visibility:hidden / display:none` | **0** |
| L281 | 281 | `opacity === 0` | **2** |
| **L282** | **282** | **`pointerEvents === 'none'`** | **0** |
| L285 | 285 | `isScrim(el)`（记为 scrim 而非 item） | **0** |

**196 个原始控件 → 保留 130**，与 617 自己报的 `total=130`、`blocked=16`
**逐位相同**（三个窗高）。**抄写的忠实性是被证明的，不是被声称的。**

> 第一版探针**没有过滤**，枚举出 132，我据此说「我的普查是 617 的超集」。
> **那是错的** —— 多出的 2 枚正是 `opacity:0` 的那 2 枚。两个普查之间
> **没有分歧**，是我的读数错了。

## 3. L282 = 0：一个有作用域的量到的零

导演台**自己的控件**里没有 `pe:none` 的，所以第三态塌缩在这个页面的
**纳入端**不发生。

**但这不代表导演台没有盲区** —— 下一节就是。

## 4. 盲区在门外，而 L282 对它**结构上无法发言**

那道门只测**控件自己**的 `pointer-events`。而 664 那 22 个元素造成的损害是
**别的 `pe:none` 元素压在控件上方**：

    24 枚控件：own = True（点得到），中心上方却盖着 pe:none 层

样本：`重置视角`、gizmo 的六枚轴按钮（`X 正向`…`Z 反向`）、`移动`/`旋转`/`缩放`…

> **门在正确的位置，问了错误的问题。**

**这 24 枚不是缺陷** —— `own=True` 意味着它们**点得到**。
本批只主张：「`own` 这一路的读数**看不见**压在它们上面的东西」。

## 6. L281 静默丢掉的 2 枚里，有一枚 658 算进了缺陷

| 被丢掉 | 是什么 |
|---|---|
| `data-directorScenePromptFile` | **1×1**、`opacity:0` 的 `sr-only` 文件输入 |
| `data-directorTimelineZoom` | 时间轴缩放 |

**而 658 的 `occludedKeys` 里正有 `data-director-scene-prompt-file|`** ——
658 把它算成「4 枚不可达的提示条控件」之一，**617 的普查根本枚举不到它**。

> **两个普查对「它存不存在」意见不一致，而两边的账本都没说这件事。**

659/660 给提示条收的闭式（中心落在裁剪盒内）是对**可见**控件说的；
那枚文件输入是 1×1 且 `opacity:0`，**用户看不见也点不到**，
但**文件选择仍可由脚本触发**。
**它是不是缺陷取决于产品意图，本批不主张。**

## 9. 我自己写错的地方

1. **第一版探针没有过滤**，枚举 132，我据此说「我的普查是 617 的超集」——
   **错的**，多出的 2 枚正是 `opacity:0` 的两枚。数据纠正了读数。
2. **`by_gate` 跨三个窗高累加**（L276 变成 180 = 60×3），
   而断言拿单窗高的总数去对 —— 记账 bug，改为逐窗高记账。
3. **`unattributed` 那个集合是个没有意义的式子**（`kept − dropped − blocked`
   把每个干净控件都算成「未归因」）。更要紧的是：**键级比对根本不可得**
   （617 不返回 kept 的键），而判据原本在声称它 —— 改成只主张计数层。
4. **又一次把字符串当 `Path` 用 `.parent`**（第三次），当场 `AttributeError`。
5. **嵌套 f-string 引号** + **`detail={…}` 少一个 `}`** —— 两次 `SyntaxError`，
   第二次靠 `tokenize` 数括号深度才定位到 437 行。
