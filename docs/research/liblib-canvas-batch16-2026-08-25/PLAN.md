# Batch 16 计划：画布下拉与项目元数据生命周期

## 1. 缺口与价值

| 缺口 | 当前 clone | 原站证据 | 价值 | 决策 |
|---|---|---|---:|---|
| 项目名状态错误 | `TopNavBar` 局部 `useState` | 原站下拉展示“当前项目 / 未命名项目” | 5 | 移入 `canvasStore` |
| 项目上下文缺失 | 下拉只有“画布”标题 | 原站菜单先展示项目上下文，再列画布 | 5 | 增加项目区块 |
| 操作后菜单残留 | 新建/切换/复制/删除/重命名不统一关闭 | 原站是一次选择后回到画布工作态 | 4 | 增加显式 close action |
| 自动化入口不稳定 | 依赖文案和层级猜测 | 后续批次需要验证导航闭环 | 4 | 增加 metadata selectors |
| 移动端项目入口 | 顶部项目名只在 `lg` 显示 | 原站手机顶部保留 Logo/画布入口 | 3 | 项目名放入下拉，移除重复顶部 pill |

## 2. 实施步骤

1. 在 `canvasStore` 增加 `projectName` 和 `setProjectName`，保持非空 trim 约束。
2. 把 `TopNavBar` 的项目名编辑迁移到 `CanvasTabDropdown`，让项目名和画布列表由同一状态源驱动。
3. 按原站截图重组下拉头部：`当前项目`、项目名、`画布`、新建按钮、活动画布勾选。
4. 为所有画布 CRUD 结果调用 `closeCanvasDropdown`，重命名 blur/Enter 也必须收口。
5. 增加 `data-canvas-*` selectors 和 Batch 16 Playwright，覆盖项目名、切换、新建、复制、重命名、删除、外部点击、Escape 和移动端溢出。
6. 更新组件规格、行为索引、组件清单、Harness、CHANGELOG、Big Picture。

## 3. 事实边界

### Source fact

- 保存的原站截图显示：顶部有 Logo 和 `画布 2` 入口；展开菜单后先出现 `当前项目`、`未命名项目`，再出现 `画布`、加号、`画布 2` 勾选和 `画布 1`。
- 原站总体审计记录画布下拉支持新建、切换、重命名、复制、删除。
- 手机端顶部只保留 Logo/画布入口，项目上下文可从画布菜单访问。

### Inference

- 菜单中的项目名是项目级元数据，而不是某一个画布的 `name` 字段。
- 点击画布或完成画布 CRUD 后应回到干净的工作台状态；本批以 close 作为 clone 的可验证生命周期实现。

### Clone-only decision

- 项目名仍只存在 Zustand 内存，不实现真实项目 API、持久化和权限。
- 重命名/复制/删除的更多菜单继续保留现有 clone 结构，因为本批没有行级更多菜单的原站截图。

## 4. 验收标准

- 打开画布菜单可见 `当前项目`、非空项目名、`画布`和当前画布勾选。
- 项目名编辑会更新 `canvasStore.projectName`，不是局部组件 state。
- 新建、切换、复制、删除、重命名完成后菜单关闭；复制/新建后的新画布成为 active。
- 外部点击、Escape 和切换到其他一级 overlay 都不会留下画布下拉。
- 桌面与 390px 视口无页面级横向溢出；Batch 11-15 不回归。
