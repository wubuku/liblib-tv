# batch 677 —— 整套遮挡判据建立在 **6 枚控件**上；而「命中者是谁」这类读数**对被测控件自己还能不能点完全无感**

## 一句话

676 发现 `收起属性` 两枚里有一枚从未进入 667 的读数，把原因归给
「探测点只取控件中心」这一条口径。

本批问两个更一般的问题：

1. **那套口径到底建立在多少枚控件上？**
2. **反过来 —— 对它确实看过的那几枚，读数对「控件自己还能不能点」有反应吗？**

## 仪器

`scripts/verify-liblib-batch677.py`，**667 自己的 6 格**
（1280×720 / 1280×1150 / 1366 / 1440 / 1600 / 1920 × 1150）。
关键设计：**在同一个页面上同时跑 667 与 676 两台仪器** ——
人口不同的比较必须在同一状态下做，否则量的不是同一个东西。

## 1. 人口：6 / 130（4.6%），且随宽度单调收缩

| 视口格 | 被遮挡的控件数 | 名单 |
|---|---|---|
| 1280×720 | **6** | 帮助 / 上传图片 / 描述想搭建的场景 / 发送 / 颜色 hex 值 / 颜色 |
| 1280×1150 | 4 | 帮助 / 上传图片 / 描述想搭建的场景 / 发送 |
| 1366×1150 | 3 | 帮助 / 描述想搭建的场景 / 发送 |
| 1440×1150 | 2 | 帮助 / 发送 |
| 1600×1150 | **1** | 帮助 |
| 1920×1150 | **1** | 帮助 |

并集 = **6 枚 / 130 枚**。出现格数：**帮助 6/6**、发送 4/6、描述想搭建的场景 3/6、
上传图片 2/6、颜色 hex 值 1/6、颜色 1/6。

**667 说的「6 格恒定」是对的 —— 但它只对 `帮助` 成立。**
其余 5 枚都是**窄视口现象**，最宽的两格里只剩 `帮助` 一个。

**658 / 661 / 662 / 664 / 666 / 667 这一整族判据，量的是 130 枚里的 6 枚。**

## 2. 同一视口、同一批控件，两条口径给出不同人口

667 的普查额外要求「存在一层 `pointer-events:none` 的外层元素」（664 记的那条守卫），
676 的没有：

| 视口格 | 667 口径 | 676 口径 |
|---|---|---|
| 1280×1150 | 2 | 4 |
| 1440×1150 | 1 | 2 |
| 1920×1150 | 1 | 1 |

667 的人口**逐格是** 676 人口的子集，且在多数格严格更小。

## 3. 注入反例：读数对「被测控件自己还能不能点」无感

给 `帮助` 注入 `pointer-events:none`（1440×1150 与 1920×1150 两格）：

| 仪器 | 注入前 | 注入后 |
|---|---|---|
| 667 口径人口 | `[帮助]` | **`[]`** |
| 667 的 `帮助` 读数 | `收起属性` | **`None`**（连读数都产不出来） |
| 676 口径人口 | `[帮助, 发送]` | **`[帮助, 发送]`（一字未变）** |
| 676 的 `帮助` 读数 | `收起属性` | **`收起属性`（一字未变）** |

**为什么 676 无感**：那几枚**本来就不是命中者** —— 命中者一直是它们上面那层。
把一个从不接收事件的东西设成不接收事件，`elementFromPoint` 的答案当然不变。

**没有任何一台仪器给出过不同的命中者名字。**

### 667 的反应是崩，不是判不成立

667 的 `help_everywhere = all(len(help_rows[k]) == 1 ...)` 会变 False，
所以**它不会静默通过**。但它的读数阶段先无条件索引 `help_rows[k][0]`
（`verify-liblib-batch667.py:277`）⟹ **IndexError: list index out of range**。

**是响亮的崩溃，不是绿灯，也不是「判定不成立」。** 验收器把「崩了」和「判错了」
混为一谈时，读者容易以为它判过了 —— 它没有。

## 4. 结论与可执行的修法

这套判据全部建立在「命中者是谁」上，所以它能回答**「谁挡了它」**，
**不能回答「它自己还在不在」**。

要把这两件事分开，**多读一个 `getComputedStyle(el).pointerEvents` 就够** ——
而 658 / 661 / 662 / 664 / 666 / 667 **都没有读它**（667 反而用它做了一道跳过守卫，
正是那道守卫制造了「读数消失」）。

## 5. 自记：两处预期被读数推翻

1. 动手前我以为「注入 `pe:none` 会让那枚控件从被遮挡名单里消失」。
   **读数说不会** —— 消失的是**控件本身**（667 的守卫把它从人口剔掉），
   而「被遮挡」这个判断**一字不变**。
   **「谁从名单里消失」和「名单的内容变没变」是两个问题。**
2. 第 6 条判据我写成「两台仪器的读数都不变」，运行失败：667 那条**不是不变，是变成 `None`**。
   **「读数变了」和「读数消失了」是两件事。**
   改成断言真正成立的那句：**没有任何一台仪器给出过不同的命中者名字**。

## 6. 不声称

- **不声称**那 6 枚之外的 124 枚「没有遮挡问题」——
  **从未被普查过 ≠ 没问题**（见 676 的第三条：`从未遮挡任何人` 与 `是坏的` 是两件事）；
- **不声称**667 的结论错了 —— 它在 `帮助` 上是对的；
- **不声称**注入等价于真实遮挡 —— 是构造，不是源站行为；
- **不声称** 6/130 这个比例在别的纳入过滤下也成立 —— 665 已记「纳入过滤本身是盲区」；
- **不改任何历史批次。**
