顺带记下一个既有事实：390 的顶栏只有 4 枚控件（进入 FrameOS 画布 / 项目菜单 / 工作区名称 / 画布 2），1920 有 10 枚 —— 工作流、故事板、发布与分享、Agent 与两枚 inert 芯片在窄屏隐藏。这是早于本批的响应式决定，普查是第一个把它数出来的东西。

## 发现一：普查漏了画布页自己的浮层约定（清单缺项，不是缺陷）

`/tmp/dbg620c.py` 在 390 打开「缩放选项」浮层，普查报出 5 枚遮挡：

```
移动 / 打开工具箱 / 素材库 / 角色库 / 生成历史   ← 都在 y 751.5
hit <div> 28%放大⌘ +缩小⌘ 0缩放至50%缩放至800%
```

这是**浮层正常工作**：缩放菜单从右下角向上弹出，正好盖住它上面那一排工具按钮。误报的原因是清单里没有它。

查代码发现画布页**已经有统一的浮层约定** —— `data-liblib-overlay`，13 个文件、7 个取值（`zoom-menu` / `canvas-dropdown` / `asset` / `add-node` / `agent` / `shortcuts` / `share`）：

```jsx
<div data-liblib-overlay="zoom-menu" className="absolute bottom-9 right-0 w-[188px] …">
```

所以不该再往清单里逐个加名字，而是让普查认这个属性（导演台那批浮层用的是各自的 data 属性，具名清单保留）。改完该态归因 5 条、缺陷 0 条。

## 发现二：真缺陷 —— 资产侧栏自己的收起按钮被画布页底部工具条埋掉

同一轮里另一条经得起推敲：390 打开「资产管理」后，侧栏页脚那枚「收起节点侧栏」被报为遮挡。

`/tmp/dbg620d.py` 的命中链说清了是谁压谁：

| | 盒 | z | position |
|---|---|---|---|
| 资产侧栏 | `[0,0,320,844]` | 50 | relative |
| 画布页底部工具条 | `[16,786,262,40]` | **60** | fixed `bottom-[18px]` |
| 被埋的按钮 | `[16,813.5,22,22]` | — | — |

命中打到的是工具条第二簇的「资产管理」。截图里那枚「«」还**半截露在药丸外面**（`/tmp/shot620-asset-390.png`）—— 不只是点不着，是 visibly 破相。

**为什么不抬侧栏的 z**：抬过 60 会把工具条左侧五枚活控件（资产管理 / 切换小地图 / 隐藏节点连线 / 网格吸附 / 缩放选项）反过来埋掉 —— 拿一枚死控件换五枚活控件，不做。

**改法**：窄屏不渲染页脚这枚。同一面板页眉右上角还有 `aria-label="关闭资产管理"` 的 ✕（同一个 `onClose`），工具条的「资产管理」也是同一个开关，功能没有缺口；≥900px 不重叠，原样保留。

```jsx
className="rounded p-1 hover:text-white max-[899px]:hidden"
```

## 验收（57 项）

十态各 5–7 项：普查到足够多的控件、零未预期遮挡、唯一可能的遮挡是 `帮助`、浮层态断言该浮层真的打开、无页面/控制台错误。资产侧栏两态另各加：390 断言「被埋的收起按钮确实不再渲染」+「页眉 ✕ 仍命中自己」（功能没缺口），1920 断言「页脚收起钮仍命中自己」（桌面没被顺手改掉）。

### 验收脚本自身修了一处

探针 `own()` 先判尺寸后判 `display`，于是 `display:none` 的按钮被报成 `zero-size` 而非 `hidden`，把「不渲染」与「渲染但塌成零尺寸」混为一谈。调换顺序。
