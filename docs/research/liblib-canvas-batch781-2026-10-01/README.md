# batch 781 — 补上 780 矩阵的最后一行，并回答「放行会不会引入新伤害」

> 780 建立的放行判据是「**该键在该类型上有没有原生兜底**」，矩阵铺了
> `Escape` / `Meta+z` / `Delete` / `Backspace` 四行，而
> `Meta+c` / `Meta+v` 那一行被**显式标注为「本批未测」** ⟹
> 它是矩阵里**唯一没有读数支撑的一行**，而判据却已经按它推过一轮。
>
> ★ 更要紧的是一个**没人问过的安全问题**（见 §2）。

## 1. ① 预测（从源码逐行推出）

桌的 `Cmd+C` / `Cmd+V` 分支在 `DirectorDesk.tsx:490` / `:495`，**排在 `:487`
那道 `isEditable` 守卫之后** ⟹ 焦点在 gesture 控件上时两者都够不着。

## 2. ② 「放行」安不安全？—— 这是个真问题

780 说「range 上 `Meta+c` 无原生兜底 ⟹ 该放行」。但放行之后，桌的 `Cmd+C`
分支会调 `copyDirectorSelection()`。★ **若它写的是系统剪贴板，用户按 `Cmd+C`
就会把系统剪贴板内容换成导演台内部数据 ⟹「修复」变成新的伤害，方向正好相反。**

**查源码得到的答案让这个问题落地：**

| 读数 | 值 |
| --- | --- |
| `copyDirectorSelection` 写哪儿 | **内部** `clipboard: built.packet`（`src/store/directorStore.ts:3941`） |
| 内部包类型 | `DirectorClipboardPacketV1` |
| 扫了 director 面**多少**文件 | **28** 个 |
| `navigator.clipboard` / `writeText` / `readText` 命中 | **0** 处 |

⟹ 导演台的复制/粘贴**完全内部** ⟹ **放行不会碰系统剪贴板** ⟹
**矩阵里不存在「系统剪贴板被污染」这一列**。

★ 而这个搜索**必须带作用域**：`app/frameos/canvas/[id]/page.tsx` 与
`components/jimeng/*` 里都有 `navigator.clipboard` ⟹ **全仓搜会得到一个
完全相反的结论，而那会否掉一个正确的修法**。

## 4. 结论

### 4.1 ★ 更正 C781-2：我预测的「静默的死键」**被否掉**，而否掉的方式让结论更准

我预测 live 区「无任何文案」。**实测是占位文案「无命令反馈」**
（777 的 D1e），而且 `lastCommand` / `lastDisp` **两个读数都是陈旧值**
（`GESTURE_BEGIN` / `COMMITTED`，来自聚焦时开手势那一刻）⟹
它们**没有**被这两下按键更新。

对照臂给出了正确对照：`Meta+v` 在内部剪贴板为空时是 **`NOOP`**，而 live 区
显示**真实消息** ⟹ **桌是有「无操作/拒绝」反馈通道的**。

⟹ 准确说法是「**死键 + 面板显示占位文案**」，
**不是「静默」，也不是「没有反馈通道」** ——
**差异在「命令有没有产生」，不在「有没有通道」。**

### 4.2 ★ C781-1：**D1f 的键种清单要补全为 4 个**

`Meta+c` / `Meta+v` 在 range 滑杆上**同样是死键**，而它们同样没有原生兜底
（滑杆上不可能有文本选区）⟹ 清单从 2 个键补成 4 个。

★ 但**这不改变「该放行」的结论**：range 侧该放行的仍然是
`Meta+z` / `Delete` / `Backspace`；**C/V 放行属「新增功能」而非修缺陷**
（「让 `Cmd+C` 从『什么都不做』变成『把导演台选中写进内部剪贴板』」）
⟹ 单独列为**产品决定**，不进修法。

### 4.3 矩阵（五个键全部有读数）

| 键 | number（原生兜底） | range（无原生兜底） | 该放行吗 | 测于 |
| --- | --- | --- | --- | --- |
| `Escape` | **无** | **无** | ★ **两族都该放行** | 779 |
| `Meta+z` | **有**（文本撤销） | **无** | **只 range 放行** | 778 |
| `Delete` / `Backspace` | **有**（删字符） | **无** | **只 range 放行** | 780 |
| `Meta+c` / `Meta+v` | **有**（文本复制/粘贴） | **无** | ★ **待产品决定** | ★ **781** |

族规模从 776 的 raw **重算**并与 780 产物**对账**：number 27 / range 26 / 合计 53。

★ **矩阵里不存在「系统剪贴板被污染」这一列**（director 面 28 文件 0 命中）。

**验收 99/99、阴性对照 10/10**（含 **1 条注入假文件**的对照
+ 3 条改源码的静态对照）。

| 维度 | 条数 |
| --- | --- |

| 原始读数（每臂起点与逐次 `cap≥1` 正向对照） | 22 |
| gesture 臂逐次 + 两条聚合 | 43 |
| 对照臂 / 反馈通道 | 6 |

| 阴性对照 | 目标判据 | 漏判方向的代价 |
| --- | --- | --- |
| 让 `numberCopy` **真的执行** | 最后一行被测出来了 | 矩阵最后一行**仍没有读数** |
| ★ **对称**：让 `rangePaste` **真的执行** | 最后一行被测出来了 | 两族读数可单独坏掉 |
| 把 live 区改成**空** | 死键伴随占位文案 | 误报成「静默的死键」⟹ 777 的 D1e 被漏掉 |
| 把对照臂 live 区改成占位文案 | 桌有拒绝反馈通道 | 会得出「桌**没有**通道」⟹ 修法指向「加反馈」而不是「让命令产生」 |
| 把对照臂 disposition 改成 `COMMITTED` | 非 `COMMITTED` 的拒绝 | 那条只测了「live 区非空」 |
| ★ 改一个不存在的字段 | 不许有判据翻红 | 对照自身失效（R108） |
| ★ **注入**一个调 `navigator.clipboard` 的文件进 director 面 | 零命中 | ★ **这是「带作用域的搜索」唯一真正的对照** —— 只改真源码里的字符串，命中数仍是 0 |
| ★ 把守卫挪到 C/V 之后 | `Cmd+C` 排在守卫之前 | 归因落在「分支存在」而非顺序 |
| ★ 把内部包类型改名 | 内部 clipboard 包 | 「完全内部」只测了「有个 clipboard 字段」 |
| ★ 让 `getDirectorCommandFeedback` 不再对 COMMITTED 返回 null | `COMMITTED`→null | 「Copy 成功时只能显示占位」失去机制依据 |

★ **本批验收器自己踩了两次坑，都由阴性对照抓到**：
① 静态层把**行列表**当字符串用 `in` 判断 ⟹ 三条静态判据**恒假**；
② `FB_LIB` 走直读磁盘、没接 `sources` ⟹ 那条改源码的对照**自己变成惰性的**。
（这是 R128「拿对了容器、拿错了类型」与 R108 的同族错误。）

## 6. 探针教训

- **R138** ★ **判据要覆盖全集才敢用。** 780 用三个键的样本立判据，第四行却
  没测 ⟹ 矩阵出现一行「凭判据推出来、但没有读数」的结论。立判据时要说清
  **它覆盖哪些键**，并把未覆盖的**显式列出来**。
- **R139** ★ **提一条修法时先问「放行之后会发生什么」。** 若
  `copyDirectorSelection` 写的是系统剪贴板，780 那条「修复」就是**新的伤害**。
  ★ 本批静态查了 28 个 director 文件才敢下结论。
- **R140** ★ **搜索带作用域在这批是生死线。** 全仓搜 `navigator.clipboard`
  会得到「导演台会污染系统剪贴板」的**完全相反**结论。
