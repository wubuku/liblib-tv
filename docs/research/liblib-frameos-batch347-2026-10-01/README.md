# Batch 347（2026-10-01）：交互盲区清零，并把它变成**门禁**

## 结论一句话

Batch 345（toast 无标识）和 Batch 346（帮助面板行无标识）是**同一个元缺陷踩了两次**。
两次就是模式：「记得加测试钩子」不是可靠流程。本批把欠账**测出来**（4/38）、
**清零**，并把「清零」变成**门禁**——今后新增 UI 元素忘加钩子，套件当场失败。

## 运行时普查（修复前）

探针 `scripts/probe-frameos-batch347-interactive-blindspots.py`：

```

[with_help          ] 可点元素 39  有稳定钩子 35  盲区 4  (10%)

```

**三个核心导航控件 + 一个头部按钮，恰恰是测试最需要寻址、却唯一没法寻址的东西。**

> data 属性」，看起来是笔大账。**运行时测量才是真的** —— 那些按钮大多有
> `aria-label`（Batch 342/346 我正是用 `button[aria-label="搜索节点"]` 选中的），
> 盲区只有 4 个。
> **不要用静态猜测替代运行时测量** —— 我差点按错误的量级去改动一片代码。

## 修复

- `FrameosBreadcrumb.tsx` — 共用的 `Crumb` 渲染函数加 `data-frameos-crumb={label}`，
  **一次覆盖三个面包屑按钮**（项目/场景/画布）
- `FrameosAppHeader.tsx` — 「下载桌面端」加 `data-frameos-download-client`

「下载桌面端」**仍然是 mock**（`window.alert`），这是有意的：源站那里是外部下载
地址，未采样 → 不发明。但**可寻址必须做到** —— 正因为它将来可能出问题，我们才要
能抓到它。

## 门禁（本批真正的产出）

验证器在**三种 UI 态**（默认 / 打开帮助面板 / 选中节点）下枚举所有可点元素
（`button, [role=button], a[href], input, textarea, select, [tabindex]`），
任何缺少稳定钩子（无 `data-*` / 无 `aria-label` / 无 `id` / 无 `title`）的元素
都让验证器**失败并指名**。

这一条才是把教训固化下来的地方：

> 之前两次都是「写验证器时发现抓不到 → 临时补一个属性」。这次变成
> **门禁**——以后新增 UI 元素忘加钩子，套件会直接指出来，而不是等到某个
> 验证器写不出来时才发现。

门禁还有一条防「假绿」的断言：`scan:not-empty` 要求至少扫到 20 个元素，
否则判定「选择器可能写错了」——避免因为选择器失效导致扫不到任何东西而假绿。

## 验证器

`scripts/verify-frameos-batch347.py` — **12 项断言全 PASS，0 诊断**：

1. 扫描确实扫到 ≥20 个元素（防假绿）；
2. 默认态**零**盲区；
3. 帮助面板打开时**零**盲区；
4. 选中节点（浮动工具条出现）时**零**盲区；
5. 三个面包屑按钮都能被 `data-frameos-crumb` 寻址；
6. 每个钩子的值与按钮显示文本一致；
7. **钩子真的能用来操作**：点 `[data-frameos-crumb="画布 1"]` 能打开画布下拉
   —— 钩子不是摆设；
8. 「下载桌面端」可寻址；
9. 诊断零错误。

**变异测试**：撤掉 `data-frameos-crumb` 后门禁如期 FAIL。

证据：`runtime-audit.json`（本目录）。
复现探针：`scripts/probe-frameos-batch347-interactive-blindspots.py`（只读）。

## 方法论沉淀

本批真正的新东西不是两个属性，是这三条：

1. **元缺陷踩两次就该变成门禁。** 一次是意外，两次是流程缺陷。
2. **静态扫描会高估欠账，运行时测量才是真的。** 我差点按错误量级改一片代码。
3. **门禁必须防假绿。** 「扫到 0 个元素」和「0 个盲区」在断言里长得一样，
   所以要单独断言扫描总数不为 0。
