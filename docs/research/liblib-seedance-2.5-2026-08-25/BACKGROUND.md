## 2. 一页结论

外部调研展示的 LibTV 能力可以归纳为 Seedance 2.5 基础接入加四类工作流增强：

1. **Seedance 2.5 生成**：在同一创作输入区选择模型、模式、画幅、分辨率、时长、音频和预计消耗。
2. **片段重拍**：在已有视频中选取局部时间片，只针对选中片段输入修改意图。
3. **智能引用 Auto Link**：从当前画布素材中匹配角色、场景、道具等引用，并把有序素材投影到 Prompt。
4. **超长视频**：把单段视频生成能力组织为可查看中间产物的长视频过程。
5. **逐帧拉片**：把参考视频拆成分镜关键帧、动态片段和音乐参考，作为可继续使用的媒体卡片。

这些能力共同降低四类创作成本：

| 创作成本 | LibTV 的工作流响应 |
|---|---|
| 局部错误导致整条视频重做 | 片段重拍 |
| 反复查找素材、手工输入引用 | Auto Link |
| 长叙事需要人工拆分、生成、续写、拼接 | 超长视频过程 |
| 参考视频需要人工暂停、截帧、记运镜和扒音乐 | 逐帧拉片 |

重要背景判断：LibTV 的产品价值不只是接入一个模型 ID，而是把模型能力放入“资产组织、提示词映射、局部修改、长叙事编排、结果再利用”的连续流程。

## 3. 五项能力知识卡

### 3.1 Seedance 2.5 生成

**用户可见形态**

- 模型选择器中出现 Seedance 2.5；
- 生成输入区同时承载生成模式、画幅、分辨率、时长、音频、数量、预计积分和提交；
- 外部文章展示最长 30 秒的直出能力。

**当前证据**

- `article-screenshot`：原文展示 `2.5`、`16:9`、`720P`、`30s` 和音频/积分区域。
- `live-confirmed`：原站模型菜单显示“最强视频模型，全能参考，30s 音画同步”；普通参数时长为 `4-30s`，模式和模型菜单详见 [`LIVE_AUDIT.md`](LIVE_AUDIT.md)。

**边界**

`30s` 是当前产品采样事实，不在本仓库写成永远不变的 Provider 契约。真实模型请求、计费和生成任务不属于本克隆范围。

### 3.2 片段重拍

**用户可见形态**

1. 从视频节点顶部工具栏进入“片段重拍”；
2. 在横向缩略时间带中选择 4 秒片段；
3. 选择计数由 `0/5` 变为 `1/5`，文章截图显示最多 5 个片段；
4. Prompt 自动投影视频编号和时间范围，例如 `视频 1`、`00:00-00:04`；
5. 用户输入局部修改意图并提交。

**当前证据**

- `article-screenshot`：完整选择、计数和 Prompt 流程。
- `live-confirmed`：当前线上 bundle 存在片段重拍入口、4 秒最小片段、最多 5 段相关文案；本项目当前原站视频不可用，因此未在源站真实提交任务。

**本克隆采用的前端语义**

时间片选择、最大五段、Prompt 投影、局部提交状态均已实现；提交只产生本地 mock 状态，不声称替换真实视频。

### 3.3 智能引用 Auto Link

**用户可见形态**

- 从当前画布或工作上下文中召回角色、场景、道具等素材；
- 以缩略图组成有序参考列表；
- 在 Prompt 对应位置投影“图片 1/2/3”等引用；
- 用户检查后可以替换或移除，不应被自动结果永久覆盖。

**当前证据**

- `article-screenshot`：画布素材、参考缩略条和引用编号逐步出现。
- `live-confirmed`：当前视频生成面板显示 AutoLink 开关、3 个参考图和结构化 Prompt 引用；高级设置中的 AutoLink 采样为开启。

**稳定产品原则**

Auto Link 是“候选匹配 + 人工确认 + 编号投影”，不是不可解释的自动改写。素材的内部身份和语义职责不能被临时 UI 编号替代。

### 3.4 超长视频

**用户可见形态**

- 生成模式菜单中有独立的“超长视频 Beta”；
- 参数行可显示 `300s`；
- 可以查看生成过程和中间镜头/素材关系；
- 文章截图显示过程图，而不是单一不可解释的进度条。

**当前证据**

- `article-screenshot`：`300s`、`14700` 和过程节点图。
- `live-confirmed`：当前原站存在 `30-300s` 滑块；拖到 `300s` 显示 `14700`；模式和过程入口已复核。

**解释边界**

Seedance 2.5 单次 30 秒与 LibTV 300 秒产品入口属于不同层级：前者是模型能力采样，后者是产品层的长视频编排表现。本仓库只复刻过程视图和参数呈现，不实现真实多任务拆分或拼接。

### 3.5 逐帧拉片

**用户可见形态**

- 视频节点顶部工具栏提供“逐帧拉片”；
- 选择“分镜 / 动态 / 音乐”拆解维度；
- 分镜结果以 `S01...` 等关键帧卡片出现；
- 动态结果以 `M01...` 等短视频卡片出现；
- 音乐结果以带时长和播放控制的波形卡出现；
- 结果可以继续作为生成参考。

**当前证据**

- `article-screenshot`：入口、维度和完整结果形态。
- `live-confirmed`：当前原站“添加节点”有独立“逐帧拉片 SD 2.5”入口，并创建专用 `shot-breakdown` 节点空态；结果态主要依赖文章截图。

**边界**

文章称拉片不消耗积分，但这是第三方产品策略陈述，不推导为没有计算成本，也不写入本克隆业务契约。

## 4. 共性的 LibTV 产品模式

### 4.1 统一画布作为上下文

角色图、场景图、输入视频、生成节点和处理结果出现在同一深色节点画布中。用户可以围绕当前对象继续执行生成、重拍、拉片和结果再利用，不必下载后重新上传。

但“统一画布”不等于所有关系都用无语义自由连线表达。外部文档指出，截图中的连线不能直接告诉用户它表示引用、派生、替换还是接续；当前原站审计也把 React Flow 结构作为视图和候选作用域，而不是直接推断领域关系。

### 4.2 高级能力放在对象工具栏

- 片段重拍和逐帧拉片属于当前视频对象的处理命令；
- 超长视频属于生成模式参数；
- 拉片结果属于当前视频派生出的结构化媒体资产。

这形成一个可复用的上下文规则：**生成参数在生成面板，视频后处理在视频工具栏，派生结果在节点或结果面板中继续使用。**

### 4.3 参数、费用和提交靠近

模型、模式、比例、分辨率、时长、音频、数量、预计积分和提交按钮在同一个操作上下文内。用户在高成本操作前可以看到请求形状和预计消耗。

### 4.4 自动化保留人工检查

Auto Link 先给候选，用户确认后再写入引用。逐帧拉片返回可预览、可移除、可继续引用的媒体卡，而不是一段不可操作的分析文字。
