## 源站实测结构（SOURCE_FACT）

摄像机面板「运动轨迹」页签、关键帧选中态下的字段组，自上而下为：

| 顺序 | 字段 | 控件形态 | 截图实测值 |
|---|---|---|---|
| 1 | 时长 | **滑杆 + 数值框** 同行；轨道深灰、已填充段青色、白色圆形滑块 | 滑块贴左端，数值 `0.1` |
| 2 | 位置 | 三列圆角数值框 `X / Y / Z` | `3.3 / 2.2 / 10` |
| 3 | 旋转 | 三列圆角数值框 | `0 / 0 / 0` |
| 4 | 缩放 | 三列圆角数值框 | `1 / 1 / 1` |
| 5 | 统一缩放 | **滑杆 + 数值框** 同行，滑杆几何同上 | 滑块约在轨道 9% 处，数值 `1.0` |

- 位置值与时间线「主机位 → 位置」行一致（`3,3.3,2.2,10`），确认该字段组
  镜像的是选中关键帧所持的机位变换（batch 576 结论，本批沿用）；
- 「时长」与「统一缩放」是**两个同款滑杆组件**，不是开关：统一缩放滑杆
  左侧有青色已填充段（`#09caf5`），时长滑块在 0% 处故填充段不可见；
- 数值框为深色圆角输入（`0.1` / `1.0`），与 XYZ 三列输入同一视觉族。

## 证据边界（INFERENCE，非 SOURCE_FACT）

- **滑杆量程 0–10**：`0.1` 落在轨道 0%、`1.0` 落在约 9%，两者共用
  0–10 量程是唯一自洽读法（1.0/10 = 10% ≈ 实测 9%）。源站实际 max
  未经拖拽复核——本轮 CDP 会话中「打开导演台」按钮点击无响应
  （JS click 与原生 click 均未触发导航，`window.open` 未被调用），故
  源站导演台无法进入，量程只到截图证据为止。
- **「时长」取值语义**：截图现场选中的是 t=0 关键帧（batch 578/579 记录），
  若时长即关键帧时间应显示 `0.00`，实测却是 `0.1`，故**时长 ≠ 关键帧
  时间**。它更可能是机位运动轨迹的过渡时长或路径时长，但源站未提供
  可复核的交互证据，不做进一步断言。

## clone 合同（CLONE_DECISION）

- 字段组顺序固定为 时长 → 位置 → 旋转 → 缩放 → 统一缩放，标签在上、
  控件在下，与源站一致；
- `MotionSliderField` 复刻源站滑杆几何：深灰轨道 + 青色已填充段 +
  白色圆形滑块（内联渐变 + `::-webkit-slider-thumb`，AGENTS.md §5 允许
  记录动态内联样式），量程 0–10、时长步进 0.01、统一缩放步进 0.1；
- **时长** 映射为播头时间（运动轨迹面板所处的时长位置），编辑即 seek；
  与源站 `0.1` 的取值差异属未复核项，不伪造一个持久化的"过渡时长"
  字段（会连带改 `directorProjectDocument.ts` 的严格校验层，且语义无据）；
- **统一缩放** 镜像选中关键帧 `scale[0]`，编辑时经
  `commitTransformValue` 逐轴写入 X/Y/Z 三轴（源站缩放三轴同为 1 时
  统一缩放显示 1.0，符合"三轴同值"读法）。

## 顺带修正的 576 遗留缺陷

1. **摄像机轨道字段恒显 NaN**：batch 576 直接读 `value[field]`，而摄像机
   轨道关键帧 `value` 形如 `{ transform, target, fov }`（`cloneCameraValue`），
   `value[field]` 恒 `undefined` → `Number(undefined)` = `NaN`。而运动轨迹
   页签**唯一的场景就是摄像机**，即 576 交付的字段组在目标上下文里三个
   XYZ 组全部显示 NaN。本批改为：相机轨道取 `value.transform[field]`，
   变换/群组轨道取 `value[field]`（`readKeyframeTransform`）；
2. **字段提交写错关键帧**：`updateObjectTransform` 落在**当前播头**。当
   播头不在选中关键帧时间上时，编辑会静默写到另一个关键帧（或在播头处
   新建一个），与字段所镜像的选中关键帧脱节。本批提交前先
   `setTimelineTime(selectedKeyframe.time)` 对齐（batch 579 起菱形点击已
   seek，此处覆盖程序化选中等其余路径）。
