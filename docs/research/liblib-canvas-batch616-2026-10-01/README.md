## 关于取证条件（先说清楚）

本批的读数是 `probe613i` 在**本轮早前**采到的：1920×1150、导演台打开、选中一个机位。写这批时共享的源站 tab 已被他人改动 —— 视口变成 1600×1000、导演台被关掉了（`probe616` 确认 `rail 场景 present: False`、属性列 `column: None`），因此**无法再做 live 复测**。

所以本批只做能被那批读数**逐字**支撑的事：类名与边宽都是 `probe613i` 实际返回的字符串，原样引用，不重新推导、不外推。

## 两处**不改**的，以及为什么

1. **多出来的两个 36px 工具条**（`h-9 shrink-0 items-center gap-1 border-b border-white/[0.06] px-2`）装的是 clone 自己的分组/机位动作。按既定原则，不删 clone 独有功能来对齐子节点数。列表起点因此比源站低 72px（172 vs 100）—— 这是 (1) 的**后果**而非独立缺陷，记录在验收断言里而不是消掉。
2. **48px 树头里装的东西**：源站是一条 `text-[12px] leading-5 text-white/90` 的文字标题，clone 是搜索框 + 若干按钮（aria「搜索场景内容」）。本批只对齐外框，搜索框保留，并且验收里断言它**仍然能过滤**（输入「机位」后条目数变化，清空后复原）。

第三条差异量到了但不在本批：源站列表起点 100、clone 172，已在上面说明。

## 下一批候选（已记）

- **属性面板的分节结构**：源站滚动区是 6 个 `<section class="border-b border-white/8 px-4 py-4">`（页签行在滚动区**内**、sticky 预览、摄像机属性、FOV、相机截图、隐藏的虚拟相机），clone 是一条 `space-y-4 px-4 py-3` 加若干 `label`/`div`、页签行在滚动区**外**、只有 1 条分隔线。这需要一次 ~400 行的 JSX 重构，且必须先能 live 复测源站。
- **源站的 3D canvas 是满幅** `[0,0,1920,1150]`（`probe614e`），clone 是 `[281,88,1358,880]` 内缩框 —— 取景差异。但源站底部药丸中心在 **844** 而非窗口中心 960，参照系尚未弄清，动手前得先解这个。
