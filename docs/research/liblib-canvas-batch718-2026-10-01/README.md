# batch 718：断点分区完整，「差 1」是 Tailwind 的语义 —— 撤回 717 的待拍板项

日期：2026-10-03　验收器：`scripts/verify-liblib-batch718.py`（6 条判据，零 store 写入，不改 `src/`）

## 起点

717 撞见「`max-[899px]` 字面 899、实际生效 898」，并留下一个拍板项：
**要不要把这类写法统一成无歧义的**。

本批把问题一次性问全：**代码里所有任意媒体查询断点的分区是不是完整的？**
办法是**静态普查（必须排除注释）+ 运行时逐像素验证**。

## 静态普查（排除注释后，`src/` 7 个文件）

| 断点 | `min-[Npx]` | `max-[Npx]` | 分区 |
|---|---|---|---|
| **899** | **15** | **22** | `≥899` ∪ `<899` = **完整** |
| 850 | 0 | 2 | 单向 |
| 680 | 1 | 0 | 单向 |
| 620 | 0 | 1 | 单向 |
| 520 | 0 | 6 | 单向 |
| 480 | 1 | 0 | 单向 |
| 430 | 0 | 1 | 单向 |

**只有 899 是成对的**，而且成对写法正是 `min-[899px]` + `max-[899px]` ⟹ **没有 1px 空洞**。
其余 6 个断点都是单向变体，不存在配对问题。

## 静态普查的第一个结果是假阳性

第一次普查（**没有排除注释**）报出 `DirectorIconRail.tsx` 同时用
`min-[900px]` 与 `max-[899px]`，并据此以为分区漏了 899 那一格。

**那两个 token 只存在于 `DirectorIconRail.tsx:430-436` 的注释里** ——
那正是 batch 623 记录并**早已修好**这件事的地方，原文写着：

> Tailwind v4 把 `max-[899px]` 编译成 `@media (width < 899px)`（≤898）、
> `min-[900px]` 编译成 `@media (width >= 900px)`（≥900），于是 **899 那一格两边都不命中**

代码里实际是 `min-[899px]:flex`。**623 记的、717 又从外面撞了一次的，是同一件事。**

## 运行时：同一个名字，两种边界语义

`vw = 899` 这一格：

| 查询 | 命中？ |
|---|---|
| `matchMedia('(max-width: 899px)')` —— **CSS 原生** | **True（含等号）** |
| `matchMedia('(width < 899px)')` —— **Tailwind v4 变体实际编译成的** | **False** |
| `matchMedia('(width >= 899px)')` | **True** |
| 头部 `padding-right`（`max-[899px]:px-2` 的一处） | 已是 **260px** ⟹ max 变体**没生效** |

⟹ **`max-[899px]` 与同名的 CSS `(max-width: 899px)` 边界相反。**
名字一样，语义差一个等号 —— 这就是那个 1px 陷阱的本体。

## 运行时：分区完整，三个独立探针同步翻转

逐像素扫 894…906，三处**互相独立**的证据在 **898|899** 之间同时翻转：

| 探针 | ≤898 | ≥899 |
|---|---|---|
| icon rail（`hidden … min-[899px]:flex w-12 top-[52px]`） | `display: none` | `display: flex` |
| 头部 `padding-right` | **8px** | **260px** |
| 抽屉 `left`（`min-[899px]:left-12`） | **0px** | **48px** |

每个宽度上**恰好命中一个分支**（互斥且穷尽）⟹ **分区无空洞**。
717 说的「899 本身走宽屏分支」是**构造出来的**：竖条自己的类就是 `min-[899px]:flex`。

## 断点换的是「常驻竖条 ↔ 浮动按钮对」

717 记的两枚 `display` 切换叶子，现在都有身份了：

- **48×1098**（≥899 出现）：`w-12` + `top-[52px]` + `hidden min-[899px]:flex` 的 **icon rail**
- **68×32**（≤898 出现）：`absolute left-3 top-3 z-10 hidden gap-1 max-[899px]:flex`
  的**浮动按钮对**，内含两枚命名按钮「打开场景对象」「打开属性面板」

**两枚切换完全互补**：宽屏给常驻竖条，窄屏把两个面板开关收成一对浮动按钮。
那个容器本身没有 `data-*` 与 `aria-label`，但它是纯 flex 包裹层、两个子按钮都有可及名
⟹ **不是无障碍缺口**。

## 方法论收获（可复用）

**① 静态普查必须排除注释，否则会报出早就修好的 bug。**
本批第一版普查报出「`min-[900px]` + `max-[899px]` 分区漏一格」，
读代码才发现那是 623 写下的**修复说明**。
⟹ **凡是对源码做 token 普查的批次，第一步就要把注释剥掉**，
而且**要同时报告「只在注释里出现」的 token** ——
那既是对普查结果的证伪材料，也常常是「这个问题以前处理过」的索引。

**② 框架变体的名字不必等于它编译出来的查询。**
`max-[899px]` 读起来像 CSS 的 `max-width: 899px`（**含等号**），
实际编译成 `width < 899px`（**严格小于**）。
两者在 `vw = 899` 这一格给出**相反**的答案，而且都能在 `matchMedia` 里直接验证。
⟹ **报「某个断点的实际边界」时，同时报「同名 CSS 查询的边界」** ——
差一个等号是这类问题最常见的形态，而它只在**恰好等于断点的那一格**显形。

**③ 「找一个元素」不要用几何条件。**
本批三处返工都是同一个错：用 `width === 48` 找竖条、用 `68×32` 找按钮对 ——
而**它们在被隐藏的那一侧宽度恰好是 0**。
⟹ **认领元素用稳定的类名或 `data-*`，几何只用来量、不用来认**。
这条与 710 那条「节点 id 从 `closest()` 读、不硬编码」是同一族：
**认领用标识，测量用几何，两者别混。**

**④ 中文断言不要用列表顺序。**
`sorted(['打开场景对象','打开属性面板'])` 按码点排（场 0x573A < 属 0x5C5E），
我写的期望顺序反了，判据误报。**集合比较才是对的写法。**
