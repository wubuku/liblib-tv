### ④ **推翻我自己探针的一处测法错**（本批最要紧的一条）

探针 B/C 把监听挂在 **`capture: true`** 上，然后读 `e.defaultPrevented`：

```js
document.addEventListener('keydown', (e) => { if (e.key === 'Tab' && e.defaultPrevented) n++; }, true);
```

捕获阶段**先于目标节点的处理器**跑，那一刻 `defaultPrevented` 必然还是 `false`
⟹ 读出「被拦 0 次」。**同一组数据在冒泡阶段是 20/20。**

736 的验收器用的就是冒泡阶段，**它的读数没错**；错的是我 737 的中间探针。
若不把这一格重测，本批会写下一条假结论「围栏完全失效」。

### ⑤ 围栏的边界：管得了「里面」，管不了「外面」

`useDirectorFocusContainment.ts:174` 把 `keydown` 挂在 **root** 上 ⟹ 事件不经过 root 就够不着它。

| 起点 | 20 步 Tab 冒泡计数 | 落点归属 |
|---|---|---|
| 台内 | **20 / 20 被拦** | 台内 20 |
| **台外** | **0 / 20 被拦** | **台外 20** |
| 台外 + `Shift+Tab`（起点「项目菜单」） | 17 / 20 被拦 | 台外 1 + body 1 + **台内 18**（**第 2 步就进台内**） |

⟹ 围栏**不能把已经在台外的焦点拉回来**（台外按 Tab 一路走在画布控件上）；
但**反向一步半就能进**，一进去就被接管。
（起点换一个控件读数就变：起点「工作区名称」时第 **0** 步就已在台内、20/20 被拦 ——
**这一格的判据必须点名起点，否则不可复现**。）

### ⑦ 键盘**走不到**台外那个状态

点开「添加角色」flyout 后焦点**留在台内**（停在轨按钮上），
接着 30 步 Tab **30/30 在台内**；连续 8 轮「点开 → Tab 5 步 → 再点」焦点**始终在台内**。

⟹ **围栏的缺口是潜伏的，不是键盘可达的** —— 进去的唯一方式是程序化 `focus()`，

## 方法论

① **「一格读不出来」先怀疑探针的量程** —— 五个入口全读 +0，第一反应该是「我的计数器看不见它们」，
而不是「它们不加东西」。**先量全文档，再量某个子树。**

② **`defaultPrevented` 只能在冒泡阶段读** ——
捕获阶段先于目标处理器，那一刻必然是 `false`。
**同一个量在两个阶段的读数不同，是发现测法错的信号。**

③ **判据必须点名起点** —— 同一段 Shift+Tab，起点「项目菜单」第 2 步进台内、起点「工作区名称」第 0 步就在台内。
**「随便挑一个控件」出来的读数不可复现，也就不能当判据。**

④ **互斥的页签/面板不能相加** —— 735 撞过一次（撤回「97」），737 再撞一次（姿势 45 ≠ 净增 12）。
**报增量要同时报「出现几枚、消失几枚、净增几枚」三个数。**

⑤ **纠错要记在自己的批次里，不改历史批次** —— 736 的读数没错，错的是我 737 的中间探针；
纠正记在本批，历史批次一个字不动。

## 探针返工三处

① **计数器把范围限死在 workspace 根内** ⟹ 5 个 flyout/modal 入口全读 +0；
改成「根内 / 根外」两个桶分别数，才看见 portal 里那 11 枚。

② **`defaultPrevented` 在捕获阶段读** ⟹ 读出「被拦 0 次」这个假结论；
同一份数据冒泡阶段是 20/20。**若不重测，本批会写错一条核心结论。**

③ **判据算术错了三处、首轮 7/10** ——
C6 把 Shift+Tab 的落点写成固定的 18（实际取决于 flyout 开没开、起点是哪个控件）；
C9 把「姿势面板自身 45 枚」当成净增量（实际净增 12，差的 33 枚是属性页被换掉）；
C10 把「flyout 开着时的 47 枚」当成基线（关闭态是 36）。
三处都是**我写判据时算错**，不是产品读数错 —— 与 736 的 C7/C9 同类，两批连续四处在判据算术上栽了。
