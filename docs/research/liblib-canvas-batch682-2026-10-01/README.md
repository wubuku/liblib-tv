# batch 682 —— 把高度扫描推广到全体：**59 枚是「只随高度变」的带状缺陷**，而遮挡区域**永远不是非矩形**

## 一句话

680 只跟了 6 枚控件的 20 格高度扫描，发现它们分属三种驱动。
本批把那套扫描**推广到全部 130 枚控件**，问分类问题：
**哪些控件的「完全不可点」是恒定的，哪些是带状的？**

**答案推翻了整条线索的框定：恒定的那一类，全仓库只有 1 枚。**

## 仪器

`scripts/verify-liblib-batch682.py`，复用 678 的网格 JS。
**2 宽度 × 10 窗高 × 130 枚 × 25 样本 = 65,000 次命中判定**（与 680 同一批格）。
身份用 **(data 键, 盒)**，不按名字（678 的纪律）—— 130 枚落成 **121 个身份**。

## 1. 分类是一个**满划分**

| 类别 | 身份数 |
|---|---|
| `always-fully-blocked`（每个可测格都全被挡） | **1** |
| `varies-by-height-only`（只随窗高变） | **59** |
| `varies-by-width-only`（只随宽度变） | **3** |
| `never-fully-blocked`（每个可测格都至少 60% 清空） | 55 |
| `never-measured`（20 格里都没有视口内样本） | 3 |
| `irregular` | **0** |

**只有一枚是恒定的 —— `data-director-rail-entry=help`（32×32 那个身份）。**

**这细化了 680**：680 说那 6 枚分三种驱动；
本批量到全体后，**「恒定」这一类在全仓库只有 1 枚成员**，
其余 5 枚里 2 枚是带状、3 枚是宽度驱动。

## 2. 遮挡区域**永远不是非矩形**（`irregular = 0`）

`varies-by-height-only` 的定义是「同一宽度下、跨所有窗高取值恒定」；
`varies-by-width-only` 是「同一窗高下、跨所有宽度取值恒定」；两者都不成立才落进 `irregular`。

**`irregular` 的成员数是 0** ⟹ 这批控件的「全被挡格集合」在 (宽, 高) 平面上
**全部是矩形条带**，**没有一枚是 L 形、点状或对角分布的**。

**这是 679 那条结论的更强一版**：679 只证明了单个视口内遮挡比例是 1/25 的整数倍
（盖住者是轴对齐矩形）；本批把它**跨视口**也证明了。

## 3. 59 枚的「全被挡高度集合」只有 **7 条带**

| 全被挡的窗高 | 身份数 |
|---|---|
| {300} | 17 |
| {400} | 3 |
| {500} | 10 |
| {600} | 8 |
| {300, 400} | 9 |
| {400, 500} | 10 |
| {600, 720} | 2 |

（`颜色` / `颜色 hex 值` 的 {600, 720} 就在这里 —— 680 追的就是这一带。）

**59 个缺陷落在 7 条高度带上，而不是 59 个独立的高度。**

## 4. 派生量：只测一格就下全称判断，会判反几枚

| 取样格 | 与全扫描「恒被挡?」相反的身份数 |
|---|---|
| **1280×300** | **29** |
| 1280×400 | 25 |
| 1280×500 | 23 |
| 1280×600 | 13 |
| 1280×720 | 5 |
| 1280×850 … 1280×1700 | **3** |
| 1920×300 | 26 |
| 1920×400 | 22 |
| 1920×500 | 20 |
| 1920×600 | 10 |
| 1920×720 | 2 |
| **1920×850 … 1920×1700** | **0** |

**一格取样的可信度在 0 到 29 之间浮动。**
最差 `1280×300`（29 枚判反），**最好 `1920×850` 及以上（0 枚判反）** ——
**因为所有带都在 H ≤ 720 结束**。

而本仓库惯用的 `1280×1150` 会判反 **3** 枚。

## 5. 第三态：3 个身份从未被测到，其中一个是**被压扁的盒**

- `data-director-rail-entry=help|32x20` —— **`帮助` 的盒在 H=300 时是 32×20，不是 32×32**。
  它的盒在短视口被**压扁**了，随后就没有视口内样本。
  **这正是 680 在 H=300 记「无样本」而不是「可点」的原因。**
- `data-director-keyframe-id=director-keyframe-camera-8|11x11`
- `data-director-keyframe-id=director-keyframe-character-8|11x11`
  —— 两条轨道的**第 9 枚关键帧片**，在全部 20 格里都在视口外。

**这三个是 `missing`，不是「测得可点」。**

## 6. 自记

- 第一版我按 data 键聚合类别，`帮助` 返回 `<2 ids>` 而失败 ——
  **不是代码 bug，是读数**：它在 H=300 有第二个身份（那个 32×20 的压扁盒）。
  改成**聚合时排除从未被测到的身份**，并把被排除的那条单列成第 5 节的读数与一条判据。
- 第一版我把「唯一恒定的一枚」钉成 `== 1`，跑完发现确实只有 1，于是那条断言看起来
  像在钉一个数。**改成钉结构**：四类做成**满划分**（每枚恰好一类、类数之和等于身份数），
  并把 `irregular == 0` 单独列一条 —— **后者才是真正承载「跨视口也是矩形」的那一条。**

## 7. 不声称

- **不声称** 7 条带是精确边界（本次扫了 10 个窗高，带的两端只到**实测点**）；
- **不声称** 130 枚控件的总体（纳入过滤本身是 665 记的盲区）；
- **不声称**「恒定只有 1 枚」在别的视口网格下仍成立；
- **不声称**源站在这些窗高下有同样行为（**未取证**）。
