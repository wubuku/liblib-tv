# batch 694 — 原生 range 普查：**鼠标可达集由像素几何决定，与声明的 `step` 无关**

> 起点：693 在**一枚**控件（FOV 滑块）上量到「同一个控件、两个输入设备、两个不同的
> 可达集」。那是个案还是通例？本批先普查再判定。
>
> 验收：`scripts/verify-liblib-batch694.py`（5/5）　读数：`runtime-audit.json`

## ① 普查：11 枚 `input[type=range]`，4 枚可测，7 枚记为未量

`src/components/director/**` 全部原生 range，声明值数从 **21**（地面不透明度）
到 **361**（全景旋转）差 17 倍。

| 键 | 位置 | 打开它需要 |
|---|---|---|
| `camera-fov` | `DirectorInspector.tsx:1646` | 选中机位 |
| `uniform-scale` | `DirectorInspector.tsx:2531` | 选中机位 |
| `timeline-zoom` | `DirectorTimeline.tsx:1337` | 常驻 |
| `phone-vcam-stability` | `DirectorPhoneVcamPanel.tsx:603` | 虚拟相机面板 |
| `motion-slider` | `DirectorCameraMotionTab.tsx:95` | 摄像机面板「运动轨迹」页签 |
| `scene-scale` / `scene-panorama-rotation` / `scene-panorama-radius` / `scene-ground-opacity` / `scene-ground-height` | `DirectorInspector.tsx:2764…3079` | 场景设置区（需另开） |
| `pose-control` | `DirectorInspector.tsx:1352` | **默认（选中角色）下仍不出现，原因未查** |

未量的 7 枚**不是省略**，每一行都记了「哪个控件能打开它」，下一批可以照单取用。

## ② 两条规则，4/4 成立

| 键 | 轨道 px | 声明值数 | **鼠标可达** | 键盘 |
|---|---|---|---|---|
| `camera-fov` | 170 | 76 | **20** | ✓ |
| `uniform-scale` | 96 | 199 | **11** | ✓ |
| `phone-vcam-stability` | 314 | 101 | **35** | ✓ |
| `timeline-zoom` | 71 | 101 | **8** | ✓ |

- **规则一**：鼠标可达值数 **≤ 轨道像素宽** —— 4/4。一次点击只给一个像素位置，
  所以鼠标区分不出比像素更多的值。**这条规则不需要给浏览器的 thumb 内缩建模**
  （而 thumb 宽度 693 已明确未量）。
- **规则二**：键盘 `Home`=min、每按一次 `ArrowRight` **恰好加一个声明的 step**、
  `End`=max —— 4/4。**声明的量程是真的能到的，只有鼠标给不出。**

## ③ 最刺眼的一枚：96px 可见滑块，声明 199 个值

`uniform-scale`（统一缩放，0.1–10，step 0.05）是**普通可见的原生 range**
（`opacity: 1`，不是盖在自绘轨道下的隐藏原生件）。鼠标只到 **11** 个值：

```
0.1, 1.1, 2.2, 3.2, 4.3, 5.3, 6.4, 7.4, 8.4, 9.5, 10
```

**199 个里 188 个点不到。** 其余几枚是 `opacity: 0` 的隐藏原生件，平台被自绘轨道
盖住、用户看不见；**这一枚的粗步进是肉眼可见的**。

## ④ 更强的一条不变量（本批的主要结论）

「**一个鼠标可达值摊到多少像素**」：

| 键 | 轨道 px | 声明值数 | 鼠标可达 | **px / 值** |
|---|---|---|---|---|
| `camera-fov` | 170 | 76 | 20 | **9.44** |
| `uniform-scale` | 96 | 199 | 11 | **10.67** |
| `phone-vcam-stability` | 314 | 101 | 35 | **9.52** |
| `timeline-zoom` | 71 | 101 | 8 | **11.83** |

**区间 [9.44, 11.83]，离散比仅 1.25** —— 而轨道宽跨 **4.42 倍**、声明值数跨 **2.62 倍**。

⟹ **鼠标可达集由轨道的像素几何决定，与声明的 `step` 无关。**
这比规则一强得多：规则一只是上界、说不出**丢了多少**；这一条把丢失量钉成
一个近似常数，于是丢失**可预测**。

**机制未声称**：为什么是「约十个像素一个值」**没有被量到** ——
thumb 宽度、浏览器的值↔像素映射、控件内部的取整规则**全部未测**。
693 已因同一理由把 thumb 内缩记为推断。本批**只主张这条不变量，不主张它的成因**。

## 自记

- **`[data-director-scene-*]` 不是合法 CSS 选择器**（属性名里不能带 `*`）——
  找「所有以某前缀开头的 data 属性」只能遍历 `el.attributes`。
- **缺席的控件会让整批崩掉**：第一版直接 `scroll_into_view_if_needed()`，
  在不存在的 `pose-control` 上等满 30 秒然后抛异常。**先查存在性再操作** ——
  缺席是一种结果（第三态），不是错误。
- **预期错了一处**：我以为选中角色就能露出 `pose-control`（于是断言 5 可测 / 6 未测），
  实际是 **4 / 7** —— 那个控件在默认状态下也不出现，原因我没查。
  **读数对、预期错** ⟹ 断言改成实测的 4/7，并把 `openedBy` 写成实话。
- **判据名是要进账本的长期主张**：修完断言后把判据名里的「six / five controls」
  一并改成「seven / four」—— **名字和数字不一致，会让下一批读错账本**。
