# batch 649 —— 给画布页那 7 个浮层造**它自己那套竞争集**，而竞争集是**从结构导出**的

## 一句话

648 查出画布页 7 个浮层的打开路径是现成的 store 动作，但**不能**套 626 的尺子
—— 626 的 `PANELS` 六项全是导演台选择器，套过去结构半恒空。
本批**不再手写第三份名单**，改成从结构导出竞争集，
**先拿 626 的已知答案校准**，再把那 7 个浮层量完：
**21 格、192 枚活控件、0 伤亡**，并挖出一条**真实但潜伏**的结构重叠。

## 1. 为什么不再手写名单

640/641/642 那一串教会一件事：**手写的选择器清单必然过期**。
626 的 `PANELS` 就是这样过期的 —— 它对导演台是对的，对画布页**一条都不命中**，
于是 648 只能说「尺子够不着」。

本批改成：

    竞争集 = { 与浮层矩形相交 ∧ 非祖先非后代 ∧ 自己形成层叠上下文 的元素 }

**没有任何一个选择器被写死**，所以这套尺子换页面也成立。

## 2. 校准：新尺子先在已知答案上跑一遍

一把新尺子必须先校准。626 的 3 个导演台浮层有已落盘的答案，导出式尺子重跑它们：

| | 结果 |
|---|---|
| 结构半 | **9 格逐格与 626 一致**（全是 `structBad=[]`），盒坐标也一致 |
| 伤亡半 | **按设计就该不同** —— 649 的门槛多了「≤1px」与「clip/clip-path」，正好排掉 648 那枚 `sr-only` |

**伤亡半的差异是被钉住的**：它必须**只**出现在 `model-library-panel` 上。
若别处出现新的伤亡差，这条照样变红 —— 所以它是**断言**，不是放行。

## 3. 导出式比手写式宽多少

| | 画布页上的竞争者数量 |
|---|---|
| 626 的手写 `PANELS` | **0**（六项全不命中 → 结构半空转） |
| 649 的导出式 | **21 格全部非空**，3…41 个/格，全角合计 **308** |

**结构半也顺带收紧了**：649 把「z 更高」这个说法**拿 `elementsFromPoint` 交叉校验**
—— 候选必须**真的出现在交集区域的绘制栈里**才算。
第一版没有这一步，把 `nav.pointer-events-none.fixed`（z 70）报成「画在资产面板之上」：
**z 序上成立，事实上不成立** —— 顶栏是 `bg-transparent`，它什么也遮不住。
这与 640/641 用地面真值校验探针是同一条纪律。

|---|---|---|---|---|---|---|

**伤亡半 21 格全 0**（192 枚活控件）。
**7 个都不是 `pointer-events:none` 浮层**（否则伤亡半会平凡成立）。
**菜单没有一个破 8px 安全边** —— 而 626 在导演台找到过两个破的。

## 5. 真发现：两个通高抽屉**都**滑到顶栏底下

`asset`（320 宽左抽屉）与 `agent`（400 宽右抽屉）都是 `inset-y-0` 通高、`z-50`。
顶栏是 `fixed left-4 right-4 top-4 z-[70] h-8` —— **横跨整个窗宽、z 更高**，
而且压住它们的是顶栏里**不透明**的簇按钮（`bg rgb(38,38,38)`）：
`a.flex.h-8`（左抽屉）/ `button.flex.h-8`（右抽屉）。
资产抽屉还额外丢掉右下角给 `div.fixed.bottom-[18px]` z-60。

**导出的常数：盖住者的底沿恒为 48 = `top-4` 16 + `h-8` 32，三视口逐格一致。**

**但它不是缺陷 —— 潜伏而已。** 理由有两条，都被量了：

1. **伤亡半全 0。**
2. **矩形读数与可点性读数是两个问题。** `agent` 抽屉第一枚活控件的**顶边在 y=14**，
   比盖住者的底沿 48 **高出 34px**（矩形余量 **−34**），可它的伤亡**仍然是 0** ——
   因为探针取的是控件的**中心**，不是顶边。
   **这正是 646 那条「矩形测试 ≠ 中心测试」，在画布页上的同一形状。**

所以处置是**记下来、判成潜伏、钉死常数**，不写成缺陷。
（`asset` 的矩形余量是 −640/−820/−1070，因为它的最底那枚控件被底栏那簇覆盖 ——
同样 0 伤亡。）

## 6. 菜单 vs 抽屉：8px 安全边不能混用

626 的 8px 安全边是**菜单**的不变量（它就是为两个破了的导演台菜单设的）。
第一版把它套到资产抽屉上，报它「超标恰好 8px」——**也就是「齐着窗边」，而那正是通高抽屉该有的样子**。
与 648 把 626 的 `PANELS` 套到画布页上是**同一类范畴错误**。

于是规则拆成两类，并断言**两类都非空**（否则拆分本身空转）：
`kind = panel` 当且仅当 `高度 ≥ 90% 视口高`。
**5 个菜单 0 破边，2 个通高抽屉按自己的规矩记。**

## 7. 我自己写错的三处

1. **结构半只信 z 序** —— 报出 `nav.pointer-events-none.fixed`（z 70）是假阳性。
   改成拿 `elementsFromPoint` 在**交集区域**交叉校验；候选必须真的在绘制栈里。
2. **把菜单的安全边套到通高抽屉上** —— 报资产抽屉超标 8px。改成 menu/panel 分类，
   并断言两类都非空。
3. **常数钉错了一个量** —— 我断言 `overlapDepthY == 48`，但那是**交集高**（32）；
   真正的导出常数是**盖住者的底沿**（48 = 16 + 32）。红是对的。
   顺带在同一轮里发现 `agent` 的矩形余量是**负 34** 而伤亡是 0 ——
   矩形读数与可点性读数不是一回事，于是把「清白」也改成**逐格伤亡为 0** 来断言。

## 8. 本批**不**主张的事

* **不主张**画布页那 7 个浮层没问题 —— 只主张它们**现在被量到了**（21 格 / 192 控件）。
* **不主张**两个抽屉滑到顶栏底下是缺陷 —— 它是**实测到的结构事实**，判成潜伏。
* **不主张**导出式尺子是更好的尺子 —— 只被证明**在两个页面上与手写式一致**。
* **零源站断言**。
