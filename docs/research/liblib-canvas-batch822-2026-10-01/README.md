# batch 822 —— 导演台·追加运镜：**那条边界恰好晚 2 毫秒**

> 821 记了两条拒绝分支（跟随目标、锁定），「不声称」里明写
> **分支序3（append 无可追加时长）没测** ⟹ 本批补它。
> 补完才看清一件事：**三条分支共用两条通道，而这两条通道都会说错话。**

## 一、起点：前提天然成立

`directorStore.ts:7600` 分支序3 的拒绝条件：

```js
if (mode === "append" &&
    (!lastKeyframe || lastKeyframe.time >= state.timeline.duration - 0.001))
```

侦察读数：种子里相机轨道 3 个关键帧、时间 `[0, 4, 8]`、总时长 `8`
⟹ `8.0 >= 8.0 - 0.001` **成立** ⟹ ★ **不需要造任何状态**，
打开导演台就能走进这条分支。

★ 顺手更正 821：「要把播放头拖到时间轴末尾才能造出那个状态」**是错的** ——
**这个条件跟播放头一点关系都没有**。

## 二、★★ 那条边界，比时长框能表达的最细刻度**晚 1 毫秒**

`DirectorTimeline.tsx:192`（ms 模式，**默认单位就是 ms**）：

- `format = String(Math.round(seconds * 1000))` ⟹ **框里只能表达整数毫秒**
- 而容差是 `0.001` 秒 = **正好 1 毫秒**

| 总时长取值 | `last(8000) >= dur - 0.001` | 结果 |
| --- | --- | --- |
| 序8000ms | `8000 >= 7999` | 拒 |
| ★ **序8001ms** | `8000 >= 8000` | ★ **拒** |
| ★ **序8002ms** | `8000 >= 8001` | ★ **过** |

⟹ ★★ **「加一点点就行」这个最自然的猜测，恰好是错的那个**；
真实临界点在 **+2ms**，比 UI 能表达的最细刻度**晚一格**。

★ ★ 我原本还假设「敲 `8000.5` 落进容差内部、可以绕过」⟹ **实测是错的**：
`8.0005 - 0.001 = 7.9995`，而末关键帧是 `8.0` ⟹ `8.0 >= 7.9995` **成立** ⟹ 仍拒。

⟹ 但冒出一条独立读数：`parse`（`:193`）**不校验整数** ⟹ store 里真存了 `8000.5ms`，
而框里 `format` 立刻 `Math.round` 回 **`8001`** ⟹ ★ **框里显示的数与 store 真值可以差 0.5ms，用户无从察觉**。

| ★★ S8 | 面板内绿色「追加运镜 · 环绕」＋ 面板外「跟随…」**同屏** | ★ `:1468` 是 `error ?? application ?? 占位`，**error 优先** ⟹ 所以这条臂一次失败都不能插 ⟹ ★ 绿色那行是**上一次**的结果，此刻**根本不能再追加** |

## 四、★★★ 「追加」是一个没有终点的循环

| 时刻 | 末关键帧 | 总时长 | 关键帧数 | 结果 |
| --- | --- | --- | --- | --- |
| 臂7·成功 | 8000 → **9000** | 9000 | 3 → **11** | 成功状态 `start=8000ms`／`end=9000ms` |
| 臂9·**紧接着再按一次** | 9000 | 9000 | **11（一点没长）** | ★ **又拒** |

源码 `:7656`：`[...track.keyframes, ...generated.slice(1)]` ⟹
生成 9 个、**只接 8 个**，首帧沿用旧值 ⟹ 3 → 11 的**净增 8**。
而新关键帧一路铺到**新的总时长** ⟹ 末关键帧又贴住了 ⟹ 条件**重新成立**。

⟹ ★★ 用户每想追加一次，就得**先把总时长再拉长** ⟹ **没有终点**。

## 五、★★ 框里的数字和真实的总时长对不上

`setTimelineDuration`（`:6903`）把时长**钳到不早于最后一个关键帧**：

| 读数 | 值 |
| --- | --- |
| 用户写入 | `8000` |
| ★ **失焦前框里显示** | **`8000`** |
| store 真实总时长 | **`9000`** |
| DOM `data-...-duration` | **`9000`** |
| ★ **失焦之后框里显示** | **`9000`** |

⟹ `draft` 是受控 state、`useEffect` 依赖 `[value, unit]` ⟹ **value 根本没变 ⟹ effect 不触发 ⟹ 框里继续显示 8000**。
⟹ ★ 这是「**乐观显示 + 失焦纠正**」：用户在编辑过程中会盯着一个**根本没生效**的数字。

## 六、★ 面板开着时点时长框，面板会被点关

`DirectorTimeline.tsx:576` 的 `pointerdown` 外部点击关闭 ⟹ 点框 = 面板外点击。
⟹ ★ 而时长框**恰恰是解开「追加被拒」的那把钥匙**
⟹ 用户的真实路径要多绕：关面板 → 改时长 → **重开面板** → **重选「追加运镜」** → 再按预设。

★ 好消息（对用户有利的一面）：`presetMode` 的 `useState` 在 `DirectorTimeline` 里、面板是条件渲染
⟹ ★ **关掉再打开面板，模式不会被重置回「替换运镜」**。

## 七、这一批的探针缺陷（两处，**两处都造出了假结论**）

| # | 现象 | 真因 |
| --- | --- | --- |
| 序1 | 逐字符 `keyboard.type` 敲时长，读出 `900.005` 这种数 | ★ 时长框 `onChange` 里**立刻 commit**，而 `useEffect` 又把 draft 重置 ⟹ **连续键入互相打架**；那个数是**光标落点 + 交错提交**的产物、**不是产品行为**。改法：`Meta+A` 后 **`fill()` 一次性**提交 |
| 序2 | 「臂2 之后面板怎么没了？」差点被当成「面板自己会关」 | ★ **不是产品 bug** —— 是序1 的写法让 `pointerdown` 落在了面板外。★ 但顺着查出了 `:576` 那条**真实**的外部点击关闭（第六节）⟹ ★ **基线红 ⟹ 先怀疑探针** 这条纪律又救了一次 |

★ 另有一处**判据差点失真**：第二版探针只记了「失焦之后」的框里显示，
而 `onBlur` 的 `setDraft(format(value))` 会**当场把不一致抹掉** ⟹
补了「失焦前显示」那一行之后，第五节那条读数才拿得到。
