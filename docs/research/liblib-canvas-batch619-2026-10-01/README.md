618 的抽屉那条腿是**手工排除**的 —— 普查把两样并非缺陷的东西报成缺陷：全屏遮罩自身的中心（它本来就该落在它所遮的面板底下），以及被打开的抽屉盖住的一切。618 把原因写进了 audit，但没解决，于是这条成为本批靶心。

## 两条豁免规则

### 规则一：遮罩不是控件

**判据**：一个控件若**铺满自己的包含块**、有底色、且自身没有文字，它就是「点空白处关闭」的那种捕捉器 —— 它的中心**理应**落在它所遮的东西底下。

**第一版写错了**：我先按「覆盖视口约 90%」来判，结果规则**一次都没触发**。实测移动端遮罩是工作区那一格里的 `inset-0`，在 390×844 下只占视口约 68%。看起来对的做法在这儿是错的 —— 「铺满包含块」才是它真正的形状。

### 规则二：被已打开的临时浮层盖住，不是缺陷

**判据**：从**实际抢到点击的那个元素**向上找祖先，若它落在某个「已打开的临时浮层」里，这枚控件就记到那个浮层名下（`coveredByPanel`），不算缺陷。

**中间试过一版更聪明的写法，没成**：按命中元素做 key 分组，若某个命中者占了大半就整体豁免。失败原因是抽屉内的控件命中的是抽屉**最内层**的元素（一个普通 `div 属性姿势`），于是一堆互不相同的 key，规则永远看不出「这是同一个面板」。**从命中元素往上走**既更准也更强：抢到点击的元素按定义就在浮层内部，归因不可能是巧合。

**再往前一版也错了**：用「浮层矩形是否完全包住控件」判断。上下文菜单只盖住旁边行按钮的**右半边**（`隐藏/锁定/删除` 24×24 那一列），于是 12 枚一枚都没被豁免 —— 这正是第一版把场景树右键菜单报出 12 条遮挡的原因。

**为什么用具名清单而不是面积阈值**：面积阈值两个方向都错。全屏模态根本不需要借口，而 200×300 的 flyout 需要；同时常驻 chrome（281px 的属性列、时间线条）又大到会被误认成面板。真正区分它们的是**意图**，而这套代码里意图本来就记着 —— 每个临时浮层都带 data 属性（`data-director-tree-context-menu` / `-panorama-flyout` / `-character-flyout` / `-aspect-flyout` / `-geometry-submenu` / `-motion-path-menu` / `-camera-preset-panel` / `-export-panel` / `-ai-import-backdrop` / `-ai-import-modal` / `[data-director-mobile-panel-state="open"]`），且只在打开时挂载。匹配到即证明它开着。每一条归因都写进 audit，不吞掉。

`covered` 保持 617 的原义 —— **z 序缺陷**。617 与 618 的断言一字未改，照旧全绿。

验收不只看「零遮挡」，还钉住**豁免规则确实触发过**，否则规则是死代码、扫描会空转通过：每个浮层态都断言「该浮层被找到处于打开」+「归因到至少一枚控件」或「该浮层一��控件都没盖」（导出面板在 1920 确实不覆盖任何控件，这条断言反而更强），外加一条**归因无遗漏**：非滚动原因的失败数 == 缺陷数 + 已归因数，任何一枚控件不许掉进两个桶之间。抽屉态另有一条：遮罩必须出现在 `scrims` 里（即它没被当成控件审计）。

## 顺带挖出的真缺陷：窄屏导出面板被视口底条压死

第一条腿（390 导出面板）报出一条**没有任何浮层可归因**的遮挡：导出面板自己的提交按钮「导出视频到画布」（`data-director-export-submit` @`[109,624,260,32]`）。

`dbg619c.py` 追出命中链：抢到点击的是 `div[data-director-viewport-toolbar]`，它的父级 `div[data-director-bottom-bar]` 是 **`absolute inset-x-0 bottom-0 z-[200]`**，占据 y 620..668 —— 导出面板从工具条右格**向上**弹出（`bottom-full`），390 下正好落进这条带里。两者不在同一个包含块：底部条在 `main` 里，时间线 section 是兄弟节点，于是 **z-200 的底部条赢了 z-40 的时间线**。

1920 下不重叠（面板在 x 1626..1912，底部条居中在 ~780..1140），所以此前几批都没看见。

**抬的是时间线，不是压底部条**：底部条的 200 是 batch 604 **从源站实测抄来的解析值**（`z-(--z-sticky)`），不能为了 clone 的浮层把它改掉；何况角色浮标是 `pointerEvents:"none"` + `zIndexRange [40,0]`，底部条并不需要 200 那么高来压它们。

```jsx
"z-40 … backdrop-blur-xl max-[899px]:h-[176px]",
"max-[899px]:z-[210]",     // 必须压过视口底条的源站实测值 200
```

**只在窄屏抬**：桌面上抬到 210 会越过场景树右键菜单的 `fixed z-[120]`，把贴着视口底边打开的菜单下半截盖掉，而桌面根本不需要这次抬升。改后 390 与 1920 的提交按钮都是 `hitIsTarget: true`。

## 更正：618 那条「导出面板打开」的腿其实没打开面板

619 给浮层态加「面板必须真的可见」断言时，618 的导出面板腿红了 —— 它点的是 `[data-director-project-export]`，那是**顶栏的项目 JSON 导出**，直接下载文件、根本不打开面板。也就是说 618 那一版普查的是**未打开任何浮层的桌面态**，却在标签和 README 里声称是「导出面板打开」，并据此写下「batch 611 修过的那个 z 序问题在窄屏没复发」——**那句不声称**。已改点 `[data-director-export-trigger]` 并在 618 的 README 写明更正。改点之后才暴露出上面那个真缺陷。
