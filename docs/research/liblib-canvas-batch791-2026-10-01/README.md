## ★ 本批修了**两个**缺陷，第二个是做回归臂时撞出来的

| 编号 | 缺陷 | pre 实测 |
| --- | --- | --- |
| D791-1 | 监听器注册在**冒泡**阶段，而 React Flow 在 pane 处 `stopPropagation` ⟹ **收不到** | 双击空白画布 面板条目 0 → **0** |
| D791-2 | 闸用 `closest('.react-flow__pane')`，但 v12 的 pane 是 viewport 的**最外层**、节点在它**里面** ⟹ **挡不住节点** | 双击**节点** 面板条目 0 → **9**（误开） |

### D791-1 的机制（运行时读数，不是抄 758）

| 计数器 | pre |
| --- | --- |
| 容器**捕获** | **1** |
| pane 冒泡 | 1 |
| 容器冒泡 | **0** |

事件路径：容器捕获 → pane 冒泡 → **断**。挂在容器上等冒泡的那个监听器
**永远收不到**。捕获阶段自顶向下、**先于** pane 上的处理器 ⟹ 改
`{ capture: true }` 就能收到。

### ★ D791-2 为什么不算「发明」

源码注释写的是「源站**空**画布双击 = 打开添加节点面板」——「空」字就是契约。
而运行时读到的 v12 DOM 是：

```
.react-flow__renderer > .react-flow__pane > .react-flow__viewport
                                             > .react-flow__nodes > .react-flow__node
```

`.react-flow__pane` 是 viewport 的**最外层**容器，节点在它**里面**
⟹ `closest('.react-flow__pane')` 对**节点**双击同样为真，那道闸从来没生效过。
而空白处双击时 `elementFromPoint` 命中的正是 pane **自己**
（`isPaneItself=true`）⟹ 正确判据是 `classList.contains`。

## ★ 758 列的第三个修法**不可用**

758 给了三个方向，其中「改用 React Flow 的 `onPaneDoubleClick` prop」在
`@xyflow/react` v12 **不存在**（验收器 `S9` 会去 `node_modules` 里数）。
⟹ 只剩「挂到 pane 上」与「改捕获阶段」，而运行时读数（容器捕获 = 1）支持后者。
