# batch 731 — 换一条通道：在无障碍树里，「已接线」和「未接线」是同一种东西；顺带推翻 730 自己一句话

## 起点

730 用 **DOM 通道**证明：46 处 `data-inert` **一处都没挡住可聚焦性**
（43/43 `focus()` 成功、43/43 聚焦时焦点环变化、Tab 停靠重数 === 挂载重数）。

但 730 的 README 顺手写了一句：

> 19 处 `data-inert` 按钮没有 `aria-label` —— 它们的可及名只能来自可见文字。
> **纯图标按钮会得到空的可及名**：运行时 `video-card` 视图里那两枚就同时既无
> `aria-label` 也无文字。

**那句话没有被测过**，是推断。本批去测它 —— 而且**换一条独立通道**：
不看 DOM 属性，直接读浏览器自己算出来的**无障碍树**
（CDP `Accessibility.getPartialAXTree`，逐元素按 `backendNodeId` 取）。

## 口径

- **静态**：同 730 —— 扫 `src/**/*.tsx`，排除 `app/frameos`/`components/frameos`/
  `components/jimeng`；先抹注释再匹配开标签。
- **运行时**：clone `http://localhost:4317`，1280×1150，导演台**全程关着**，
  同样 7 个视图、同样 **43 枚**挂载。零 store 写入。
- **无障碍树**：`Accessibility.enable` + 对每个 `button[data-inert]` 的
  `backendNodeId` 取 `getPartialAXTree(fetchRelatives=False)`，
  读 `role` / `name` / `ignored` / `ignoredReasons` / `properties`。

## 决定性读数

### ① 静态：19 / 46 没有 `aria-label`，且 19 处**全都带 `title`**

| 口径 | 数字 |
|---|---|
| `data-inert` 写点 | **46**（16 个文件） |
| 带 `aria-label` | **27** |
| **不带 `aria-label`** | **19** |
| 19 处里带 `title`（含 `title={`${label}在克隆侧尚未接入`}` 这类表达式） | **19 / 19** |

### ② AX 树逐条复现 730 的 DOM 读数：43 枚全是 `role=button`、`ignored=false`、`focusable=true`

独立通道给出同一结论 ⟹ **730 那格不是探针的错觉**。

### ③ **AX 树里没有 `disabled`：未接线与已接线的 `properties` 逐字相同**

```
未接线（43 枚全部）： {"focusable": true, "invalid": "false"}
已接线「教程」      ： {"focusable": true, "invalid": "false"}
已接线「项目菜单」  ： {"focusable": true, "invalid": "false"}
已接线「缩放选项」  ： {"focusable": true, "invalid": "false"}
已接线「添加节点」  ： {"focusable": true, "invalid": "false"}
```

⟹ **屏幕阅读器面前，「已接线」和「未接线」是同一种东西**：
role 相同、状态相同、**没有任何「这个不能点」的信号**。
这与 730 在 DOM 通道上的结论（`disabled` 0/46、`aria-disabled` 0/46）合流 ——
**两条通道都没有留下禁用语义**。

### ④ 纠正 730：可及名**兜底到 `title`**，没有一枚是空的

730 那句话**错了**。那两枚既无 `aria-label` 又无可见文字的按钮，
AX name 是：

| AX name（= 可及名） | 来源 |
|---|---|
| `该功能在克隆侧尚未接入` | **`title` 兜底** |
| `该设置在克隆侧尚未接入` | **`title` 兜底** |

**不是空名，是「失败说明句」当成了按钮的名字。**
所以 730 待拍板 2 的原话「纯图标按钮会得到空的可及名」**作废**，
改成：**「纯图标按钮的可及名会变成失败说明句」**。

而且这两条 `title` 是**泛指**的（「该功能」「该设置」）—— 连是哪个功能都没说。
这与 729 记录的「三枚芯片 toast 逐字相同」是同一族问题：
**未接线控件给用户的说明彼此无法区分**。

### ⑤ `title` 只在「既无 `aria-label` 又无文字」时才参与命名 —— 污染面很小

43 枚去重后 **25 种身份**，可及名来源分布：

| 来源 | 身份数 |
|---|---|
| `aria-label` | **13** |
| 可见文字（内容） | **10** |
| **`title` 兜底** | **2** |
| 空 | **0** |

⟹ 「补 `title`」这一步**是对的**，它兜住了命名（43 枚零空名）；
**代价集中在纯图标那一小撮**：25 种身份里只有 **2 种**的可及名被 `title` 污染成说明句。
有 `aria-label` 或可见文字时 `title` 不参与命名 —— 所以
**「加了 title 就有名字了」是不完整的说法**。

## 不声称

- **不声称静态的 19 处里有多少是纯图标** —— 分类需要求值 JSX 表达式
  （`.map()` 的 `{label}`、`{generationSettings}`、`{mode ?? "默认模式"}`）；
  本批试过用正则分类，**它把带「时间倒序」「周星驰经典名场面」等文字的按钮
  也判成了纯图标** ⟹ 正则分类在这一族上不可用，**故不在静态侧分类**，
  分类只在运行时（以 AX name 与可见文字比对为准）做。
- **不声称 AX 树等同于真实屏幕阅读器的播报** —— 这里读的是浏览器算出的
  `role`/`name`/`properties`，不是 NVDA / VoiceOver 的实际输出。
- **不声称 46 处 `data-inert` 都是「未接线」** —— 沿用 729。
- **不声称这构成可及性缺陷的裁决** —— 本批只报告「这条通道上留下了什么」。

## 新增待拍板

1. **730 待拍板 2 收窄** —— 原话「纯图标按钮会得到空的可及名」**作废**；
   改成「**可及名会变成失败说明句，且这两条 `title` 是泛指的**」。
   要不要给纯图标按钮补 `aria-label`（名字写成功能名，失败原因留在 `title` 里）？
   **需改 `src/`，等授权。**
2. **43 枚里 0 枚在 AX 树里有 `disabled`** —— 与 730 待拍板 1 合并：
   `data-inert` 在 **DOM 通道与无障碍树通道两条上**都没留下「不能点」的语义。
   要不要补 `aria-disabled`？**需改 `src/`，等授权。**
3. **两条泛指 `title` 要不要写具体**（`该功能在克隆侧尚未接入` → 具体是什么）——
   与 729 的「三枚芯片 toast 逐字相同」合并成一条：
   **未接线控件给用户的说明彼此无法区分**。

## 方法论

1. **换一个通道复验上一批的结论** —— 730 用 DOM，731 用无障碍树；
   两条通道在 `role` / `focusable` 上逐条吻合，才敢说 730 那格不是错觉。
2. **顺手写下的话也是结论，也要被测** —— 730 的「纯图标按钮会得到空的可及名」
   是推断，本批一测就错 ⟹ **写进 README 的推断要标明它没被测过**，
   而「读数对、理由错」这一档（本批就是）要把纠正记在下一批而不是改历史。
3. **静态不要分类 JSX 表达式** —— `.map()` 的 `{label}`、`{mode ?? "默认模式"}`
   只有运行时知道；正则分类会把带文字的判成纯图标（本批实测踩到）。
   **该交给运行时就交给运行时。**
4. **`title` 是兜底不是命名** —— 有 `aria-label` 或可见文字时 `title` 不参与命名 ⟹
   **「加 title 就有了名字」是不完整的说法**；要说清代价落在哪一撮上。
5. **对照要选对** —— 与未接线按钮对照的必须是**同一批视图里真接线的按钮**，
   否则「两者不可区分」这句话就没有基线。

## 探针返工两处

1. **静态正则只认字面量 `title="…"`** —— 三处写点的 `title` 是含嵌套花括号的
   JSX 表达式（`` title={`${label}在克隆侧尚未接入`} ``、`title={why}`），
   断言「19 处都带 `title`」因此红了两轮 ⟹ 改成只断言**属性在不在**
   （`title=` 到空白为止的那一串），不去求值内容。
2. **第一版漏掉了 agent 视图** —— 挂载数只有 38 而不是 43，
   断言当场失败 ⟹ 补上顶栏「Agent」那一格，与 730 的 43 枚对齐，
   这样两批的覆盖口径才可比。
