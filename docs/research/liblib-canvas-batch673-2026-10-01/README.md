# batch 673 —— 按名字计数的普查，**28 枚控件被静默折叠**

## 一句话

672 归因时撞见一件小事：gizmo 那 3 个拖动说明标签其实来自 **9 个元素**
（每个标签 3 层嵌套同名），而本仓库所有普查的 `lab()` 都读 `textContent`。
672 把它记成「第 11 个盲区形状：身份按文本折叠」。

**一个形状不等于一个人口。** 本批去数它有多大，并回答「它咬到过历史吗」。

## 1. 人口：130 控件只对应 102 个名字

| 量 | 1280 | 1440 | 1920 |
|---|---|---|---|
| 控件 | **130** | 130 | 130 |
| **不同名字** | **102** | 102 | 102 |
| **被名字吞掉的控件** | **28（21.5%）** | 28 | 28 |
| 碰撞名字 | **8** | 8 | 8 |
| 涉及控件 | 36 | 36 | 36 |

碰撞名单（三视口逐格相同）：

| 名字 | 倍数 | 是什么 |
|---|---|---|
| `当前帧有关键帧` | **11** | **9 枚 20×28 轨道片 + 2 枚 24×24 检视器钮** |
| `<input>` | **10** | **1 枚 248×28 + 9 枚 59×28**；且 `<input>` **不是名字**，是 `lab()` 三个来源全落空时的兜底串 |
| `左右拖动调整 X/Y/Z 轴` | 各 **3** | 20×28，每个相机行一枚 |
| `上一关键帧` / `下一关键帧` | 各 **2** | 24×24，每个时间轴对象行各一枚 |
| `收起属性` | **2** | 20×20，每个对象行各一枚 |

## 2. 两类折叠，**第二类才狠**

| 类 | 名字数 | 含义 |
|---|---|---|
| **同类重复** | **6** | 同一个控件在每个行/格重复一份（`收起属性`×2、`上一/下一关键帧`×2、三条拖动标签×3） |
| **异类合并** | **2** | **两个不同的控件共用一个可及名** |

`当前帧有关键帧` 是最刺眼的一个：**时间轴轨道里 9 枚 20×28 的关键帧片，
和检视器里 2 枚 24×24 的关键帧钮，名字完全一样。**
**一个按名字建的字典会把它们并成一条。**

## 3. 咬合：这些名字在既往验收器里被当键用过

用 `ast` 精确普查 `scripts/verify-liblib-batch*.py`（**排除本文件**）：
名字字面量出现在**代码**（排除注释与 docstring）且处在
**比较 / 下标 / 字典键 / 集合或列表成员**位置的次数。

| 量 | 值 |
|---|---|
| 扫过的文件 | **370** |
| 有命中的文件 | **9** |
| 键用总次数 | **27** |
| 被咬的碰撞名字 | **7 / 8**（只有 `<input>` 无人拿它当键） |

最严重的那个：**`收起属性` 活体有 2 枚，却被 4 个验收器当键用过** ——
`593 / 661 / 664 / 667`，**其中 661/664/667 的推理正是按名字做的**。
其余：`上一/下一关键帧` 各 2 个文件（591/593）、`当前帧有关键帧` 2 个（593/610）、
`左右拖动调整 X 轴` 3 个（609/612/672）、`Y 轴` 1 个（672）。

**不声称**这些历史结论因此是错的 —— 多数是「在某一格量到某一枚」，
不受折叠影响。**本批只主张：按名字聚合的那些读数有歧义。**

## 4. 这条普查量到了它自己（记下来，不藏）

普查覆盖「它所在的语料」，而语料里包含**引用了这些名字的既往验收器**。
更糟的是**它自己的源码里也有**（`bite_files["收起属性"]` 就是一处下标键）。

于是同一个普查在三次运行里给出 **7 → 6 → 7** 个被咬名字 ——
**纯粹因为我在这三次运行之间改了这个文件**。

处理：
1. **普查排除自身源码**（`selfExcluded` 记在载荷里）；
2. **不钉死那个计数**，只断言稳定部分（9 个文件、`收起属性` 4 个文件），
   把实数记下来。**一个会因自身编辑而变的数字，钉死它就是造一条会因
   记账理由失败的测试。**

## 5. 本批自己犯的错

1. **第一版探针把祖先也算进「同名」**（祖先的 `textContent` 天然含后代文本），
   报出「折叠 263 / 703 个元素」—— **高估**。限制在普查口径内的控件之后，
   真数字是 **28 枚控件**。**两个数都不该报，正确的只有后者。**
2. **断言「每组都在格点阵上」是错的**：`当前帧有关键帧` 那 11 枚
   是 3×3 格阵**加几枚散兵**（x 步长出现 957 这种非格值）。
   改成「同组盒宽高相同」后**仍不成立**（20×28 与 24×24 两种）⟹
   最终换成真正的发现：**异类合并**。
3. 又一次把读数纠正前的预期写进断言（`keyUses == 26`、被咬名字 7 个）。

## 6. 不声称

* **不声称**历史结论错了（见 §3 末）。
* **不声称**这 8 个碰撞名字是全部的折叠情形 —— 本批只普查了
  **导演台打开态、三个视口、这一套 `SEL` 口径**。
* **不声称**「同名」在源站也成立（那是 clone 的结构）。
* **不声称**第 11 个盲区形状已找齐（这是本批第一次给它人口，不是最后一次）。
