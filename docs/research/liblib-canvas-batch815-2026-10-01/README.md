814 只比了**文本**，没比**位置**。本批补上几何：

判据读的是 DOM `getBoundingClientRect`（**用户看得见的几何**），
**不读 store 的 `position`** —— 809／810 的规矩。

### 机理可归因

`src/store/canvasStore.ts:1784-1792`：

```
const sourcePosition = getAbsoluteNodePosition(source, nodesById);
...
position: {
  x: sourcePosition.x + sourceWidth + offset.x,
  y: sourcePosition.y + offset.y,
},
```

位置是「**源节点**绝对位置 + 源宽 + offset」。而连点三次的 `sourceId`
**每一次都是同一个源节点** ⟹ 三次必然算出**同一个坐标**。

★ 注意 `:1785` 的 `nodeId = \`${type}-${Date.now()}\`` —— id **是**不同的
（实测三个 id 毫秒戳各异），所以它们是**三个真实的节点**，只是**压在同一个位置**。

### 真实后果

- 用户在画布上**只看到一份**（三份压在一起，Z 序最上面那份挡住其余两份）；
- 但 store 里有**三份**、撤销栈里有**三条**记录；
- ⟹ 「点三次」的**反馈**和「点一次」**完全一样**。

## 四、★ 探针返工两处（一处是假红、一处是字段缺失）

## 五、★ 判据上我踩的第三个坑（不是假红，是**预期写错**）

我给 S6 配了一条「反向对照」：把每一份都标成选中，**期望它不翻**
（理由是「S6 明确排除选中态」）。它**翻了**。

查下去：**它翻是对的**。「同一 kind 的多份文本逐字相同」这个主张
在**零可比样本**时本来就**无法成立** ⟹ 判据理应可证伪。
那不是「反向对照」，那是**一条正当的可证伪点**。

★ 教训：「我以为它不该翻」之前要先问
**「这条判据在这种输入下应不应该成立」**，而不是先问「它翻没翻」。
（第一版曾把「三类互斥」当成可证伪判据、配了个打不中的对照 —— 同一类错误。）

最终拆成两条：

| 对照 | 变异 | 期望 | 实测 |
| --- | --- | --- | --- |
| N8 | 每一份都标成选中（**零可比样本**） | **S6 必须翻** | 只翻 S6 ✔ |
| N9 | 只把**选中**那一份的文本改成完全不同的内容 | **不翻** | 未翻 ✔ |
