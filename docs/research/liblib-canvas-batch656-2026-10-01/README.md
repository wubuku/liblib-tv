# batch 656 —— 答 655 **明确答不了**的那一条：rail 入口枚举出 7 个，其中 3 个从没被驱动过；而**第一跑推翻了我自己的仪器**

## 一句话

655 派生出 95 个条件标记，但那 95 个**全部**来自已知的 15 条打开路径，
所以它明确写下「不主张存在这 15 条之外的未覆盖条件表面 —— **这正是本批答不了的**」。

本批去答，办法不是「再想想还有哪些面板」，而是**从活的 DOM 里枚举入口**：
`[data-director-rail-entry]` 的全部取值 = **7 个**。
其中 **`scene` / `add-camera` / `help` 从没被任何一批驱动过**（由枚举结果求差得来的，不是我事先知道的）。

结论：**没有任何 rail 入口带出 95 之外的新标记** ——
唯一没被驱动过的真入口 `add-camera` 带出 **31** 个，而 31 个**全在 95 之内**。

但真正值钱的是过程：**第一跑把我自己的差集仪器推翻了**，并由此得出**第七个盲区形状**。

## 2. 头条：第一跑推翻了我自己的仪器

第一跑把 `help` / `scene` / `timeline-toggle` 三个入口一律报成「**什么也没带出**」。
追下去发现**这是三件完全不同的事**，而根因只有一个：
**655 的差集是单向的（只算 `after − before`）。**

| 入口 | 单向差集读数 | 真实情况 |
|---|---|---|
| `help` | 0 | **点击根本没落地** —— `TimeoutError`，而且等待的 10 秒里布局自己移了 **1446** 个矩形。那个 0 是**探针的读数**，不是产品的。 |
| `scene` | 0 | **真的是 no-op**：元素 1390→1390、标记 175→175、**一个矩形都没动**。 |
| `timeline-toggle` | 0 | **卸掉 338 个元素、57 个标记**。只减不增的差集把「关闭」读成了「空」。 |

**第七个盲区形状：只测「出现」的仪器，对「消失」是瞎的；而抛错的探针会被读成否定。**
（前六个：零尺寸、位置≠层叠、只打中心、祖先命中、零尺寸门槛、探针副作用。）

仪器因此改成**三段读数**（出现 / 消失 / 几何），
并把**探针失败单列为第四种读数** `probe-failed` —— 绝不折进零里。
判词：`opened` / `closed` / `moved` / `noop` / `probe-failed`。

> 顺带纠正一句 654 的教训：**闸门静默不等于探针成功**。
> 654 的 `no-gate-cell-threw-while-being-evaluated` 查的是「打开时有没有抛」，
> 它**没有**覆盖「点击根本没点着」这一类 —— 那是 656 才撞上的。

## 3. 我的预测错了，而且错得有信息量

事先写下（跑之前）：「静态普查发现 4 个 `data-director-scene-*` 标记**没有任何验收器引用**，
所以点 `scene` 应该会把它们带出来」。

**结果一个都没出现。** `scene` 在默认态是彻底的 DOM 级 no-op。

这条预测之所以值得留在台账里，是因为它**测的是一件事**：
那 4 个无人引用的 `scene-*` 标记**不是**从 `scene` 这个 rail 入口进来的。
它们要么挂在别的状态下，要么属于 655 那 95 里的某块（可能性低 —— 655 的 ownerMap 里没有它们），
要么**根本没被渲染**（那 4 个标记只存在于源码字符串里）。
**这是本批留下的一个真开口，不是结论。**

## 4. 跨批次可复现

655 走过的 4 个入口（`add-character` / `panorama` / `aspect-ratio` / `ai-import`），
在 656 **换了仪器**（双向 + 几何）之后，带回的标记与 655 的 audit **逐条一致**，多出 0 条。

两批、两次运行、两套口径，同一个结论。差集不是只在单批内可复现。

## 5. 回答 655 的那个问题

> **这 15 条打开路径之外，还有没有条件表面？**

**没有 —— 至少在 rail 这一层没有。**

7 个入口里 4 个 655 已经走过；剩下 3 个：
`add-camera` 带出 31 个，**全在 95 内**；`scene` 什么也不带；`help` **测不到**（探针失败）。

顺带把 655 的一个隐含前提顶了出来：
**655 那个「175 的默认表面」本身就是一个状态。**
折叠时间轴之后是 **1052 个元素 / 118 个标记** —— 不是 175。
所以「默认表面」应当读作「**时间轴展开态的表面**」。

## 6. 不声称

* **不主张**新带出来的标记是缺陷 —— 未被测过**不是**有毛病。
* **不主张**枚举 rail 入口就穷尽了导演台的全部交互 —— 入口是**一层**。
  开关（`panels-toggle` / `timeline-toggle`）不叫 rail entry，本批另外单跑；
  再往下（检视器里的二级控件、轨道行的右键菜单）**本批一层都没碰**。
* **不主张**`scene` 是死代码 —— 只主张**默认态下一次点击不改变任何标记、元素与矩形**。
* **不主张**`help` 后面没有东西 —— 只主张**这个探针点不着它**，且在等待期间布局移了 1446 个矩形。
  `help` 仍然是**未测**的，不是「测了没有」。
* **零源站断言**。

## 7. 我自己写错的地方

1. **差集是单向的**，把「关闭」读成「空」。三个入口的 0 读数里有两个是假的。
2. **新仪器里一个 `break`**，把同一元素上的多个 `data-director-*` 只记一个
   —— 基线因此读成 **111**（655 是 **175**），`add-camera` 的新增从 31 掉到 27。
   **又一次仪器在静默少报**，和 654 缺的方括号、655 那个吓人的 80 是同一族。
   修完之后基线回到 175，**与 655 逐位对上**。
3. **「每条入口都得报错、且不得带出 0」** 这个要求本身是错的：
   `help` 该失败（点不着），折叠时间轴就该带出 0 个新增。改成了
   「每条入口都要有真实读数，且**失败不许被折成零**」。
4. **事先写的 `scene` 预测是错的**（第 3 节）。
5. 三次误编辑把相邻两行粘成一行（`ast.parse` 每次当场抓住）。
