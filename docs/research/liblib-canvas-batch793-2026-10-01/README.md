# batch 793 — 分组框**跟随**成员：修掉「store 说它在组里、屏幕说它不在框里」

## 为什么选这件事

790/791/792 修的是「点不到」「坏了」「数据没了」。本批是 757 待拍板里
**最高优先**的那条：分组框与成员之间**没有任何跟随关系**。

## 承重事实（757，本批**独立复现**）

把子节点拖出分组框之后：

| 读数 | pre |
| --- | --- |
| 分组框 store 位置 | `(2374,-12)` → **`(2374,-12)`**（不动） |
| 分组框 store 尺寸 | `722×460` → **`722×460`**（不变） |
| 子节点绝对位置 | `(2436,50)` → `(4134,50)` |
| 子节点**在不在框里** | `True` → **`False`** |
| `parentId` 挂载 | 仍挂着 |

⟹ **store 说它属于这个组，屏幕说它不在框里。** 框不移动、不缩放，也不提示。

## 修法

在 `routeReactFlowChanges` 写 `plan.nextNodes` 的**唯一收口**上，挂一个纯函数
`fitStoryboardGroupsToChildren`——把每个组重算成恰好包住它的子节点，并把子节点的
相对位置**一起重基**（组 `position` 一变，所有子节点绝对位置都会跟着偏）。

### 两条刻意的边界

1. **0 成员的组不动。** 收缩/隐藏空组是 757 待拍板 ②，源站未采样，本批不碰。
2. **组按「先外后内」处理**，每轮**重新**从当前列表算绝对位置 ⟹ 嵌套时内层拿到的
   绝对位置已经是对的。

## 读数（同一份探针，pre / post 各 2 轮，3 臂）

| 臂 | pre | post |
| --- | --- | --- |
| ★ 拖子节点出框 | 组 pos **不动**、`在框内 True→**False**` ✗ | 组 pos `(2404,18)→(3998.7,18)` **跟上**、`True→**True**` ✓ |
| 对照一：拖**非成员** | 组 pos 不动、`True→True` ✓ | 组 pos 不动、`True→True` ✓ |
| 对照二：拖**组本身** | 组 y `-12→371.7`、尺寸不变、子节点 `50→434` 跟着走、`True→True` ✓ | 同上 ✓ |

★ 两条对照缺一不可：只测「子节点拖出去框跟着走」的话，一个「凡是拖动就把
**所有**组都重算一遍」的粗糙实现也能全绿。

## ★ 一处**可见变化**：基线框被归位

种子里 `g-EFbbHpwq5w` 是 `722×460`，而它**唯一**的成员是 `622×350`（多出
50/55px 的任意余量）。react-flow 挂载时会发 `dimensions` 变更 ⟹ 走同一条收口
⟹ post 首屏就把框归位成 **`686×414`**，且**精确等于**按 `32×2` 独立重算的贴合值
（`(2436-32, 50-32)` / `622+64, 350+64`）。

`StoryboardGroupNode` **没有 resize 控件**（只有两条连线用的 `Handle`）⟹
框的尺寸纯属派生值 ⟹ 归位**不覆盖任何用户意图**。但这是对默认画布的可见变化，
所以写出来。

## 验收

`scripts/verify-liblib-batch793.py`，**独立实现**、不 import 汇编器。

- 断言 **7 条 / 4 个源码锚点 / 0 失败**（汇编器）
- 验收 **10/10**、阴性对照 **5/5**

| 对照 | 验的是 |
| --- | --- |
| N1 | 「空组不动」这条边界被拆掉会判红（否则它会把空组也收缩） |
| N2 | 「框不动导致子节点出框」这个读数**被真读了** |
| N3 | 能抓住「凡是拖动就重算所有组」这种粗糙实现 |
| N4 | 组「移动」不等于组「重算」⟹ 尺寸不变才是真不变量 |
| N5 | 修复必须挂在**唯一收口**上；只在别处补一个监听不算修好 |

### 本批踩的坑

| 编号 | 坑 | 后果 |
| --- | --- | --- |
| 通用内圈扫描抓不到组 | 组 `zIndex:-1001`、中心被子节点盖住、标题 `pointer-events-none` | 第三条臂两轮全 FAILED「点不到组框」 |
| 修好后探针又失效 | 框贴合后 padding 只剩 ~12 屏幕像素，从 8% 起扫会越过 padding 落到子节点上 | pre 通、post FAILED ⟹ 改成**沿四边细扫** |
| R26 | 给组新写 `drag_group` 时把 `def drag(...)` 那行当成锚点替换掉了 | `drag` 的函数体变成 `drag_group` 里 `return` 之后的死代码 —— **语法照样通过**，另外两条臂一调就 `NameError` |
| 浮点噪声 | 「已经贴合就 no-op」用精确相等 | 纯拖组时高度变成 `414.00000000000006` ⟹ no-op 分支永不成立，每次拖组都白白重建对象 ⟹ 加 `EPS = 0.01` |

★ R26 值得单说：它**不会**让探针报错，只会让某条臂在**别的**臂里 `NameError`。
`ast.parse` 通过、探针能启动——所以改完必须 `grep` 确认**所有**被调用的函数
都还有 `def`。

## 本批未覆盖 / 遗留

- ★ **没有**单独的空组探针臂 ⟹ 「空组仍画完整框」只是被顺带观测到，
  **不当结论**；757 待拍板 ②（空组要不要收缩/弱化、0 成员组的连线 handle
  要不要一起去掉）**本批没碰**
- ★ **未与源站对照**（源站需登录、点击语义未采样）⟹ 只保证 clone 里
  「框包住成员」这条契约成立，**不声称**源站的框也这样跟随
- ★ **嵌套分组没验**（种子里没有「组套组」的数据；792 也明确没实现嵌套组合）
- 没测**键盘移动**成员（方向键）是否同样触发跟随
- 没测节点**删除**后组的框是否收拢（成员变少 ⟹ 框应变小，这条路径没验）
- 没测 `onNodeDragStop` 记历史时组的几何变化是否被正确纳入撤销
- `src/` 改动范围：一个纯函数 + 写点一行；typecheck rc=0；未用 `--no-verify`，
  未跑别人的 build-site.sh
