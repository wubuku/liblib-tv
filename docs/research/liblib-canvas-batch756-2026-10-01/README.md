# batch 756 — 多选 N=10 与分组边界：查出「组合」会**静默掏空已有分组**

## 起点

753 验的是多选的**可达性**（静态上五个入口都够不着，运行时被
`routeReactFlowChanges` 的 `select` 变更接住），并顺带量到了 `Cmd+D` 的
N 分支：N=1 边 +3、N=2 边 +1。754 又补了第四条多选生产者。
755 转去画布切换隔离与行内菜单。

于是留了一个洞：**N 大于 2 的时候行为是什么样，完全没量过。**
而 N 大恰恰是唯一会同时碰到**多个分组**的场景 —— 753/754 测的每一个
多选场景里，选区最多跨一个分组。

本批把 N 拉到 10（框选全选），逐个跑 `Cmd+D` / `G` / `Shift+G` / `Delete`，
重点看分组边界。结果在这条路上撞出一个**高严重度缺陷**。

种子（`canvas-2`，store 无持久化，每轮整页 reload 回到这里）：

| 分组 | 标题 | 尺寸 | children |
|---|---|---|---|
| `g-245IDFh8sB` | 分镜图 · 第一集：咖啡馆对峙-图片组 | 430×452 | **0** |
| `g-EFbbHpwq5w` | 视频组 · 第一集：咖啡馆对峙-视频组 | 722×460 | 1（`v-UGQZzZOpbv`） |

10 个节点里只有 1 个带 `parentId`，就是 `v-UGQZzZOpbv` → `g-EFbbHpwq5w`。
**这张表必须先记下来**：如果只看操作后的快照，会把「本来就空」
误读成「被操作掏空」。

## 一、缺陷：组合（N=10）会把已有分组的子节点抢走

### 现象

`Shift` + 从 (20,56) 拖到 (1388,956) 一次选满 10 个节点，按 `G`：

| 读数 | 值 |
|---|---|
| 节点 | +1 |
| 边 | ±0 |
| past | +1 |
| 选中集 | 1（只剩新组） |
| 新组 | 3014×2446，`groupKind: selection`，title「组合节点」 |
| 新组 children | **8** 个 |
| `g-EFbbHpwq5w` children | **1 → 0** |
| `v-UGQZzZOpbv` 的 parentId | 变成新组 id |

选区是 10 个节点，但新组只收到 8 个子节点。差的 2 个正是那两个
`storyboard-group` 自己 —— `groupSelectedNodes` 的 `children` 过滤
把分组类型硬排除了：

```ts
// src/store/canvasStore.ts:3266-3268
const children = currentCanvas.nodes.filter(
  (node) => selectedIds.has(node.id) && node.type !== "storyboard-group",
);
```

于是形成一条**没有任何一层提示过**的链：

1. 两个旧分组都在选区里；
2. 它们被 `type !== "storyboard-group"` 排除在 `children` 之外 ⟹
   既不进入新组，也不被移动；
3. 但它们的**成员**命中了 `selectedIds` ⟹ 被 `nextNodes` 无条件
   改写成新组的子节点（`:3301-3312`）；
4. 旧分组从此 0 成员，退化成空壳，而它的 title / 尺寸原封不动；
5. 界面上只是「组合成功」。

新组的 8 个 children 里明确包含 `v-UGQZzZOpbv` —— 就是被抢走的那一个。

### 五条独立证据

| 证据 | 读数 |
|---|---|
| 结构 | 新组 children=8 = 选区 10 个里的非分组节点；逐个 id 对得上 |
| re-parent | `v-UGQZzZOpbv.parentId` = 新组 id，且它出现在新组 children 里 |
| 基线排除 | `g-245IDFh8sB` 种子阶段 children 本就是 0 ⟹ 受害的是 **1** 个组不是 2 个 |
| 零提示 | toast / alert / status / 确认框 五类选择器命中 **0** |
| 阳性对照 | 只选「组 + 它自己的子节点」按 `G` 是**零变化** ⟹ 破坏只发生在跨组多选 |

浮层普查只命中 1 个常驻元素 —— 跟随模式的「正在跟随 取消 ESC」提示条，
与本次操作无关。

### 严重度：破坏是静默的，且难以自救

`Shift+G`（解组）**修不了**。解组只作用于「被选中的那一个组」，此时
选中集是新组，两个旧组根本不在参数里：

| 读数 | 值 |
|---|---|
| 解组后 children=0 的组 | `g-245IDFh8sB`, `g-EFbbHpwq5w`（两个都还是空） |
| repaired | **false** |
| 再按两次 `Cmd+Z` | 节点 10 / 边 11 / past 0（回到种子） |

用户最自然的补救动作无效，唯一的修复路径是撤销。一次组合是 1 个事务、
一次解组是 1 个事务，所以要 **2 次**撤销 —— 与 past 归零吻合。

对比同批的删除路径：N=10 `Delete` ⟹ 节点 0 / 边 0 / **空态出现** /
`Cmd+Z` 复原。store 的删除本身是干净的，问题不在删除，在组合。

## 二、复制一个含子节点的分组：节点 +2，边 ±0

只选中 `g-EFbbHpwq5w`（722×460，带 1 个子节点）按 `Cmd+D`：

| 读数 | 值 |
|---|---|
| 节点 | **+2**（选区只有 1 个） |
| 边 | **±0**（种子有 4 条边触及该组及其子节点） |
| 选中集 | 1（选中的变成副本） |

+2 是**子孙展开**：`duplicateGraphSelection` 用一个 while 循环把
`parentId` 命中的所有后代并进 `copyIds`（`:699-707`）。所以「复制一个分组」
在实现里是「复制这个组 + 它所有后代」。

三格细节都钉死了（`756d` 专门补的探针）：

| 格 | 读数 |
|---|---|
| 新分组是**新 id** | 不在种子的两个 group id 集合里 ✓ |
| 子节点也是**新 id** | `video-<ts>-<rand>` ≠ `v-UGQZzZOpbv` ✓ |
| 分组位置 delta | **[+40, +40]** |
| 子节点**相对**位置 delta | **[0, 0]**（原样保留） |
| 子节点**绝对**位置 delta | **[+40, +40]** |

两个 delta 拆开看才说得通：`:730` 给节点 `position {x+40, y+40}`，但
`:744-746` 在「父也被复制」时改回 `copiedNode.position = {...node.position}`
（保留相对量）。只看绝对位置会误以为「相对布局被破坏」。

边 ±0 的原因不是巧合：该子节点只有向组外的边，两端同在选区的边一条都没有
⟹ `includeExternalEdges=false` 的 `sourceCopied && targetCopied` 过滤掉全部。

## 三、`includeExternalEdges` 四档对照表

同一函数，四个分支，边行为各不相同，**而这个布尔表达式没有暴露给用户**：

| 选区 | 节点 Δ | 边 Δ | `includeExternalEdges` | 出处 |
|---|---|---|---|---|
| N=1 非分组节点 | +1 | **+3** | true | 753 |
| N=1 含子节点的分组 | **+2** | **±0** | **false** | 756 |
| N=2 相邻两节点 | +2 | +1 | true | 753 |
| N=10 全选 | +10 | +11 | true | 756 |

判定式只有一行：

```ts
// src/store/canvasStore.ts:3166
const result = duplicateGraphSelection(currentCanvas, requestedIds,
  requestedIds.length === 1 && !includesGroup);
```

「选 1 个节点」得到 3 条边，「选 1 个分组」得到 0 条边 —— 差别完全来自
一个用户看不见的布尔值。

## 四、一个反直觉但自洽的边界

选中「`g-EFbbHpwq5w` + 它自己的子节点 `v-UGQZzZOpbv`」共 2 个，按 `G`：

| 读数 | 值 |
|---|---|
| 节点 / 边 / past | 0 / 0 / **+0** |

因为非分组 children 只剩 1 个，撞上 `:3269` 的硬门
`if (children.length < 2) return state;`。**什么都不会发生**，
也就不会触发第一节那次抢子节点 —— 破坏只在**跨组多选**时出现。

这也是第一节那条缺陷的阳性对照：如果组合是无差别地破坏，那这条也该出现
「组被掏空」，但它没有。

## 五、判据

17 条，两轮一致（`756c` 两轮 + `756d` 两轮，`roundDiff` 为空）。
完整 evidence 见 `runtime-audit.json` 的 `judgments` / `boundary`。

1. 种子结构普查：10 节点 / 11 边 / 2 分组，只有 1 个节点带 `parentId`
2. N=10 框选可达：Shift+拖 (20,56)→(1388,956) 一次选满 10
3. N=10 `Cmd+D`：+10 节点 / +11 边 / past+1 / 选中集=10 个副本
4. 复制是单一原子事务：一次 `Cmd+Z` 就回 10/11（future=1）
5. `includeExternalEdges` 四档对照表
6. N=10 按 `G`：+1 节点 / ±0 边 / past+1 / 选中集=1
7. 新组只收 8 个；10 个选区里有 2 个是分组被过滤
8. **★ `g-EFbbHpwq5w` 被掏空，其唯一子节点被 re-parent**
9. 被掏空的是 1 个组不是 2 个（`g-245IDFh8sB` 种子本就空）
10. 掏空全程零提示（五类选择器命中 0）
11. **★ `Shift+G` 修不了：repaired=false**
12. 只有 `Cmd+Z` 能修，且需要 **2 次**
13. N=10 `Delete`：节点 0 / 边 0 / 空态出现；撤销复原
14. **★ 只复制含子节点的分组 ⟹ +2（子孙展开）**
15. **★ 子树整体平移 (+40,+40)，相对位置 [0,0] 原样**
16. 边 ±0：种子 4 条边触及该组，但两端同在选区的 0 条
17. 边界：组 + 自己的子节点同选按 `G` 零变化（硬门）

两轮一致性用 `Shift` 框选 / `Meta+d` / `g` / `Shift+g` / `Meta+z` /
`Delete` / `Meta+0` 固定动作清单，**轮间整页 reload** 让两轮独立；
过滤器把 `<prefix>-<epochMillis>-<rand6>` 形态的 id 替换为 `<generated-id>`
（**键和值都要清洗**，见 R16）。

## 六、探针返工三处（本批全部是我自己的探针 bug，不是产品问题）

| id | 现象 | 教训 |
|---|---|---|
| R16 | 两轮一致性过滤器只清洗字典的**值**，`childrenAfter` 以 id 为**键** ⟹ 随机 id 造成误判 `consistent=False`（两轮实际都是 8/0/0） | **归一化必须覆盖字典键** |
| R17 | 模板里 `by.get(%(G)s)` 漏引号，格式化后 JS 变成 `g-EFbbHpwq5w` ⟹ 浏览器报 `Cannot access 'g' before initialization` | **Python `%` 格式化嵌进 JS 时，字面量必须自己带引号** |
| R18 | 取「新分组」按「有 1 个子节点」筛，结果取到**种子分组自己**（它恰好也有 1 个子节点）⟹ `childIsNewId=false`、两个 delta 全 `[0,0]`，差点把「子孙展开」判成假 | **新增对象只能按「不在基线集合里」识别**，按特征筛在基线有同特征对象时必错 |

R18 尤其值得记：原始读数其实**完全支持**结论，是取项规则错了。
第一反应必须是先怀疑探针 —— 这已是本会话第四次靠这条救回一个假读数。

## 七、待拍板（需改 `src/`，等授权）

1. **组合跨组多选时的成员保护**（本批新，最高优先）：
   要么把被选中分组的既有成员一并纳入新组、要么把已在选区内的分组整体
   跳过、要么在检测到「选区跨分组」时先提示；现在是无条件 re-parent。
2. **掏空零提示**：至少给一条「已解散 N 个原分组的成员关系」的中性提示。
3. **`Shift+G` 修不了**：解组后如果存在 0 成员分组，要不要提供
   「把空壳删掉」或「一键还原」；或让解组对空壳分组也可作用。
4. **空壳分组的几何**：旧分组保留了 722×460 的尺寸，视觉上会留一个空框，
   要不要在成员归零时收缩/隐藏（本批没验这一格，见下）。
5. `includeExternalEdges` 的四档差异要不要在 UI 或 tooltip 里说明。
6. 沿用 753 挂起项：`setEdges` 死 action、Win/Linux 无 `Meta+点击` 等价手势。

## 八、不声称

- N=3..9 的复制/组合/删除没测；只测了 N=1（含/不含分组）、N=2、N=10
- 框选的**半选**行为没测（框边界正好压在节点上）
- 跨分组多选后，旧空壳分组的**几何**没查（它仍保留原尺寸，
  即尺寸不随成员归零而收缩 —— 视觉上留空框，这一格没验）
- 组合后边是否仍正确指向新组，只看了计数 ±0，没看指向
- `undoAtomic` 只验了 1 次撤销；没验 2/3 次撤销是否单调
- **没有与源站对照**：源站在跨分组多选时是否也掏空旧分组
- 判据 17 依赖 `g-EFbbHpwq5w` 恰好只有 1 个子节点；若有 2 个子节点，
  硬门结论会不同，未构造该场景
- 跟随模式那条常驻浮层只做了「它不是 toast」的排除，没追它是谁渲染的
