## 二、本批抓到的三处

### ① ★★ 「这一段没有标题行」是一条**结构事实**

源站实测：这一段的右栏**第一层就是滚动区**（`min-h-0 flex-1 overflow-y-auto px-6 pb-24 pt-3`），
而「脸部精修」段的第一层是 **40px 的页签行** ⟹ ⟹ 两者内容起点差 **48px**。
clone 之前**每段都顶着页签行** ⟹ ⟹ 那是**结构上的假象** ⟹ ⟹ 本批改正（另起一个 panel 变体）。

★ 「48px」这个数是**由 batch 841 raw 与 batch 844 raw 的两个盒机械算出来的**，
不是手打常数 ⟹ ⟹ 门禁里也是这么算的。

### ② ★ 「自定义」那枚**没有** `aria-pressed`

前 5 张是 `aria-pressed="false"` ⟹ ⟹ 源站**确实有选中态**，只是初始一个都没选中。
而「自定义」**连这个属性都没有** ⟹ ⟹ 它不是「可选中的卡」，是**上传入口** ⟹ ⟹
clone 也**不给**它那个属性（⟹ 连「有没有这个属性」都要一样）。

### ③ ★ 一处**继承**造成的对不上：缩略区的 `color` 与 `line-height`

源站的缩略区**继承**正文的字体（16px／**24.8px**／纯白），而 clone 的全局是
16px／**24px**／`#ededed` ⟹ ⟹ 计算样式对不上 ⟹ ⟹ 本批在 `.ce-trait-thumb` 上
**写死**源站那组值 ⟹ ⟹ 逐键比对 0 不一致。

★ 这就是「**几何对齐 ≠ 外观对齐**」的又一例：盒全对上了，颜色/行高仍可能差。

### ④ ★★ 阴性对照逼出来的**两处字段重叠**

★★ 「每条臂只翻它自己那一条」这条纪律，**逼出了两条判据自己的毛病**：

- **N4（初始就把「痣」设成选中态）翻的是 S3 ＋ S4** ⟹ ⟹ 真因：选中态的样式里
  写了 `border-color` ⟹ ⟹ 而 `border-color` 是**外观判据**读的字段
  ⟹ ⟹ **选中态污染了外观判据** ⟹ ⟹ 修法：选中态**只改 `box-shadow`**
  （★ `box-shadow` 不在外观判据的键表里 ⟹ ⟹ 改它**不影响任何几何/外观读数**）。
- **N6（页签行在这一段也出现）翻的是 S1 ＋ S6** ⟹ ⟹ 真因：**页签数**被
  S1 与 S6 **同时**读了 ⟹ ⟹ 修法：**页签数归 S6**，S1 不再读它。

★ 通用形态：**两条判据读了同一个字段 ⟹ ⟹ 一条缺陷就会同时翻两条**
⟹ ⟹ 而阴性臂要证明「**哪一条**有牙」⟹ ⟹ 字段必须**互不重叠**。

★ N6 的注入方式也换了：batch 844 把页签行**抽成了 `renderTabs()`**
⟹ ⟹ 阴性臂可以注入「页签行在**不该**出现的段也出现」这条**真实**缺陷
（★ 那正是 clone 843 之前的**老毛病**）⟹ ⟹ 而不必塞一个假的标记元素
（★ 假标记测的是「标记在不在」，不是「结构对不对」）。
