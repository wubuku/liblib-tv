# batch 666 —— CH3 那 24 枚归到机制：**两个盖住者，两条盒包含闭式**

## 一句话

665 的四路表里 CH3 有 **24** 枚（1280 宽恒定，1366 是 25、1440 是 26、1600/1920 是 27），
含义是「`own` 为真（**点得到**）却中心上方压着一个 `pointer-events:none` 层」。
665 只说了这一格**存在**，没说是被谁压的。**662 的教训是报机制而不是报成员** ——
本批把它们归到机制，结果是：**24–27 枚受害者，只有 2 类盖住者。**

## 1. 两个机制

| 机制 | 吞掉 | 盒 |
|---|---|---|
| **视口的 pe:none 层**（`<div>`，无 data 属性无 class，`relative`/`z:auto`） | **19 → 20 → 21 → 22 → 22** | `x 281 .. W−281`、`y 88 .. H−182` |
| **对象行的选中高亮层**<br>`span.pointer-events-none.absolute.inset-x-0.inset-y-0`<br>（`DirectorTimeline.tsx:1636-1642`，每行一个，共 **2** 个） | **恰好 5** 枚，**六格一字不差** | 每个 `320×32` |

**第一类的盒逐位等于视口格**：

| 边 | 值 | 是什么 |
|---|---|---|
| 左 | **281**（恒定） | 48（rail）+ 233（场景树列） |
| 右 | **W − 281** | 检视器 281 宽 |
| 上 | **88**（恒定） | 顶带下沿 |
| 下 | **H − 182** | **时间轴顶边** —— 这一层恰好停在时间轴开始的地方 |

实测宽 718/804/878/1038/1358（1280/1366/1440/1600/1920）= `W−562` 逐位符合；
高 450/880（720/1150）= `H−270` 逐位符合。

## 2. 盖住者**没有一次**是受害者的祖先

这是本批唯一可能推翻结论的那一问，而**第一版测错了**：
我用「身份字符串」在祖先链里找，盖住者的身份用 class/`<div>`、
祖先链用 data 属性，**两套命名对不上**，于是报出「0 个祖先」——
连真的是祖先的情形也一起报成不是。

改成**对象身份**（沿真实 `parentElement` 链比 `===`）之后，
**6 格 × 24–27 枚，全部仍然不是祖先**。

> **所以这不是同义反复，是真实的跨容器覆盖。**
> 665 说「门在正确的位置、问了错误的问题」—— 本批把问题补全了：
> 被问的是「你上面有什么」，答案是「**一个和你没有亲缘关系的大盒子**」。

## 3. 闭式：两条盒包含

```
属于「视口层」        ⟺  中心 x ≤ W − 281  且  中心 y ≤ H − 182
属于「对象行高亮层」  ⟺  中心落在某个 320×32 的行盒内
```

第一条解释了成员数**随宽度增长**：层向右伸到 `W−281`，于是提示条那几枚**逐个**被吃掉。

| 宽度 | 层右沿 | 提示条成员 | 视口层成员数 |
|---|---|---|---|
| 1280 | 999 | — | 19 |
| 1366 | 1085 | `上传图片` | 20 |
| 1440 | 1159 | `+ 描述想搭建的场景` | 21 |
| 1600 | 1319 | `+ 发送` | 22 |
| 1920 | 1639 | （同上） | 22 |

**123 次成员判定、零例外。**

> **顺带纠正我第一版的读数**：我抽了三个宽度就写「19 → 21 → 22」，
> 暗示只多一枚。**五个宽度各测一次是 19 → 20 → 21 → 22 → 22** ——
> **三次独立的加入**。三点采样把一条阶梯画成了一条斜线。

**这与 633 的结论正好相反**：633 发现掩埋曲面**与宽度无关**，
而这里**非常有关**（宽度就是那一条右沿）。

## 4. 这不是缺陷主张

那 24–27 枚**全部 `own=True`**，也就是**点得到** ——
`pointer-events:none` 的层本来就是**点击穿透**的，
而视口那层盒住整个视口格**多半正是它该做的**（让画布不吃点击）。

本批主张的只有一句：**`own` 这一路的读数看不见它们上面有什么。**

## 7. 我自己写错的地方

1. **祖先判据用身份字符串**，与祖先链的命名词汇不同源，
   于是报出「0 个祖先」—— **一个不可能失败的测试**。
   改成对象身份后结论不变，但**它本该可能失败**。
2. **身份分组把多个元素并成一个盒子** —— 那个 class 字符串对每个对象行都一样，
   第一版只记了第一个元素的盒，于是「5 枚被一个 320×32 盒住」这种
   几何上不可能的读数差点写进 audit。改为**按元素计盒数**。
3. **断言 `height == H−182`** —— `H−182` 是**下沿**不是高度（720 时 450 ≠ 538）。
   高度是 `H−270`。**又一个「派生量当成实测量」**，与 634/638/660 同类。
4. **三点采样写成一条斜线**（19→21→22 实际是三次加入）——
   抽三个宽度就下结论，和 660 那次「拿数字跟另一个数字比」同源。
