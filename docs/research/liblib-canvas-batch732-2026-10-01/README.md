## 方法论

1. **「写点数 ≠ 控件数」要以量级说话** —— 730 测到 `1→4`、`4→10`，
   打开 `LibraryShowcasePanel` 才发现 `1→24`。**没打开的族不能算「已普查」。**
2. **不可见与不可聚焦是两件事** —— `opacity: 0` 让元素看不见，
   却没有把它移出焦点顺序 ⟹ **凡是加 `opacity-0` 的地方，都要连带查 Tab 可达性**。
3. **注释里的数字也要能被实测** —— batch 358 注释写「40 多个」，本批实测 40。
   **注释可信的前提是有人去测过。**
4. **入口失配先怀疑探针** —— 「添加节点」的文本匹配失配让 5 族没打开，
   那一整格记**未取证**，而不是写成「不可达」。
5. **别用聪明的一行表达式** —— 本批为算「开标签行号」写了一行花哨的生成式，
   结果把自己绕进去、读数只给出 `[236]`；改成直白的循环后一次过。
   **可读性优先于炫技**，尤其在判据里。

## 探针返工三处

1. **JS 选择器跨行** —— `[...][a,\n   b]` 写进单引号字符串，JS 直接
   `SyntaxError`，探针跑了一半才炸 ⟹ 选择器写单行。
2. **收尾段崩了导致 JSON 没落盘** —— 数据在内存里、文件没写成，
   后面的分析脚本读不到 ⟹ **每族采完即落盘**，别攒到最后。
3. **行号差一位** —— 判据先写死「收藏按钮在 `:131`」，实际
   `<button` 开标签在 **`:130`**、`data-inert` 属性那行是 **`:134`**；
   断言失败才把两行分开记 ⟹ **属性行与开标签行是两个数，别混用。**
