## 选题

763 抓到了缺陷 D1（`useDirectorGestureBoundary` 的 `stopPropagation` 吞掉
Escape），但留了一条最要紧的「不声称」：**另外 8 个同一边界 hook 的控件当时
不在渲染态，只写了「推测同样受影响 —— 推测不是读数」**。本批两件事：

1. 把那句推测变成读数（764a），并顺带补上 763 完全没测的 ⌘C/⌘V（764b/764c）。
2. 查清「⌘C 在数值框里没反应」到底是不是 D1 的连带后果。

结论：**是两条独立缺陷**。D1 的影响面比 763 记的宽（滑杆也中招），
修饰键失效是另一条机制（`isEditable` 早退），修法完全不同。

## 缺陷

### D1（中，承自 763，本批把影响面量宽了）

`src/components/director/useDirectorGestureBoundary.ts:92-98` 的
`onKeyDown` 在 Escape 上 `preventDefault()` + `stopPropagation()`，事件在
React root 冒泡处被掐断，永远到不了 `DirectorDesk.tsx:475` 挂在 window
冒泡上的 Esc 阶梯（包括 `:481-485` 那条「移动端先关抽屉」的分支）。

**764 的增量**：

- 逐字段可比的上下文里，**43 个**带边界标记的控件**全部**吞 Esc，
  另有 **5 个**非边界控件**一个都不吞**（阴性对照）。
- 类型不止 `number`：角色「姿势」上下文里 **25 个 `type=range` 滑杆**同样中招。
  ⟹ **更正 763 的「全是 type=number」**。
- 焦点确实落在目标控件上（`focused=true` 43/43），排除「没聚焦到」这个解释。
- 机位「运动轨迹」「截图」两档在种子里没有可测的边界控件。
- **仍然未验证**：路径锚点（`:825`）、路径变换（`:866`）、FOV（`:1579`）
  三类控件两轮都没渲染出来。

修法提示与 763 相同（需授权）：`onKeyDown` 的 Escape 分支加
`if (!activeRef.current) return;`，并且 `onFocus` 不再 `begin()` ——
**两处必须一起改**，不拆第二处的话加了守卫也等于没加。

### D2（低，新增）

焦点停在**任何可编辑控件**里时，⌘C 与 ⌘V **两个键完全没反应**。

- 机制：`DirectorDesk.tsx:481` 的 `if (isEditable) return;` 排在 ⌘C/⌘V 分支之前。
  **不是** D1 那个 stopPropagation —— 判别点是按 ⌘C 前后
  `data-director-active-gesture` **逐字符不变**（边界 hook 因 `activeRef`
  已为 true 而空转，说明它没拦）。
- 实测：数值框里 ⌘C 对象数/历史/`lastCommand` 全不变；⌘V `countDelta=0`、
  `historyDelta=0`。两轮一致。
- 判断：对 `type=text` 框，这个守卫是**刻意且正确的**（用户要的是原生复制）。
  对**变换数值框**没有意义 —— 框里没有可选中的文本，原生复制也无从发生，
  于是这两个键在该位置**彻底失效**。
- 替代路径已实测可用：树里 `data-director-selection-action=copy/delete/clear`
  三枚按钮全部生效（copy 不改对象数、delete −1、clear 只清选择）。

## 观察

- **O1 方法论约束**：764b 两轮的种子数不同（5 vs 6）—— 正是 763 O1 记的
  「导演台项目持久化在 localStorage」的直接后果。本批所有跨轮比较都按
  「派生量逐字段相等」而不是「绝对值相等」来判。
- **O2 探针约束（也可能是真实的可用性问题，待查）**：移动端两个抽屉互斥，
  而且**开着的那一个会盖住另一个的触发按钮** —— 树 aside 占 x=0..220 / y=88..，
  属性抽屉触发按钮 rect 在 (48,100,32,32)，`elementFromPoint` 命中的是 aside。
- **O3 事实记录**：建出运动路径后属性面板可聚焦控件 52→67（+15），
  但**边界控件数没变**（仍是 12）⟹ 新增的 15 个控件不带手势边界；
  路径锚点数值框仍然没渲染。

## 探针教训（返工项）

- **R58 读标志必须在清标志之前。** 764a 初版里 `TAKE` 会把
  `reachedWinBubble/reachedWinCapture` 清成 false，而我先 `TAKE` 再读
  ⟹ 27 个边界控件 + 3 个阴性对照**全被算成「吞了 Esc」**。
  修法是加 `PEEK` 在 `TAKE` 之前读。**同一个探针两轮「一致」并不能说明它对**
  —— 确定性的读法错误两轮必然一致。
- **R59 开一个抽屉之前先关另一个。** 两个移动端抽屉互斥，开着的那个 aside
  会盖住另一个的触发按钮 ⟹ 扫网格 0 命中。属性面板的 tab 按钮在抽屉关着时
  x=817（视口宽只有 800）也栽在同一类问题上：**先量可点性，再点**。
- **R60 别把同一个症状当成同一个机制。** 数值框里 ⌘C 没反应，乍看像 D1 的
  stopPropagation 一起吞了复制粘贴。真正的判别点是 `activeGesture` 按键前后
  **逐字符不变** —— 拦住的是 `isEditable` 早退。D1 与 D2 是两个独立缺陷。
- **R61 派生量要判方向、判效应**（承自 R53）。`countDelta` 必须相对同一格内的
  前后读数，不能拿整轮种子数去减（763 栽过这个）。
- **R62 探针自己的失败有时会变成有用的读数，但要如实记账。** 764c 的五次
  `pick` 全部失败（我把返回字典的 `OBJECTS` 当成了列表），导致焦点一直留在
  数值框里 —— 这才量到了 D2。但这个「意外」不能当设计：单列成
  `picksFailedIn764c` 写进产物，并在不声称里写明「五次选中都失败了」。

## 不声称

- 无源站对照。
- 路径上下文（`path+camera:*`）**两轮不可比**，本批不对其下任何判断。
- 路径锚点（`:825`）、路径变换（`:866`）、FOV（`:1579`）三类控件两轮都没渲染
  出来，**没有测过**；763 的「推测同样受影响」对这三类仍然只是推测。
- 764a 的边界检测是**按 data-* 标记**做的。若某个带手势边界的控件标记挂在
  外层容器上（如 FOV 那样标记在 `…-fov-field` / `…-fov-slider` 而可聚焦的是
  里面的 input），就会漏检 —— 本批**没有**做「全控件无标记扫」兜这个底。
- D2 只在 1440 桌面 + 变换数值框上测过；没测 text 框、textarea、select，
  也没测移动端抽屉形态下的表现。
- 没测原生剪贴板内容（没有读 `navigator.clipboard`）；「框里没有可选文本所以
  原生复制也无从发生」是浏览器常规行为，不是读数。
- ⌘C/⌘V 只测了单个选中；多选、跨类型（角色↔道具）粘贴未测。
- 764b 两轮起点不同（5 vs 6 个对象），绝对计数不可跨轮比较，只比较同一格内的 Δ。
