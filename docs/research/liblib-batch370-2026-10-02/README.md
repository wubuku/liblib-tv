# Batch 370 — 受控实验推翻了我自己的归因；给 runner 加上「跑歪了就说」的自觉

日期：2026-10-02
范围：`scripts/run-liblib-verifiers.sh`（**工具批，产品代码零改动**）

## 起因：想给一个我已经写进提交信息的结论做验证

Batch 367 的提交信息里写着一句：

> 全量 320 项：`-j 8` 下 88 项红，其中 **64 项在 `-j 3` 下通过**（并发伪影）

结论是「高并发会产生伪影，基线不可信」。这是个会影响后续所有判断的结论，
所以本批要做的第一件事是**验证它**，而不是换个默认值了事。

## 受控实验：并发本身复现不出伪影

取 24 个**不含 director/jimeng** 的画布本体门禁（避免跨线 WIP 干扰），
同一时间窗内先后跑两轮：

| 轮次 | 并发 | 结果 | 耗时 |
|---|---|---|---|
| 1 | `-j 4`（当前默认） | **24 通过 / 0 失败** | 73s |
| 2 | `-j 8`（2× 默认） | **24 通过 / 0 失败** | 45s |

**并发翻倍，零伪影。** 我在 batch 367 写下的归因**不成立**。

顺带纠正一个我一直没核过的事实：runner 的默认并发**本来就是 4**，
而那次全量我是**显式用 `-j 8`** 跑的。所以我从来没有「默认不可信」的证据，
只有「我自己调到 2 倍默认时那次结果很脏」的观察——而那次还叠加了别的条件。

## 真正的因是 dev server 抖动，但它很难被干净地单独归因

第三轮我在运行中 `touch` 了一个源文件（**只改 mtime，不改内容**）触发 Next dev
重编译，同一批 24 个门禁立刻大面积 `Page.wait_for_function: Timeout`。这与
batch 367 变异测试撞到的 `Page.goto: net::ERR_CONNECTION_REFUSED` 是同一族签名。

**但这一轮不能算干净的证据**：跑到一半我发现**另一个并行 session 正在同时跑它
自己的验证器套件**（batch 446–453、94），两个套件抢同一个 dev server。我这一轮
最后撞了 1200 秒任务上限被中止。

所以诚实的结论分两层：

- **可以确定的**：并发本身（2× 默认）不产生伪影。
- **不能确定的**：那 64 项的单一成因。本仓库的 dev server 是**共享可变资源**，
  并行 session 改文件会触发重编译，同时跑两套验证器也会互相抢——这些真实发生过，
  但我无法把它们从并发里干净地分离出来，因为**我控制不了别人的进程**。

## 修的不是一个数字，是「汇总敢不敢说自己不可信」

不管触发源是「我改了文件」「别人改了文件」还是「两套验证器同时跑」，
对使用者来说是**同一件事**：这一轮的失败里混着基础设施噪声。
而现状是 runner **只在开跑前探活一次**（`exit 2`），跑完不复查，
于是照样输出一行看起来很干净的 `liblib verifiers: N passed, M failed`。

**失败与「代码真的坏了」在汇总里长得一模一样**，这就是要修的。

实现（`scripts/run-liblib-verifiers.sh`）：

1. 开跑前起一个后台探针，每 2s `curl` 一次（3s 超时），失败就记时间戳；
2. 收尾时统计探针失败次数；
3. 抖过就在汇总数字**旁边**打印显式 WARNING，指明 probe log 位置，
   并说明「重跑失败批次再当回归看」；
4. **仍然照常报数字**——只是同时声明这份数字不能单独当代码判决；
5. `trap` 保证探针一定被收掉，不留游离后台进程。

## 双向自检：监测最常见的失败就是「恒绿」

这类监测的典型失败是条件永远不成立，于是「跑歪了会告警」变成**空断言**，
而门禁全绿恰恰证明不了这一点。所以必须有阳性对照。

`probe_liblib_batch370_health_monitor.py` 起一个**假服务器**（临时端口，不碰
4317——上面还有并行 session 在用）：

- **阳性**：前 6 个请求返 200（骗过**前置探活**），之后返 503
  → 汇总**必须**出现 WARNING、必须指出 probe log 位置、必须仍报数字；
- **阴性**：一直返 200 → 汇总**必须不**出现 WARNING（否则是噪声，久了没人看）。

> 用「先活着后挂掉」而不是直接指向死端口，是刻意的：死端口会被前置探活挡在
> `exit 2`，**根本进不到运行阶段**，等于只验了那条老路径。

结果 **5/5**。

## 自检跑出来的一处真 bug

第一次跑阴性自检就红了：

```text
scripts/run-liblib-verifiers.sh: line 356: [: 0
0: integer expression expected
```

`grep -c` **无匹配时会打印 0 并且返回 1**，于是 `|| echo 0` 把结果拼成 `"0\n0"`。
改成 `grep … | wc -l`（永远只吐一个数）。

> 监测类代码的 bug 往往表现为「不告警」而不是「崩溃」——这类最难发现，
> 所以双向自检不是形式主义。
