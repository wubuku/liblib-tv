# batch 712：播放头的可达集 + zoom 控件到底是「点」还是「拖」

日期：2026-10-03　验收器：`scripts/verify-liblib-batch712.py`（5 条判据，3 条臂，零 store 写入，不改 `src/`）

## 起点

711 普查持久化边界时留下两格**第三态**（没造出差异）：

- 点了标尺 75% 处，刷新前 `playheadTime` **仍然是 0**
- `[data-director-timeline-zoom-cluster]` 里只有一枚按钮，点完 `zoom` 仍是 44

第三态不能记成「过刷新」也不能记成「不过刷新」。本批把那两格补上。

## 五条预测（写死在验收器里，先于任何测量）

| 预测 | 内容 | 结果 |
|---|---|---|
| **P1** | 标尺左侧精确按 `t = frac × duration` 映射 | **成立** |
| **P2** | frac 超过某个位置之后是**死区**，不是夹紧 | **成立** |
| **P3** | 上限是 `t = 4.24`，**不是 4.0**（尽管关键帧在 4） | **成立** |
| **P4** | 键盘方向键**不**移动播放头 | **成立** |
| **P5** | zoom 控件**只能拖不能点**，拖拽范围 0..100 | **成立** |

## 播放头的可达集：标尺左侧 53%，上限 t = 4.24

`duration = 8`、标尺 1779px 宽。逐点点击（每一格都是**真实鼠标点击**）：

| frac | 期望 `frac × 8` | 实测 t | |
|---|---|---|---|
| 0.02 | 0.160 | 0.16000 | 一致 |
| 0.10 | 0.800 | 0.79994 | 一致 |
| 0.25 | 2.000 | 1.99986 | 一致 |
| 0.50 | 4.000 | 3.99972 | 一致 |
| 0.51 | 4.080 | 4.080 | 一致 |
| 0.52 | 4.160 | 4.160 | 一致 |
| 0.53 | 4.240 | 4.240 | 一致（**上限**） |
| 0.54 | 4.320 | **4.240** | 冻结 |
| 0.60 / 0.75 / 0.90 / 0.99 | ≥ 4.8 | **4.240** | 冻结 |

**上限是 `4.240000131736106`，而关键帧在 t = 4** ——
所以**上限不是关键帧位置**，也不是 `duration` 的一半（4.0）。

## 最锋利的一格：右半是**死区**，不是夹紧

「点 54% 之后 t 不再涨」有两种读法：**(a) 被夹紧**（吸到上限）、
**(b) 那一段根本不响应**。区分它们只需要**换一个起点再点一次**：

1. 先点 25% → `t = 2`
2. 再点 75% → **`t` 仍然是 2**

**它没有吸到上限，它什么都没发生。**
⟹ 标尺右侧约 47% 的宽度是**死的**：点它不会移动播放头，也不会有任何反馈。

**「看起来像被限制」和「被限制」必须用「换一个起点再点一次」来分** ——
只在一处点两次，看到的都是同一个数字，分不出是夹紧还是死区。

## 方向键不移动播放头

连按 `ArrowRight` ×3 + `ArrowUp`，`t` 纹丝不动（`2.0 → 2.0`）。
和 707 查到的「源码里没有任何方向键绑定」一致。

## zoom 控件：只能拖，不能点

那枚 71×24、`cursor: pointer` 的控件：

| 动作 | `zoom` |
|---|---|
| 初值 | 44 |
| **点一下** | **44（没变）** |
| 从中间**向右拖到底** | **100** |
| **向左拖到底** | **0** |

⟹ 它是一枚**拖拽划块**（scrubber），**没有点击落点**。
这和 703 查到的 `shot-end`「能输入但没提交路径」是同一族问题：
**控件在，但交互路径少一条**。

## 顺带把 711 的两格第三态解释掉了

711 点的是 75%（**落在死区里**），zoom 点的是一枚**只能拖**的控件 ——
两个动作**都没造出差异**，所以那一格是**第三态**而不是「没变化」。
**第三态不是待办，是「我点的那个位置/那个交互方式不产生差异」——本批把两格都补上了。**

## 方法论收获（可复用）

**① 「无响应」有两种，必须换起点复测。** 同一个数字在两种机制下长得一模一样
（夹紧与死区都是「再点也不变」）—— **换一个起点再点一次**是唯一能分开它们的动作。
这条和 703 的「补两臂」是同一个道理，但对象从「像素偏移」换成了「起点」。

**② 「控件存在」不等于「每种交互都接上了」。** zoom 划块有 `cursor: pointer`
（看起来完全可点）、有一个按钮的体量、有一个 `data-` 属性 ——
**唯独没有点击落点**。**体量与光标都不构成「可点」的证据，只有点一下才算。**

**③ 第三态要记成「我点的那个位置/那种方式不产生差异」，而不是记成待办。**
711 那两格的正确后续不是「再测一次」，而是**先查那个位置/那种方式本身有没有效** ——
本批一查就发现：一个在死区里，一个只能拖。**查清楚之后，第三态就消失了。**

## 待拍板（不阻塞）

- **标尺右侧 47% 是死区**：是不是缺陷？用户会把标尺**全长**当成可点的
  （`cursor: ew-resize` 铺满整个元素），点到右边却毫无反应
- **播放头上限 4.24 的来源**：是刻意夹紧、还是某个几何/常量算错了
  （`duration = 8`、关键帧在 0/4/8、标尺全长 1779px，三者对不上 4.24）
- **方向键不能移动播放头**：时间轴上「逐帧步进」是不是应该有
- **zoom 划块没有点击落点**：要不要给点击也加一条路径
  （同一枚控件在别处（`motion:duration`、`uniform-scale`）能不能点，是另一个问题）
