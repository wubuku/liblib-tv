## 一、为什么要重测一个「读源码看着对」的函数

802 用 AST 普查把 37 个动作按风险分档，`groupSelectedNodes` 排最高（会建组 +
碰 `parentId`，而 792 刚修过同一个函数的「静默掏空已有分组」）。读 `:3546-3548`
的 `position: absolutePositions.get(node.id) - groupNode.position.x`
——**是对的**。

但 794 立过一条硬规矩：只有静态证据时，报告**不许**说「验过了」。
所以本批去取行为证据。结果：读源码的结论**成立**。

## 二、三条不变量（只认绝对几何）

- **N1 不该跳的东西没跳**：被组合的成员，组合**前后绝对位置逐位相同**。
  ★ 判据**不预设** `position` 存绝对还是相对：绝对值由 raw 里的 `pos` 沿
  `parentId` 链**独立重算**，并要求与探针记录的 `abs` **一致**。
- **N2 成员在框内**：新组的绝对框包含所有被组合成员（793 立的不变量）。
- ★★ **N3 操作要么生效、要么有反馈**：792 遗留的判据。

## 三、三条臂的读数（两轮逐位相同）

宿主组是**通过 UI 造出来的**（选 2 个散节点按 `G`），不是注入的 —— 792 那条修法
的前提就是「UI 造得出组」，注入会绕过这条前提。

### 臂 1：宿主组的一个成员 + 一个散节点

| 成员 | 组合前绝对 | 组合后绝对 | 新父 |
| --- | --- | --- | --- |
| `t-9j2MoccxBj` | `(108,-125)` | `(108,-125)` | 新组 |
| `i-lBzmo67AHv` | `(410,932)` | `(410,932)` | 新组 |

宿主组：`(68,-165) 722×828`、2 个成员 ⟹ `(92,233) 698×430`、**1 个成员**。

⟹ **逐位没跳**（N1 成立）；新组框**包含**两个成员（N2 成立）；节点数 **+1**。

★ 顺带解释一个看着像巧合的读数：两个组的左上角都是 `(68,-165)` —— 因为
`group.position = min(成员绝对) − padding`，而两组成员共享同一个左上角成员
`t-9j2MoccxBj (108,-125)` ⟹ `108−40 = 68`、`−125−40 = −165`。不是巧合。

### 臂 2：宿主组的两个成员

两个成员的绝对位置同样**逐位不变**；宿主组变成 **0 成员**。

★ **附赠读数**：空组的框**仍然是 `1000×1487`**，没有收缩、没有消失。
验收器**独立重算**：那两个人当时的包围盒 ⊕ 2×padding 正好是
`(410+618) − 108 + 80 = 1000`、`(932+350) − (−125) + 80 = 1487` ⟹ 逐位吻合。

⟹ 这是 793 那条待拍板 ②（空组要不要收缩/弱化）的**实测读数**：现状是
**保持原框**。

### 臂 3 ★：一个组 + 一个散节点

| 读数 | 值 |
| --- | --- |
| 节点数 Δ | **0** |
| 新增 `data-*` 键 | **[]** |

## 六、给 792 的结论，以及为什么本批不修它
