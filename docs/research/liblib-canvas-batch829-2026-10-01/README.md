## 2. 怎么进源站导演台（batch 581 旧账的翻案）

★ batch 581 记的是「点『打开导演台』**点击无响应**」，并说导演台浮层**常驻 DOM**。
本批实测（2026-10-21，当前构建）：

- 浮层**当前不在 DOM**（页面里没有「3D导演台」字样）⟹ 581 那次的「常驻」是因为当时
  **别的入口**把它开着，不是常态；
- 真正的入口：画布节点 **`.react-flow__node-director-console-3d`**（「导演台 2」）上的
  **「打开导演台」**按钮；
- ★ 那枚按钮是**悬停才显形**的：
  `opacity-0 pointer-events-none group-hover:pointer-events-auto group-hover:opacity-100`
  ⟹ **不悬停就点不到**；而且它会被节点自己的缩略图
  `<img alt="构图预览">` 盖住 ⟹ Playwright 直接报
  `subtree intercepts pointer events` ⟹ **「点击无响应」可能是「按钮没显形 / 被挡」，
  不是「产品不响应」**；
- 关闭控件：浮层左上角 **`aria-label="关闭"`**（40×40 @0,6）⟹ 但页面里有**多个**同名
  「关闭」按钮（其中隐藏的）⟹ 必须用 `:visible` 过滤，否则会点到看不见的那一个；
- 浮层形态：**全屏 1920×1080**，内含 **2 个 `canvas`**；
- 底栏有「发送」「截图」「上传图片」⟹ **本批一个都没点**（生成/付费一律不碰）。

## 3. 源站的滑杆是「透明原生 range」

batch 581 早就记过：FOV 是 `min=15 max=90 step=1` 的**原生 range**，且它 `opacity:0`
盖在自绘轨道上。本批实测确认：右栏 **5 枚 range 全部 `visible:false`**（opacity 0）。

⟹ ★ **可见轨道 ≠ 真实控件** ⟹ 从截图量滑块位置会量错 ⟹ 交互必须点**原生控件**那一层
（本批点的就是它，产生了真实的 pointerdown/change）。

### 4.1 ★★ 顺带测出「源站的滑杆改动**不是即时落盘**」

★ 第一轮复原**只改了客户端、没落盘**：改完立刻关掉浏览器 ⟹ 再开时读到的**还是脏值**
（FOV 34、场景缩放 3.1）⟹ 于是第二轮 live 跑起来时**开局就是脏的**
（`FOV_初始` 读成 34、`场景缩放_初始` 读成 3.1）。

⟹ 改用「改值 → **干净关台** → **刷新页面** → 重开 → **回读**」之后，复原才真的生效：

| 读数 | 值 |
| --- | --- |
| 复原后（刷新页面再读）**场景缩放** | **3** ✔ |
| 复原后（刷新页面再读）**FOV** | **67** ✔ |

★ 证据留了两份：`raw/source-829-restore-attempt1-unpersisted.json`（失败的那次）与
`raw/source-829-restore.json`（成功的那次）。

⟹ ★★★ **落盘触发点 = 关台**（干净关台/刷新才写下去）⟹ **与 clone 同构**
（clone 是 `closeSession` → `directorProjectPersistence.save`）。
⟹ 也就是说：**源站与 clone 都是「关台时保存」，不是「改一下就立刻存」**。

### 4.2 ★★ 「复原」要**换 context** 才算验证过

★ 同一个 context 里「改值 → 刷新页面 → 读回原值」**只能证明本地那份还在**——
而源站的滑杆值**也存在服务端**，所以真正的问题是「服务端那份改了没有」。

⟹ 于是加了一手：**开一个全新的浏览器 context**（localStorage 独立）再读一次：

| 读数 | 场景缩放 | FOV |
| --- | --- | --- |
| 全新 context ① | **3** | **67** |
| 全新 context ② | **3** | **67** |

⟹ ★★ 服务端**确实**干净（两个互相独立的 context 读数一致）⟹ 这条做成了判据 **S10**。
★ 顺带查到：源站 localStorage 里**没有任何导演台相关的键** ⟹ 这些值确实来自服务端。

★ 还有一个**操作层**的坑：复原时若右栏停在**机位1 的属性面板**上，「场景缩放」那枚 range
**根本不在 DOM** ⟹ 按旧坐标去点等于**点了个寂寞** ⟹ 必须先**重开台**（新开的台右栏在
「3D场景」页签）再复原。

## 7. 方法论收获（可复用）

**① 「点击无响应」有三种，得先分清是哪一种。**
源站那枚「打开导演台」是 `group-hover` 才显形的 ⟹ 不悬停就**点不到**，还会被缩略图挡住
⟹ 表现为「点了没反应」。⟹ 拿到「点了没反应」先问：**这个控件此刻可见吗？可命中吗？**

**② 透明原生控件：可见轨道 ≠ 真实控件。**
源站的 range 是 `opacity:0` 覆盖在自绘轨道上 ⟹ 截图量位置会量错 ⟹ 要点**原生控件**。

**③ 改值必须回读校验，「读数没变」不能直接当「产品没反应」。**
我第一版点 FOV 的 0.7 处恰好等于原值 67 ⟹ 读数「没变」⟹ 若就此收工，就会把
「我的点击没生效」写成「源站不改 FOV」。⟹ 做法：**改完回读，没变就换一格再点**。

**④ 标签匹配要「同列」。**
我第一版按「上方最近的一行文字」取标签，把左栏的「搜索场景对象」（55,99）当成了右栏
「场景缩放」（1656,64）的标签 ⟹ 改错了控件。⟹ 标签必须**水平区间重叠**（同一列）。

**⑤ 源站是「用户的真实项目」⟹ 测完必须复原；而「复原」本身也要**回读验证**。**
第一轮复原只改了客户端、**没落盘** ⟹ 我差点把一个**没生效的复原**当成「已复原」写进结论
（第二轮 live 开局读到的就是脏值 34/3.1 才发现）。
⟹ 复原的正确姿势：改值 → **干净关台** → **刷新页面** → 重开 → **回读** ⟹ 并把它做成一条判据（S7）。

**⑥ 「回读验证」要选对读面。**
第一轮复原后我只读了**内存里的值**（67、3）⟹ 那是**客户端状态**，不是**落盘状态**。
⟹ 判据要问的是「**重新加载之后**读到什么」，不是「改完立刻读到什么」。

- ★★ **599/604 那条遗留问的「zoom」，本批没有对上号**：它们问的是**导演台的 zoom**
  （clone 侧对应 `timeline.zoom`），而本批测的是源站的**场景缩放**（3D 视口，0.1–10）

  clone 用 localStorage 持久化**方向与源站一致**。
- ★ **源站有没有撤销栈**（历史）本批**没测** ⟹ clone「历史刷新后归零」这件事**仍无源站对照**。

  但**字段未必等价** ⟹ 记为**待查**，本批**不**定性为 clone 的缺陷。
- ★★ **落盘时机**两边不同：源站是**关台时**才存（改完直接关浏览器会丢），
  clone 是**每次命令即写** localStorage ⟹ 这**可能**是 clone 更稳，也可能只是时机不同
  ⟹ 本批**只记录**，**不**定性。
