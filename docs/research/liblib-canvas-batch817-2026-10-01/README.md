## 三、★ Z 序：五份里**只有一份**在最上面

| 份 | DOM 序号 | `z-index` |
| --- | --- | --- |
| 第 1 份 | 10 | 0 |
| 第 2 份 | 11 | 0 |
| 第 3 份 | 12 | 0 |
| 第 4 份 | 13 | 0 |
| 第 5 份 | 14 | **1000** |

★ 叠加顺序**不是**「后建的在上」，而是「**选中的那份**在最上」——
`addDerivedNode` 末尾有 `selectedNodeIds: [nodeId]`，React Flow 给选中节点
`z-index: 1000`。**份数从 3 抬到 5，这条机理一模一样**。

⟹ 用户在五份上**永远只看见最后点的那份**。

⟹ 「点五次 + 右键删一次」要按 **6 次** `Cmd+Z` 才退干净 ——
**撤干净的次数 = 操作次数**，不多不少。

## 五、★ 右键菜单的可见读数

```
保存到我的资产  创建主体  复制节点  ?⌘C  创建副本  ?⌘D  粘贴 ⌘V  删除 ⌘⌫  复制到剪贴板
```

7 项（**DOM 可见读数**，808 的纪律）：保存到我的资产、创建主体、复制节点、
创建副本、粘贴、删除、复制到剪贴板。

★ `⌘C`／`⌘D`／`⌘V`／`⌘⌫` 前面的符号被 `textContent` 读成 `?` ——
那是**快捷键字形图标**，不是文本；这是**读数形态**，不是缺陷。

⟹ 于是右键**既不是**「另一条能选中底下那几份的路」（第二节），
**也不是**「另一条能一次清干净的路」——它和左键一样只碰得到最上面那份。
