# Batch 621 — 窄屏时间线工具条改两行，顺手修好一个到处都在折行的按钮

日期：2026-10-01
验收脚本：`scripts/verify-liblib-batch621.py`（38 项，三腿：390 / 768 / 1920，含收起态）
取证脚本：`/tmp/dbg621.py`（十个宽度的窗口 vs 内容）、`/tmp/dbg621b.py`（断点真实落点）、`/tmp/dbg621c.py`（内容宽是不是常数）、`/tmp/dbg621d.py`（两行几何 + 收起态 + 截图）、`/tmp/dbg621e.py`（「新建轨道」折行测量）

本批**零源站断言**（`probe616`：源站仍被他人占用，1600×1000、导演台被关）。

## 起点：618 修好了「不撒谎」，但没修「挤」

618 把工具条内容的裁切线从 padding box 收到 content box，四枚控件从「被不透明块压死」变成「横向滚一下就到」。那解决的是**诚实**：不再假装画出点不着的东西。但挤压本身原封不动 —— 390 下用户仍只能看到 776px 内容里的 122px。

## 先量，别猜

`/tmp/dbg621.py` 逐宽度量「左格窗口 vs 内容」：

| 视口 | 390 | 600 | 768 | 899 | 1024 | 1280 | 1440 | 1600 | 1920 |
|---|---|---|---|---|---|---|---|---|---|
| 窗口 | 122 | 332 | 500 | 631 | 756 | 1012 | 1172 | 1332 | 1652 |
| 被藏 | **654** | 444 | 276 | 145 | 20 | 0 | 0 | 0 | 0 |

窗口 = 视口 − 8（`px-2`）− 260（给右格留的 `pr-[260px]`），内容是**常数 ≈776px**（`/tmp/dbg621c.py` 逐子节点核过；宽视口上读到的 1012/1172 是「没溢出时 scrollWidth 塌成 clientWidth」，不是内容变长）。

所以：**工具条只在 ≥1044 才放得下**，而项目里 ≥900 就切桌面布局 —— 900..1043 这一档有 20..145px 被藏。390 只露出 16%。

## 改法：窄屏右格自己占第二行

沿用项目既有的 `max-[899px]` 断点：

- `header` 去掉 `pr-[260px]`（`max-[899px]:pr-2`）；
- 右格 `max-[899px]:static max-[899px]:w-full max-[899px]:justify-between max-[899px]:pl-2` —— 缩放簇靠左、导出靠右，不再浮在右端。

窗口变成 视口 − 16：

| 视口 | 390 | 600 | 768 | 898 |
|---|---|---|---|---|
| 改前被藏 | 654 | 444 | 276 | 145 |
| **改后被藏** | **402** | **192** | **24** | **0** |

即 **≥792 就完整放得下**；390 仍放不下 776px —— 那是物理限制，本批不假装解决了，只把「几乎看不见」变成「将近一半」，并且第二行的缩放与导出在任何窄屏宽度下都**完整可见**（244 < 视口−16）。

### 收起态要单独给一个数

两行吃掉 72px，`88 − 72` 只剩 16px 轨道区。窄屏收起高度改为 **124 = 36 + 36 + 52**，轨道条与今天（88 − 36 = 52）**一模一样**。

## 顺带修一个到处都在折行的按钮

截图里「新建轨道」的文字折成两行。`/tmp/dbg621e.py` 量了三个宽度，**完全一致**：

```
vw=1920  box=[82, 24]  clientH=24  scrollH=26  13px/13px  行盒=[13, 16, 16]
vw=1440  同上
vw= 390  同上
```

也就是说这是**既有缺陷**，此前没人看见是因为它一直待在横向滚动区之外 —— 直到 620 把窄屏工具条变成两行，它才第一次露在手机屏幕上（而 621 正是让它露出来的那一步）。

修法不是新造样式，是让 601 实测的数字自洽：82 宽 − 标签 52（13px 四字）− 图标 13 − gap 4 = **余量 13**，每侧内边距必须 ≤6.5px 标签才能单行；而源站那个 82×24 的按钮显然是单行的（24px 高的行内项折两行就溢出了，601 量的就是那个 24）。故 `px-2` → `px-1.5` 并锁 `whitespace-nowrap`。601 钉的 x=230 / 宽 82 / gap 15 / 圆角 8 / 13px 字号都没碰。

## 顺手查清断点：落点是 898/899，不是 899/900

`/tmp/dbg621b.py` 逐像素量：

```
vw=896  stripPos=static    window=880
vw=898  stripPos=static    window=882
vw=899  stripPos=absolute  window=631   ← 变回单行
vw=900  stripPos=absolute  window=632
```

而同一时刻 `matchMedia('(max-width: 899px)')` 在 899 仍报 `true`。原因：Tailwind v4 把 `max-[899px]` 编译成 `@media (width < 899px)`，**严格小于**。也就是说项目里所有 `max-[899px]` 规则的切换点都是 898/899。

本批**沿用**这个约定、不动它（改它会一次性移动代码库里每一条 `max-[899px]` 规则），只把落点记进 audit 与断言。

## 本批自己带出的真回归：导出面板的 z-50 从来没生效过

两行方案把右格从 `absolute` 改成 `static`，于是它变成了 section（`flex flex-col`）的**flex item** —— 这一点改变了层叠：`z-30` 对静态定位的 flex item **同样生效**并创建层叠上下文（我最初只按「定位元素 + z-index」判上下文，漏了这条，脚本判据也跟着错了一次）。

导出面板就在这个右格里（`div.relative > section[absolute z-50]`），于是面板的 `z-50` 被关进右格的 `z-30`，**永远够不到同为 section 后代的拖拽把手**（`absolute z-40`，8px，`top-0`）。两行布局把右格下移一行，面板随之抬起，其提交按钮 `data-director-export-submit` `@[109,660,260,32]` 底缘恰好跨过 section 顶边那 8px 把手带 —— 按钮点不动。

三个实验把「层叠」和「命中抖动」分开（`/tmp/dbg621h.py`）：

| 实验 | 提交按钮中心命中 |
| --- | --- |
| 面板 z 抬到 60 | 仍是把手 → **抬自己没用**，被困在父上下文里 |
| 把手 `pointer-events:none` | 命中提交按钮 |
| 把手 z 压到 10 / 5 / 整个 `display:none` | 都命中提交按钮 |

压到 10 就够了，说明层叠就是原因（不是命中抖动，也不是 8px 带太窄）。完整祖先链（`/tmp/dbg621j.py`）确认最近**共同**层叠上下文就是 section 本身，中间只隔着右格这一个陷阱。

**修法是抬陷阱，不是抬被埋的面板，更不动把手**：把手 `z-40` 压头行 `z-30` 是 596 注释里记着的源站实测关系；面板几何则是 clone 推断（源站未测，见 `DirectorExportPanel` 注释）。所以窄屏给右格加 `max-[899px]:z-[45]`（> 把手 40），让打开的面板能盖住把手带；右格与把手在几何上不重叠，轨道区不受影响。`≥900px` 的 `z-30` 一字未动。

这与 batch 611 是同一类问题的**镜像**：611 是「面板的 z-50 被 `backdrop-filter` 造的 section 上下文困住、够不到外面的属性列」，抬的是 section；这次是「面板被父级 flex item 的 z-30 困住、够不到兄弟把手」，抬的是父级。两次的共同教训是：**子元素的 z-index 只有在它的最近祖先层叠上下文里才有意义**，`position: static` 的 flex item 同样会创建上下文。

## 验收（38 项）

三腿各 12–14 项：

- **390 / 768**：工具条仍 36px；右格 `static` 且顶边正好接在第一行之下；`pr` 回到 8px；左格窗口 = 视口 − 16；**被藏 < 420**；缩放簇贴左且导出贴右、两枚都完整落在该行内；轨道条 103px。
- **1920**：右格仍 `absolute` 贴右缘、`pr-[260px]` 仍在、轨道条 145px、收起仍 88px —— 源站实测的那套一行布局一字未动。
- 三腿都断言「新建轨道」单行（`clientHeight == scrollHeight`）且仍 82 宽。
- 收起态：窄屏 124px + 轨道条 51–52px；桌面仍 88px。
- 逐腿无页面/控制台错误。
