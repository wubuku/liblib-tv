# batch 776 —— 验「D1 的两处必须一起改」这句话**本身**

> 结论先行：**「两处必须一起改」作为授权依据不成立。** 这句话是 763 挂起的
> 最高优先项里**唯一一句从来没有证据**的话，而它要用户批一次 `src/` 改动。
> 本批把它拆成两条可独立否证的推论，用**现码直接测**（不注入、不改 `src/`）：
>
> - **推论二成立**，而且是**直接观测**不是推理：**(b) `onFocus` 不再 `begin()` 单独改是空操作。**
> - **推论一被否证**：**(a) Escape 加 `activeRef` 守卫单独改不是空操作** ——
>   它把「按 N 次都不生效的死键」变成「按第 2 次生效」。
>
> 准确的说法（**更正 C776-1**）是：**只改 (a) = 按两次；两处都改 = 按一次。**
> **这是授权范围的缩小，不是修法的推翻 —— (a) 是可以单独做的。**

## 1. 上一批挂着什么

775 结清了「方向① 够不够」，把镜头交回给 763 挂起的**第一优先项**：

> `useDirectorGestureBoundary` 的 Escape 分支加 `if (!activeRef.current) return;`
> + `onFocus` 不再 `begin()` —— **两处必须一起改**

这句话由两条推论组成，而**两条都没有证据**：

| 推论 | 内容 | 若成立则 |
| --- | --- | --- |
| **一** | (a) 单独改是**空操作**（`onFocus: begin` ⟹ 焦点一落手势就 active ⟹ 守卫恒不触发） | 必须连 (b) 一起改 |
| **二** | (b) 单独改是**空操作**（Escape 分支**无条件** `preventDefault` + `stopPropagation` ⟹ 阶梯永远看不到） | 必须连 (a) 一起改 |

**两条都成立才需要「一起改」。任一条被否证，授权范围就能缩小。**

## 2. ★ 关键手法：不需要注入就能验「(b) 单独改」

这是本批最要紧的一句，所以放在最前面。

`useDirectorGestureBoundary.ts:92-98` 的 Escape 分支是：

```ts
onKeyDown: (event) => {
  if (event.key === "Escape") {
    event.preventDefault();   // :94
    event.stopPropagation();  // :95
    cancel();                 // :96  ← 清掉活动手势
    return;
  }
```

`cancel()` 会把活动手势清掉，**但不移动焦点**。于是「**第 1 次 Escape 之后**」
正好落在这个状态：

> 焦点仍在 gesture 控件上，但 `activeRef.current === false`

而这**正是拟议修法 (a) 会放行的状态**。所以 ——

**本实验第 2、第 3 次按压所处的世界，就是「(b) 单独改」之后的世界**
（永远没有活动手势）。若那两次按压什么都没做，**(b) 单独改是空操作**，
而且是**观测出来的**，不是推理出来的。

★ 同一批读数还**顺带否证了推论一**：既然那个状态**可达**且 (a) 会放行它，
**(a) 单独改就不是空操作**。两条推论在**同一批格子**里同时被判定。

## 3. 读数方法

| 读数 | 怎么读 | 为什么这样读 |
| --- | --- | --- |
| 有没有活动手势 | 桌根的只读属性 `data-director-active-gesture`（`DirectorDesk.tsx:889`） | 不需要改 `src/`，也不需要 store 句柄 |
| 用户可见的后果 | **导出面板有没有关**、**桌有没有关** | 字段的 handler 会 `stopPropagation()` ⟹ 挂在 window 的间谍**收不到事件** ⟹ `defaultPrevented` **读不出来**。「读不到」本身是证据。 |

★ 主读数**必须**是用户可见的后果。775 的 R100 说「只断言 `false` 没有鉴别力」，
本批是它的加强版：**连 `dp` 都读不到**，所以只能问「东西关了没有」。

## 5. 结果

### 5.1 实验臂：**11/11 是死键**，而且**毫无反馈**

- 聚焦 gesture 控件 ⟹ **11/11** 起了活动手势（`onFocus: begin` ⟹
  `beginDirectorGesture` 返回 `COMMITTED`）
- **第 1 次 Escape**：手势**被清空**，而**导出面板仍开、桌仍开** **11/11**
- **第 2、3 次**：**22/22** 次**毫无作用**
- **33/33** 次按压后**焦点始终在控件上**（Escape 不移焦）

⟹ 用户看到的是：按了 3 次，什么都没发生，也**没有任何提示**。

### 5.2 对照臂：测量**有鉴别力**

桌内非 gesture 元素上：**第 1 次 Escape 关掉导出面板**、**第 2 次关掉桌** ——
正是桌的 Escape 阶梯顺序（`:558` 导出面板档 → `closeWorkspace()`）。

⟹ 实验臂的「什么都没发生」**不是**「面板本来就关不掉」。
（验收器有一条专门的阴性对照把这条读数改坏，证明该判据不是恒真。）

## 6. 探针教训（本批抓自己的，比结论还多）

- **R111** —— ★**同步的 `.focus()` 之后必须等 React 重渲染再读 DOM 属性。**
  第一版在同一次 `evaluate` 里读完就读 ⟹ 得出「`onFocus` 不起手势」——
  **差一步就把 D1 拍板项的理由给否了**。「看起来是机制发现」的第一嫌疑
  应当是自己的**测量时序**。
- **R112** —— ★**「少测」与「不存在」在产物里长得一模一样**（775 的 R104 复现）。
  姿态族卡在 `characterTab === "pose"`（`DirectorInspector.tsx:2339`）、
  路径控件是 `paths.map`（`:1041`）、锚点手柄还要求
  `selectedAnchor.type !== "vertex"`（`:1189`）。补上前置后是 **25 / 9 / 6** 个 ——
  **代价是 31 个差点被记成「不存在」的控件。**
- **R113** —— ★**「点不动」是没有鉴别力的失败信息**。本批连踩三次，三个不同原因：
  ① 拿**菜单面板**的选择器当**触发器**（真触发器是时间轴的
  `[data-director-track-draw-trail]`，`DirectorTimeline.tsx:1677`）；
  ② `SCAN_CLICK` **不滚动** ⟹ 元素在检查器的 `overflow-y-auto` 折叠区外就点不到；
  ③ 锚点类型取值**猜**成 `smooth`，而源码里是
  `vertex`/`symmetric`/`asymmetric`（`:1141-1144`）。
- **R114** —— ★**`if not x != "true"` 是优先级陷阱**：Python 里**比较先于 `not`**，
  于是解析成 `(not x) != "true"` ⟹ **成功反而报错**。可怕之处是
  「手动复现成功、函数却报失败」—— 两者不一致时**先怀疑判据**。
- **R115** —— ★**前置链要一层一层拆到底，不能停在「点不到」。**
- **R116** —— ★**内嵌时间戳的 id 会让「两轮逐字节一致」永远不可能**，而它长得像
  「机制不一致」。手势 id 形如 `director-gesture-<毫秒>-<序号>` ⟹ 11/11 格都「不同」。
  正确做法是**归一化**（只扔时间戳、保留「有没有手势」）**并把归一化写进产物** ——
  不是把该字段**整个排除**，那样会让人以为那一格没被比较过。
- **R117** —— ★**静态扫描里「找结束标记」必须带作用域**。`block()` 找 `},` 时从
  文件头开始 ⟹ 匹配到起点**之前**第 90 行的另一个 `},` ⟹ 返回空串 ⟹ 读成
  「Escape 分支里没有 `preventDefault`」—— **一个假零，且方向恰好是
  「我们的机制不存在」**。与 R107、R110 同族：**搜索没作用域 ⟹「找不到」
  被读成「不存在」。**
- **R118** —— ★**阴性对照的 `kw` 必须取自判据标签里的字面量**，不能取自「意图」。
  第一版写 `kw="测量有鉴别力"` —— 那句话只在 `why` 里、标签里根本没有 ⟹
  翻红列表一条都匹配不上 ⟹ 被读成「判据不灵」。**775 也踩过一次同一个坑：
  这是复发性陷阱，不是手滑。**

## 7. 更正

### C776-1 —— 改的是**一条挂着的拍板项**的措辞

**原措辞**（763）：「Escape 分支加 `if (!activeRef.current) return;` +
`onFocus` 不再 `begin()`（**两处必须一起改**）」。

**据实订正**：

- **(a) 单独改不是空操作。** 第 1 次 Escape 之后（`cancel()` 清了手势、焦点不动）
  就落在「`activeRef` 为假」的状态，而它**可达** ⟹ (a) 单独改会把死键变成
  「按第 2 次生效」。
- **(b) 单独改仍是空操作** —— 第 2/3 次按压**直接观测**了那个世界：什么都没发生。
- 所以「必须一起」应改写成 **「只改 (a) = 按两次；两处都改 = 按一次」**。

⟹ **(a) 是可以单独做的。** 这是**授权范围的缩小**。
