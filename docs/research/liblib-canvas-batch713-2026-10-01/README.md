# batch 713：712 的「4.24 上限」是视口边缘，不是夹紧

日期：2026-10-03　验收器：`scripts/verify-liblib-batch713.py`（6 条判据，含一条撤回判据，零 store 写入，不改 `src/`）

## 起点

712 测出：标尺左侧精确按 `t = frac × duration` 映射，frac ≥ 0.54 之后 `t` 冻结在
**4.240000131736106**，而 `duration = 8`、关键帧在 0/4/8 —— 三者对不上。
712 把它记成「死区而不是夹紧」，并把 **4.24 当成播放头的上限**。

**本批证明那个上限不存在。** 读法换成：**时间轴是横向可滚动的，标尺比可见视口宽** ——
点不到的那一段**在视口外面**。

## 决定性读数

| 读数 | 值 |
|---|---|
| 标尺宽度 | **1779.125** |
| 滚动容器 `clientWidth`（可见） | **958** |
| `scrollWidth` / `overflow-x` | 1779 / `auto` |
| **可见边缘对应的 frac** | **958 / 1779.125 = 0.5385** |
| 712 里冻结开始的 frac | **0.53** |
| 滚到底（`scrollLeft = 821`）后点 frac 0.75 | **`t = 6`** |
| 滚到底后点 frac 0.99 | **`t = 7.92`** |

**同一个 frac，滚不滚差 1.76 秒。** 播放头**能到 7.92 ≈ duration = 8**。

⟹ **712 的读数全部存活，解释要换**：那不是死区、不是夹紧、不是上限 ——
**是标尺有一半在视口外面，点不到。**

## 默认缩放下 46% 的时间轴在视口外

`zoom = 44` 时标尺 1779px、面板可见 958px，**宽度比 1.857**。
用户看到的时间轴只到 **t ≈ 4.31**，剩下 46% 需要**横向滚动**才能看到 ——
而滚轮是有效的（`scrollLeft` 0 → 821 → 0）。

## 顺带一条可操作的事实：想看全程只能拖那枚「不能点」的 zoom 划块

712 测出 zoom 控件**只能拖不能点**（点它 `zoom` 不变，拖它 0..100）。
现在把两批接起来：`zoom = 44` 放不下 8 秒，**要缩小 zoom 才能把全程装进面板** ——
**唯一的入口是一枚点击无效的划块。**

⟹ 这不是两个孤立的小问题，而是**同一条链**：默认缩放装不下 → 用户要滚 →
而「缩小以看全程」这条更直接的路，只有一枚不能点的控件。

## 方法论收获（可复用）

**① 712 那个「换个起点再点」的测试是对的，但它只能分两类。**
它把「夹紧」与「不响应」分开了 —— 两个起点都落在**视口内**，
所以两种机制都表现为「不变」。
**要再分一层（「不响应」与「点不到」），必须换一个能点到它的位置**，也就是**先滚动**。

⟹ **「无响应」至少有三类：夹紧、点不到、被吞。**
两两区分要用**两个不同维度的变化**：712 换的是**起点**（时间维），
本批换的是**位置**（空间维）。
**一次实验只能分一类，这是设计实验时就要想清楚的。**

**② 数字对不上的地方，先量几何。** 712 卡在「4.24 和 8 对不上、也和 4 对不上」，
本批第一件事是量 `clientWidth` 与 `scrollWidth` —— **958/1779 = 0.5385**，
和冻结点 0.53 一拍即合。
**「算不出来的常数」通常不是算错，是量错了对象**（量的是元素，问题是视口）。

**③ 「4.24」这种奇怪的数不是缺陷的指纹，是「我量错了对象」的指纹。**
真的夹紧通常落在 `duration`、`duration/2` 或某个关键帧上（712 就逐一排除了）；
**落在一个谁也解释不了的数上时，先怀疑自己的读面。**

## 待拍板（不阻塞）

- **撤销 712 的两项**：标尺右侧不是死区、4.24 不是上限
- **默认缩放装不下全程**（1.857 倍，46% 在视口外）：
  要不要把默认 zoom 调到能装下 8 秒，或者给时间轴一个可见的滚动提示
- **想看全程只能拖一枚不能点的 zoom 划块** —— 要不要给 zoom 加点击落点
  （这是 712 与 713 接起来才发现的链，单独看任一批都看不出来）
