# Batch 628 —— 把尺子扫到高度方向，并把两族「被盖住」拆成源站事实与退化视口

日期：2026-10-01 · 零源站断言 · **一个界面的字符都没改**

627 把 86 个宽度扫完了，**但那张网格的高度是固定的 900**。而 626 挖出的两个真缺陷恰恰**只在高度上出现**：`motion-path-menu` 的盒底恒为 `视口高 + 63`，`geometry-submenu` 的盒底恒 778 —— 两者与宽度无关、与高度强相关。所以 627 的网格从定义上就覆盖不到 626 那类缺陷。

## 零源站断言

`probe616`：源站仍 1600×1000、导演台被他人关闭。**本批改的是普查的量法与豁免，不是界面** —— 源码改动为零。

## 一、扫法

- **高度**：360→1400 每 20px，加上 626 那个 778 阈值附近的密集带 778..799，再加 **1150**（源站自己的实测视口高，而每 20px 的网格正好跨过它：1150−360 不是 20 的倍数，第一轮 CROSSCHECK 就因此 `KeyError`，见第七节）。
- **状态**：`展开`（时间轴 182）与 `收起`（88）。收起步意味着时间轴贴底更高、下方可用空间少 94px，几何上最容易出事的组合，627 完全没测。
- 共 **75 个高度 × 2 态 = 150 格**，主扫靠 resize 一页，再用 **11 个全新加载**交叉校验。

## 二、结论一：几何边界轴在高度方向是干净的

| 读数 | 值 |
| --- | --- |
| 「视口外且不在任何裁剪祖先之内」 | **0**（150 格全部） |
| 视口外控件累计 | 882（展开）+ 1252（收起） |
| **「一个视口外控件都没有」的格数** | **0** ← 非空转 |

## 三、结论二：层叠那半在矮视口下确实有事，而且是**两族**，性质完全不同

619 一直有一条名字豁免 `KNOWN_BLOCKED = ("帮助",)`。本批发现被盖住的其实是**两族**，混在一起会导致两种错误处理，所以必须拆开。

### 第一族：时间轴作为覆盖层压住三列 —— **这是源站事实**

`vh=400` 时的精确归因（探针 D/F）：

```
受害者 隐藏咖啡桌  @[176,276,24,24]
  祖先  div[data-director-object-id=director-prop-table]      ← 场景树里的对象行
        section[data-director-tree]      box=[48, 52, 232, 348]
        aside[data-director-mobile-panel-state=closed]  pos=absolute z=30
命中者 div {data-director-timeline-track-list}                ← 时间轴的 320px 左列
```

机制：工作区是 `fixed inset-0`（**满视口**），时间轴是 `relative z-40` 贴在底部 182px，而三列是 `absolute bottom-0` 的面板。**613 在源站 1920×1150 实测过这件事**，`DirectorDesk.tsx:1167` 的注释原话是「时间线是浮在中间列上的独立覆盖层，会盖住 rail 的下段」。

所以矮视口下三列底部一条带被时间轴压住，场景树最后一个对象行的 **隐藏/锁定/删除三连**点不到。读数呈整齐的 3 的倍数（3/6/9/12/13/14/16/18），正是逐行被吃掉的曲线；阈值与「内容底 ≈ y368、时间轴顶 = 视口高 − 182」吻合。

**为什么必须换成结构化豁免**：原来的 `KNOWN_BLOCKED = ("帮助",)` 是**一个名字碰巧对上**。而这一族在矮视口下埋的是整组三连，标签随场景变化（咖啡桌 / 冷掉的咖啡 / 咖啡馆背景 / 角色01 · 陈默 / 机位01 · 对峙中景）—— **任何名字列表都盖不住这个族**。

新的豁免需要**两个半边同时成立**：

```js
hitInTimeline   // 命中者在 [data-director-timeline] 内
victimInColumn  // 受害者在 aside[场景对象] / aside[属性] / [data-director-icon-rail] 内
```

任何一边不成立照旧报缺陷。**621 那个真缺陷（导出面板提交钮 vs 把手）因此不受影响** —— 受害者不在三列内。

### 第二族：3D 视口的 gizmo 被底部 prompt 条压住 —— **这不是源站事实**

| 视口高 | 视口盒 | prompt 条顶边 | `X 正向` 盒 | 结果 |
| --- | --- | --- | --- | --- |
| 900 | [281,88,878,**630**] | 670 | [1114,**146**,15,15] | 安全 |
| 440 | [281,88,878,**170**] | 210 | [1114,**146**,15,15] | 安全 |
| 400 | [281,88,878,**130**] | 170 | [1114,**146**,15,15] | 被盖 |
| 360 | [281,88,878,**90**] | 130 | [1114,**146**,15,15] | 被盖 |

gizmo 的轴标签锚在**视口顶部**（y 恒为 146，不随视口高度变），而 prompt 条锚在**视口底部**（顶边 = `视口高 − 230`）。两者在视口高度塌到约 120px 以下时相撞，受害的是 15×15 的轴标签与「重置视角」。

两件东西**都是** 1920×1150 下的源站实测值，在那个视口相距甚远 —— 所以**源站在矮视口下会不会撞，未取证**。因此它不能混进第一族，而是一条**自带边界的独立豁免**：

- 豁免条件同样是两个半边（命中者在 `[data-director-scene-prompt-bar]` 内 **且** 受害者在 `[data-director-viewport]` 内）；
- **边界从扫描自身推导**，不手挑阈值：取「仍然触发豁免的最高视口高」为界，本轮实测为 **440**，并断言高于它的任何高度都不许再触发。

这样这条豁免就**不能被无声放宽**：将来若有人改布局让碰撞向上蔓延，这条断言会红，而不是被吸收掉。

## 四、本批**不修**第一族，理由写死

两条看似自然的修法都会破坏源站实测：

| 修法 | 破坏什么 |
| --- | --- |
| 把三列缩短到时间轴之上 | 破 613 钉住的 `aside` 盒子（源站 1920×1150 实测） |
| 给可滚内容加底部留白 | 破 `DirectorObjectTree.tsx:415` 标注为「**源站列表逐字**」的 `px-2 pb-3` |

要修需要**源站在矮视口下的读数**，那是待授权项。所以本批只做「把解释从名字巧合升级成结构理由」，并把每格被解释掉的枚数写进 audit —— **豁免是解释，不是通过**，读者要能自己判断这条豁免在这个视口下盖掉了多少东西。

第二族同理：视口被压到 90px 高时 3D 场景本身已不可用，但**该怎么处置是产品决定**，不是我能从几何推出来的。

## 六、本批探针自己踩的五个坑

每一个都差点变成假结论，按惯例记录：

1. **CROSSCHECK 越界**：`1150` 不在 `HEIGHTS` 里（每 20px 的网格跨过它），第一轮在算交叉校验时 `KeyError: 'expanded@1150'`。教训：交叉校验清单必须是主扫清单的**子集**，这个约束该写成断言而不是靠人记。
2. **抓错元素（第一次）**：用 `[data-director-timeline-object-row]` 取前两行以为在查对象行按钮，量到的却是 `收起属性`，全高度 `own=True`。那三枚在更下面的行里，被 `slice(0, 2)` 截掉了。
3. **抓错元素（第二次）**：改用 aria-label 前缀 `隐藏/锁定/删除` 全文档搜，`删除` 匹配到了 react-flow 的 `删除连线` —— 619 的普查用 `isFlow` 排除它们，我的探针没有。
4. **假设错了两次**：先猜「两列叠在一起」，探针 E 把 320px 单列整条打出来，**零重叠**、四个子元素排得整整齐齐（y=251/283/315/347，全 `pos=relative` `z=auto`）；再猜「轨道区叠了两层」，探针 F 的祖先链显示受害者根本**不在那一列**里，而在场景树面板中。第三次才用祖先链问对。
5. **`hitLabel` 不足以归因**：普查给的命中标签是**文本**，`<div>` / `<span>` 这种没法定位归属，而 `角色01 · 陈默` 本身就歧义（既是对象名也是轨道名）。真正的抓手是普查 item 里自带的 `data` 字段（`Object.keys(el.dataset)`）。

第 4 条最值得记：**我连续两次用「看起来能解释现象的机制」替换测量，两次都错**。最后是对**祖先链**的一次测量才定住 —— 这与 625 记的「x 几何断言看不见 z 序问题」是同一类：位置对不上的原因，未必在位置那一层。

## 不声称

- **源站任何事**，尤其不声称源站在矮视口下会撞（第二族）或会怎么处置（第一族）。
- **第一族与第二族是同一个问题**。它们都表现为「被盖住」，但一个根因在源站实测的几何里、一个根因在两个 clone 组件的锚定方式冲突，处置路径完全不同。
- **`重置视角` 的存在**：本轮探针用 aria-label 精确匹配时没找到它（`not found`），它出现在普查的标签里但来源是 `title`/`textContent` 回退。所以关于它的归属我只主张「它出现在被盖列表里」，不主张它具体是哪个元素。
- **只扫了 1440 宽**。宽度轴由 627 覆盖（86 个宽度 × 900 高），本批是高度轴（75 个高度 × 1440 宽）。**两者的交叉点（又矮又窄）没有测过**。
