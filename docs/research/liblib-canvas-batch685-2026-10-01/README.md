## 读数二：「零尺寸」这个类里混着三种成因，而普查把它们读成一个值

683 记的是「**2 枚**零尺寸是恒定的，不是矮视口造成的」。本批沿宽度轴量到 **11 枚**
「rect 为零」的读数，**其中没有一枚是「渲染了但被压成 0」**：

| 读数 | 数量 | 出现在 | 成因（`computed` 宽度 vs rect） |
|---|---|---|---|
| `rail-entry = {scene, add-character, add-camera, panorama, aspect-ratio, ai-import, help}` | **7** | vw ≤ 898 | `computed 32px` / rect `[0,0,0,0]` ⟹ 在**桌面资源栏的 `display:none` 里，根本没渲染** |
| `data-director-viewport=true` | **2** | vw ≥ 899 | `computed 32px` / rect `[0,0,0,0]` ⟹ 在**窄屏浮层条的 `display:none` 里，根本没渲染** |
| `timeline-object-name = {director-camera-main, director-character-lead}` | **2** | vw ≤ 898 | `computed 0px` / 无 `display:none` 祖先 ⟹ **真的被 flex 缩成 0** |

**两个 `display:none` 容器互为补集**（源码事实）：

- `DirectorIconRail.tsx:439` — `hidden w-12 … min-[899px]:flex` ⟹ **只桌面**
- `DirectorViewport.tsx:3365` — `hidden gap-1 max-[899px]:flex` ⟹ **只窄屏**

所以零尺寸人口在 898/899 处**整组对调，且两组不相交**：窄屏 9（7 未渲染 + 2 真零），
宽屏 2（2 未渲染 + 0 真零）。读数侧的资源栏盒：vw ≤ 898 是 `[0,0,0,0] / display:none`，
vw ≥ 899 是 `[0,52,48,668] / display:flex`。

### 这一条改的是 683 的**框架**，不是它的读数

683 说「2 枚恒定」在高度轴上**是对的**（两枚在每个高度都零），错的是**归类** ——
它们不是「渲染了被压没」，而是**未渲染**，这是**第三个状态**，按台账纪律必须与实测值分开。

623 的注释其实已经写下了这件事：

> 缝里的资源栏塌成 `[0,0,0,0]` —— 7 枚活控件一起消失，而**普查不把「零尺寸」算作遮挡**，所以 899 的普查报 covered=0，看不出来。

**所以 671 记的「零尺寸是普查盲区」要再深一层：普查筛的是元素**自己**的 `display`，
而 `display:none` 祖先里的控件**自己仍然报 `display:flex`** ⟹ 它带着一个零 rect 混进计数里。**

派生后果：**132 是普查人口，不是画布上的控件数。** 真正 `rendered` 的数量随宽度在
**125（vw=480）到 130（vw=1280）**之间变。

## 读数三：普查的 `Math.round` 把连续斜坡伪造成平台

第一遍普查（`getBoundingClientRect` + `Math.round`，即 678/682/683 用的那把尺）报：

- `data-director-project-import` 有 **16 个平台**，其中 `31` 平台横跨 **620..627**，
  于是读起来像「**非单调凹陷**」；
- `data-director-capture` 是**每像素 +1 的 35 级台阶**。

换 `getComputedStyle().width`（**不取整**）之后：

| 键 | 取整平台数 | 未取整步数 | 真形态（526 宽度内） |
|---|---|---|---|
| `project-import`（380..640） | 16 | **129** | 一条 **1/64px 栅格上的连续斜坡**（380 的 16.5781px → 493 的 32px） |
| `capture`（725..759） | 33 | **35** | 连续斜坡，步长 61–62 个 1/64（≈0.953px/px），51.5156 → 84 |
| `header-object-name`（380..500） | 44 | **118** | 连续斜坡，步长 8–24 个 1/64 |
| `project-export`（380..1360） | 1 | **1** | 真恒定，`32px`，526 个宽度逐字相同 |

`620..627` 那一段，取整读数恒 `31`，而未取整读数**严格递增**：

```
620 30.7656  621 30.875   622 30.9688  623 31.0625
624 31.1719  625 31.2656  626 31.375   627 31.4688   ← 取整全部读成 31
```

**所以本批最抢眼的那条读数（「非单调的 8 像素凹陷」）是仪器造的。** 真实形态是
「**一条斜坡 + 一处跳变**」，跳变点在 **620**（见读数四），不是一段带。
而且整条 `import` 序列（380..640）**只有一处下降**，就在 619→620 —— 除此之外只升不降。

> 栅格判定用容差而不是等号：`getComputedStyle` 返回的是**四位小数字符串**
> （`30.7656px`），绝对误差 ≤ 0.00005px，×64 = 0.0032 个 1/64 单位。
> 第一版容差取 1e-3，三条斜坡全判 false —— **是容差定错，不是读数错**。

**只在整数单位上成立**。本批没有推翻它，只是指出它**没有覆盖亚像素变化**。

## 读数四：宽度轴上有**两条**断点，第二条是**跳变**

| 断点 | 读数 | 机制 |
|---|---|---|
| **898/899** | 12 个键同时换尺寸；两个 `display:none` 容器对调 | `min-[899px]`（`DirectorIconRail.tsx:439`）/ `max-[899px]`（`DirectorViewport.tsx:3365`）/ `matchMedia('(max-width: 898px)')`（`DirectorDesk.tsx:392`） |
| **620** | `project-import` 未取整宽度从 **`32px` 掉到 `30.7656px`**（**−1.2344px** = 79/64），随后单调爬回 32（**vw=633 追平**，633..640 恒 32） | 它的兄弟 `data-director-capture-status` 上有 `max-[620px]:hidden`（`DirectorDesk.tsx:1072`）⟹ **620 起这个兄弟变成 flex item** |

623 记过 `min-[900px]` → `min-[899px]` 那一对**错开一像素**的缝并已修好；本批复核
**899 这一档没有缝也没有叠**（新开页在 899：资源栏是 `display:flex` / `48×668`，
`matchMedia('(max-width: 898px)')` 为 `false`）。

**但 `(max-width: 899px)` 这个写法是个还活着的坑**：在实测的 6 个宽度里，
它**恰好只在 vw=899 一处为真**，而那一处布局**已经是桌面**：

| vw | `(max-width: 898px)` | `(max-width: 899px)` | 资源栏 |
|---|---|---|---|
| 480 / 898 | `true` | `true` | `display:none` |
| **899** | **`false`** | **`true`** | **`display:flex` `48×668`** |
| 900 / 1280 / 1920 | `false` | `false` | `display:flex` `48×668` |

622 把 JS 侧改成了 `(max-width: 898px)`；**`(max-width: 899px)` 只在注释里被否掉，
字符串本身还在仓库里可被复制**。**这不是活缺陷**（没有代码在查它），是一个仍然可被复制的坑。

## 读数五：两个名义相同的图标按钮行为完全相反

`project-export`（`DirectorDesk.tsx:1122`）与 `project-import`（`:1128`）是**同一个
`flex h-8 w-8` class**，但读数相反：

| | `min-width` | 父元素 | 未取整宽度 |
|---|---|---|---|
| `project-export` | `auto` | `<div class="relative">` 包装层 | **恒 `32px`**，526 个宽度逐字相同 |
| `project-import` | `auto` | 右格**直接**子元素 | **16.5781px（vw=380）→ 32px**，129 个未取整值 |

包装层是块级、`min-width: auto` ⟹ **不可缩到 min-content 以下** ⟹ 按钮是刚性的；
裸按钮是右格的可缩直接子元素（`flex-shrink: 1`，**没有 `shrink-0`**）⟹ **连续缩**。

**所以「这个按钮是 `w-8` 定宽」这句话对其中一个不成立。** 这是本批唯一的候选缺陷，
修法是加 `shrink-0`（或给包装层同样处理）—— **改 `src/` 是产品决定，本批不动**；
而且该右格是 clone-only（`DirectorDesk.tsx:1056` 自己写着「源站导演台顶栏无对应物」）。

这不是假设而是读数，也正是 683 与本批能引用「同一个 132」的前提。

## 读数七：同键两尺寸在**三个**方向上都不变

两条 `data-director-track-label` 键在**全部 6 个宽度**（横跨断点两侧）上都是
`{(24,24), (36,18)}`。683 在高度轴上读到同一件事，684 认定 `36×18` 那枚是**轨道标题按钮
`机位`**（`truncate` class）、另三枚 `24×24` 是导航钮。

**三个独立方向都不变 ⟹ 它是结构，不是症状。**

## 自记：本批的仪器错了两次，两次是同一个形状

1. **resize 后不等沉降**（`/tmp/dbg685b.py`）：只等 45ms 就在 899/900 上读到
   `transition-transform duration-200`（`DirectorDesk.tsx:1190/1295`）的**中间帧**
   （树停在 `x=−185`、属性列停在 `x=899`），**造出一条不存在的缺陷**。
   改成「连续两次读数相同才算沉降」之后，**13/13 个标定点与逐页开桌法逐字一致**
   （`n` / 两个 `matchMedia` / 四个盒全部相同）。
2. **`Math.round` 造平台**（读数三）：第一版普查里最抢眼的一条**完全是仪器的产物**。

两次的共同形状：**我拿到的不是布局，是尺子。** 第一版探针的脚本还先在 Python 里写了
JS 的裸键名（`{vw: …}`）与 Python 集合推导（`{x for x in y}`），两次都是**仪器自己先报错**
才没让错误读数流到结论里 —— 探针对 ≠ 路对（683 已记），这里是第三次。
