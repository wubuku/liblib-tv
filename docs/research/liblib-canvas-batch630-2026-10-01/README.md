# Batch 630 —— 把尺子扫到**时间轴高度**这条第三轴，并修掉一个真实的钳制缺失

## 零源站断言

本批**没有一条源站读数**，而且这一条比前几批更要紧：**源站的拖拽量程未取证**
（`DirectorTimeline.tsx:273-274` 原话：*量程 88（收起档）..420 是 clone 自定的*）。
所以本批**不主张源站会钳制**，只主张 clone 自己这个魔数区间在短窗口下留出了一个
坏状态，而全应用对「不许超出窗口」已有 626 立的一致惯例。

## 一、这条轴为什么值得扫

627 扫宽度、628 扫高度、629 扫两者的交叉角——三批合起来覆盖了窗口
`innerWidth × innerHeight` 这个平面。**但窗口不是唯一能改变纵向布局的输入**：
时间轴面板可由用户拖拽调高，量程 `DIRECTOR_TIMELINE_HEIGHT_MIN=88` ..
`MAX=420`（`directorStore.ts:99-100`），实测自 `data-director-timeline-resize-handle`
（`cursor-ns-resize`、8px 透明条、`z-40`）。这条轴**一个格子都没被扫过**。

扫法：时间轴 12 档（88/120/150/182/210/240/270/300/330/360/390/420，量程两端到
默认值之间取中间值）× 10 个窗口（900/1150/720/660/560/480/400/360 高 assorted 宽
）× = **120 格**，另加 4 次**全新加载**交叉校验。

## 二、真缺陷：高度只被钳在魔数区间里，从没和可用空间比过

`setTimelineHeight` 只把值钳在 88..420（`directorStore.ts:5506-5512`），
**没有任何东西拿它和可用纵向空间比**。修复前实测：

| 窗口 | 请求时间轴 | 时间轴底边 | 超出窗口 | 视口高 |
| --- | --- | --- | --- | --- |
| 1440x900 | 420 | y=900 | 0 | 392 |
| 1440x660 | 420 | y=660 | 0 | 152 |
| 1440x480 | 420 | y=508 | **28** | **0** |
| 1440x400 | 420 | y=508 | **108** | **0** |
| 1440x360 | 420 | y=508 | **148** | **0** |

面板是 `flexShrink=0` + `overflow-visible`（为了不裁掉那些绝对定位的下拉），
工作区是 `fixed inset-0` 不滚动，于是超出的 148px 直接在屏幕外；同时面板顶边被顶到
y=88，**3D 视口塌成 0 高**。

**为什么普查没报——这一点比缺陷本身更值得记**：几何边界轴在所有这些设置下
`offViewportUnreachable` 都是 **0**。因为落在屏幕外那块的所有控件**恰好都在时间轴
自己的 `overflow-y-auto` 滚动容器里**，于是被 `offViewportScrollable` 判为
「滚得到、不失败」。这正是 627 立的那条规则（*落在任意一个裁剪祖先之外就算被裁，
滚一下就到，记录不失败*）的**代价**：它在这里把一个真实的布局问题**掩盖**成了健康。

> **「够不着 = 0」不能当作「布局没问题」的证据。** 一条判据为了不误报而设计的
> 豁免分支，在另一种情形下会变成漏报。

**为什么这仍然是真缺陷而不是可接受行为**：拖拽把手全程可达（5 个横向采样点全部
命中把手本身），所以用户能拖回来，**不是死局**；但一个面板能被拖到 35% 在屏幕外、
且主视口高度为 0，本身就不是任何合理实现该有的状态。

## 三、修法

沿用 626 立的「不许超出窗口」惯例（路径菜单、rail 子菜单都是
`window.innerHeight − 8`），**越界多少上移多少，不越界一个像素不动**（不越界时
根本不调 `setTimelineHeight`）。挂在 `timelineRootRef` + `useLayoutEffect` 上，
并挂 `window.resize`——只钳 store 值处理不了「窗口后来被拖矮」这一路。

**安全边取 0 而不是 8**：8px 那条是给**浮层**留抓取余量的，贴底面板本来就该贴住
窗口下沿，套上 8 会把 613 在源站实测并钉住的 **182** 悄悄压成 174。修复后 182
逐像素不变（有断言）。

**不发明最小视口高**：视口能不能被拖到 0 高是**产品决定**，不是能从几何推出来的
（与 628 对第一族的处置同一条纪律）。本批只保证面板不越界。
**已知边界**：窗口矮于 88 + MIN(88) = 176 时，store 自己的 MIN 会把值顶回 88，
面板仍会越界——那种窗口下时间轴与视口无法共存，不是钳制能解决的。

## 四、629 的闭式公式在第三条轴上被证实

660 高的窗口配 420 的时间轴 → 视口 152px → `重置视角` 被盖住。**这正是 629 公式
预测的那一格**（阈值 182.5，152 < 182.5）。更完整的证实是**宽度无关性**：660 高 +
420 时间轴下，`视口高 = 152` 在 360/480/620/780/898/899/1200/1440 **全部 8 个宽度
上逐像素相同**。629 那条律不只在窗口平面上成立，它在时间轴轴上也成立。

## 五、本批更正两条既往结论

1. **629 的「这类碰撞只出现在从未采样过的矮/窄视口」被推翻**。1440x660 配时间轴
   420 就是一个**普通窗口**下可达的状态。**豁免本身不变**（`victimInViewport`
   不关心成因），变的是**说法**：它不是「窗口太矮导致的退化视口」，而是
   「视口比 gizmo 簇自身所需还矮，成因不限」。已写成断言
   `the-squeeze-is-reachable-at-an-ordinary-window-height`，免得日后被改回去。
2. **628 第一族的掩埋数是时间轴高度的函数**。660 高的窗口上把时间轴从 88 拖到
   420，掩埋数 **1 → 4 → 4 → 10 → 15**；而 900 与 1150 高的窗口上**恒为 1**。
   所以 628 台账里的「299 枚」**只在默认 182 上成立**，本批把限定词补上。

## 六、顺带挖出第三族盖住者

视口高为 0 时，视口自己贴底的 96px（工具条 + prompt 条）被顶到**自己的盒子上方**，
落进顶部 chrome 区。那里等着它的是**镜头条**：

`nav[data-director-shot-bar]` 自身盒在 y=281，但它的选项按钮
`data-director-shot-option` 定位在 **y=56** —— **向上溢出 225px**，正好压在视口
工具条的 `移动`/`旋转`/`缩放`/`16:9`（y=48..80）上。

于是合法盖住者集合要显式枚举成三个，且后两个**仅限视口高 ≤ 0 时**：底部带
（629 常态）、时间轴面板自身、镜头条。出现第四种即红。
`bottomBand@zeroHeight=True` **从未发生**——视口一旦没高度，面板总是先赢命中测试，
底部带轮不到当盖住者。这个**缺失本身有信息量**，故记录而不强求。

## 八、本批探针与判据自己踩的六个坑

1. **`clamped` 标志把两件事混为一谈**。首版用「面板比请求值矮」判定，基线里
   `640x480/tl=182` 报 True——可那不是钳制，是 **CSS 的窄族取值 176**（629 记过的
   clone-only 值）。得拆成 `clamped`（越界所致）与 `shrunkByCss`（族声明所致）。
   **「比要求的矮」有两种完全不同的成因。**
2. **「钳制被行使」最自然的定义是自毁的**。用「面板越出窗口」当证据，而那正是修复
   消除的东西——于是修复后判据报「钳制从未触发」并**因为错误的原因通过**。改成
   几何 signature：被钳的面板**贴着窗口下沿**且比请求值矮。修复后 `byOverflow: 12`。
3. **非空转集合里写了一个几何上不可能的组合**。我要求
   `{bottomBand@zero, bottomBand@positive, timeline@zero, shotBar@zero}`，
   而 `bottomBand@zero` 永不发生，于是这条检查红了。**要求一个不会发生的组合，
   等于把「非空转」变成「必须出现怪事」。**
4. **182 不是所有宽度的默认值**。`182` 属于 ≥899；≤898 声明的是 **176**。
   断言「默认 182 从不被压」必须**按族限定**，否则窄族那格会以「实际 176 ≠ 请求 182」
   的形式误报。两族各自的默认值现在都被钉住。
5. **探针按标签找元素抓错了同名节点**。探针 D 按文本 `移动` 找，落到 y=428 的另一个
   `移动`；audit 记的是 y=48。祖先链因此完全不可信。改成**按 audit 记录的盒取中心
   点**才对（探针 E）。这是 628 记过的同一个坑的第三次出现：**抓元素要按坐标，
   不要按标签**。
6. **DOM 归属与几何归属会不一致，而我先信了 DOM**。我一度认为「命中元素文本是时间轴
   内容，`hitInTimeline` 却报 False」是矛盾；实际那一族命中的是**镜头条**，本来就
   不该在时间轴里。是我把两族的读数混在一起比了。
   **两个读数「矛盾」时，先确认自己在比同一件事。**

## 不声称

- 源站任何事，尤其不主张源站会钳制、也不主张源站在这些视口下会撞。
- **视口 0 高该怎么处置**。本批只保证面板不越界；最小视口高是产品决定。

- **钳制能解决 176px 以下的窗口**。那里 store 的 MIN 会把值顶回 88。
