# batch 671 —— 「假阴性 0」是**结构性**的：2,673 次密集采样，一个都没逃出去

## 一句话

670 在 **19,680 格**上量到「rect 说没挡、实际挡了」**0 格**。
**但 664 早就记过：空集不算证据。** 本批就是去问那个 0 是**为什么**。

答案：**因为那 1px 的差总是落在父壳自己的 rect 之内** ——
不是巧合，是包含关系。**2,673 个采样点（0.01px 步长）零逃逸。**

## 1. 先把式子写出来，再去证伪它

检视器那三枚的**命中区左沿**比 rect 左沿靠左 ≈1.0px（668/669 实测），
所以「命中含、rect 不含」的那条带是

```
S = (rectLeft − 1, rectLeft)
```

* `aside` / `section` 的 `rectLeft = W − 281` ⟹ `S = (W−282, W−281)`，
  而视口面 `div.absolute.inset-0` 的 rect 右沿**也正是 `W − 281`** ⟹ 整条带被它盖住。
* `column` 的 `rectLeft = W − 280` ⟹ `S = (W−281, W−280)`，
  视口面**盖不住**（它的右沿就是 `W−281`）⟹ **救它的是父壳 `aside`**，
  后者的 rect 左沿 `W − 281` 恰好在列左沿左边 1px。

**所以我第一版的推理有一处错**：670 把救场者一律归给视口面。
**对列不成立。** 读数纠正了预期（见 §3）。

## 2. 密集采样（否证尝试）

三枚盒 × 三个宽度（1280 / 1405 / 1600）× 三枚提示条控件
= **27 条带**，每条带在 `S` 内取 **99 个采样点**（0.01px 步长），
逐点问两件事：**那枚盒在不在命中栈里**、**有没有任何 `pe:auto` 盒的 rect 含它**。

| 量 | 值 |
|---|---|
| 采样点 | **2,673** |
| 其中该盒**在栈里**的 | **2,646**（每条带 98–99 / 99） |
| **假阴性采样点** | **0** |

**而且先证这条带非空**：每条带都有 ≥98 个采样点真的把盒踩进了栈 ——
否则「零逃逸」会是一条**空断言**（664 记的老坑，本批专门防了它）。

## 3. 救场者按盒子分层（读数纠正了我的第一版推理）

| 盒 | `rectLeft` | `视口面右沿 − rectLeft` | 救场者（9 次测量的交集） |
|---|---|---|---|
| `aside`（`absolute.-top-9.bottom-0.right-0.z-30`） | `W − 281` | **0** | `div.absolute.inset-0`（视口面）等 5 枚 |
| `section`（`…flex-col.border-l`） | `W − 281` | **0** | 同上 |
| `column`（`min-h-0.flex-1.overflow-y-auto`） | `W − 280` | **−1** | **`aside` 本身** + `section` 本身 |

**「视口面救场」只对外面两枚成立**；列的条带在视口面**之外**，
是**父壳的 rect** 救的。而父壳之所以能救，恰恰是因为它**比列宽 1px**
—— 那 1px 就是 `section` 自己的 `border-l`（源站实测事实，667/668 记过）。

**所以那 ≈1.0px 的差是自我抵消的**：子盒的命中区多出来的那 1px，
永远落在**父盒 rect 以内**，所以任何只看 rect 的判据都仍然说「挡了」。

## 4. 结论该怎么写

* **670 的「假阴性 0」现在有理由了**，不是运气，也不是巧合。
* **668 的 ≈1.0px 仍然成立**，但它的后果被本批钉死在两个层面：
  **影响边界宽度的算术**（1405/1406 两格），**不影响任何一格的布尔判定**。
* **可推广的那一句**：只要一个盒子的命中区溢出它的 rect 的那部分
  **落在其父盒的 rect 之内**，rect 通道就仍然可靠。**本批证的是这一例**，
  不是全体。

## 6. 不声称

* **不声称**「只要溢出部分落在父 rect 内就永远可靠」是定理 ——
  本批证的是这一例，**没有构造反例，也没有声称不存在反例**。
* **不声称**那 ≈1.0px 的成因（668/669/671 连续三批遗留）。
* **不声称**换掉 `border-l`、换掉底部条的 `px-3`、或把提示条挪出视口面之后，
  这条包含关系还成立。
