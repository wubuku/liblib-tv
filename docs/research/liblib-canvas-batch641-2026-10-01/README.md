# Batch 641 —— 640 报的那 111 枚不是缺陷，是**我的探针在量圆的角**

## 零源站断言

**源站的 gizmo 轴按钮在窄屏是不是 15px、是不是 `rounded-full`、六枚之间是否重叠，
未取证。** 本批只主张 clone 的读数，不主张该改。

## 一、源码给出的候选机制

`DirectorViewport.tsx:381-433`：

```
容器   absolute right-5 top-5 z-20 h-20 w-20        （80 × 80）
按钮   absolute h-[15px] w-[15px] rounded-full      （实测 border-radius 3.36e7px）
命中层 absolute inset-0                            （按钮的父层，铺满容器）
```

**`border-radius` 会裁剪命中测试**。3×3 晶格在 8% / 50% / 92% 处的落点距圆心：

| 探针 | 距圆心 | CSS 盒暗示的半径 |
| --- | --- | --- |
| 四个角 | **8.91px** | 7.5px → 在圆外 |
| 四条边中 | 6.30px | 7.5px → 在圆内 |
| 圆心 | 0 | 可点 |

**看起来恰好 4 个角被挡** —— 于是 640 的 111 枚被「解释」成圆角。
**但那只是看起来。**

## 二、量出来的形状不是圆，而是 4.9–8.9px 的各向异性团

`border-radius` 的命中测试会**吸附到设备像素**，所以真实可点形状**不是** CSS 盒
内接的 7.5px 圆。逐方向以 0.1px 步长扫出去，量到：

```
E 7.4   W 8.4   S 7.4   N 8.4   SE 7.5   SW 8.1   NE 8.1   NW 8.9
```

84 枚按钮上出现过的全部半径：`4.9 / 6.5 / 7.4 / 7.5 / 8.1 / 8.4 / 8.9`。

于是：

- **四角 8.91px，最大半径 8.9px —— 余量 0.01px。** 角点算不算被挡，
  **由亚像素取整决定**。
- **边中点 6.30px，最小半径 4.9px** —— 84 枚里有 **28 枚**的边中点落在
  自己实测形状之外。

## 三、决定性的证据：同一页、同一批按钮，两个 harness 给出**不同答案**

隔离探针在 1440×900 量到 **4/9**；验收器在同一宽度量到 **6/9**。
**这个分歧就是结果本身，不是该被平均掉的噪声。**

结论很硬：**3×3 晶格在 `rounded-full` 控件上落在形状的边界上，它的判定不稳定。**
640 那 111 枚不是 111 个坏控件，是晶格探针量圆角与相邻圆点重叠时**必然**报出来的东西。

于是判据改成**以实测形状为锚**，而不是以 CSS 盒为锚：

```
一枚探针被判「被挡」  ⟺  它到圆心的距离 ≥ 该按钮实测到的最小半径
```

这不是循环论证：半径来自**每方向 120 步**的扫描，探针距离来自几何，两者独立求得。
两条断言把律钉住：**没有任何落在实测形状之内的探针被判被挡，也没有任何落在
实测形状之外的探针被判干净**（84 × 9 个探针全过）。

## 四、唯一剩下的真实缺陷

把圆角与重叠都算清之后，14 个宽度扫下来「无法解释的被盖」**仍然只有一处**：
`收起` @339，被 632 钉死的 **170px 居中视角组**盖住。clone-only、未修、
卡在源站顶栏取证。

## 五、顺带量清的一件事：两枚轴点真的相交，但只相交 1.48px

`x-negative` 与 `z-positive`、`x-negative` 的对偶 `z-negative` 与 `x-positive`，
圆心距**恒为 13.52px**（14 个宽度完全相同）。两枚半径 7.5 的圆在圆心距上
**相交 1.48px**。在 15px 的圆点上，那是一枚 1.5px 的透镜。

**这不是缺陷**——两枚相邻的轴点本来就该几乎贴在一起。是否该分开是**产品决定**，
且它依赖相机（位置来自 `getDirectorViewportGizmoButtonStyle(snapshot, …)`），
本批不主张改。

## 六、判据自己踩的坑

1. **按 CSS 盒推算形状，而不是量。** 我推出「恰好 4 个角」并据此写闭式，
   真实值是 4、5、6 三种都有。**形状要量，不要从盒推。**
2. **把「遮挡半径」当成「形状半径」。** 扫描在 4.9px 处断掉，是**邻居圆点**
   截断的，不是形状的边界。第一版没区分这两者，断言「边中点必然在圆内」——
   红了，而**红得对**。
3. **拿 640 的 111 当既有事实去解释。** 640 的非空转断言坚持「盲区必须被真实
   控件走到」，追下去得到的正是**证明量具出错而不是应用出错**——
   这条纪律本批拿到了它应得的回报。
