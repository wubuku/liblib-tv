# batch 714：zoom 划块的低端 23% 是空行程 —— 划块在动，时间轴不动

日期：2026-10-03　验收器：`scripts/verify-liblib-batch714.py`（6 条判据，含一条撤回判据，零 store 写入，不改 `src/`）

## 起点

713 测出：默认 `zoom = 44` 时标尺 1779.125px、可见 pane 958px，**46% 的时间轴在视口外**，
必须横向滚动（滚到 `scrollLeft = 821`）才看得到全程。
712 顺手测了 zoom 划块，结论是「**只能拖不能点**」，
并留下一个拍板项：「想缩小看全程只能拖一枚不能点的划块，**要不要给它加点击落点**」。

713 把两批接成了一条链：默认缩放装不下 → 用户要滚 → 而「缩小以看全程」这条更直接的路，
只有一枚点击无效的控件。

**本批把这条链从头问一遍：那枚划块到底把什么放大缩小了？它有没有可能根本调不出全程？**

## 决定性读数

| 读数 | 值 |
|---|---|
| `timelineWidth` 公式（`DirectorTimeline.tsx:495`） | `Math.max(640, duration × (3.36 + 4.978 × zoom))` |
| canvas 内联宽（zoom 0/5/10/15） | 恒为 **`640px`**（下限生效） |
| canvas **渲染**宽（zoom 0/5/10/15/20/23） | 恒为 **`958px`** |
| `scrollWidth` / `clientWidth`（zoom 0..23） | 恒为 **958 / 958**（不溢出） |
| **第一个真正改变几何的 zoom** | **24**（982.66px，`scrollWidth` 983 > 958） |
| zoom 0 与 zoom 23 的**刻度 x 位置**（81 条） | **逐条完全相同** |
| zoom 0 与 zoom 23 的**秒标签位置** | **逐条完全相同** |
| zoom 0 与 zoom 23 的**关键帧菱形位置**（6 枚） | **逐条完全相同** |
| 划块轨道宽 | **71px** |
| 点轨道 35% / 38% | zoom 跳到 **87** / **91** |
| 点圆钮中心 ±6px | zoom **不变**（44） |
| 聚焦后 `ArrowLeft×5` / `ArrowRight` / `Home` / `End` | 44→**39** / **40** / **0** / **100** |
| ctrl+滚轮 | zoom **44→44**，`scrollLeft` **0→0** |
| 整段 sweep 后 `history.past` / `lastCommandResult` | **0 条** / **仍为 null** |

**⟹ 滑块低端 24 个整数档（0..23，占行程 23%）对时间轴零影响**：
圆钮在走、填充条在长，刻度、秒标签、关键帧菱形**一个像素都不动**。

## 为什么：`min-w-full` 把源码里写着的 640px 下限吃掉了

`data-director-timeline-canvas` 同时挂着 `width: timelineWidth` 与 **`min-w-full`**
（`:1861`）。`min-width: 100%` 相对滚动容器（`clientWidth = 958`），
于是**渲染宽度 = `max(640, zoom 算出来的宽, 958)`**。

zoom 0..15 时内联宽确实是 `640px`，但渲染出来是 **958px** ——
**源码注释里专门解释过的那个 640px 下限，在这个布局里永远观察不到**
（它只在 pane 窄于 640px 时才会显形）。

## 顺带：缩到最小并不会让播放头失去可达性

`Math.max(640, …)` 的本意是「别把标尺压成一条缝」，但 `min-w-full` 双重保护了它。
实测 `zoom = 0` 时点标尺：

| frac | 0.25 | 0.50 | 0.75 | 0.99 | 右端往里 2px |
|---|---|---|---|---|---|
| `t` | **2** | **4** | **6** | **7.920** | **7.983** |

`t = frac × 8` 精确成立，且此时 `scrollWidth == clientWidth == 958`，**一个横向滚动条都没有**。

⟹ **713 那个「46% 在视口外」是能靠缩放化解的**：把 zoom 拖到 ≤ 23，全程就装下了。
**默认缩放是个选择，不是死局。**

## 撤回 712 的「只能拖不能点」

712 测到「点它 `zoom` 不变、拖它 0..100」，据此判定点击无效。
本批按 708 的 instead-of 纪律问「**变成了什么**」，而不是「有没有变」：

- 点轨道 **35%** → zoom **87**；点 **38%** → zoom **91**（**点击落点一直存在且有效**）
- 点圆钮**中心 ±6px** → zoom 仍是 **44**（**712 点到的正是这一格**）
- 聚焦后 `ArrowLeft×5` → **39**、`Home` → **0**、`End` → **100**（**键盘完全可用**）

⟹ 圆钮约 16px 宽，点在钮上不动是**浏览器对 range 的标准行为**（点在钮上 = 准备拖，不是跳转），
不是「不能点」。712 的读数存活，**解释作废**。

⟹ **「给 zoom 加点击落点」这个拍板项作废 —— 落点早就有了。**

## 唯一的入口，且是纯视图态

`setTimelineZoom` 在整个 `src/` 只有**一个调用点**（`:1346` 那枚 range 的 `onChange`）；
ctrl+滚轮既不改 zoom 也不滚动 ⟹ **没有第二个入口**。
而它是个裸 `set` + 钳制（`directorStore.ts:7003`）——
整段 sweep 0..100 之后 `history.past` 仍是 **0 条**、`lastCommandResult` 仍是 **null**。
⟹ **zoom 是纯视图态**，与源码注释（`:272` 「zoom 走 `timelineCollapsed` 同一条路，不进持久化」）一致。

另附一条小读数：range 没有 `step` 属性，浏览器默认 `step = 1`，
实测 22.5 → 23、23.5 → 24 ⟹ **小数 zoom 不可达**，
所以几何临界点 `zoom* = 23.379` 在界面上只能表现为「23 不动、24 开始动」。

## 空行程会随工程时长变长（推断）

由测得的公式反推，空行程的上界是
`zoom* = (pane宽 / duration − 3.36) / 4.978`（**推断**：只在 `duration = 8` 上实测过）：

| `duration` | 2s | 4s | 8s | 16s | 60s |
|---|---|---|---|---|---|
| 空行程上界 | **95** | **47** | **23**（实测） | **11** | **2** |

⟹ **工程越短，滑块的空转行程越长**：一个 2 秒的工程有 **96% 的行程是划块在动、时间轴不动**。
8 秒这一档的 23% 已经不是小数目了。

| 判据 | 断言 |

| `the-lower-23-of-the-zoom-slider-is-a-dead-band` | zoom 0/5/10/15/20/23 的 `canvasW == clientWidth` 且 `scrollWidth == clientWidth`；zoom 24 才开始溢出、宽度开始变；**zoom 0 与 23 的刻度/秒标签/关键帧位置逐条全等** |

## 方法论收获（可复用）

**① 「无响应」要分第四类：被控对象在这段区间上是输入的常函数。**
前三类是 713 立的（夹紧 / 点不到 / 被吞），都发生在**一次操作**上。
本批是**一整段连续输入**：控件诚实地接收、诚实地显示反馈（圆钮移动、填充条增长），
**被它控制的东西却是常函数**。
⟹ 「点了没反应」和「拖了 24 档没反应」要分开问，
**后者的正确读法是「量被控对象的输出曲线在哪些输入上重合」，不是「再看一次有没有变」**。

**② 判据要卡在「两端全等」上，而不是卡在某一个值上。**
只测「zoom=0 时宽度 = 958」只能证明下限生效；
测出「zoom 0 与 zoom 23 的 81 条刻度 + 8 个秒标签 + 6 枚关键帧**逐条 x 坐标全等**」
才证明这一段**什么都没发生**。
**「无变化」的强判据是逐叶全等，不是抽样。**

**③ 源码里写着 ≠ 屏幕上看得见。**
`:494` 的注释专门解释了 640px 下限的来历，但 `min-w-full` 让它在本布局里永不显形。
⟹ **读源码推出的性质，必须在运行时复核一遍**；反过来，
**运行时测不到的性质，也要回去问「是哪条 CSS 把它吃掉了」**。

**④ 判一条控件「不能点」之前，先问「点的是不是它自己」。**
712 的错不是量错，是**目标选错**：点在了 12px 宽的圆钮上，
而圆钮上的点击在标准 range 语义里就是「准备拖」。
⟹ **「控件不响应」这类读数，必须附带「点/按的那个点落在控件的哪个部位」。**

**⑤ 拍板项会因为前提被推翻而作废。**
713 攒下的「要不要给 zoom 加点击落点」看起来是个待办，
但只要「不能点」是假的，这个待办就没有对象了。
⟹ **待拍板清单本身也是需要复核的读面** —— 每隔几批回头看一遍，常常发现它已经过期。
