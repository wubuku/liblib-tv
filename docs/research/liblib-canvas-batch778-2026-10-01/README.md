# batch 778 — `Cmd+Z` 在检查器控件上的早退，是「按设计」还是「缺陷」？

> 这一批**更正我自己 777 的结论**。777 把「焦点在检查器输入框上时删除不可撤销」
> 记成缺陷 D1d（中-高），我 778 规划时进一步假设：
>
> > D1d **过宽**。正确范围 =「只有**没有原生撤销**的控件才是真空」⟹ 实测即 range 族；
> > number 族有原生撤销可用 ⟹ 早退是**取舍、按设计** ⟹ **D14 修法的授权范围缩小，
> > number 族的早退语义不必动。**
>
> **这个假设的前半被否掉了，后半被反转了。**

## 1. 777 留下的窟窿在哪

777 只回答了两个问题里**一个**，而且样本是 **n=1 的 range 滑杆**：

| | 问的是什么 | 777 的读数 |
| --- | --- | --- |
| **Q-doc** | 桌的 `Cmd+Z` 分支**够不够得着**？ | 够不着（`past` 1→1） |
| **Q-native** | 控件**自己**的文本撤销**顶不顶得上**？ | 没测 |

777 的 `fovInput` 臂用的是 `[data-director-camera-fov]`，而那个元素是
`DirectorInspector.tsx:1646` 的 **`type="range"` 滑杆**，不是数字输入框。
于是「焦点在检查器**输入框**上」这个措辞，当时是 **n=1 的 range 样本**。

⟹ 我规划时把「777 只测了 range」误当成「只有 range 是真空」。

## 2. 把它拆成两个独立问题

混在一起就会得出 777 那句过度概括。拆开之后两个问题**答案不同**：

- **Q-doc**：守卫 `if (isEditable) return;`（`DirectorDesk.tsx:487`）排在
  `Cmd+Z` 分支（`:506`）**之前**，而判据 `:475-480` **只看 tagName、不看 `type`**
  ⟹ **两族走同一条分支，都够不着**。
- **Q-native**：`number` 有浏览器的文本撤销栈 ⟹ 顶得上；
  `range` **没有** ⟹ 顶不上 ⟹ **死键**。

## 3. 方法

- **动作臂**：2 族 × 3 臂 = **6 格**（探针跑了 4 个臂，但其中两个是同一格，见 §4），
  另加**手势生命周期普查**（每族三阶段：聚焦后 / 改动后 / blur 后）。
- **对照**：两族**成对**比较 —— 只断言「range 没回退」的话，一个「根本不会撤销
  任何东西」的坏探针也能过。
- **两轮**，`tries`/`retried` 排除在一致性比较外。
- **族规模从 776 的 raw 现算**（跨上下文取 max，不是求和），不手抄。
- 静态层**独立实现**，并配**改源码**的阴性对照。

## 4. 我自己这一批的设计错：8 格里有 1 格是重复

`native` 与 `whileFocused` 动作完全相同（聚焦 → 改动 → `Cmd+Z` 不 blur）——
我在探针 docstring 里**自己写了**「与 `native` 同动作」，却仍然跑成了两格。
归一化（剥掉 gesture id 里内嵌的 epoch ms）后两臂**逐字段一致** ⟹ **6 格而非 8 格**。

## 5. 结果

### 5.1 生命周期：改动**要等移开焦点才进历史**（两族一致，4/4 读数）

| 族 | `input type` | 聚焦后 | 改动后 | blur 后 |
| --- | --- | --- | --- | --- |
| number | number | 手势开 `past=0` | 手势开 `past=0` | 手势清 `past=1` `GESTURE_COMMIT` |
| range | range | 手势开 `past=0` | 手势开 `past=0` | 手势清 `past=1` `GESTURE_COMMIT` |

⟹ 机制是 `useDirectorGestureBoundary.ts:80 onBlur: commit`。

### 5.2 Q-doc：**两族都够不着** ⟹ D1d 范围**没有被收窄**

`delWhileFocused` 两族读数**完全同构**：

| 读数 | number | range |
| --- | --- | --- |
| 道具回来 | **否** | **否** |
| `past` | 1 → 1 | 1 → 1 |
| `future` | 0 → 0 | 0 → 0 |
| `lastCommand` | 不出现 `UNDO` | 不出现 `UNDO` |

**理由很直白：input 的文本撤销栈里没有「删了一个对象」这件事** ——
原生撤销顶不上删除。

### 5.3 Q-native：**只有 range 是死键**（26 个）

`native` 臂（焦点还在控件内时按 `Cmd+Z`）：

| 族 | 改动到 | `Cmd+Z` 后 | 值回退 | `lastCommand` |
| --- | --- | --- | --- | --- |
| number | `7.5` | `4.8` | **是** | 停在 `GESTURE_BEGIN` |
| range | `48` | `48` | **否** | 停在 `UPDATE_CAMERA` |

range 那一格是**三读数同时不动**（值 + `past/future` + `lastCommand`）
⟹ 桌的键处理**根本没被触到**，而不是「触到了但没生效」。

### 5.4 被反转的结论：守卫在 number 族上是**承重墙**

`docAfterBlur` 两族都是 `past` 1→0、**`future` 0→1**、值回退、`lastCommand=UNDO`。

`future` 0→1 是「**唯一**的撤销槽被这次编辑占掉」的直接证据。而守卫的作用
正是让 number 用户按 `Cmd+Z` 撤**自己刚打的字**。

⟹ **整体去掉守卫会让 number 用户输入后按 `Cmd+Z` 撤掉上一个文档动作** ——
不是体验差，是**数据错**。

## 6. 修法的形状：同仓已有先例

`useDirectorGestureBoundary.ts:82-90` 的 `onPointerUp` **已经**在按
`type === "number"` 提前 return：

```
onPointerUp: (event) => {
  if (event.currentTarget instanceof HTMLInputElement &&
      event.currentTarget.type === "number") {
    return;
  }
  commit();
},
```

而 `DirectorDesk.tsx:475-480` 的 `isEditable` 判据**只看 tagName、不看 `type`**
⟹ 缺的正是这一层分派。**照抄 `:82-90` 的形状即可，不必发明新写法。**

## 7. 族规模（从 776 的 raw 现算）

| 族 | 控件数 | 组成 | 原生撤销 |
| --- | --- | --- | --- |
| number | **27** | `xf` 12 + `ptransform` 9 + `panchor` 6 | 有 |
| range | **26** | `pose` 25 + `fov` 1 | **无** |

★ 跨上下文**取 max** 而不是求和 —— 同一族控件在 camera / camera-path / prop /
character 里是**同一批 DOM 元素**（`xf` 在 camera 与 camera-path 都是 12）。
**独立交叉校验**：27 + 26 = **53**，与 776 README 自述的「共 53 个可用控件」相符。

## 9. 探针教训

- **R123** 探针里两臂动作写得一样，它们就是同一格。剔掉**臂标签**再逐字段比较。
- **R124** **「变化=是」有可能是「基准值没取到」的假象**：本批 `summarize()`
  只认 `valueBeforeUndo`/`valueAtUndo`，而 `native`/`whileFocused` 臂两者都没有
  ⟹ `str(None) != str("4.8")` **恒真**。实测 range 那格**其实没变**却被打印成
  「变化=是」。这是 R121（把「读不到」当成「没变」）的同族错误。
- **R125** 内嵌时间戳的 id 让「两轮一致」与「两臂同格」**两件事都测不了**。
- **R126** 「三个读数都没动」里的每一个「没动」都有三个不同原因 ⟹ 靠
  `lastCommand` 兜底，才能断言「键处理根本没被触到」。
- **R127** **臂的名字会替读数说话**：`fovInput` 读起来像数字输入，实际是 range 滑杆。
  **`type` 才是族的判据。**
- **R128** 静态搜索的四种「找到错的」本批各犯一次：忘 `.split("\n")`；
  命中 `:17-24` 的**类型声明**而非实现；`type="range"` 取首次而非末次；
  **`\b` 在 `-` 前也算词边界** ⟹ `fov\b` 命中 `fov-field`，而探针的 CSS
  `[data-director-camera-fov]` 是**精确属性名**匹配。**搜索式必须与选择器对齐。**
  ★ 第**五**种在**验收器**里：`last_before` 名字是 last、实现写成了 `next(...)`
  ⟹ 报出 `:1353` 而不是 `:1647`。**两个独立实现互相抓到它** —— 这正是
  「静态层独立实现」这条纪律的用处。
