# batch 810 —— 组框到底有没有收敛成**不动点**？答案是：有

> 799 在代码注释里留了一句警告（`canvasStore.ts:722-726`）：
>
> > **单趟不足，靠反馈补齐**。……也就是说「先外后内 + 每轮重算」单跑一趟是
> > **不够**的，正确性依赖那条反馈。
>
> 它当时是在**嵌套**结构上看到第 2 趟才收敛的。而 792 已经决定**UI 造不出嵌套组**。
> ⟹ 那条依赖在**用户可达**的形态里还成不成立，**没有人量过**。
>
> **本批的结论：在所有用户可达的形态上，组框每次都恰好贴合，而且停下来之后
> 已经是不动点。** 799 提的「在 fit 内部显式迭代到不动点」**不需要做**。

## 一、★ 判据：四边留白相等（不是「等于 40」）

组框必须**恰好包住所有成员**：

    左留白 = min(成员绝对 x) − 组绝对 x
    右留白 = 组绝对 x + 组宽 − max(成员绝对 x + 成员宽)
    上留白 = min(成员绝对 y) − 组绝对 y
    下留白 = 组绝对 y + 组高 − max(成员绝对 y + 成员高)

★ **留白从 raw 独立重算**，不抄源码里的 `GROUP_PADDING = 40`
（805 的「不预设常量」纪律：30 那个数是界面自己写着的，留白同理是**读出来的**）。
★ 判据只要求「**四边相等**」，**不要求等于 40** ——
「是不是 40」是源站对照的事（797 仍挂起），把两件事混成一件就会在没核对源站时乱改。

★ 判据只用**绝对几何**沿 `parentId` 链重算，**不预设** `position` 存绝对还是相对。

⟹ 停下来之后**已经是不动点**。

## 三、757 ① 的原始场景：拖成员，组框**跟得上**

第一版这条臂是用 `setNodes` 直接改成员坐标的，结果组框**纹丝不动**。
我差点把它写成缺陷。真因是 ——

> ★ **`setNodes` 绕过了 `onNodesChange`** ⟹ `routeReactFlowChanges` 没跑 ⟹
> **`fitStoryboardGroupsToChildren` 压根没被调用**。
> 「组没跟上」只是**我绕过了 fit 的触发点**，不是应用的问题。

改成**真 pointer 拖拽**（`mouse.down` → 8 步移动 → `mouse.up`，走完整事件路径）
之后，组框**重新贴合**（四边 40）。

★ 而 `badBox` 那两条臂证明了一件有意思的事：**改「组自己的尺寸」会触发 fit，
改「子节点的位置」不会**。前者改变 React Flow 测量到的尺寸 ⟹ 产生
`dimensions` 变化 ⟹ 走 `onNodesChange` ⟹ fit 跑起来；后者不产生这类事件。
**这正好说明 799 那条「靠反馈补齐」不是空谈** —— 反馈确实存在、也确实会跑，
只是**用户路径上它总能及时跑到**。

## 四、★ 一条新读数：拖拽之后组框坐标是**小数**

| 读数 | 值 |
| --- | --- |
| 组框 y | **`856.4765100671141`** |
| 组框宽 | **`1589.6845637583892`** |
| 组框高 | **`465.5234899328859`** |

而**用 `G` 造出来的组坐标全是整数**。⟹ 成员被拖动之后，组的 `position` 与
`width/height` 都会带上亚像素脏值。

★ 源码对此**有准备**：`fitStoryboardGroupsToChildren` 自己就带 `EPS = 0.01`
的容差（`canvasStore.ts:792`），注释里写明拖组会带来 `1e-14` 量级噪声。
⟹ **这不是新缺陷**，但它和 796 记的「亚像素脏值」、798 记的「尺寸吸附未测」
是同一族问题：**要不要吸附到整数**属产品决策，**本批不发明**。

## 六、探针返工四处（三处差点变成假结论）

| # | 现象 | 真因 |
| --- | --- | --- |
| 序1 | 用 `setNodes` 挪成员，组框**没跟上** | ★ 绕过了 `onNodesChange` ⟹ **fit 压根没被调用**。这是**我**的问题不是应用的 ⟹ 改用真 pointer 拖拽 |
| 序2 | 阳性对照读到的「扰动瞬间」**还是原值** `976×1089` | ★ 「施加扰动」和「读瞬间」是**两次** `page.evaluate`，中间隔了一次进程往返 ⟹ `setNodes` 触发的 React 重排已经把框修回去了。**读到的已经不是扰动后的值**。修法：把 `setNodes` 与**同步 `getState()`** 放进**同一个** `evaluate`（`set` 是同步的，此刻读到的就是还没被 React 洗过的原始值） |
| 序3 | `dragMember` 报「未知臂」 | 上游分派表里还写着旧名 `moveMember` ⟹ 新臂根本没跑到 |
| 序4 | S6（静态锚点）判红 | ★ 「单趟不足」那句在函数的 **JSDoc 里（函数体上方）** ⟹ 我的取段窗口从函数头开始、没盖住它。**这是我自己写的一个假红** |

★ 另有两处**验收器自身**的错误：

- **N5 的变异条件第一次写成 `o.get("扰动前")`** —— 「扰动前」在 **cell** 上、
  不在「观测」里 ⟹ 条件恒假、变异打不中、断言直接炸。
- N5 第二版**只改「第一次」**仍打不中 —— S4 读的是**「第二次」**。
  ★ 这是「**阴性对照必须打在性质真正读取的字段上**」的第二例（809 的 N1 是第一例）。

## 七、给 799 的结论

> **「在 `fit` 内部显式迭代到不动点」这个提议，在用户可达的形态上不需要做。**
>
> 五条臂 × 两轮 × 两个时刻，组框**每次都恰好贴合**、**停下后不再变化**；
> 手动破坏之后 fit **能自己修回来**。799 当时看到的「第 2 趟才收敛」发生在
> **嵌套**结构上，而 **UI 造不出嵌套组**（792 的决定，六次复核仍成立）。

★ **因此 `src/` 一行没改、没跑 build**（与 789／796／798／801／803／806／807／
808／809 同处理）。

## 八、不声称

- ★ **嵌套组仍未测**。UI 造不出（792），本批**没有**注入嵌套结构 ⟹
  「嵌套下第 2 趟才收敛」这条**本身没有被复现、也没有被推翻** ⟹
  799 那条注释仍然成立，只是**在不可达路径上**。
  ★ 一旦实现了嵌套，本批五条臂**必须全部重测**（799 的同类结论）。
- ★ **只测了「组 → 成员」这一个方向**。把**组本身**拖走（793 注释里说那是
  no-op）、把成员**拖进另一个组**、**拖到组外面再拖回来**，都**未测**。
- ★ **只测了图片与派生节点**。视频／音频／分镜／逐帧拉片节点当**组内成员**时
  的贴合**未测**（`nodeWidth`／`nodeHeight` 对不同类型可能走不同兜底）。
- ★ **只测了「非空组」**。空组的「保持原框不收缩」是 807／808 的读数，
  本批**没有**重新测（它不参与贴合判据）。
- ★ **拖拽只测了一次方向、一个距离**（`+501,+233`）。连续拖拽、拖到组外、
  拖到画布边缘（被视口裁剪）**未测**。
- ★ **没有测「第几趟收敛」**。本批只证明「停下来之后是不动点」，
  **不证明**它是第 1 趟还是第 5 趟收敛的。
- ★ **留白「等于 40」这件事仍未与源站对照**（797 仍挂起）。本批只判「四边相等」。
