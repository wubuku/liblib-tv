# batch 783 —— 11 个 `Escape` 主人「**能不能同时活着**」：**我的预测被否掉了**

> 日期：2026-10-01 ｜ 范围：782 普查出的挂载域 **11 个** `Escape` 主人
> ｜ 本批**未改 `src/`**、无注入、不做破坏性操作
> ｜ 判据与阴性对照数见「验收」一节

## 本批验的是 782 留下的缺口

782 数出了挂载域里 **11 个** `Escape` 主人，但只数了**形态**
（相位 / 有没有 `sIP`），没数**它们能不能同时活着** ——
而这才决定 Escape 的真实行为：同时活着时，一次按压会关掉几个？

## ★★ 预测（从源码逐行推出）与实测：预测错了

**预测**：`DirectorTimeline:570` 与 `:594` 是**同文件、相邻两个 `useEffect`、
两个独立状态变量、零交叉守卫** ⟹ 静态上没有任何东西保证它们不同时活着；
而唯一的互斥机制是 `:569` 的 `pointerdown` 外点关闭
⟹ **键盘激活不产生 `pointerdown`** ⟹ 键盘下应该能同时开着。

**实测**：`bothByMouse` 与 `bothByKeyboard` 的读数**完全一样** ——
第二个面板打开后，**第一个（路径菜单）被关掉了**。

⟹ 「键盘能绕过外点关闭」**被否掉**；
⟹ 「唯一的互斥机制是 `pointerdown`」**被否掉**。

## ★ 真机制：互斥写在**打开者**里，是双向显式交叉写入

| 打开者 | 那一行 | 位置 |
| --- | --- | --- |
| `togglePathMenu` | `setPresetPanelLeft(null);` | `:603`（**排在** `setPathMenuLeft(` 之前） |
| `togglePresetPanel` | `setPathMenuLeft(null);` | `:704`（**排在** `setPresetPanelLeft(` 之前） |

⟹ **双向、可证、设计好的不变量。** 运行时**两个方向都测了**：
`path → preset` 与 `preset → path`，两次都是「开第二个 ⟹ 第一个被关掉」。

★ **顺序不是细节**：两处交叉写入都必须**排在打开自己之前** ——
否则打开预设面板会先把路径菜单关掉、再打开预设，顺序恰恰是这条不变量
能成立的**原因**。验收器对此有独立判据。

## ★★ 本批真正的结论：「主人的门互相独立」≠「主人可以同时活着」

从普查看，这两个主人是**两个门状态互不相关**的主人：

| 主人 | 门 |
| --- | --- |
| `DirectorTimeline.tsx:570` | `if (pathMenuLeft === null) return;` |
| `DirectorTimeline.tsx:594` | `if (presetPanelLeft === null) return;` |

⟹ 两道门**互不提到对方的状态** ⟹ 「它们可能同时活着」。
★ 而**任何只看 Escape 主人的普查都看不见那个不变量，因为它写在打开者里。**

⟹ 这条**限制了 782 那份普查能承载多少结论**：普查给的是**形态**与**门**，
**不是「可达的共活集合」**。后者只能靠运行时，或专门去扫打开者。

⟹ 普查器因此**加了一层 `crossWrites` 扫描**（找每个门状态的写入点落在
哪个函数、那个函数**有没有顺手写另一个门状态**）—— 真机制立刻就出来了。
★ 推论：「我扫的东西里没有 X」**不能**推出「X 不存在」，
只能推出「X 不在我扫的范围里」—— 而这句话对上一批那份普查的**每一列**都成立。

⟹ **整条撤回。** 两者**任何时候都不同时活着**，D8 不会造成那个结果。

**不是两个菜单之间的关系** —— 782 已实测那个阻断**真的**发生

## 普查器自己踩的两次坑（R146）

两次都是同一族：**把「看起来能自动判的东西」交给正则**。

1. **第一次**想给每个主人标「激活门」，规则是「提到 `event.key` 的是键守卫、
   其余是激活门」。两处都错：**正则吃不下条件里的 `)`**
   （`f(uiState)` 里 `uiState)` 先把 `[^)]*` 截断 ⟹ `page.tsx:1400` 的门
   **整条丢失**，而输出里仍有另一条门的标识符，**看起来仍像个正常结果**）；
   而且那个**分类学本身也站不住** —— 它把桌的 `:487`
   `if (isEditable) return;` 也算成激活门，而那是**分发守卫**
   （它筛修饰键，不是「我是否活着」）。
2. **第二次**改成一两两判「A 的条件有没有提到 B 的状态」，被
   `Escape` / `key` / `target` 淹没 —— 45 对「互相牵制」全是噪声。

⟹ **改法不是把分类修对，是把分类整个扔掉**：普查只**采集**
（条件用**括号配对**取、记行号），**结论由汇编器用行锚定的字面量断言下**。

## 验收

`scripts/verify-liblib-batch783.py` —— **独立实现**，不 import 汇编器也不 import 普查器。
静态层全部用**行锚定的字面量断言**（「`togglePathMenu` 的函数体里必须出现这一行，
且必须排在那一行之前」），因此普查器把归属函数认错时这里会红。

阴性对照覆盖三个最容易出错的判断：

- 删掉**任一**处交叉写入 ⟹ 「双向」的判据必须红（只找到一处会得出假结论）
- 把交叉写入**挪到打开自己之后** ⟹ 顺序判据必须红
- 把**键盘臂**读成「两个面板同时开着」⟹ 「**预测被否掉**」这条必须红 ——
  否则一次把探针调偏就会静悄悄把结论翻回去
