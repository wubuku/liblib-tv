# batch 739 — 11 枚连线删除手柄：`pointer-events: none` 是「hover 才启用」的设计；但**「命中自己」不是「能点」的等价判据**

## 起点

738 测到这 11 枚常态下 `pointer-events: none`、中心 `elementFromPoint` 命中 0/11，
并把「是不是 hover 才启用」列为待查。**本批去查，结论是：是有意的启用态。**
全部读数来自 clone（`src/components/nodes/DeletableEdge.tsx` + 运行时），**不碰源站**。

## 决定性读数

### ① 源码双层启用条件

```tsx
// DeletableEdge.tsx
:90    const isActive = hovered || selected;                       // 两条启用路径
:131   <path … strokeWidth={20} style={{pointerEvents:"stroke", cursor:"pointer"}}
:137     onMouseEnter={() => setHovered(true)}                       // 路径 ①：hover 那条线
:156   <div … style={{pointerEvents: "none"}}>                      // 外层 wrapper 恒 none
:170   className={cn("flex items-center justify-center w-8 h-8 …",  // 32px
:171     isActive ? "opacity-100 scale-100 pointer-events-auto"
:172             : "opacity-0 scale-50 pointer-events-none")}
```

⟹ **默认态不可点是有意的**：`isActive` 为假时按钮主动关掉自己的 `pointer-events`，
靠 hover 那条 20px 宽的隐形描边把按钮「叫出来」。

### ② 默认态 11 枚，**算术完全闭合**

| | 读数 |
|---|---|
| `pointer-events` | **11/11 = `none`** |
| `opacity` | **11/11 = `0`** |
| 渲染盒子 | **8.4 × 8.4** |
| 中心 `elementFromPoint` 命中自己 | **0/11** |
| `focus()` | **11/11 成功** |

```
按钮 w-8 h-8 = 32px  ×  scale-50 = 16  ×  画布 zoom 0.526  =  8.416
```

723 记的「**8×8**」与 738 记的「**8×8**」都是这个 8.4 的取整 —— **两个数都对，是同一格读数。**

| 悬停点 | 结果 |
|---|---|
| 包围盒中心 `(−106, 375)`（**在视口外**） | 11 枚纹丝不动 —— 探针错 |
| 包围盒中心 `(29, 346)`（在视口内，但**不在线上**） | 11 枚纹丝不动 —— 探针错 |
| **`getPointAtLength(len/2)` 换算的 `(345, 490)`** | **1 枚被启用**：`pe: auto`、`opacity: 1`、盒子 **16.8×16.8** |

```

```

**贝塞尔曲线的包围盒中心通常不在线上** —— 前两次「hover 无效」是我的探针错，不是产品行为。

### ④ hover 启用后点它，**真删掉一条边**（11 → 10）

### ⑤ **本批最要紧的一条：「命中自己」不是「能点」的等价判据**

被启用那枚的中心 `(345, 490)`，`elementFromPoint` 返回的是 **`path`**（那条 20px 隐形描边
`pointer-events: stroke` 正压在按钮上），**但点击照样删掉了边**。

⟹ **738 和 739 两次都把 `hitIsSelf` 当判据，这个方法有洞**：
「命中自己」只能证明**没有别的元素挡在前面**，不能证明**事件到得了目标**。
（默认态读出 0/11 是对的——`pe: none` 确实阻断——但**依据不能是 `hitIsSelf`**，
依据是 `pointer-events: none` 本身。）

### ⑥ 键盘这一格：**11 枚全在自然 Tab 序列里，按 Enter 真删**

| | 读数 |
|---|---|
| 自然 Tab **300 步**落在删除手柄上 | **44 次** |
| 覆盖的不同手柄 | **11 / 11 枚**（全覆盖） |
| 聚焦后按 **Enter** | 边数 **11 → 10**（真删） |
| 聚焦后按 **Space** | 边数 **10 → 10**（不删） |

Space 不删的原因：`page.tsx` 的画布键盘契约把 `Space` 吃掉做「按住空格拖画布」
（`isSpacePressed`），事件没落到按钮上。**读屏用户听到「删除连线」按钮，
用 Enter 有反应、用 Space 没反应** —— 这是 Space 键的全局占用，不是这个按钮的缺陷。

### ⑦ 与 735 那 40 枚收藏按钮的对比：「不可见却可达」分两种

| | 默认态 | Tab 落得到 | 按下去 |
|---|---|---|---|
| **40 枚收藏按钮**（`LibraryShowcasePanel:130`） | `opacity: 0` + `pe: none` | 是（Tab 260 步停靠 **77** 次，24 个连续死路） | **毫无反应**（732 记录的读屏长死路） |
| **11 枚连线删除手柄** | `opacity: 0` + `pe: none` | 是（Tab 300 步停靠 **44** 次，**11/11 覆盖**） | **Enter 真删一条边** |

⟹ **同样是「不可见却可聚焦」，一种是无害的、一种是有真实后果的** ——
**「不可见」本身不是缺陷，「不可见且按下去毫无反应」才是**（承 732 的判断，本批给出反例把它坐实）。

### ⑧ 「选中连线」这条启用路径：**未取证**

`isActive = hovered || selected` 有两条路径，本批只证了第一条。
在曲线上点一下后 `selectedEdgeIds.length` 仍为 **0** ⟹ **没触发**，
但**是「点不中」还是「这条路径在这个状态下根本不通」未取证** —— 记未取证，**不下结论**。

## 新增待拍板

① **`Space` 键的全局占用要不要给按钮让路** ——
读屏用户聚焦到「删除连线」后按 Space 毫无反应，而 Enter 有反应。
修法二选一：按钮自己拦 `Space` 并转成 click，或画布的 Space 处理在焦点位于可交互元素时让路。
**需改 `src/`，等授权**（本批只记不裁决）

② **738 待拍板① 已有答案，可以结清** ——
`pointer-events: none` 是**有意的启用态**（hover 那条线才叫出来），
**不是缺陷、无需改 `src/`**。唯一残留的是 ⑤：判据方法要用 `pointer-events` 读数、不能只用 `hitIsSelf`。

## 方法论

① **「两处读数不一致」先怀疑测法，再怀疑产品** ——
hover 连线连续两次读出「无变化」：第一次点在**视口外**、第二次点在**包围盒中心（不在线上）**。
**曲线的包围盒中心不是曲线上的点** —— 命中类操作要用 `getPointAtLength` + `getScreenCTM`。

② **`hitIsSelf` 只回答「前面有没有挡」，不回答「事件到不到」** ——
本批实测：命中的是 `path`、点击却删掉了边。
**判「能不能点」要读 `pointer-events` 与实际后果（边数变没变），不能只看 `elementFromPoint` 返回谁。**

③ **把读数算到闭合** ——
8.4 与 16.8 都能从 `32 × scale × zoom` 算出来；
723 记的「8×8」与 738 记的「8×8」是同一格的取整。**算术闭合能同时解释两个历史读数。**

④ **同族现象要分档比较，不能只记一个** ——
735 那 40 枚「不可见却可聚焦、按下去毫无反应」被当成一类；
本批这 11 枚「不可见却可聚焦、按 Enter 真删」是另一类。
**没有反例时容易把一族当成全部。**

## 探针返工三处（全部是我自己的错）

① **悬停点挑在视口外**（包围盒中心 `(−106, 375)`）⟹ 读出「hover 无效」的假结论。
② **悬停点挑在包围盒中心**（`(29, 346)`，在视口内但**不在线上**）⟹ 又读出一次「hover 无效」。

B 枚没启用、`pe: none` ⟹ 命中穿透到 `DIV` 是**正确行为**，我却差点写成「启用后仍点不到」。
⟹ **三次都是「先怀疑探针」救回来的**（这是 733 立下的规矩，本批第三次用上）。
