# Batch 640 —— 中心点普查**可靠但不完整**，而它的盲区有一族清楚

## 零源站断言

第一族是 613 在源站实测的源站事实；源站矮视口下掩埋多少行**未取证**。
本批只主张 clone 的读数。

## 一、632 留下的悬案

632 发现普查只打**中心点**，所以「中心干净、身体被盖」的控件会通过。它量到的
是**间接后果**——339..377 这条 39–40px 带宽里矩形相交已成立、普查却报零。
632 没有回答：**到底是哪些控件、多少枚**。

## 二、判据：对**任意**覆盖物，用九点探针当离散覆盖估计

对每个控件在 3×3 晶格（8% / 50% / 92%）上打点，统计**被挡点数**，再和中心点
自己的判据对比。于是两类**方向相反**的错误分出来：

| 类 | 条件 | 含义 |
| --- | --- | --- |
| **假阴性** | 中心干净 + 身体被挡 | 真缺陷，普查**根本看不见** |
| **假阳性** | 中心被挡 + 身体干净 | 报了被盖，其实大部分还能用 |

**假阳性 0 个**，14 个宽度全部。理由是硬的：中心本来就是九个探针之一，
两者用**同一个测试**分类，中心说「被挡」就必然在中心被挡。
**这是中心点探针唯一犯不了的错。**

## 三、盲区的确切内容：**111 枚，全是 gizmo 轴按钮**

| 宽度 | 假阴性数 |
| --- | --- |
| 339 / 350 / 359 / 360 / 370 / 377 / 380 / 400 / 620 / 780 / 898 | **6** |
| 899 / 1024 / 1440 | **15** |

111 枚**全部**是那六枚 15×15 的 gizmo 轴按钮（`X 正向/反向`、`Y 正向/反向`、
`Z 正向/反向`），每枚在九个探针点里被挡 **4–5** 个，挡它们的是**视口自己**。

也就是说：**gizmo 轴按钮的四角被视口内的 gizmo 覆盖层压住了，中心是干净的。**
用户点按钮的正中最准，点到最边角就会打到视口。窄族 6 枚、桌面族 **15** 枚
（三个桌面宽度**完全相同**——又一处宽度无关）。

## 四、一条**否证性**记录：时间轴带在这些宽度下是全有或全无

`the-timeline-band-is-all-or-nothing-at-these-widths` —— 对时间轴带，
**部分相交的控件数在 14 个宽度上全是 0**。

这一条是**故意留下的**，因为它决定了我**不能**声称什么：
若只对时间轴带断言「中心点普查完备」，那是**平凡成立**（那一类里根本没有成员），
冒充成成绩。所以判据写成**对任意覆盖物**的形式，并把这个陷阱明写进 audit。

## 五、632 那条带里到底有什么：**一个宽度、一枚控件**

`632s-band-contains-exactly-one-control-at-exactly-one-width` ——
全 14 宽度扫下来，「无法解释的被盖」**只有一处**：`收起` @339，
被 632 钉死的那个 **170px 居中视角组**盖住。

**它是已知的、clone-only、未修的**（632 的处置卡在源站顶栏取证上）。
本批做的是把它**点名**并钉住「它是唯一一个」——不是重新断言它归零。

顺带纠正一处我自己的混淆：632 那条 39–40px 带说的是**顶栏居中组**，
**不是**时间轴带。第一版检查把两者当成同一个覆盖物，红了之后这个区分才浮出来。

## 六、判据自己踩的坑

1. **把覆盖层的后代也算成「被它盖住」** —— `播放`/`循环播放`/`时间线最小化`
   本来就是时间轴工具条自己的按钮，中心点测到自己是**对的**。这制造了
   **211 个伪违规**，也让我一度报出「280 个假阴性」这个**夸大约 2.5 倍的数**。
   真实值是 **111**。**结构半必须先声明「谁在里面」，否则盖住这个动词没有意义。**
2. **在第二次浏览器采样填充字段之前就读它** —— 「无法解释的被盖」被读成空，
   于是那条本该红 339 的检查绿了。已并进主采样。
3. **拿一个 regime 的结论去要求另一个** —— 见第四节，已把失败的理由写进 audit
   而不是删掉那条检查。

## 不声称

- 源站任何事。**源站的 gizmo 轴按钮在窄屏是不是这个尺寸、角上是不是也被压住，
  未取证**——本批只主张 clone 的读数，也不主张该修。
