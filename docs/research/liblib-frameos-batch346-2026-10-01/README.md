### 逐节点类型实测后才发现的真相

一开始只测「双击某个节点」发现什么都没发生，差点判成「完全没实现」。加临时
计数器逐节点试才发现差别在**双击被谁消费**：

```
[0] text-1   中心元素 DIV.text-display  handler 触发=0
[1] text-2   中心元素 DIV.text-display  handler 触发=0
[2] video-1  中心元素 path(SVG)          handler 触发=0
[5] image-1  中心元素 IMG                handler 触发=1  视口变了
```

- `FrameosTextNode.tsx:34` — `onDoubleClick` + `stopPropagation()` → **进入编辑**
- `FrameosVideoNode.tsx:119` — `onDoubleClick` → **预览/停止播放**
- 图片等没有自己双击语义的节点，双击才冒泡到 React Flow 的 `onNodeDoubleClick`

所以「双击节点」这个通用手势对多数节点到不了「聚焦」。源站是否也如此**需采样
确认**，已记为待核。

## 修复

```tsx
onNodeDoubleClick={(e, node) => {
  e.stopPropagation();
  fitView({ nodes: [{ id: node.id }], duration: 300, padding: 0.2,
            minZoom: 0.5, maxZoom: 1.6 });
}}
```

**必须显式给 `minZoom`/`maxZoom`**：`fitViewOptions` 把缩放**钉死在 1**
（`{minZoom:1, maxZoom:1}`），不覆盖的话「填满视口」退化成「什么都不动」。

## 保留的保真度差距

「双击空白处添加节点」是**源站逐字承诺**，克隆未实现。原因：承诺只说「添加
节点」，**没说添加哪一种**，而工具条的添加节点是带类型选择的菜单 —— 选一个
默认类型就是发明产品行为。源站行为未采样（人机验证阻塞，见
`SOURCE_ACCESS_BLOCKED_2026-10-01.md`）。

处理方式：**原文留着、差距记着**。待源站可采样后按采样结果实现。

## 元缺陷（第二次重演，Batch 345 的 toast 同款）

帮助面板的行也只有内联样式、没有可寻址属性 —— 与 Batch 345 的 toast 完全同类。
「面板是否在撒谎」根本测不了，任何相关断言只能写成空断言，而空断言正是
Batch 336 门禁要清理的东西。已加 `data-frameos-help-row` / `-label` / `-desc`
（**纯增量，不触碰任何文本**）。

> 同一个坑在**两个批次连踩两次**。「补可测性」不该靠临场想起，而该在新增 UI
> 元素时作为默认动作。
