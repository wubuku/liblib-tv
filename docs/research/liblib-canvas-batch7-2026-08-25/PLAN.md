# LibTV 画布 Batch 7 计划：整理预览忠实度

> 建档日期：2026-08-25  
> 原则：优先修复已有可见功能中的明确失真；先写证据与规格，再实施和验证。

## 1. 缺口盘点

| 缺口 | 当前 clone | 原站证据 | 价值 | 本批决策 |
|---|---|---|---:|---|
| 整理拓扑 | 普通节点固定三列网格 | 截图呈现素材 → 执行/分镜 → 分组/视频 → 剧本的语义拓扑 | 5 | 重写 |
| 分组位置 | 分组统一放到 `x >= 2280` | 图片组、视频组位于右侧同列 | 5 | 修正 |
| 视频与视频组 | 视频和分组没有视觉包含关系 | 失败视频位于视频组内部 | 5 | 修正屏幕位置 |
| 整理缩放 | `fitView()` 后旧截图约 `51%` | 原站截图显示 `28%` | 5 | 用拓扑边界计算 |
| 整理对齐 | 旧结果大量出屏且纵向关系混乱 | 原站在 `929x874` 下从左上约 `(48, 49)` 展开 | 5 | 修正 |
| 确认卡锚点 | 底部居中横条 | 原站固定左下，两行结构 | 5 | 重写 |
| 保留/还原 | 已有按钮 | 原站文案和双按钮直接可见 | 4 | 保留并回归 |
| 动态节点整理 | 固定按数组索引 | 原站截图只覆盖当前项目 | 3 | 增加明确标注的稳定 fallback |
| 新整理模式菜单 | 当前无 LibTV 直接证据 | FrameOS 证据不能作为 LibTV 事实 | 2 | 不做 |

## 2. 实施范围

### P0

1. 当前目标项目的 10 个已知节点按原站截图语义重排；
2. `929x874` 下得到约 `28%` 的构图，左侧内容约从 `x=48`、`y=49` 开始；
3. 图片组与视频组位于同一右侧列；
4. 失败视频在视觉上位于视频组内部；
5. 剧本位于更右上方；
6. 确认卡固定左下，采用“问题文案 + 两个按钮”的上下两行结构；
7. 保留和还原都关闭确认卡；
8. 保留后 undo/redo 继续恢复整理前后节点位置。

### P1

1. 未知顶层节点使用稳定 fallback，不依赖随机值；
2. 有 `parentId` 的 child 保留相对 parent 坐标；
3. viewport 由实际整理后边界计算，不写死单一屏幕宽度；
4. `929x874`、`1440x900`、`390x844` 都不产生页面横向溢出；
5. 自动化验证节点数、边数、关键 transform、确认卡几何和控制台。

## 3. 不做

- 不声称反推世界坐标是原站 DOM 原始数据；
- 不把当前项目专属 ID 布局伪装成通用自动布局算法；
- 不引入图布局依赖；
- 不改变普通拖动、多选、成组、复制或 FrameOS 路线；
- 不根据 FrameOS 的横向/纵向/网格整理菜单扩建 LibTV；
- 不实现没有过程证据的整理动画曲线。

## 4. 验收标准

### 原站目标视口 `929x874`

- 缩放显示为约 `28%`；
- 女性、咖啡馆、男性、咖啡形成左列；
- 剧本执行与分镜图形成中列；
- 图片组、视频组形成右列；
- 视频位于视频组内部；
- 剧本位于更右上方；
- 确认卡左边约 `49px`，底边约 `53px`；
- 确认卡宽约 `168px`，文案与按钮分两行。

### 事务

- 整理不改变节点数 `10` 和边数 `11`；
- “还原”恢复整理前节点 transform 和 viewport；
- “保留”保留整理结果并关闭确认卡；
- 保留后 `Cmd/Ctrl+Z` 回到整理前节点位置；
- `Cmd/Ctrl+Shift+Z` 回到整理后节点位置。

### 工程

- Batch4、Batch5、Batch6 回归通过；
- Batch7 专项脚本通过；
- `npm run check` 通过；
- 桌面与移动端控制台 error 为 0。
