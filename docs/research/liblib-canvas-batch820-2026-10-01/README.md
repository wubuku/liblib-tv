| 11 | **点不动** | — | 0（循环自然终止） |

循环之后：**剩 0 份、节点数 20 → 10**（= 起点）。

★ 机理就是 816 那条读数的直接后果：
「点中心只选中最上面那一份」⟹ 删掉它之后**下一份自动顶上来** ⟹
循环 N 次就清掉 N 份。

★ 「第 11 轮点不动」是关键证据：它证明循环是**因为清空了才终止**的，
**不是**探针按够次数硬截断的。

## 二、★★ 本批对 819 的**修正**

| 路径 | 819／818 的读数 | 本批 |

★ 这正是「**没量就下结论是最贵的教训**」的又一次兑现：

## 三、★ 归因：「同一坐标」是 `addDerivedNode` **独有的**

B 臂：在同一个 T3 状态（还剩 10 份）下右键最上面那份 → 「创建副本」。

| | x | y |
| --- | --- | --- |
| 原节点 | 445 | 268 |
| 副本 | **460** | **283** |
| 屏幕位移 | **+15** | **+15** |

`duplicateGraphSelection` 的副本实现：
`position: { x: node.position.x + 40, y: node.position.y + 40 }`
（偏移量**从源码正则读出**、判据里**不写死**）
⟹ **副本会被挪开**，**不像 `addDerivedNode` 那样压在同一个坐标**。

★ 所以 815／816 的问题**归因到具体那一个 store 动作**，
而不是「这套画布都这样」。

★ 「创建副本」**不是**自救路径（副本只增不减），它只是提供**对照**。
