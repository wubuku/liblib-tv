## 3. ★★ 挖出四个真缺陷（★ 全都不是「环境问题」）

### 缺陷一：★ 「跳过」被实现成了「失败」

★ `753`–`759` 分三层：**静态层**（从 `src/` 读）／**产物层**（从 `runtime-audit.json` 读）
／**原始读数交叉核对层**（从 `/tmp/vb*.json` 读）。
★ 前两层**不依赖任何外部文件** ⟹ ⟹ 只有第三层依赖那**不可恢复**的文件。

★ ★★ 而它们把「第三层缺失」实现成了 **`pass: False` 且计入分母**
⟹ ⟹ ⟹ ⟹ **「跳过」被实现成了「失败」**
⟹ ⟹ ⟹ ⟹ ⇒ 门禁**永远红** ⟹ ⟹ ⟹ ⟹ ⇒ 而前两层**全绿也没用**。

★ `753` 的实测：13 条真判据**全绿**，只有那一条「跳过」被当成红 ⟹ ⟹ 退出码 1。

★ **修法**（★ **不是**改成「通过」⟹ ⟹ 那是**掩盖**）：

| | 做法 |
| --- | --- |
| 分母 | ★ 改成**真正跑了的那几条**（`ran`）⟹ ⟹ 跳过的不算 |
| 留痕 | ★ 报告里加 `skipped` 清单 ＋ `skippedCount` ⟹ ⟹ **看得见**「有东西没验」 |
| 退出码 | ★ 仍由**真正跑了的那几条**决定 |
| 真失败 | ★ **照红**（★ 有负控证明 ⟹ ⟹ 见 §4） |

★ ★★ `753` 与 `754`–`759` 的**区别**（★ 这一步很关键）：

| 门禁 | 文档头**自己**声明的语义 | 判定 |

## 6. ★ 本批的方法学（★ 五条）

### 6.1 ★★★★ 「必然红」的门禁是一份**环境依赖清单**

★ 「哪些门禁**永远红**」这个问题本身产出了**四个真缺陷**
⟹ ⟹ ⇒ **规则**：★ 每当发现一批门禁红 ⟹ ⟹ **先问「它依赖什么外部东西」**
