# batch 794 —— 删掉一个成员之后，分组框**不收拢**

> 探针 `probes/dbg794a.py` · 汇编器 `probes/mk794audit.py` · 验收 `scripts/verify-liblib-batch794.py`
> 读数 `raw/vb794a-pre.json` / `raw/vb794a-post.json` · 断言 `runtime-audit.json` · 验收 `verify-report.json`

## 一句话

793 把「分组框跟随成员」挂在 `routeReactFlowChanges` 的**唯一收口**上，于是成员**移动**会跟随。
但删除走**另外两个写点**、不经那个收口 ⟹ 删成员后框**完全不收拢**。本批把同一个纯函数挂到那两处。

## ★ 起点：793 自己列出来的未验路径

793 的遗留里写着一句「未测成员删除后框是否收拢」。这不是新缺陷，是 793 修好的那一半的**另一半**：
**移动**跟了，**减少**没跟。

| 写点 | 函数 | 走不走 793 的收口 | 793 之后 |
| --- | --- | --- | --- |
| `canvasStore.ts:3742` | `routeReactFlowChanges` | ✅ 就是收口本身 | 跟随（793 修好） |
| `canvasStore.ts:3327` | `removeNode` | ❌ | 不收拢 |
| `canvasStore.ts:3363` | `removeSelectedNodes` | ❌ | 不收拢 |

## ★ 为什么不能直接用种子的那个组

种子里那个组**只有 1 个成员**。删掉就变 0 成员，而 793 的边界 1 明确「**0 成员的组不动**」
（那是 757 待拍板 ②，源站未采样）⟹ 拿它测「收拢」会**测不到本批要修的东西**，
反而把边界 2 的行为当成缺陷。

⟹ 所以探针每轮都先**造一个两成员的组**（前置对照臂同时证明这一步本身是对的）。

## ★ 修法：把同一个纯函数挂到**两个**写点

`fitStoryboardGroupsToChildren`（793 已有，本批**没另造一个**）挂到 `removeNode` 与
`removeSelectedNodes` 的 `nodes:` 写入处。**两处一起改** —— 这是同一条路径的两个半边，
只改一个就是半个修复（791 的教训）。

## ★★ 汇编器自己踩的三个坑（都已修，判据留在代码里）

1. **needle 打在错误的一行。** 原判据要 `fitStoryboardGroupsToChildren(` 与
   `filter((node) => !removedIds.has(node.id))` **同行**，但 prettier 把实参换到了**下一行**
   ⟹ 断言一处都没命中。改成「call 行 + 其后两行」一起收。
2. **`owner()` 爬出了 store 体。** 按 `\s{2,4}` 匹配 `name: (` 会一路爬到外层
   `create((set, get) => ({` ⟹ 两处 owner 被判成同一个函数。store 的 action 是
   **恰好 2 空格**缩进（嵌套的 `set((state) => {` 是 4/6）⟹ 收紧正则并把搜索下界
   锚在 `export const useCanvasStore = create` 那一行。
3. **手写的普查数字本身是错的。** docstring 原写「16 处 / 覆盖 3 / 未普查 13」，
   机器数出来是 **17 / 3 / 14**。这是「断言必须从源码逐行读出、不能从记忆推」的又一笔代价。

## ★ 写点普查（机器核对）

`canvasStore` 里把 `nodes` 写进一个 canvas 对象的源码形态共 **17 处**。本批覆盖 **3 处**
（拖拽/尺寸 1 + 删除 2），**其余 14 处未普查**。三个数字由汇编器**从源码数出来**（check A）。

★ 普查器**只采集，不做语义判断**：每处连同实参行一起收下来，「覆盖 / 未覆盖」交给 B、B2 逐处判定。

## ★★ S11：本批最重要的一条**限定**

探针的 `Delete` 键（`page.tsx:1344` 的分支，`:1348` 调 `removeSelectedNodes`）只走
`removeSelectedNodes`。全仓普查：**`removeNode` 在画布 UI 上零调用者** —— `page.tsx` 里
`removeSelectedNodes(` **2 处**、`removeNode(` **0 处**；`frameos` / `jimeng` 各有自己的
同名 store，与画布无关。

⟹ **raw 的行为读数只支撑一个写点。** `removeNode` 那处只有**静态证据**（S1/S4），
**没有行为证据**。它按「同一条路径两个半边一起改」的一致性修法处理，是**推断**不是测出来的。
报告**不许**说「两处都验过了」。

★ S11 只读 `page.tsx` ⟹ **raw 变异翻不动它**（N1–N8 全是 raw 或 `canvasStore` 的变异，
S11 一路保持绿）⟹ 必须有一条**作用于 `page.tsx` 源码**的对照，这就是 N9。
若没有 N9，「零调用者」这个限定就只是一句没人盯着的断言。

★ N9 自己踩了两个坑：手写 needle 的**缩进**（真实是 10 空格不是 12）⟹ 改用正则定位；
插入时多带一个换行导致**净增 2 行**⟹ 改成接在同一行末尾，行数天然中性。
