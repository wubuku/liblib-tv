## 与 734 的关系

- 734 记的「新卡自身 6 枚 `data-inert`（播放视频 + 该功能/翻译视频提示词/该设置 +
  撤销视频处理/重做视频处理）」与本批**方向一致且能对上**：
  新卡 = 节点内 **4** + 工具栏 **2** = **6**；种子卡 = 3 + 0 = **3**。
- **口径必须分清**：734 的「7 个写点」量的是 `data-inert` 写点普查（730 的 46 写点），
  本批量的是**记账命令入口**（742 的 29 个命令）。**两个数不可混**。
- 734 待拍板①「种子 fixture 把视频卡钉在 `failed` 是不是有意的」——
  本批把它的**影响量化成 3 枚 `data-inert` 写点 + 0 个记账命令入口**：
  **记账命令一个都没少**（11 个芯片全在、都可点、都记账）。

## 撤回的一条

- **「failed 卡比 ready 卡少 3 个命令入口」**（第一版只比总数）——
  failed 18 个可交互元素 vs ready 21 个，差 3；逐项比完 **11 个按钮文案差集为空**，
  真正只差 `data-inert`（节点内 1 + 工具栏 2）。

## 另修两处探针错

- `INVENTORY` 里 `all` 存的是**原始 DOM 元素**而非 `grab()` 后的对象，
  于是 `e.tag` 恒 `undefined` ⟹ `buttons`/`inputs` 全读成 **0**
  （又是一次「读数像模像样、实际什么都没验到」）。
- 位置过滤 `closest('footer,aside,nav')` 不可靠——顶栏那 2 枚也在 `footer` 里，
  被算成「卡片相关」。改用**集合差**，两态都有的自动抵消。
