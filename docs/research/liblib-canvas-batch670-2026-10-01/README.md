# batch 670 —— rect 通道与命中通道的分歧：**假阴性 0，假阳性 61%**

## 一句话

668 说「`getBoundingClientRect()` 的左沿和 `elementFromPoint` 用的左沿差 ≈1.0px，
所以拿 rect 推可点性会错」。**本批把这句话数了一遍：方向要分开数，而结论
和 668 的读法不一样。**

* **假阴性**（rect 说没挡、实际挡了）= **19,680 格里的 0 格**。
  那 1px 在元素级是真的，但**从来没有传成一个错的布尔判定** ——
  因为每一次都有一枚更大的盒（视口自己的 `div.absolute.inset-0`，右沿 `W−281`）
  rect 仍然含住那个点，rect 通道照样说「挡了」，与命中一致。
* **假阳性**（rect 说挡了、实际没挡）= **每档 77 格里的 73–76 格（61–63%）**。
  而它们**无一例外是「盒重叠但画在自己之下」** —— 666 那句「位置不等于层叠」，
  这次带上了比率。

**所以 668 的 1px 该被限定成：它影响边界宽度的算术，不影响任何一格的布尔判定。**

## 1. 两条通道

对每枚控件的中心点：

* **命中通道**：`elementsFromPoint` 的整条栈（栈顶在前）。栈顶不是自己/后代
  ⟹ `hitBlocked`。
* **rect 通道**：`pe:auto`、零尺寸除外、**非祖先非后代**且 rect 含该中心点的元素。

分歧分两类，方向相反：

| 类 | 定义 | 危险程度 |
|---|---|---|
| **假阴性 FN** | rect 说没挡，实际挡了 | **危险**（会漏报缺陷） |
| **假阳性 FP** | rect 说挡了，实际没挡 | 噪声（会把重叠当遮挡） |

## 2. 人口：120，不是 130

`1280→1600` 每 2px 共 **164 档** × **120** 枚视口内控件 = **19,680 格**。

**第三态照旧要单列**：669 数控件得 **130**（不做视口内过滤），本批把
`cy > H` 的 10 枚排除后是 **120**。**两个数都对，差别就是那条过滤** ——
不要把它们当成互相印证（这正是 663/664 记的「第三态必须与空集分开」）。

## 3. 假阴性：**0**

| 量 | 值 |
|---|---|
| 1px 签名格（栈里有元素、而它 rect 不含该点） | **2** |
| 出现在 | `描述想搭建的场景`（`cx = 1124.5`）@ **1405 / 1406** |
| 涉及元素 | `aside.absolute.-top-9.bottom-0.right-0` / `section.flex.h-full.min-h-0.flex-col` / `div.min-h-0.flex-1.overflow-y-auto` |
| **真假阴性** | **0 / 19,680** |

**为什么那 2 格不是假阴性**（这是本批唯一需要推理的一步，已单独复核）：
1406 时 section 与 column 的 rect 左沿都是 1125，**都不含 1124.5**；
但**视口自己的 `div.absolute.inset-0`（rect `[281, 88, W−281, …]`）含住它**，
且它就在栈里。rect 通道于是说「挡了」，命中也说「挡了」—— **两通道一致**。
1405 同理（`section` 的 rect 左沿 1124 ≤ 1124.5）。

## 4. 假阳性：每档 77 格，61–63%

| 量 | 值 |
|---|---|
| 带 rect 候选的格 | **77**（164 档逐档相同） |
| 其中真被挡 | **1–4**（随宽度变） |
| 其中假阳性 | **73–76** |
| 假阳性率 | **60.8% – 63.3%** |
| 恒等式 | **`trueFP + hitBlocked == fpCells`（164 档全部成立）** |

**成员名单比计数更有意思**：
* **66 枚控件在每一档宽度上都是假阳性**（名单见 audit，含全部 9 个 gizmo 轴按钮
  `X/Y/Z 正向·反向`、`16:9 / 1:1 / 9:16`、全部 `删除/隐藏/锁定…` 行、
  `导演视角 / 机位视角`、`收起属性` 等）；
* 另有 **3 枚**只在部分宽度上中招 ⟹ 164 档里出现 **4 个不同的名单集合**。

**计数稳（77）、名单动（4 套）** —— 报计数时不要让它看起来像在点名谁。

## 5. 两个「派生量 ≠ 读数」的坑

* `fpBelowTotal`（元素**对**数）在 164 档上是 **128/130/131/132/133/134** 六种值，
  随宽度动；**格数**才是读数（77）。第一版把前者写进「逐档恒定」的断言，失败。
* 我第一版把「在栈里位于自己之下」也算成需要排除的情形，于是断言
  `trueFP ≤ hitBlocked` —— **那是个不可能成立的式子**（73 ≤ 4），
  读数没错、判据错了。

## 6. 本批自己犯的错

1. 探针第一版的 `disagree` 字段在我改 JS 时被删掉了，`filter(r => r.disagree)`
   于是恒为 0 格 —— **一个缺失字段读起来就是一个零**。差点把
   「两通道零分歧」当成结论报出去。**零必须先证明它不是字段缺失。**
2. 三次把断言的预期写成我以为的数（trueFP 恒定 / 真 FN 恰好 1 格 /
   `trueFP ≤ hitBlocked`），三次都是**读数纠正预期**。
3. dev server 被上一个 batch 的 `build` 抢占后没起来，第一次跑直接
   `ERR_CONNECTION_REFUSED`；重启 `.next/dev` 后正常。

## 7. 不声称

* **不声称**那 1px 的成因（668/669 遗留）。
* **不声称**「两通道零假阴性」是普遍性质 —— 它是在**这一张表、这 164 档宽度、
  这一套纳入判据**下测到的；换一组墙或换一种纳入过滤，结论可能变。
* **不声称** 77 格里的假阳性对应源站任何东西 —— 它们全是 clone 自身的层叠。
