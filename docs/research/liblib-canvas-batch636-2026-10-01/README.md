# Batch 636 —— 633 的「宽度不是变量」在**短窗区**重验通过；顺带挖出 182 快捷方式的 store/DOM 分歧

## 零源站断言

第一族是 613 在源站 1920×1150 实测的**源站事实**；源站在矮视口下掩埋多少行
**未取证**。本批只主张 clone 的读数。

## 一、为什么要重验 633

633 在窗口高**固定 660** 的网格上量到「宽度不是变量」。而 660 恰好落在 635 刚测出的
**饱和区**（饱和线 = 窗高 436）。**635 证明曲面有一个 633 没看见的第二变量** ——
于是 633 那句「宽度不是变量」只在其采样域内成立。

**634 栽的坑和 633 是同一个**：在饱和区里量，然后外推。既然已经知道域外有东西，
就必须把 633 的断言拿到**两个区**里重新测一遍。

做法：**把顶边钉死、只扫窗高**，对每个宽度取一条掩埋曲线，再逐格对比。

## 二、结论：633 的断言被**推广**，不是被推翻

| 顶边 240 的曲线（窗高 328→660） | 5 | 12 | 12 | 15 | 15 | 15 | 15 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 899 / 1024 / 1280 / 1440 / 1920 | **逐格相同** | | | | | | |

- `633s-width-is-not-a-variable-holds-in-the-short-window-regime-too` — 5 个桌面宽度
  × 13 格，**分歧 0**。**掩埋集合**（不只是计数）逐格相同。
- `the-saturation-line-is-the-same-for-every-desktop-width` — 436 在**每个**桌面宽度
  上都一样，不只是 1440。
- 635 的 1440 曲线被本次运行**逐格复现**；633 记录的桌面行在两个共享点上吻合
  （`req 420 → 15`、`req 300 → 4`）。

## 三、顺带钉住：**家族断崖是宽度驱动的**

633 的「两个族」划分在**任何窗高**下都成立：898 在 13 个窗高上掩埋**恒为 0**
（列是屏外 `inert` 抽屉），899 是 `[4, 5, 12, 15]`。断崖卡在 **898/899 这 1px** 上，
不随窗高移动 —— 家族划分确实由宽度独断。

## 四、真发现：`182` 快捷方式让 store 与 DOM 在窄屏**分歧 6px**

第一版判据在 `w898 / 请求 182` 这一格红了。追下去发现的是**一类新问题**：

`DirectorTimeline.tsx:843-845` ——

```tsx
timelineCollapsed || timelineHeight === DIRECTOR_TIMELINE_DEFAULT_HEIGHT
  ? undefined                    // 高度恰好是默认值时**不设行内样式**
  : { height: timelineHeight }
```

**不设行内样式**时高度交给 CSS，而 `max-[899px]:h-[176px]`（同文件 `:814`）给出的是
**176**，不是桌面族的 182。于是：

| 宽度族 | 请求 182 | 其余每一个值（88/120/150/170/176/180/186/200…420） |
| --- | --- | --- |
| **≤898** | 实测 **176** | **原样通过** |
| **≥899** | 182 | **原样通过** |

**78 格里恰好 1 格分歧**，且 store 仍存 **182**、DOM 是 **176** —— 状态与 UI 不一致。
这不是区间钳制（180、186、200 都原样通过），**只发生在默认值这一个值上**，
差值恰好是 629 记过的族差 **6px**（≤898 是 176/124，≥899 是 182/88）。

**不修**，理由有两条：

1. **不发明 UX 数字**。渲染出的 176 很可能正是源站窄屏的默认值（630 已钉住 176）；
   该给哪一边让位 —— 是让 store 改成断点感知的，还是让窄屏 CSS 回到 182 —— 是
   **产品决定**，不是能从几何推出的。
2. **源站未取证**。不能照着一个想象的源站去改。

本批做的是把它**钉死成三条断言**（只在此值此族分歧 / 差值恰好 6px / 除被点名的
那一格之外全部符合钉住顶边），这样谁要处置它都有精确的边界。

## 五、判据自己踩的一个坑：非空转写成「每条曲线都要动」

第一版非空转断言要求**每条**曲线都随窗高变化，红在**顶边 360 的曲线恒为 4**。
但那不是缺陷，是事实：**360 高于所有固定行**（最后一行是 424），所以 band
`[360, 窗高]` 随窗高增长也**装不进任何新行**。

正确的要求是两层：**每个宽度至少有一条会动的曲线**（顶边 240 的那条），**加上**
把「顶边 360 平坦」改成一条**正面断言**（且只在顶边 360 平坦）—— 这样它从
「红」变成「被解释并钉住」。
