# Batch 12：资产管理抽屉的画布/资产视图

> 日期：2026-08-25
> 范围：LibTV clone 的底部“资产管理”入口和左侧 240px 抽屉。
> 目标：修复抽屉内“资产”页签无行为的问题，同时保持当前画布节点选择和原型边界。

## 缺口

当前 `AssetManagerPanel` 已经能展示当前画布节点并点击选择，但头部的“资产”按钮没有状态或内容变化。用户看到的是可点击控件，却无法进入资产视图。

## 证据边界

### Source fact

- 当前登录态原站复核确认“资产管理”是底部画布工具条入口，打开约 `240px` 左侧抽屉并列出当前项目节点；见 [`../liblib-live-2026-08-25/README.md`](../liblib-live-2026-08-25/README.md)。
- 原站完整的账户资产、上传、下载和服务端数据不是本前端原型的范围。

### Current-code fact

- clone 抽屉已经渲染“画布 / 资产”两个页签，但“资产”按钮没有 `onClick`，只能看到画布节点列表。
- `canvasStore` 已持有当前画布的图片、视频和其他节点数据，可作为本地原型资产来源。

### Clone decision

- “资产”页签展示当前画布中可引用的图片和视频节点，按媒体类型过滤。
- 点击资产项沿用画布节点选择，不创建新节点、不上传、不连接真实账户。
- 保持抽屉宽度、节点行几何、顶部页签和关闭行为；新增内容只解决死按钮。
- 资产视图是本地派生视图，不声称等同原站账户资产库。

## 验收

- “画布”页签显示当前画布的 10 个节点。
- “资产”页签显示当前画布的媒体节点，不显示脚本、分组和执行节点。
- 点击资产项后对应 React Flow 节点被选中。
- 切回“画布”页签后原节点列表恢复。
- 关闭抽屉后仍可通过 Batch 11 的互斥生命周期打开其他顶层入口。
- 桌面和 390px 视口无横向溢出，console/page error 为零。
