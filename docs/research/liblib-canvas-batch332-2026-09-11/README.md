## 背景与动机

batch 309–331 的 35 模型费率地图存在两类污染：

1. **查找器污染**：batch 330/331 最终轮的 trig 全部读到
   「1080 × 1446」——那是故事板视图里图片资产的尺寸标签
   （见 `evidence/probe332_state.png`），不是视频面板模型触发器；
2. **面板态污染**：清晰度/时长/比例是**逐模型会话持久化**的，
   batch 240 时代的「16:9·720P 基准」标注对多个模型不可信。

本轮以受控单变量流程重测：逐模型切换后**显式归一化**
（设置弹层点 720P → 点 5s），稳定双读 + 触发器换名校验后才记录。

## 核心发现（`SOURCE_FACT`，2026-09-11）

### 1. 清晰度决定积分（费率必须分层）

Wan 3.0 Prime 同会话 A/B：**480P = 45、720P = 90**（16:9·5s·1个）。
由此改判多个历史读数的清晰度归属：

| 模型 | 720P（本轮受控） | 旧地图值 | 旧值实为 |
|---|---|---|---|
| Wan 3.0 Prime | **90（18/s）** | 45（9/s） | 480P 态 |
| Wan 2.7 | **50（10/s）** | 65（13/s） | 1080P 态（78/6s 复核一致） |
| Vidu Q2 | **45（9/s）** | 40（8/s） | 低清晰度态 |
| Happy Horse 1.1 | **75（15/s）** | 120（24/s） | 1080P 态 |
| Happy Horse 1.0 | **80（16/s）** | 192（38.4/s） | 1080P 态 |
| Vidu Q2 Pro | **45（9/s）** | 110（22/s） | 1080p 态（132/6s 复核一致） |

1080P 倍率**非统一**（1.3×–2.4× 逐模型不同），维持 clone 仅
720P/1080P 分层、且 1080P 表仅收 Seedance 1.5 系的建模。

### 2. Pixverse V5.5 = 60（12/s）反证

batch 291/330 的 135 **恰等于默认模型 2.0 的积分**——该两轮的行
点击链路已失效（同轮 `Pixverse V5: row missing` 佐证），读数为
陈旧值。本轮受控复测 60/5s，与 batch 240 截图直证一致。clone 的
12 入表值**正确**，无需改动。

### 3. 源站调价风险

Wan 3.0 Prime 45→90 的改判以「batch 240 误标清晰度」解释成立；
但不排除源站同期调价。费率表按「2026-09-11 时点观察值」口径入表。

### 4. Hailuo 2.3 Fast 菜单行不可选（`SOURCE_UNKNOWN` 维持）

其菜单行经**三种点击机制**（CDP 原生点击 / JS dispatch /
elementFromPoint 验证点击 + 滚轮滚动）均选中相邻模型（Vidu Q2 /
Kling 2.5）——源站虚拟化列表对该行疑似存在行错位 bug。
clone 维持 batch 240 的 4.8/s 并记 `SOURCE_UNKNOWN`。

### 5. 附带源站事实

- 新鲜视频节点默认模型为**会话最后使用的模型**（本轮为
  Wan 3.0 Prime / 2.0）；
- 工作流/故事板切换（aria-label `工作流`/`故事板`）控制
  画布 ↔ 资源总览（音频/图片/视频三栏）双视图；
- OmniHuman 1.5 需求槽未满足态积分 **14**（图片 0/1·音频 0/1，
  与 batch 291 一致）；其面板无时长段（自适应 · 1个）；
- Kling 2.5 档位会话持久化：标准 = 15/5s（3/s）、高品质 = 25/5s
  （5/s）；Hailuo 2.3 直采 36/6s@自适应·1080P（6/s），与地图
  36/5s（7.2/s）并列记为数据点，clone 入表 7.2 与 Hailuo 02 对齐。
