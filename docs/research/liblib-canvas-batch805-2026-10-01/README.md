> 每项写「· 剩余 30 天」，**两处原本都是字面量** —— 周边 160 字符内没有任何

## 一、live pre：把源码换回 HEAD 跑出来的症状

这一批的 pre **不是**在阴性对照里模拟的，是真的换回旧代码跑了一遍：修好的文件先另存到
`/tmp`，`git show HEAD:src/app/project/page.tsx` 换入，跑探针，再**字节级还原**
（sha256 核对通过）。

造数：`store.setState` 把 4 个条目的 `removedAt` 分别往前挪 0 / 1 / 7 / 29 天。
**造数是 fixture，判据全部在渲染出来的文字上。**

| 相位 | 造的天数 | 面板上显示的「剩余 N 天」 |
| --- | --- | --- |
| **pre** | 0 / 1 / 7 / 29 | **30、30、30、30** ← 一字未变 |
| **post** | 0 / 1 / 7 / 29 | **30、29、23、1** |
| **pre** 边界 | 29 / 30 | 两条**都在**，都写 30 天 |
| **post** 边界 | 29 / 30 | 只剩 29 天那条；**提前 30 天的消失了** |

★ 这就是 759 ② 的原症状：「把 `removedAt` 改成 20 个月前，条目日期变了而
『剩余 **30** 天』**一字未变**，且照样列在那个面板里」。本批独立复现。

## 二、★★ 本批的核心纪律：30 这个数**不许写死**

「30 天」是**界面自己写着的字**，不是我的期望值。所以判据不是「它等于 30」：

- **S1**：面板标题里的天数 **必须等于**当天删除项显示的剩余 ⟹ 字面量与行为对齐。
- **S2**：每个条目的剩余 **必须等于** `标题天数 − (今天 − 该条目展示的日期)`，
  **只用 raw 里的日期与剩余重算**，不读源码公式。
- **S3**：剩余 **0** 天的条目必须**消失**，剩余 **1** 天的必须**还在**。

⟹ N 是从数据里**反推**出来的。把 30 换成任何别的数，这三条照样成立；
而如果实现是写死的，N 就会和老化结果对不上而红 —— 这正是阴性对照 **N1** 干的事
（把老化样本的剩余冻成恒定 30，S2 立刻翻红）。

## 三、修复

```ts
const RECYCLE_TTL_DAYS = 30;
const daysBetween = (fromIso: string, toIso: string) =>
  Math.round((Date.parse(`${toIso}T00:00:00Z`)
            - Date.parse(`${fromIso}T00:00:00Z`)) / 86400000);
const remainingDays = (removedAt: string) =>
  RECYCLE_TTL_DAYS - daysBetween(removedAt, today);
const visibleRemoved = removedCanvases.filter(
  (canvas) => remainingDays(canvas.removedAt) > 0,
);
```

面板标题与每项剩余天数都绑到**同一个** `RECYCLE_TTL_DAYS`（S6 守着），
所以改一处不会只改一半。

`removedAt` 是 `new Date().toISOString().slice(0, 10)`（`canvasStore.ts:1239`），
即 **UTC 日粒度的 `YYYY-MM-DD`** ⟹ 天数差可以**纯整数**算，不涉及时区。
两个字符串都按 `T00:00:00Z` 解析，避免浏览器本地时区把结果挪一天。

★ **无回归**：当天删除时「剩余」恰好等于 TTL ⟹ **与修复前字面量显示的是同一个数**
⟹ 用户在修复前后看到的东西**没变**，变的只是它从今起会真的随时间走（S5 守着）。

### 边界约定（**待与源站对照**）

剩余 **0** 天的条目**不再列出**，与面板那句「仅显示最近 30 天内」一致
⟹ 面板里永远不会出现「剩余 0 天」。**恰好第 30 天算「已过期」** ——
这条是我定的约定，**不是源站实测值**。

**无效/被污染的读数比没有读数更危险**。共同的教训是：读数不对时，
