# batch 777 —— 删除之后**用户有没有出路**？把一句捆了三件事的话拆成四个读数

> 结论先行：**763 那句话要拆。** 它把「破坏性 / 跨 reload 持久化 / 无提示」
> 捆成一句，而实测**「不可逆」不成立** —— 撤销是有的（`Cmd+Z`，非输入框落点 2/2），
> 只是**界面上一个入口都没有**。同时测出一个**新缺陷**：
> **焦点在检查器输入框上时，删除不可撤销** —— 而这与 D14 是**同一道守卫**。

| 原话里的三件事 | 实测 | 依据 |
| --- | --- | --- |
| 「破坏性」（读作不可逆） | **不成立** —— 非输入框落点 **2/2** 能用 `Cmd+Z` 撤销 | R-undo |
| 「跨 reload 持久化」 | **成立** —— 且**撤销历史不随之保留**（`past` 归零） | R-persist |
| 「无提示」 | **成立**，且比原话更具体 | R-affordance |

## 1. 上一批挂着什么

776 结清了 D1 的**前半句**（Escape 死键与它的修法依据，结论是「(a) 可以单独做」）。
后半句至今**零读数**：

> 导演台删除破坏性且跨 reload 持久化，却无「未保存/重置」提示

## 2. 为什么必须拆成四个读数

捆着的后果很具体：**任何一件为真都会让另外两件显得已被处理。**
实测正是这样 —— 「`Cmd+Z` 确实能撤销」差点把「无提示」一起放过。

**「不可逆」与「无入口」是两种严重度完全不同的缺陷**：
前者要申请一个「重置项目」功能，后者只要给现有快捷键配一个可见入口。
搞混的代价是**让用户去申请一个根本不需要的功能**。

| 读数 | 问题 | 怎么测 |
| --- | --- | --- |
| **R-past** | 删除进不进历史？ | 桌根只读属性 `data-director-history-past`（`:887`） |
| **R-undo** | 撤销在**哪些落点**上可用？ | 用户可见后果：道具是否回到 `objectIds`、`history-future` |
| **R-persist** | 跨 reload 还在吗？ | **普通 reload**（★ 不能用 `fresh()`，它清 localStorage） |
| **R-affordance** | 有没有撤销入口 / 确认 / 提示？ | 桌内 `[role=status]/[role=alert]/[aria-live]` 的文本 + 撤销类控件计数 |

## 3. ★ 方法学上最要紧的一条：落点必须设在动作**之后**

这一条我错了两次才做对，而它决定了这批结论对不对。

- **第一版**：把「焦点在检查器输入框」当落点，但**删除动作自己把焦点移走了**
  （点的是树工具条上的删除按钮）⟹ 「两种落点结果相同」是**实验设计失败**，
  不是机制。
- **第二版**：删掉的又正好是**当前选中对象** ⟹ 检查器字段随之消失 ⟹
  那一臂根本没成立（`err: no el`）。
- **第三版**（本批采用）：改用**按行删除按钮** `[data-director-delete-object="<id>"]`
  —— 它带 `event.stopPropagation()`（`DirectorObjectTree.tsx:537`）⟹
  **不改选中** ⟹ 被选中相机的 FOV 滑杆在删除之后**仍在屏上**，
  「撤销时焦点在输入框」才成为一格真正的读数。

★ **落点的定义是「删除之后用户所在的地方」，不是「删除之前」。**

## 4. 结果

### 4.1 四个落点，撤销的可用性**由焦点决定**

| 落点 | 删除后 `past` | 焦点 | `Cmd+Z` → 道具回来 | `past` / `future` |
| --- | --- | --- | --- | --- |
| `fovInput` | 1 | **INPUT** | **否** ❌ | **1 / 0**（没动） |
| `deskButton` | 1 | BUTTON | 是 ✅ | 0 / 1 |
| `body` | 1 | BODY | 是 ✅ | 0 / 1 |
| `tree` | —— | —— | **预期失败**：落点不可聚焦 ⟹ 与 `body` 臂是同一格 | —— |

★ `fovInput` 那一格的 `past` 仍是 1 ⟹ **不是「撤销了但没生效」，而是命令被吞了**。
静态层给出机制：守卫 `if (isEditable) return;` 在 **`DirectorDesk.tsx:487`**，
`Cmd+Z` 的 undo 分支在 **`:506`** ⟹ 守卫早退。

★ `tree` 臂被探针的**自证**判成无效，而不是照报成两格；汇编器再断言
**这个失败是预期的**。于是「非输入框落点」是 **2 个独立格**（BUTTON 与 BODY），
不是 3 个。

### 4.2 出路存在，但界面上一个入口都没有

- 桌内**撤销类控件 0 个**（普查与删除后各测一次，都是 0）
- 确认对话框 **0** 个
- 而常驻的**命令反馈面板在成功删除之后显示占位文案「无命令反馈」** ——
  `getDirectorCommandFeedback` 对 `COMMITTED` **返回 `null`**
  （`src/lib/directorCommandFeedback.ts`），面板于是落到 `?? "无命令反馈"`
  （`DirectorDesk.tsx:1008`）

⟹ 用户刚做完一件破坏性操作，界面告诉他「无命令反馈」。

### 4.3 跨 reload：删除留下了，撤销历史没留下

删后 4 个对象 → 普通 reload 并重开桌 → **仍 4 个、道具不在** ⟹ 持久化成立；
而 `past` **归零** ⟹ **reload 之后，删除真的没有退路了。**

## 5. 两个缺陷

- **D1d（中-高）** —— 焦点在检查器输入框上时，**删除不可撤销**。
  删除进了历史但 `Cmd+Z` 被 D14 的守卫吞掉。**与 D14 同一道守卫** ⟹
  **修 D14 时顺带修掉它。**
- **D1e（中）** —— 删除的出路是一个**没有任何提示的快捷键**。
  ⟹ 「能不能撤销」取决于一个**用户看不见的焦点状态**，而界面不告知。

## 6. 更正

### C777-1 —— 改的是 763 挂起项里那句话的**分桶**

**原话**读作「删除不可逆 + 没有任何提示」。

**据实订正**：

1. **不可逆不成立** —— 非输入框落点 2/2 能用 `Cmd+Z` 撤销。
2. **跨 reload 持久化成立**，且撤销历史**不**随之保留。
3. **「无提示」成立**，但比原话更具体：不是「无未保存/重置提示」，而是
   **零撤销入口 + 零确认 + 反馈面板在成功删除后显示「无命令反馈」**。

## 7. 探针教训

- **R119** —— ★**落点必须设在「动作之后」**：删除动作自己会移走焦点，
  所以「删除前的落点」不是「删除后用户所在的地方」。
- **R120** —— ★**两格若实测落在同一元素上，它们就是同一格。**
  「对象树」落点不可聚焦 ⟹ 与 `body` 臂完全重复 ⟹ 合并它们等于把
  「非输入框焦点」只测一次却报成两次。⟹ 补一个真的能聚焦的非输入控件作独立臂，
  并**自证**不重复；重复就记 FAILED 而不是照报。
- **R121** —— ★**读属性别把选择器当属性名**：
  `getAttribute('[data-x]')` 永远返回 `null` ⟹ 读到空串 ⟹ 而**空串看起来像
  「历史是空的」**。另一条同族：这些属性挂在 `role="dialog"` **元素本身**上，
  而 `d.querySelector()` **只搜后代** ⟹ 读成「读数方法不成立」。
- **R122** —— ★**「可撤销」与「有入口」是两种不同的缺陷**，捆在一句话里会让
  其中一件为真时把另一件一起放过。
