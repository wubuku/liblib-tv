# Batch 47 Maturity Assessment

## Outcome

The Director model-library slice is mature as a bounded frontend prototype:

```text
source-shaped entry and categories
  -> clone-owned proxy catalog
  -> serializable prop insertion
  -> tree/Inspector selection continuity
  -> visible R3F result
```

It is not evidence that the clone contains the complete LibTV model catalog or
that its proxy geometry is a source-accurate replacement for production assets.

## Closed Contracts

- a model-library trigger is discoverable in the viewport toolbar;
- five source-shaped category labels are reachable;
- each implemented category has three owned proxy cards;
- clicking a card creates exactly one ordinary Director `prop`;
- the new object stores stable asset/category/visual metadata without remote
  URLs or external model files;
- the new object is selected in the store, object tree and Inspector;
- the new object renders through the existing R3F scene;
- `我的模型` has an explicit empty state;
- Escape and outside pointer close the floating panel;
- desktop/mobile panel bounds and no-overflow contracts are verified.

## Deliberate Non-Claims

- no real FBX, OBJ or GLB loader was added;
- no upstream `模型库/` files or thumbnails were copied;
- no local-import persistence was added to the Director model-library tab;
- no remote library/provider contract was invented;
- no environment/panorama library was added;
- no claim is made about exact current LibTV geometry from this upstream-derived
  implementation.

## Residual Risks

| Risk | Why it remains | Trigger for a new batch |
|---|---|---|
| real model loading | requires asset files, loader lifecycle and license boundary | approved owned asset fixture |
| local `我的模型` import | current Director store has no model-library asset collection | a typed local-asset schema and persistence decision |
| panel visual fidelity | dimensions are calibrated to the existing clone and upstream CSS, not authenticated LibTV measurements | live LibTV model-library evidence |
| dense catalog browsing | the prototype has only three cards per category | a verified source catalog or explicit product fixture |
| environment library | different data/rendering contract from object props | source evidence plus environment schema |

## Next Queue

The next highest-value Director work should stay within proven foundations:

1. add a typed local model-library collection only if local import is approved;
2. improve card keyboard/focus semantics and selected-card feedback if source
   evidence supports it;
3. otherwise evaluate Director shell polish and then return to the main canvas
   gaps with the same evidence-first process.

Do not start real asset loading solely because the proxy cards exist.
