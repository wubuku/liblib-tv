# batch 691 — 「整数入、小数出」有**第二条**独立机制；顺带撞出一处 1px 错位

> 起点：690 写下「**不声称**标尺宽度律之外的派生布局长度也带非整数常数」。
> 本批去销它 —— 结论是**那一条确实是唯一的像素族**，但**百分比族里藏着
> 一条不需要任何拟合常数就能出小数的路径**。
>
> 验收：`scripts/verify-liblib-batch691.py`（6/6）
> 仪器：`scripts/census-directorstore-value-domains.mjs --geometry`（本批加的模式）
> 读数：`runtime-audit.json`

## ① 普查：31 条几何属性、9 条派生表达式、像素族只有 690 那 1 条

`src/components/director/**` 全部几何类 `style`（`width|height|left|right|top|bottom|
transform|min*|max*|flexBasis|gap|padding|margin*`），**并把标识符追到它的定义**：

| 族 | 条数 | 内容 |
|---|---|---|
| 像素族 | **1** | `DirectorTimeline.tsx:1866` `max(640, duration*(3.36+4.978*zoom))` —— **唯一带非整数常数的一条**（690） |
| 百分比族 | **8** | 其中 `DirectorExportPanel.tsx:106` 显式 `Math.round` ⟹ 该条**按构造就是整数值的**（与 689 的 `timelineHeight` 同形、不同因） |

**追定义是必须的**：690 那条在 JSX 处只是一个标识符 `timelineWidth`，算术在上面的
`const` 里。只扫 JSX 属性会报出「像素族 0 条」—— **688 那条「只读一半代码结论就少
一半」的反向版**。

## ② 靶子：姿态垫的 yaw/pitch **天生是分数**

`DirectorPhoneVcamPanel.tsx:352-366`：

```js
normalizedX = (clientX - rect.left) / rect.width
yaw   = (normalizedX - 0.5) * 90
pitch = (0.5 - normalizedY) * 60
```

**用户指针的整数坐标除以盒宽**。21 个**整数** `clientX`（662…942，步长 14）：

| | |
|---|---|
| store 值与公式**逐位相同** | **21 / 21** |
| 是整数的样本 | **0 / 21** |
| 垫子 border box 宽 | **314** = 2 × **157**（奇数 ⟹ 整数偏移除以它在二进制里**永不终止**） |

⟹ **这是与 690 无关的第二条机制**：
690 是「**乘**一个拟合出来的非整数常数」，这里是「**除**一个非 2 的幂的实测宽度」。

**可达性相反**：690 那档分数 zoom **只有 store API 到得了**（range 无 `step`，步长 1）；
而这 21 个值**全部来自真 `page.mouse` 拖动，全程零次 store 写入**。

## ③ 同一个字段，四个面读出四种精度

| 面 | 精度 | 代码 |
|---|---|---|
| store | 完整 double | — |
| `data-yaw` | `toFixed(2)` | `:502` |
| 可见文本 | `toFixed(0)` | `:507` |
| `aria-valuenow` | `Math.round` | `:519` |
| 圆点位置 | 分数 % | `:552` |

**外加一个负零**：`clientX=816` 时 store 是 `-0.286624203821656` ⟹
可见文本渲染成 **`-0 / 5 / 0`**，而 `aria-valuenow` 渲染成 **`0`**。
**同一个姿态，一个面显示负零、另一个面显示正零。**

## ④ 圆点**落不到指针下** —— 两端各偏约 1px

垫子是 `border border-white/[0.08]`，**左右各 1px 边框**。实测：

| 量 | 值 |
|---|---|
| `getBoundingClientRect().width`（**border box**） | **314** |
| `clientWidth`（排除边框） | **312** |
| 代码里除的 | `rect.width` = **314** |
| CSS 百分比 `left` 解析基准（**padding box**） | **312**，原点在内边框内侧 |

⟹ 预测偏差 `1 + off × (312−314)/314`，**21/21 与实测吻合到 1/64**，
偏差区间 **[−0.797, +0.984] px**，**跨过零点**（约在垫子中点）。

**这不是亚像素问题** —— 是整整一个设备像素，量级与 690/685 那些 1/64px 的事无关。

**不是保真偏差**：batch 563 已记源站的「虚拟相机」页签是 **QR 连接 + 录制/重试**，
姿态垫是 **clone 独有**（该文件**零处**提到源站）。
所以这是**我们自己控件的交互精度**问题。改法要动 `src/` ⟹ **不擅自改**。

## ⑤ `aria-valuenow` 表达不了圆点的实际位置

垫子是 `role="slider"`、`aria-valuemin=-90`、`aria-valuemax=90`，
但 `aria-valuenow` 是整数。实测**位置误差上界 1.479px**（理论上界
`0.5° / 90° × 312px = 1.733px`）。

⟹ **辅助技术被告知一个整数，而画出来的滑块最多离那个整数应有的位置 1.5px。**
一个 slider 播报的值与它画的滑块应当对得上。这与 ④ 的边框错位是**两个不同的成因**，
且**叠加**。

## 自记

- **普查器自己错了一版，而错误结果「看起来正好印证了 690」**：几何模式第一版把
  算术判定写成 `/[+*\/]/.test(t) && !/^["'`]/.test(t)`，于是**整族百分比模板串被排除**，
  只报出 1 条 —— 而那 1 条正是 690 已经发现的。**我拿已知答案去核对普查结果，
  于是把普查的盲区当成了「就这一条」。** 修法：判定前先剥反引号，修正后 9 条。
  **一个普查如果和上一批的结论一致，那不是它对的证据。**
- **别把 314 和 312 当成两个都对的宽度**：第一版我以为 314 是面板内宽，
  实际上 `getBoundingClientRect().width` 给的是 **border box**，`clientWidth` 才排除
  边框。两者都对，但**必须量**。
- **面板的门是代劳打开的（要记）**：姿态垫在 `connected` 分支里，而真连接要起
  本机 HTTPS 预演服务器 + 证书信任。本批用**真 setter** `setPhoneVcamStatus('local-ready')`
  打开这道门 —— 面板其余逻辑与指针处理全是真的，只把「连接」这一步代劳了。
- **写作时栽了一次**：`whyNeverInteger` 那条 f-string 末尾多了一个孤立的 `"`，
  把后面整段吞成字符串 ⟹ 括号失衡、报在几百行之后。**自己写的仪器要先 `ast.parse`**
  （JS 串 `node --check` 已是本会话惯例，这是它第一次漏网的原因：我改了 f-string
  却没重新 parse）。
