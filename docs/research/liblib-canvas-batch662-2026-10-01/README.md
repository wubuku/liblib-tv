# batch 662 —— `帮助` 的爆炸半径：**机制 vs 盖住者**，N(H,h) 闭式

## 一句话

661 说「盖住 `help` 的是 `收起属性`」。**读数是对的，但它是个成员，不是原因。**
本批把这条答案换成一条闭式，并且发现**没有任何 UI 状态能救 `帮助`** ——
这不是采样结论，是 `88 > 24` 的算术。

## 1. 头条：**第一版预测被自己的读数推翻**

661 的读数摆出一个诱人的闭式。`收起属性` 恒在 `H−39..H−19`，`帮助` 恒在
`H−40..H−8`，**两者都锚在视口底边**；时间轴顶边 = `H − h`。于是

```
重叠 ⟺ 143 − h < −8  且  163 − h > −40
     ⟺ h > 151  且  h < 203
```

即「默认 182 是唯一的坏值，151 与 203 之间有一条干净带」。

**扫了 18 档** h（含 88 收起态、151/152、202/203 两条预测边界、420 上限）：
`topIsSelf` **一格都没有翻成 True**。

把整条命中栈倒出来才看清 —— 栈顶恒在时间轴**里面**，而时间轴**左列**
（`[data-director-timeline-track-list]`，320px，`overflow-y-auto`）的盒子
**恒完整包住 `帮助` 的纵向区间**：它从 `H−h` 一直铺到视口底边，
而 `h ≥ 88 > 24`。

> **预测错在把「成员」当成了「机制」。** 一个 20×20 的按钮恰好落在探测点上，
> 是因为那条轨道行恰好在那个 y —— 而按钮只是那条行里被点到的那一个。

## 2. 仪器：`elementsFromPoint` 的栈顶是**成员**，机制要沿祖先取

```
topMechanism(el) = el 及其祖先上，第一个带 data-director-* 属性的元素
```

48 格（4 窗高 × 12 时间轴高）跑下来 —— **机制 54/54 全在时间轴内，而成员有 6 种**：

| 机制 | 次数 | 成员是谁 |
|---|---|---|
| `data-director-timeline-track-list` | **39** | 左列**自己**（点落在列的空白 / 滚动区，`overflow:auto` 的 padding box 也吃命中） |
| `data-director-timeline-object-row=…character-lead` | 4 | 角色对象行 |
| `data-director-timeline-object-row=…camera-main` | 4 | 机位对象行 ← **661 在默认格量到的就是这一枚** |
| `data-director-track-label=…character-lead-transform` | 4 | 轨道标签 |
| `data-director-timeline` | 2 | 时间轴节本身（点**正落在顶边**上，没有更近的 data-* 祖先） |
| `data-director-playback` | 1 | 播放条 |

**661 没有说错**：在它量的那一格（`1150/182`），那枚按钮确实吃到了那一下。
**它缺的是「这个答案会不会随状态变」这一问** —— 6 种成员，可达性判定一个都不受影响。

> **可复用的部分不是结论，是这个上溯。** 任何要**归因**遮挡的批次都该报机制；
> 只报成员的批次等于报了一行列表里的某一项。

## 3. 爆炸半径闭式 N(H, h)

`rail` 的 7 枚入口是**两头钉**的：

* 上 6 枚钉在**顶部** —— `cy` 恒 `76 / 132 / 172 / 212 / 252 / 292`，
  **与窗高无关**（48 格逐格相同，四个窗高完全一致）；
* `帮助` 带 `mt-auto` 钉在**底部** —— `cy = H − 24`（636 / 696 / 876 / 1126）。

时间轴通栏、左列 320px 宽，而 rail 只有 48px 且**完全落在其中**（`section` 是
`z-40`，rail 是 `z-30`）。于是

```
一枚入口被吞 ⟺ 它自己的中心落在时间轴顶边之下或齐平
              ⟺ cy ≥ H − h

N(H, h) = 1 + |{ cy ∈ 上六枚入口 : cy ≥ H − h }|

台阶在 h = H − 292 与 h = H − 252，各加一枚
```

**48 格逐格命中，零例外。**

**台阶钉在单个像素**，H=660 时：

| h | 367 | **368** | 407 | **408** | 420 |
|---|---|---|---|---|---|
| 被吞枚数 | 1 | **2** | 2 | **3** | 3 |

四个边界格**用四次全新加载逐位复现**（同页内改 store 不是唯一读法）。
H=720/900/1150 在量程内**不出现台阶** —— 第二级台阶要 `h = H−252`，
H=720 时是 468 > `DIRECTOR_TIMELINE_HEIGHT_MAX=420`。

## 4. 为什么**没有 UI 状态能救它**

把条件化简到只剩 `h`：

```
帮助中心 = H − 24        被吞 ⟺  H − 24 ≥ H − h  ⟺  h ≥ 24
量程下界 = DIRECTOR_TIMELINE_HEIGHT_MIN = 88   （src/store/directorStore.ts:99）
                                  24 < 88  ⟹  量程内无解
```

实测**唯一**的用户出口 —— 时间轴自己的「最小化」按钮
（`[data-director-timeline-collapse]`，点完 `collapsed=true`）：面板降到 88px，
`帮助` **仍然** `topIsSelf=false`，机制变成左列本身。

**630 早就记过** `setTimelineHeight` 只把值钳在 88..420 这个魔数区间、
从不与可用纵向空间比较。本批补上它的后果：**那个钳制正是拿掉唯一出口的动作。**
`DIRECTOR_TIMELINE_DEFAULT_HEIGHT = 182` 稳稳落在坏区间里。
