# batch 806 —— 回收站没有「彻底删除」：**能力在、入口无**

> 结论先行：这是**纯测量批次**（`src/` 一行没改）。要回答的是 759 ③ / 755 ④
> 「`purgeRemovedCanvas` 零调用点 ⟹ 回收站没有彻底删除」。
> 那句话只回答了「**渲染层没接**」。本批把三件事分开测，结论是：
>
> - **能力**：可用，且**真的不可逆**（绕过 UI 直接调，销毁 10 个节点的快照、不回到画布）
> - **入口**：**0 个**（两个状态下普查都是 0）
> - **文案**：确认框写「此操作不可恢复」，而删除后条目**进了回收站**、还能恢复 30 天

## 一、为什么要把「能力」和「入口」分开

如果只测入口，得到的是「回收站没有彻底删除」—— 这句话同时兼容两种情况：

| 情况 | 处置 |
| --- | --- |
| 能力没做 | 先写实现，再谈入口 |
| **能力做了、入口没接** | 只差一个入口 |

两者的工作量差一个量级。所以本批加了**能力验算**：跳过 UI 直接调 store 的
`purgeRemovedCanvas`，看它到底管不管用。

## 二、三格读数（两轮逐位相同）

### 格 1：面板动作面普查（**两个状态**）

| 状态 | 可交互元素 | 逐个 |
| --- | --- | --- |
| 未勾选 | **2** | `[data-recycle-check]` 14×14 勾选框、`[data-recycle-restore]` 40×27 「恢复」 |
| 已勾选 | **3** | 上面两个 + `[data-recycle-restore-selected]` 「恢复所选 N 项」 |

**两个状态下「删除类」命中都是 0**（文本／`title`／`aria-label`／属性名／属性值
五条路都查，验收器**独立重算**这份判定，不复述探针自报的列表）。

★ **必须记两个状态**：批量恢复按钮是**条件渲染**的（`selectedRemoved.length > 0`
才出现）。只在未勾选状态下普查会**少算一个入口** —— 而那恰好是「普查器没看进去」
的自证。第一版探针就只普查了未勾选状态，是补跑的。

### 格 2：能力验算 —— 绕过 UI 直接调

```
purgeRemovedCanvas('canvas-2')
  调用前在回收站里      true
  销毁的快照节点数      10          ← 毁掉的不是空壳
  调用后还在回收站      false
  调用后回到画布        false
  回收站条数            1 → 0
```

⟹ **能力可用、且真的不可逆**。它销毁的是那张画布的完整快照（10 个节点）。

### 格 3：阳性对照 —— 面板里现存的每个动作真的有效果

| 动作 | 结果 |
| --- | --- |
| 单条「恢复」 | 回收站 1 → 0、画布 1 → 2 |
| 勾选 + 「恢复所选 1 项」（选中文案「已选择 1 项」） | 同上 |

★ 没有这条，「删除类命中 0」也可能只是「面板本身是个空壳」。

## 三、★ 805 让那条文案矛盾变得更尖锐

删除确认框的原文（实测）：

> 删除画布确定要删除画布「画布 2」吗？**此操作不可恢复**。取消 确认

而删除后条目**进了回收站**、`removedCanvases` = 1，还能「恢复」回来。

755 ④ 当时就记过这条矛盾（「『此操作不可恢复』与实现的软删除矛盾」），
但那时回收站的「30 天」**本身是假的**（805 之前那两句都是字面量）⟹ 那时这句话
虽然是假的、但**后果也是假的**（反正也恢复不了）。

★ 805 把 30 天变成真的之后，用户被告知「不可恢复」的东西**现在真的可以恢复 30 天**，
而**恢复入口在另一个路由**（`/project` 的回收站），画布里既不提示也不链接。

⟹ 这条矛盾的处置需要拍板：改文案（源站文案逐字是什么？还是它也这么写？），
还是在画布里补一个指向回收站的提示。**两者都要源站对照**，本批**没有**源站证据
（源站需登录）。

## 六、不声称

- ★ **入口该怎么设计没有结论**，理由如上：`src/` 与 `docs/research/` 里
  **没有任何源站截图或记录**能定住它的长相（`grep 彻底删除 docs/research/*.md`
  只命中 755/805 两行我自己写的记录）。
- ★ 「此操作不可恢复」那条文案**是否是源站原文也没验**。它是 114 批按源站
  转录的（`CanvasTabDropdown.tsx:46` 注释「源站文案：此操作不可恢复」），
  但**本批没有重新对照源站** ⟹ 若源站确实这么写，那矛盾在源站也存在，
  处置方向会完全不同（可能是「照抄源站的矛盾」而不是「改文案」）。
- ★ 只测了「删除画布」这一条命令 ⟹ 其他命令的回收站行为**未测**。
- ★ 「恢复」只验了把条目**拿回来**；恢复后那张画布的**内容是否与删除前逐位相同**
  **未验**（805 的 raw 里 `snapshotNodes` 显示快照有 10 个节点，但那只是个数）。
- ★ 能力验算是**直接调 store**，不是用户路径 ⟹ 它证明「能力可用」，
  不证明「存在一条用户可达的路径能触发它」（恰恰相反，那条路径不存在）。
