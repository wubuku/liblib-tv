# Batch 686 — 高度轴的未取整普查：683 的「阈值 336」不是形变阈值

日期：2026-10-01
验收脚本：`scripts/verify-liblib-batch686.py`（**10 项，10/10 通过**）
取证脚本：`/tmp/dbg686a.py`（逐高度全量普查，**但状态被扫描本身改了** —— 见 §5）、`/tmp/dbg686b.py`（18 个高度逐页开桌，顺序无关）、`/tmp/dbg686c.py`（**顺序对照：下行 + 上行两遍**）

本批**零源站断言**（无源站授权、未开源站会话）；`src/` **一字未改**。

## 起点：685 自己留的那条限制声明

685 证明了普查那把 `Math.round` 的尺会把 1/64px 连续斜坡伪造成平台，并留了一条：

> 顺带一条对 683 的限制声明：683 的高度轴结论同样建立在取整读数上，所以
> 「随高度变形的只有 1 个键」**只在整数单位上成立**。本批没有推翻它，
> 只是指出它没有覆盖亚像素变化。

本批做两件事：**量那句话在亚像素单位上是否还成立**；**给 `帮助` 的形变一条可复算的规则**。

## 读数一：683 的结论在未取整单位上**依然成立**，而且只剩一枚

逐高度 140..1700（**1561 格**）全量普查 119 个 data 键的**未取整** `width|height`：

**只有 `data-director-rail-entry=help` 一个键的尺寸集合随高度变化。**
其余 118 个键在 1561 格上逐字不变（到 `getComputedStyle` 返回的四位小数为止）。

所以 685 那条限制声明**没有生效**：高度轴上确实没有亚像素形变。
**一条「也许会咬人」的限制声明量完发现不咬，也要记下来**，否则它会一直当传闻活着。

## 读数二：683 的「阈值 H = 336」是**另一个量**；形变是 345..356 的 12 格斜坡

| 高度 | rail `clientH` | rail `scrollH` | `帮助` 未取整高 | 发生了什么 |
|---|---|---|---|---|
| 336 | **284** | **284** | **20** | **容器不再溢出**（683 量的就是这一点的 `52+284`） |
| 344 | 292 | 292 | **20** | 仍是 20，已经过了 336 九格 |
| **345** | 293 | 293 | **21** | 尺寸**开始**变 |
| 350 | 298 | 298 | 26 | 斜坡中 |
| **356** | 304 | 304 | **32** | 尺寸**不再**变 |
| 720 | 668 | 668 | 32 | — |

**336 / 345 / 356 是三个不同的数，683 把前两个当成一个了。**
683 的**读数**（32×20 @ H≤300、32×32 @ H≥400）**一字不撤销** —— 24 格在本批的
18 个逐页开桌高度上逐字复现；错的只是「阈值正好是 336」这个说法。

683 之所以没看见：它采样 300 与 400，**跨过了整条 345..356 的斜坡而没有落在里面**
—— 和 682 跨过 336 是同一类失误，只是跨的是另一段。

### 可复算的规则（1561×2 格 + 18 个逐页开桌，全部命中，零例外）

```
帮助 的高   = clamp(视口高 − 324, 20, 32)
帮助 顶边   = max(264, 视口高 − 92)      （相对 rail 顶）
```

四个常数各有出处：

| 常数 | 出处 |
|---|---|
| **20** | 下限 —— 按钮的 `min-content` 高 |
| **32** | 上限 —— 它声明的 `size-8` |
| **324 = 60 + 264** | `60 = 52`（rail 的 `top-[52px]`）+ `8`（rail 的 `p-2` 底内边距）；`264` 是顶边被钉住的内容相对位置，且 **`264 + 20 = 284`** —— 正是 683 量的 rail 内容高 |
| **92** | 贴底时的顶边 = `railH − 8(p-2) − 32(size-8)` |
| **356** | 两条顶边公式的交点：`264 = H − 92 ⟺ H = 356` |
| **345** | 高度离开 20px 下限：`324 + 20 + 1` |

**机制一句话**：顶边先钉在内容相对 264，够高后改为贴底（`H − 92`），两式在 356 相交；
高度是随之而来的差，再被 20 与 32 夹住。**所以它是斜坡不是台阶** ——
683 看到了差值，给它起了个「阈值」的名字。

## 读数三：第三个「变化」的键是**仪器缺陷**

我第一版探测器用 `last[k] = sig` 做增量比较，它把两条 `data-director-track-label` 键
各记了 **3121 次变化**（每个高度两次）。

原因：这两条键下各有 **4 个成员**（684 已认定：一个 `36×18` 标题按钮 `机位` + 三个 `24×24` 导航钮），
而增量比较是**逐元素**的 —— 四个成员轮流把 `last` 写成不同值 ⟹ 同一高度内自激。

**这是 683「不能跨高度取并集、要逐高度比集合」那条纪律的第四次翻版**
（683 的探针、683 的验收器、683 的「两宽度」判据各犯过一次，本批的探测器是第四次）。
修法：**比集合**，不增量。

## 读数四：高度轴的形变是**整数斜坡**，与宽度轴的 1/64px 斜坡量纲不同

| 轴 | 形变形态 | 步长 |
|---|---|---|
| 宽度（685） | 连续斜坡，1/64px 栅格 | 2–9 个 1/64（0.03–0.14px） |
| **高度（本批）** | **12 步、每步整 1px**（345..356） | **1px** |

**同一种「几何随视口连续变形」，在两个轴上是两种量纲。** 宽度轴是 flex 收缩的**分数**分配，
高度轴是底锚定 flex 列里剩下的**整数像素**。

## 读数五：密集扫描的读数**有一部分是路径的函数** —— 本批最重要的方法论结果

`/tmp/dbg686a.py` 的逐高度扫描读到的 `data-director-timeline-height` **恒为 88**，
而**逐页开桌**在同一批高度上读到的全是 **182**。原因是**扫描的第一步**：
窗口被压到 140，时间轴高度被压到 store 下限，之后 1560 格都在测另一个状态。

所以本批做**顺序对照**：同一页先 **1700 → 140 下行**、再 **140 → 1700 上行**，逐格比对。

| 字段 | 类别 | 两遍不一致的高度数 |
|---|---|---|
| `帮助` 的高 / 顶边 / 底边 | 纯布局 | **0** |
| rail `clientH` / `scrollH` / `railH` | 纯布局 | **0** |
| `data-director-timeline-height` | **store 值** | **1524**（177..1700，连续） |
| 轨道区高 | 派生自 store 值 | **1524** |
| `collapsed` 标志 | 标志（本会话从未为真） | 0 |

**布局量是视口高的函数；store 值不是。**

**没有这条对照，686a 会报出「时间轴在 140..1700 的每个高度都是 88 高」—— 一条纯属虚构的缺陷。**

### 顺带确认了 630 的在案项

时间轴高度的规则是 `clamp(视口高 − 88, 88, 182)`，**在逐页开桌（18/18）与下行扫描（1561/1561）上成立，
在上行扫描上只对 `h ≤ 176` 成立** —— 因为一旦被夹到下限就**再也不涨回来**（store 只往下钳，不往上写）。

`88` 这个下限来自 `directorStore.ts:99` 的 `DIRECTOR_TIMELINE_HEIGHT_MIN = 88`，
而 **`176 = 88 + 88`** 正是 630 记的那条「窗口矮于 176 时 store 的 MIN 会把时间轴值顶回 88」——
**本批从规则推出同一个数，测量恰好夹住它**（h=177 读 89，h=176 读 88）。

## 读数六：`88` 这个值分不出「收起」与「被压到下限」

`DirectorTimeline.tsx:794` — `data-director-timeline-height={timelineCollapsed ? 88 : timelineHeight}`。
**两个分支在数值上完全相同**，因为 `DIRECTOR_TIMELINE_HEIGHT_MIN` 也是 88。

上行扫描在 720 读到 `88`，而 `collapsed` 是 `false` —— 那个 88 是 store 值，不是收起分支。
**一个能承载两种含义的属性，无法回答「我现在处在哪个状态」。**

这也是我本批**自己的一次误读**：第一遍看到 `88`，在源码里看到 `timelineCollapsed ? 88 : …`，
就断定「时间轴收起了」。**那是错的 —— 标志从未变成真。**
源码那一行让我把一个**值**读成了**标志**。与 670/678/683 同类，但更隐蔽：
那个字段既不缺名也不缺值，**是源码表达式把它重载了**。

## 自记：本批的仪器错了三次

1. **增量探测器按元素比**（读数三）⟹ 3121 次假变化。**比集合。**
2. **机制讲错了一版**：我先写「顶边钉在 272、底边跟着视口底」并当成读数，
   实测顶边钉在 **264**、且底边并非恒定 —— 我漏了 rail 的 `p-2` 底内边距 8px。
   **是我推的故事，不是量到的数**；改成把两个公式都逐格验证（1561×2 零例外）才敢写。
3. **自己把一个值读成了标志**（读数六）。源码里的三元表达式是最强的暗示，
   **它让读数看起来已被解释过，于是不再被检查**。

第 2 条与 685 那条「我拿到的不是布局，是尺子」是同一族，但更靠前一步：
**尺子没错，是我先编了个故事再去找数。**

## 附：一个可复用的工程决定

本批的密集扫描是 1561×2 格，逐格存全量 rows 会把 audit 推到 **81MB**（**不可提交**）。
改成：面板/计数字段全量（11 个小字段 × 1561 格），**尺寸签名只在相对上一格变化时记一条**，
Python 侧按「最近一次变化点向后继承」重建每高度的尺寸集合 —— 精确，且体积降到可提交量级。

另外加了 `LIBLIB_BATCH686_CACHE=1`：**纯断言修改时复用已落盘的原始读数**，
不再花 8 分钟重开浏览器；复用是显式的，且 `repr` 兜底保证任何漏进载荷的可调用对象
会以字符串出现（可 grep），不会让整轮测量白跑在最后一步。
