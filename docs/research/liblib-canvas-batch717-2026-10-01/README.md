# batch 717：断点找错了 1px —— 真换层在 898|899，而且它只切换了 2 枚元素的显隐

日期：2026-10-03　验收器：`scripts/verify-liblib-batch717.py`（6 条判据，零 store 写入，不改 `src/`）

## 起点

716 撞见一条非单调读数：`vw = 800` 时底部浮动条可见 776，`vw = 900` 时只有 314 ——
窄 100px 的窗口，底部条反而宽 462px。当时归到「899px 断点两侧定位基准换了一层」。

代码里 `max-[899px]` 遍地都是，但**没有人量过这个断点到底改了什么**。
本批用 batch 711 的「一次全叶投影的前后差集」跨断点做差，并做**字段级分类**。

## 我一开始就找错了 1px

| 对比对 | 叶子数 | 只在左侧 | 只在右侧 | 变了 | 相同 |
|---|---|---|---|---|---|
| 898 vs 898（重复读） | 842 / 842 | 0 | 0 | **0** | 842 |
| 899 vs 899（重复读） | 842 / 842 | 0 | 0 | **0** | 842 |
| **899 vs 900**（我先测的这对） | 842 / 842 | 0 | 0 | **175** | 667 |
| **898 vs 899**（真断点） | 842 / 842 | 0 | 0 | **831** | 11 |

**899 与 900 在断点的同一侧。** 那 175 处差异的位移分布是
`x=1.0 → 140 枚`、`x=0.5 → 14 枚`、`w=1.0 → 21 枚`、另有 1 枚 y 差 0.3、1 枚 h 差 0.5 ——
**全部 ≤ 1px，纯重排**。照那张表，几乎可以得出「断点什么都不做」的错误结论。

## 真断点在 898|899，一次同时跳六项

| 指标 | 898（窄） | 899（宽） |
|---|---|---|
| 树列 | **219** | **232** |
| 轨道列表 | **220** | **320** |
| 底部条框宽 / 左缘 x | **898 / 0** | **337 / 281** |
| 底部条可见宽 | **874** | **313** |
| 时间轴滚动容器可见宽 | **676** | **577** |
| 头部 `padding-right` | **8px** | **260px** |

**`max-[899px]` 在 Tailwind v4 是严格小于（`width < 899`）**，
所以 **899 本身走的是宽屏分支** —— **字面值与实际生效边界差 1**。

## 跨真断点的差集：只切换了 2 枚叶子的 display

- 叶子 **842 → 842**，**0 增 0 删**
- **0 处** `data-*` / `aria-label` / `role` / 文本 / `visibility` 变化
- **恰好 2 处** `display` 变化：
  - `root/3:div`：`none`（0×0）→ `flex`（x0 y52，**48×1098**）—— 只在 ≥899 出现的竖条
  - `root/4:div/…/section/6:div`：`flex`（x12 y100，**68×32**）→ `none` —— 只在 ≤898 出现的控件
- 其余 **829 枚**只动几何

**⟹ 断点不增删节点、不改语义，只切换两枚元素的显隐。**

顺带把 716 那条非单调读数的机制钉死了：底部条在断点处**窄 561px**（874 → 313），
溢出 70 → 631。716 只测了 800 与 900 两个点（相差 100px、整个跨过了断点），
所以只看到「800 更宽」这个现象，定位不到 898|899。

## 判据

| 判据 | 断言 |
|---|---|
| `the-same-width-projection-is-byte-identical` | 898 与 899 各连读两遍，**0 变化、0 单边、842 全同**（差集法的可信前提） |
| `the-breakpoint-is-between-898-and-899-not-899-and-900` | 898\|899 变 **831** 枚、899\|900 变 **175** 枚；后者**只动几何字段**且位移分布逐项等于 `{w=1.0:21, x=0.5:14, x=1.0:140, y=0.3:1, h=0.5:1}`；154 枚 x-only 的位移集合恰为 `{0.5, 1.0}` |
| `max-899px-is-strictly-less-than-899` | 898：tree 219 / 轨道列表 220 / 头 `pr 8px` / 底部条 x=0；899：tree 232 / 320 / `260px` / x=281 |
| `across-the-real-breakpoint-no-node-is-added-or-removed` | 842 == 842，`onlyA` 与 `onlyB` **都为空**，相同 11 |
| `across-the-real-breakpoint-nothing-semantic-changes-except-two-display-toggles` | **0 处** `data/aria/role/txt/visibility` 变化；**恰好 2 处** `display`，方向为 `none→flex` 与 `flex→none` 各一，几何为 48×1098@(0,52) 与 68×32@(12,100) |
| `the-bottom-bar-loses-561px-at-the-breakpoint` | 底部条可见 **874 → 313**（差 **561**）、框宽 898 → 337、溢出 70 → 631；时间轴容器 676 → 577；900 与 899 同侧只差 1px |

两轮连跑 **6/6**，读数逐条一致。

## 方法论收获（可复用）

**① 「变了 N 枚」里的 N 取决于你有没有选对对比对，而 N 的大小本身会误导你。**
我拿 900 vs 899 得到 175，差点据此写下「`max-[899px]` 在这个区域什么都不做」——
真断点的数字是 **831**。**差集法必须先验证「我选的两侧真的不同侧」。**
验证办法很便宜：**把对比对往两边各挪一格**，看 N 会不会突变。
898|899 = 831、899|900 = 175 —— N 跳了 4.7 倍，那 175 就自证是噪声。

**② 差集必须做字段级分类，否则「噪声」和「换层」长得一模一样。**
898 vs 899 的字段分布是 `{x+y: 545, x+y+w+h: 53, x: 55, y: 101, …}`，
第一眼看过去就是「一大片几何抖动」。
**唯一把它和噪声区分开的是 `display` 出现 2 次** ——
若不做分类，这 2 枚会被淹没在 829 枚几何变化里，然后得出「断点只是重排」的错误结论。

**③ 1px 差是可疑信号，不是噪声信号。**
`max-[899px]` 读起来是「≤ 899 走窄屏」，实测是「< 899 走窄屏」。
**同一个字面量，在「≤」和「<」之间差整整一个断点宽度。**
⟹ 看到 `max-[Npx]` 就去问「N 本身归哪一边」，别默认。

**④ 「窄屏版更宽」这类反常关系，追到底层是换层而不是渐变。**
716 记的是现象（800 比 900 宽 462px），717 记的是机制
（断点处底部条从 `vw−24` 的窗级层跳到 `vw−586` 的 pane 级层，一次差 561px）。
**现象可以跨很多点被观察到，机制只在断点那一格。**

**⑤ 探针的取值范围要包含「我猜的那个答案的邻居」。**
716 测了 700/800/900/1024，**唯独没测 898/899** ——
而答案恰好在那两格中间。⟹ 定位断点时，**在候选值两侧各补一格**。

## 待拍板（不阻塞）

- **`max-[899px]` 字面 899、实际生效 898** —— 代码里大量注释按「≤899 是窄屏」在写，
  实际 899 走的是宽屏分支。要不要统一成无歧义的写法（`max-[898px]` 或 `min-[899px]`）
- **底部条在断点处窄 561px**（716 的遗留）：断点处从窗级层掉到 pane 级层，
  溢出 70 → 631。要不要在窄屏下继续让底部条待在窗级
- **底部条横向溢出是 clone 独有**（716 的遗留，源站那条是 1920 全屏宽）
- 底部条与工具条要不要挂 `tiny-scrollbar`（715 的遗留）
- 1024 下工具条溢出 20px 裁掉「删除关键帧」（715 的遗留）
