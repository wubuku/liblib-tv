## 五、★★★ 最重要的发现：**822 的「两句同屏」是后门造出来的**

822 记录的 S5：★ **面板外「跟随目标时不可使用预设运镜」＋ 面板内「当前时间轴没有可追加的时长」同屏**。

### 5.1 两条纯 UI 路径都被堵死

| 顺序 | 结果 |
| --- | --- |
| 先让 append 被拒（面板开着）→ 再设跟随 | ★ 设跟随要点**检查器**里的 select ⟹ 那一鼠标键**落在面板外** ⟹ `:576` 的 pointerdown **当场关掉面板** ⟹ 面板内那句随之消失 |
| 先设跟随 → 再开面板 | ★ 跟随激活时开关 **disabled** ⟹ **面板根本开不了** |

### 5.2 ★★ 两条臂的实测对照

| 臂 | 用什么设跟随 | 面板还开着吗 | 两句同屏吗 |
| --- | --- | --- | --- |
| **B9** | ★ `select_option()`（**程序化设值**） | ★ **是** | ★ **是** |
| **B10** | ★ **真实鼠标** `mouse.click()` | ★ **否（被点关）** | ★ **否** |

⟹ ★★★ **同一个动作，只因为「有没有产生 pointerdown」，结果完全相反。**

### 5.3 ★★★ 于是有了一条更硬的方法论

> ★★ **`select_option()` 也是「程序化」**：它直接改 value 再派发 change，
> **不产生 pointerdown** ⟹ 于是**绕过了**「面板外部点击关闭」。
> ⟹ ★★ **「用了 Playwright 的 API」**不等于**「纯 UI」**。
> ⟹ ★ 真正的判据是：**这一步有没有产生真实的 pointerdown / keydown**。

⟹ ★★ **822 的 S5 是一个「只有后门才造得出来」的现象 —— 用户永远看不到。**
⟹ ⟹ 822 README 里「屏幕上两句互相矛盾的话」这句**要更正**（见第七节）。

## 八、★ 本批抓到的探针缺陷（**四处，四处都造出过假结论**）

| # | 现象 | 真因 |
| --- | --- | --- |
| 序1 | 画布「节点数」恒为 0，而 DOM 上明明有 10 个节点 | ★ **画布 store 没有 `nodes` 顶层键** ⟹ 节点在 `canvases[activeCanvasId].nodes` |

| 序4 | ★★ 「B9 两句同屏了」 | ★★ `select_option()` **不产生 pointerdown** ⟹ ⟹ ★ **它也是「程序化」** |

⟹ ★★ 四处里有两处（序2、序4）**差点让我把「产品缺陷」写成「探针缺陷」的镜像** ——
