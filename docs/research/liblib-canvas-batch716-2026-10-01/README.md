# batch 716：横向空间预算表 —— 两个「装不下」方向相反，一个是源站同款，一个是 clone 独有

日期：2026-10-03　验收器：`scripts/verify-liblib-batch716.py`（6 条判据，零 store 写入，不改 `src/`）

## 起点

715 测出底部浮动条把 944px 的内容塞进 694px 的框，**全程没有任何位置能点全 15 枚控件**，
并在 README 里把根因猜到容器选择上（`:604` 实测源站那条是全屏 1920 宽，
clone 挤在视口 pane 内）—— **但没量过**。

713 留下另一条**形状完全相似**的读数：默认 `zoom = 44` 下时间轴装不下 8 秒全程。

**本批把两个「装不下」各自量化，然后各自回去比源站。**

## 与源站对照：两个症状，成因相反

**① 时间轴的横向溢出 —— 源站同款行为，713 的拍板项应当撤回。**

仓库里 `:594` 已实测源站（1920×1150）：容器 **1598**，
`zoom 0/16/31 → 1598`、`49 → 2473`、`64 → 3220`、`100 → 5012`。
代入 clone 的公式 `duration × (3.36 + 4.978 × zoom)`：

- `10 × (3.36 + 4.978 × 49)` = **2473.06** ⟹ 与源站读数**逐位一致**
- `10 × (3.36 + 4.978 × 31)` = **1577.7 ≤ 1598** ⟹ 源站在 zoom ≤ 31 时夹在容器宽

clone 在 `zoom ≤ 23`（8s 工程下的对应点）时标尺正好 **1598 = clientWidth** ——
**两边都在容器宽处夹紧**，clone 靠 `min-w-full` 免费拿到了源站那个夹紧。

⟹ **「默认 zoom 装不下 8 秒全程」是源站自己的行为，不是 clone 的缺陷。**
713 攒下的「要不要调默认 zoom / 给滚动提示」这条待拍板项，**前提不成立**。

**② 底部条的横向溢出 —— clone 独有，715 的拍板项成立。**

`:604` 实测源站那条外壳是 `absolute inset-x-0` **1920 宽 @(0,968)**，即**全窗口宽**；
clone 的在 **x = 293**、宽 718，被关在视口 pane 里。
同一个文件 `:3407` 的注释还写着「clone 的控件集更大，故去掉定宽让内容撑开」。

⟹ **根因是 clone 侧的两个决定叠加**：底部条选了 pane 级容器 + 视口工具条去掉了定宽。
内容 944 是 clone 自己的，容器 718 也是 clone 自己的 —— **两边都不是源站行为**。

## 方法论收获（可复用）

**① 症状相同不等于成因相同 —— 每个「装不下」都要各自回去比源站。**
713 和 715 留下两条读数，形状一模一样（都是「横向装不下，要滚」）。
本批把它们并排放进一张表才发现：**临界宽度差了 571px（1530 vs 2101），
在源站基准宽 1920 下一个不溢出、另一个还差 181px。**
如果按「同一个布局太窄」一起归因，就会把一条**应当撤回**的拍板项和一个**真实缺陷**混在一起处理。
⟹ **并排比较是分离成因最便宜的手段**；而**分离的依据必须是各自独立的源站读数**。

**② 仓库里已记录的源站实测是现成的对照组，不必等授权。**
本批没有新增任何源站读数，两条对照全部来自 `:594` 与 `:604` 的既有实测。
⟹ **动手判定「这是不是 clone 的问题」之前，先把该控件历史上做过的源站实测翻出来** ——
那里面往往已经写着 clone 侧的容器选择，答案就在注释里。

**③ 断点两侧的关系要双向断言。**
「底部条在 900 断点处变窄」这件事，正着说（900 比 800 宽）没人会注意；
反着说（**800 比 900 宽 462px**）才立刻显得像 bug。
⟹ **量到断点时，把两侧的值都写进断言，并且断言它们的关系方向**，
否则「窄屏更宽」这种反常关系会静静躺在 audit 里没人看。

**④ 「装得下」是一个随窗口宽度变化的函数，不是一个布尔。**
本批把 715 的「全程点不全 15 枚」换算成一句可决策的话：
**`vw ≥ 1530` 时底部条 15 枚全在框内**。
⟹ 报「某控件不可达」之前，先报它**在什么条件下可达** ——
这与 703 那条「可达 ≠ 有入口」是同一族，但更进一步：**可达是「控件 × 窗口宽度」的函数**。
