# Batch 17 计划：资产管理上下文与层级浏览

## 1. 缺口与价值

| 缺口 | 当前 clone | 原站证据 | 价值 | 决策 |
|---|---|---|---:|---|
| 当前画布漂移 | 列表标题硬编码 `画布 2` | 原站顶部显示项目与当前画布 | 5 | 绑定 active canvas |
| 抽屉上下文缺失 | 顶部直接进入页签 | 原站 Logo 下有项目/画布行 | 5 | 增加上下文行 |
| 扁平节点列表 | parent/child 同级 | 原站组节点展开并缩进 child | 5 | 按 `parentId` 渲染一层树 |
| 浏览工具缺失 | 无筛选/搜索/排序 | 原站显示排序、全部、搜索 | 4 | 实现本地控件 |
| 空态错误 | 画布空态也写媒体资产 | 页签语义可直接判断 | 4 | 按 tab 区分 |
| 顶部导航冲突 | mode 控件仍压在 240px 抽屉内 | 原站 mode 控件位于抽屉右侧 | 4 | 打开抽屉时避让 |

## 2. 实施步骤

1. `AssetManagerPanel` 读取 `projectName`、active canvas name 和 active canvas nodes。
2. 增加项目/画布上下文行；点击画布入口关闭抽屉并打开顶部画布菜单。
3. 顶部 `TopNavBar` 在资产抽屉打开时隐藏重复画布按钮，并将 mode 控件移到抽屉右侧。
4. 画布页签按 top-level node + direct children 渲染层级树，保留 10 项节点选择合同。
5. 增加本地排序、类型筛选和搜索；所有控件只过滤当前可见列表。
6. 修复画布/资产空态文案并增加稳定 selectors。
7. 添加 Batch 17 Playwright：上下文、层级、筛选、搜索、active canvas 切换、空态、移动端和 console。

## 3. 事实边界

### Source fact

- 原站抽屉宽约 `240px`，打开后画布区域向右收缩。
- 顶部 Logo 下显示 `未命名项目 | 画布 2`；mode 控件位于抽屉右侧。
- 页签为 `画布 / 资产`；画布列表标题为 `画布元素`，旁边有排序、`全部` 和搜索。
- 视频组下缩进显示 `分镜视频-#9`，组关系可见。
- 底部显示 `共 10 节点`。

### Inference

- 项目/画布上下文应来自与顶部导航相同的 `canvasStore` 数据。
- clone 中已有 `parentId` 是表达组层级的可靠数据源。

### Clone-only decision

- 筛选项使用 `全部 / 图片 / 视频 / 文本 / 分组`。
- 排序在“画布顺序 / 名称顺序”之间切换。
- 搜索只匹配当前本地节点 label。
- 点击抽屉中的画布上下文会转交给顶部画布下拉，保持 Batch 11 的 overlay 互斥合同。

## 4. 验收标准

- 资产抽屉显示 store 中的项目名和 active canvas name，不含硬编码 `画布 2`。
- 当前画布 10 个节点仍可见；失败视频行 `data-asset-manager-depth="1"`。
- 搜索、筛选和排序能改变可见项，清理后恢复。
- 切换到空 `画布 1` 后，抽屉上下文显示 `画布 1`，画布 tab 显示“暂无节点”，资产 tab 显示“暂无媒体资产”。
- 点击节点仍同步 React Flow selection。
- 929px 与 390px 无页面级横向溢出；Batch 12-16 不回归。
