## 靶心

`diff609.py` 比的是**可访问名**，它看不见「源站有个 `帮助` 钮在 y=1110、clone 的在 y=928」这种事 —— 两边都只有一个 `帮助`。所以本批换了普查口径：`probe613.py` 走**每一个可交互元素**（含无名的），不只比名字。

源站 150 项 vs clone 47 项，其中冒出来的第一条真缺陷是：源站有个 `帮助` 按钮在 `[7.5,1110,32,32]`，clone 的在 `[7.5,928,32,32]` —— **差 182px**。

## 根因不在按钮，在容器

从 `场景` 往上逐层走（`probe613d`）才看清：源站的左列是**一块** `aside`，不是两个各自绝对定位的面板。

```
aside.absolute.inset-y-0.left-0.z-30.overflow-hidden
     .border-r.border-white/10.bg-[#171717]              [0, 0, 281, 1150]
  header.flex.h-[52px].items-center.border-b             [0, 0, 280, 52]
  div.flex.h-[calc(100%-52px)]                           [0, 52, 280, 1098]
    nav.border-white/8.flex.w-12.flex-col.gap-2.p-2      [0, 52, 48, 1098]   ← 资源栏
    div.flex.w-[232px].flex-col.bg-[#171717]             [48, 52, 232, 1098] ← 场景树
```

即：**资源栏与场景树都从 52（顶栏下沿）起、纵贯到视口底**，而时间线是浮在中间列上的独立覆盖层，会盖住 rail 的下段。

clone 原先把两者都以 `absolute inset-y-0` 挂在**中间 flex 子节点**里，于是：

1. 顶边被 clone 独有的 36px 高镜头条顶到 **88**（源站 52）—— 七枚 rail 每一枚都比源站低 36px；
2. 底边停在该 flex 子节点的下沿 = 时间线上沿 **968**（源站到视口底 1150）—— `帮助` 因此差 182px；
3. 场景树因此是 `46 / 220`，而源站是 `48 / 232`；底色 `#191919` 比源站 `#171717` 浅两阶。

## 顺带补上一个当年量到却没断言的洞

**batch 602 的 docstring 里早就写着源站 rail 是 `48x1098 @(0,52)`**，但它的断言只查了宽度、padding、gap、底色、右边框，以及条目之间的**相对**间距 —— 从没查过 y 和 h。所以 rail 被放在多高多低，它都是绿的。这个洞是本批的普查顺着读数翻出来的：读数是对的，位置是错的，而验收看不见。

本批给 batch 602 补 `rail:spans-[0,52]to-the-viewport-bottom`（9 → 10 项）。新断言对旧状态非空：旧 rail y=88 ≠ 52，会红。

## 源站导演台没有镜头条

`probe613h` 对全 DOM 搜 `nav` / `[role=tablist]` / `[role=tab]`，外加文案 `镜头` / `机位N`，只命中三枚 nav：

```
[0, 8, 1920, 32]     data-canvasNavbar   （画布页导航，被导演台盖住）
[0, 52, 48, 1098]    资源栏
[780, 968, 128, 48]  视口底部浮动药丸
```

所以 clone 的 `导演台镜头`（`镜头` 标签 + `机位1` chip）整条都是 **clone 独有功能**。`probe613g` 对 y 52..88 做横带扫描也印证了：那条带里源站只有资源栏、场景树 `[48,52,232,1098]`、属性面板 `[1640,48,280,972]` 和视口 canvas，**没有整幅行**。

按既定原则（不删 clone 独有功能来对齐几何），镜头条保留；只是资源栏归位到 52 之后会盖住它的左缘 48px、把「镜头」标签吃掉，于是给镜头条加了 `min-[900px]:ml-12` 让开。让开后的底色仍是 `#171717`，与源站该处的场景树同色。窄屏（<900px）资源栏隐藏、场景树是抽屉，故不加边距。

## 唯一修不好的那一处：源站的「帮助」是死控件

`probe613f` 在源站对「帮助」中心 (23.5, 1126) 做 `elementFromPoint`：命中的是时间线左控制簇

```
div.z-10.shrink-0.bg-[#1f1f1f]
```

**源站自己最底那枚 rail 项在时间线打开时是点不着的**，只有时间线最小化之后才露出来。裁图（`crop613.py`）里 (1110,1110) 那块也是纯黑，没有按钮。

本批让 clone 复现同一行为：时间线 `z-40` > rail `z-30`，`帮助` 同样在其下；把时间线关掉后，它回到 `[7.5,1110,32,32]` 并且**可命中、可点击**（验收里两条都断言了）。

反过来抬高 rail 让它压过时间线，会把时间线自己的左控制簇（`播放` / `自动帧` / `循环播放` / `时间` 输入，`[8,974.5]` 起）埋掉 —— 拿一枚死控件换四枚活控件，不划算。所以**照抄源站行为并记录**，不在任一方向默默「修正」。

## 验收脚本里两处自纠

- **dev overlay 污染命中测试**：`帮助` 在 (23.5, 1126)，正是 Next dev server 的 `nextjs-portal`（build 活动角标）挂载的位置，`elementFromPoint` 和 `locator.click()` 都被**工具**而不是应用截走。该 overlay 只存在于 `next dev`，生产构建与源站都没有，故在命中测试前把它摘掉，并在脚本里写明理由。
- **自造合同**：`flyout:closes-on-second-click` 是我先写下的断言，跑出来是红的 —— 查代码发现 `select("panorama")` 本来就不做 toggle（`setOpenFlyout("panorama")` 无条件执行），而源站 rail flyout 的点击语义属未取证项。**断言一个两边都没有的行为是不诚实的**，改成断言真实存在的契约：点另一枚 rail 项会关掉当前 flyout（`select()` 开头就 `setOpenFlyout(null)`）。

顺带记一条既有缺口（不在本批靶心，未改）：导演台的 Escape 键处理链里没有 flyout 这一档，所以 flyout 开着时按 Escape 会一路落到 `closeWorkspace()` 把整个导演台关掉。验收脚本因此用「点另一枚 rail 项」来切 flyout。
