# batch 775 —— 方向① 的谓词上到底有没有洞？把「落点」这个变量枚举一遍

> 结论先行：**我开这一批时的假设是错的。** 我以为「层内但落点不是控件」这个状态
> 是方向① 覆盖不到的洞；**普查把它测成了不存在**（6/6 浮层没有非控件区、
> 6/6 浮层根本来没有 `tabindex`）。推翻它花了一次普查，不是一次假设。
>
> 顺带查出一件对**修法**有直接用处的结构事实：桌内**已经**有一处
> 「Escape 不经 `isEditable` 守卫」的处理（移动端抽屉，`:482`），它是
> C774-1 所需的**同仓结构先例**（判据不同、形状相同）。

## 1. 上一批挂着什么

774 结清了 763 挂起的「D14 修法方向① 够不够」，留下三件：

1. **问① 充分性成立**（α 30/30、β 6/6 继承成立），但**不证识别性** ——
   谓词该怎么写要改 `src/`，仍是拍板项。
2. **问② 会误伤 Escape**：`DirectorDesk.tsx:487` 的 `if (isEditable) return;`
   一旦触发，export 的「关导出面板」能力消失（变死键）⟹ **C774-1 修法必须分段**。
3. 774 的 README「下一批」有一段**暗示**：「别的落点上可能也有伤害而没测」。

**本批就是去把那个「可能」测掉的。** 772/774 量 D14 时，落点**全部**取自
「浮层内第一个可聚焦控件」这一个取值 —— 772 和 774 用的是同一个抽样点，
所以它们**共享同一个盲区**，谁也看不见谁看不见的东西。

## 2. 先普查，再断言（R103）

方向① 的谓词是「**焦点在某个浮层内**就早退」。如果「层内但落点不是控件」
这个状态**用户根本到不了**，那么「方向① 覆盖不到」的那一类里就没有它。

第一版把 `layerNonControl`（点浮层空白处）当成一类落点写进了协议。冒烟立刻打回：

| 浮层 | 非控件区 | 浮层内可聚焦控件数 |
| --- | --- | --- |
| export | **没有** | 5 |
| preset | **没有** | 10 |
| pathmenu | **没有** | 5 |
| phonevcam | **没有** | 2 |
| crowd | **没有** | 5 |
| modellib | **没有** | 15 |

「`data-*`」挂在内层容器上，几何上被控件铺满 —— 逐点扫描 2% 步长，
`elementFromPoint` 落回浮层内的每一个点都命中了某个控件。

★ **「找不到」本身就是读数**，不是失败。它把 `layerNonControl`
从「一类落点」降级成「一条普查」，代价是 6 行代码，收益是**避免凭空造出
一批格** —— 而凭空造出的格会被后面的读数当成机制差异。

**普查自己也必须防空转**：「没有非控件区」也可能是浮层不在 DOM / 控件数为 0 /
矩形为空。所以每行都自证非空（控件数 > 0 且面板矩形有面积），
验收器把这条写成判据。

### 浮层根的 `tabindex` —— 6/6 实测**本来就没有**

这是本批最该记的一个读数。`layerRoot` 那一臂（焦点在浮层根、落点不是控件）
要求给浮层根一个 `tabindex=-1`。**产品里它本来没有** ⟹ 那个状态是
**探针注入造出来的**。

第一版把「它不可达」当成一个**标注**写进 raw，而那个标注在
landing / neutral 两个臂上还不一致（一个 True、一个 False）——
**自己的断言冒充了读数**。现在：探针只记**测量**（`hadTabindexBefore`），
「用户可达」由汇编器**从落点名推导**（单一真相源）。

★ 于是 `layerRoot` 那一臂的意义变了：它**不是**「现在有洞」，
而是回答「**若将来有人给浮层根加 `tabindex`，方向① 还成立吗**」。
**把一个注入实验写成产品结论，是本批一开始就差点犯的错。**

## 3. 协议

三个臂，缺一不可：

| 臂 | 做什么 | 格数 | 作用 |
| --- | --- | --- | --- |
| `base` | 不落点，直接按 `Delete` | 6 | **同会话基线** —— 读数方法还活着吗 |
| `landing` | 落点后按 `Delete` | 30 | **主测量** —— 五类落点上伤害还在不在 |
| `neutral` | 同样五类落点，但按桌内不处理的 `F2` | 30 | 对照 —— 键投递本身没被弄坏吗 |

五类落点：`trigger`（浮层自己的触发器）、`outsidePanel`（桌内另一个面板）、
`treeContainer`（对象树容器，不点行）、`body`（焦点谁都不在）、
`layerRoot`（合成）。每轮 66 格，两轮共 **132 格**。

**间谍**：注册在 window **冒泡**、**开完浮层之后**才装 ⟹ 排在桌内那个处理器
（挂载时注册）之后 ⟹ 读到的 `defaultPrevented` 已包含桌内那一次。
中性键 `F2` 桌内不处理 ⟹ 必须读到 `false`，**且同时断言间谍确实收到了 `F2`**
（只断言 `false` 没有鉴别力：「键没送到」也得 `false`）。

**两个前置，逐格自证**：① 浮层**仍然开着**（落点动作不能顺手关掉它）；
② **选中未变**（落点动作不能改选中）。不满足就不是读数。

### 两轮一致性与重试（如实记，不装干净）

- **两轮完全一致**：132 格逐字段比对（普查 6 层 × 2 轮亦然），
  `allConsistent=true`，无一格有差异。
- **重试：132 格全部一次跑成**，`maxTries=1`、重试过的格 **0**。
  格内重试机制**在**（每格最多 3 次、900×n 退避），但**这一轮一次都没用上**。

★ 这两件事要分开说：「零重试」是**这一次的读数**，而「机制存在且被记进
产物」是**方法学的事实**。若只写「本次全部一次跑成」，下一个人会以为
**没有重试机制**，于是遇到抖动时不知道该看 `tries` 字段。
`tries`/`retried` 因此被**排除在两轮一致性比较之外** ——
抖过一次和没抖过，机制读数应当相同。

## 4. 结果

### 4.1 五类落点上，守卫**一次都没触发**

- `base` 臂 **6/6** `defaultPrevented=true`（同会话基线）
- `landing` 臂 **30/30** `defaultPrevented=true` ⟹ 守卫在这五类落点上一律早退
- `neutral` 臂 **30/30** `defaultPrevented=false`，**且 30/30 键流里确含 `F2`**

静态层给出机制解释：`DirectorDesk.tsx:474-479` 的判据**恰好**是四类 ——
`isContentEditable` ∪ {`INPUT`,`TEXTAREA`,`SELECT`}，**没有任何**
「元素是否在某个浮层内」的判断。验收器把这条写成断言 ⟹ **一旦方向① 被实现，
这一批的静态层立刻变红**，不必等人发现结论已经过期。

### 4.2 伤害分布：20 格有伤、10 格无伤，差额**恰好**是「目标不可删」的两层

- Δ=−1 的 **20** 格：**目标可删**的四层（export、phonevcam、crowd、modellib）
  × 5 落点
- Δ=0 的 **10** 格：preset / pathmenu × 5 落点 —— 这两层的选中目标是
  `director-camera-main`，`deleteDirectorEntity` 不吃相机

★ 差额**恰好**是那两层 ⟹ 又一次演示 R97：「**没伤害**」与「**分支没跑**」
是两件事，而 `defaultPrevented=true` 把两者分开了。

### 4.3 ★ 方向① 的覆盖是完整的（**在「用户可达」这个限制下**）

每格读三个量，组合起来才决定「缺陷」还是「按设计」：

| 读数 | 含义 | 位置 |
| --- | --- | --- |
| `activeInLayer` | `document.activeElement` 是否在浮层内 —— 按 `activeElement` 写的谓词管不管得到 | `targetInLayer.activeInLayer` |
| `lastPointerInLayer` | 最近一次 `pointerdown` 是否落在浮层内 —— 用户到底在跟谁交互 | `ptrAfter.last` |

★ 只报其中任何一个都会得出错的结论（773/774 反复撞到的 R97）——
所以探针三个都记，结论只用组合。

实测：**`activeInLayer` 只在 `layerRoot` 上成立**（6/6），其余 24 格为假。
而 `layerRoot` **产品里到不了**（§2）。

⟹ **「用户可达 ∧ 方向① 覆盖」这一格，在 775 的五类落点里是空的。**
它真要靠 774 那一格（层内的**控件**）才成立。

所以：**在用户可达的落点上，方向① 覆盖的那一格与实测有伤害的那一格完全重合。**
净结论是「方向① 在当前实现下没有漏网」。

### 4.4 本批**不新增**用户可见缺陷

- 问的是「方向① 够不够」，不是「现在有没有坏」。
- 五类落点上的伤害**全部**属于「用户明确在编辑桌内」或「焦点谁都不在」，
  **没有证据**说后者是缺陷 —— 登记它等于把「按设计」写成「新缺陷」。
- 本批推翻的是**我自己**上一批 README 里的一个暗示（C775-1）。

## 5. 更正

### C775-1 —— 订正 774 README「下一批」的一个**暗示**

**原措辞**（774 §10 末段）语气暗示「别的落点上可能也有伤害而没测」。

**据实订正**：别的**用户可达**落点（触发器 / 桌内他处 / 对象树容器 / body）
上伤害**确实还在**（30/30 格 `dp=true`），但那些落点的语义是
「**用户明确在编辑桌内**」，**不是方向① 的漏网**。而「焦点在层内、落点却不是
控件」这个状态**用户到不了**（6/6 浮层没有非控件区）。所以在**用户可达**
这个限制下，**方向① 的覆盖与实测有伤害的那一格完全重合**。

### C775-2 —— 收窄 774 关于守卫位置的措辞（★ 顺带产出修法先例）

**原措辞**（774 §5）：「`:487` 的 `if (isEditable) return;` 排在**所有分支之前**，
Escape 阶梯也在其后」—— 读作「桌内没有任何 Escape 处理绕过这道守卫」。

**逐行现读之后这句话不成立**。守卫（`:487`）确实在
C/V/Z/Y（`:490`）、Delete/Backspace（`:527`）、Escape 阶梯（`:549`）之前，
**但移动端抽屉的 Escape 分支（`:482`）在它之前**：

```tsx
if (event.isComposing) return;                    // :481
if (event.key === "Escape" && activeMobilePanel) { // :482  ← 在守卫之前
  event.preventDefault();
  closeMobilePanel();
  return;
}
if (isEditable) return;                            // :487  ← 守卫
```

两件事因此改写：

1. 774 那句「所有分支」不成立（不是错读，是 774 没量到那一处）。
2. **C774-1 从「Escape 需要另写一条规则」升级为「Escape 已有同仓结构先例可抄」**。
   差别在于：先例是按**状态**（`activeMobilePanel`）分层，而需要的规则是按
   **焦点所在层**分层 —— **判据不同、形状相同**。

★ 静态层的行号是**另写一份实现**算出来的（`scripts/verify-liblib-batch775.py`
里独立重算，汇编器自己也算一遍），两边必须对上。

## 6. 探针教训

- **R103** —— ★「某个状态**不存在**」本身就是一个要测的量。把
  `layerNonControl` 写进协议当一类落点 = 凭空造出一批格；降级成普查，
  代价 6 行、收益是避免把注入实验当产品结论。
- **R104** —— ★普查也必须走与主测量**同一套前置**。普查漏选相机 ⟹
  preset/pathmenu 的触发器 `disabled` ⟹ 静默少测 2 层，且「触发器点不动」
  会被当成一条读数。
- **R105** —— ★**git 看不见 `node_modules` 里的东西**。见 §7。
- **R106** —— ★**推导量不许写进 raw**。`userReachable` 由落点名推导
  （单一真相源）；探针写它就出现两个真相源，且**两个都不报错**。
- **R107** —— ★**把源码抹过头，得到的不是零结果而是假零**。静态扫描里
  连字符串字面量一起抹白 ⟹ `tagName === "INPUT"` 读不到、`event.key === "Escape"`
  搜不到 ⟹ 判据静默退化成「什么都没找到」，看起来像通过。抹白只抹注释。
  同族：跨批读取的臂名要**先验非空再比大小**（`arm == "A"` 数出 0 行，
  而「0 == 0」在断言里长得像通过）。
- **R108** —— ★**阴性对照的 `mutatedAnything` 必须实测**。自称 `True`
  等于没有这一条检查；改成比对变异前后的**派生指纹**之后，
  「改一个判据读不到的字段名」才被正确识别成「对照自己没改成」。
- **R109** —— ★**探针与汇编器之间的字段名必须两边对齐，而且断言要落在
  真正写入的那个字段上**。汇编器读 `r["selectedIds"]`（行顶层，探针从不写）
  ⟹ 断言「目标没选中」当场触发，读起来像「探针没选中」，实际是**取错了地方**
  （真值在 `before.selectedIds`）。
- **R110** —— ★**相对行号与绝对行号混用，恒假且方向骗人**。
  C775-2 的断言写成 `mobRel < guardRel`，前者是整文件的 482、后者是处理器体内的
  相对行号（约 16）⟹ 恒假；而翻的方向恰好是「**我的发现不存在**」。
  我在注释里写下了这个陷阱，然后一头踩进去 —— 所以陷阱要**写成断言**，
  不能只写在注释里。
