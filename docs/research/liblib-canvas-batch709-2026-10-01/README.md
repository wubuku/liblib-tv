# batch 709：导演台的历史与手势活多久 —— 关掉再打开还能不能撤？

日期：2026-10-03　验收器：`scripts/verify-liblib-batch709.py`（5 条判据，4 条臂，零 store 写入，不改 `src/`）

## 起点

706–708 把「一次会话内的撤销」测透了：手势怎么并条目、`Cmd+Z` 哪些格到不了、
到不了的格子里浏览器做了什么。**但那三批全部在同一个会话里。**
用户真正会问的是跨会话的问题：**在台里改了东西、关掉导演台、回来还能不能撤？**

## 五条预测（写死在验收器里，先于任何测量）

| 预测 | 内容 | 结果 |
|---|---|---|
| **P1** | 关台再重开后 `history.past` 归零，之后按 `Cmd+Z` 记 `UNDO` / `NOOP` | **成立** |
| **P2** | 归零的原因是**换了一个 projectId** | **成立** |
| **P3** | 连开关两次会**每次**都归零 | **推翻** |
| **P4** | 开着手势（改了值没提交）时关台，未提交的改动被丢弃 | **成立** |
| **P5** | 已提交的内容在关台重开后**保留** | **推翻** |

## 判据 1：开着手势关台，未提交的改动**被丢弃**（本批最扎实的一条）

| 阶段 | fov | 手势 | 历史 |
|---|---|---|---|
| 刚开台 | 43 | — | 0 条 |
| 滑块上按 3 次 `ArrowRight`（没点画布） | **46** | `camera-fov` 开 | **0 条** |
| 关台 → 重开 | **43** | — | 0 条 |

用户在滑块上推了几下、没点别的地方就关掉导演台，**那几下推的改动没了**，
而且**一条历史都没留下** —— 也就是说它既没被保存，也**没法被撤销**（没东西可撤）。

源码侧对得上：`DirectorDesk.tsx:453` 的 `closeWorkspace` 在 `closeSession` 之前
先 `cancelDirectorGesture()`，而 `cancelDirectorGesture` 会把文档**回滚**到手势基线
（706 已测：`GESTURE_CANCEL` / `NOOP` / `projectChanged: false`）。
⟹ **关台等于「取消当前手势」**，不是「保存当前手势」。

## 判据 2、3、4：一个没人能解释的不对称

| 循环 | 已提交内容 | `history.past` | projectId |
|---|---|---|---|
| 第 1 次关台 → 重开 | **全丢**（改名回退、fov 回 43） | 1 → **0** | **变了** |
| 第 2 次关台 → 重开 | **全留** | 1 → **1**（`UPDATE_OBJECT` 那条还在） | **一字不变** |
| 关台 → **刷新页面** → 重开 | **全丢** | 1 → **0** | 变了 |

刷新页面等于「又回到第一次」；**只有同一页面会话内的第二次及以后的关台重开才保留**，
而且保留的不只是内容 —— **连历史条目都还在，projectId 都一模一样**。

源码侧能解释「为什么保留」，解释不了「为什么第一次不保留」：
`registry.open` 命中同 ownerKey 的**内存记录**就整份返回（`directorProjectRegistry.ts:276` 的 `FOCUSED` 分支），
而 `closeSession` 会先 `rememberDirectorHistory(projectId, history)` 再 `persistence.save(...)`（`directorStore.ts:3288/:3305`）——
**所以「第二次起保留」是内存记录的功劳**。但第一次为什么没命中记录，本批**没有证据**。

## 本批最重要的一行：「第一次关台丢工作」**不能当成用户可见的缺陷**

第一次开台走的是 617 仪器的 `openDirectorDesk(node.id, canvasId)` store 调用。
我读了两处源码确认**真实按钮调的是同一个函数、参数也相同**
（`ScriptExecutionNode.tsx:57` 的 onClick 只多一个 `event.stopPropagation()`），
所以「开台路径不同」这个解释站不住。

但我**两次尝试让第一次开台走真实按钮都失败了**：
在一个**从未开过导演台**的节点上，`[data-open-director]` 按钮点得到、可点，
**点了之后导演台没有打开**（刷新页面后仍然如此；
而判据 4 证明「关过台再刷新」之后同一个按钮是**能**打开的）。

⟹ **用户路径未取证。** 一个不对称摆在账上、没人能解释它的时候，
**正确做法是把它记成未取证，而不是记成缺陷。**

## 判据 5：顺带一条读数（成因未取证）

**从未开过导演台的节点上，点「打开导演台」按钮不起作用** —— 两次独立尝试都是同一形状
（一次直接点、一次刷新后点）。而**关过一次台之后**，同一个按钮能正常打开。
本批不解释成因（可能是节点缺导演项目记录、也可能是视口命中问题），
**只记「两次独立复现」这个事实**。

## 判据

| 判据 | 断言 |
|---|---|
| `closing-the-desk-discards-an-uncommitted-gesture-change` | fov 43→46→43、手势从开到无、历史恒 0 条 |
| `the-first-close-and-reopen-loses-everything-committed-including-history` | 改名在第一次循环后消失、`pastLen` 归零、**projectId 变了**（否则「归零的原因」就不是换项目） |
| `the-second-close-and-reopen-loses-nothing-not-even-the-history-entry` | 第二次循环后名字在、`pastLen` 仍是 1 且是 `UPDATE_OBJECT`、projectId 一字不变 |
| `a-page-reload-then-reopen-behaves-like-the-first-close` | 刷新后重开内容全丢、`pastLen` 归零、按 `Cmd+Z` 记 `UNDO` / `NOOP` |
| `the-open-button-does-nothing-on-a-node-that-never-had-a-director-session` | 两次尝试按钮都存在、都点了、都**没打开** |

## 顺带一条方法论：节点卡片**不是**持久化的读面

我一度想用画布节点卡片判断「导出有没有写进节点」——
实测卡片文本只有「打开导演台 →」，**那些对象名一个都不在卡片上**。
**一个看起来合理的读面，量出来是空的** —— 这和 704/706 的「读面太窄」是同一个错误的另一面：
**读面不只是太窄，还可能是压根不承载那个信息。**

## 待拍板（不阻塞）

- **关台丢未提交的手势改动**：要不要在关台前提示（「有未提交的改动，确定关闭？」），
  或者改成关台时先 `commitDirectorGesture` 再关
- 「第一次关台重开丢全部已提交内容」：**先取证再定性** ——
  需要能把第一次开台驱动成真实按钮路径（节点要先在画布视口里、且从未开过台）
- 历史活不过刷新页面：是否要在持久化里带上 history（`rememberDirectorHistory` 目前只在内存）
