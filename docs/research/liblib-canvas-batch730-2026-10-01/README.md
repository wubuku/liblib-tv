# batch 730 — `data-inert` 的 46 处写点没有一处挡住可聚焦性；顺带撞见 Tab 被画布征用

## 起点

729 在「开通会员」上实测到：`data-inert="true"` 的按钮 **Tab 能聚焦**、`focus()`
后 `document.activeElement === el`；静态侧也一致 —— 全仓 `data-inert` **从未与 `disabled`
或 `aria-disabled` 同时出现（0 处）**。729 据此写下「`data-inert` 挡的是鼠标反馈与
点击语义，没挡住可聚焦性与可及名」。

但那是**一个样本**，而 729 自己的审计数据里同时留着两个互相打架的数字：

```json
{"nInert": 46, "nInertButtons": 45, "inertByFile": {"src/components/TopNavBar.tsx": 2}}
```

**两个 `data-inert` 属性、只数到一个 `<button>`** —— 三者不能同时成立。
矛盾当时就在数据里，没人去对账。

本批做四件事：
① 把那个 45 纠回 46，并说清它是怎么错的；
② 把「可聚焦」从一例推广到**画布上能打开的每一个视图**；
③ 补上 729 根本没做的那两维：**键盘能不能激活**，以及**聚焦时看起来像不像能用**；
④ 顺着「Tab 能不能到达」往下挖，撞见 **`Tab` 在画布上被征用成快捷键**。

### ⑤ 键盘：Enter 与 Space 同样零可观测后果

### ⑥ 新撞见：**`Tab` 被画布征用成快捷键**

裸画布上按一次 `Tab`：

| 观测 | 读数 |
|---|---|
| 焦点是否移动 | **不动**（前后同为 `BODY`） |
| 添加节点面板 | **`False` → `True`** |
| 源码 | `src/app/page.tsx:1358` `if (event.key === "Tab") { event.preventDefault(); toggleAddNodePanel(); }` |
| 快捷键面板自述 | `src/components/KeyboardShortcutsDialog.tsx:27` — `{ label: "新建节点", keys: ["Tab"] }` |

⟹ **`Tab` 在画布上不再是「在控件之间移动焦点」的键，而是一条画布快捷键**
（第一次按被 `preventDefault()` 吃掉、面板弹出来；之后焦点才开始正常移动 ——
这正好解释了为什么按 Tab 遍历时能读到 60 多个身份）。

这改变了 730 那个问题的问法：**「`data-inert` 挡不挡可聚焦性」之前，
先得知道 `Tab` 归谁**。而在画布上，它归画布。

## 纠正 729：45 → 46

729 的 `nInertButtons: 45` 是**扫描口径错了**，不是数据错了。

朴素的 `<button\b[^>]*>` 会在**注释里那个 `<button>` 的 `>` 上截断**。
`TopNavBar.tsx:200`（积分余额那枚）的开标签里正好有一段 batch 358 的注释写着：

```jsx
<button
  type="button"
  aria-label="积分余额"
  // Batch 358: 积分余额是**读数**, 不是控件。此前它是个启用、无 handler、
  // 还带 `hover:bg-[#333]` 的 <button> —— 悬停会亮, 像能点。      ← 这里有个 `>`
  title="积分余额（读数，无可点操作）"
  data-inert="true"
  ...
```

正则匹配到注释里那个 `<button>` 的 `>` 就停住了，`data-inert="true"` 落在匹配范围之外，
于是**整枚按钮连同它的标记一起从普查里消失**。

**抹掉注释再匹配**（保持字节偏移不变）后：

| | 数字 | `TopNavBar` |
|---|---|---|
| 朴素扫描 | 45 | **1** |
| 抹注释扫描 | **46** | **2** |

差值恰好是 1，且恰好落在 `TopNavBar` ⟹ **不是数据漂移，是正则撞上了注释。**
729 留下的 `nInert: 46` 与 `inertByFile.TopNavBar: 2` 都是对的，只有 `nInertButtons`
错了 —— **三个数字之间的矛盾本身就是线索**。

## 「46 处」既不是控件数，也不是按钮数

`data-inert` 写在 JSX 里，`.map()` 会把它撑成多枚：

| 组件 | 静态写点 | 运行时实例 |
|---|---|---|
| `LeftSidebar.tsx:101`（教程面板的 `.map()`） | **1** | **4**（使用教程 / 联系客服 / 联系销售 / 关注公众号） |
| `HistoryPanel.tsx`（1 + 3 枚 `.map()` 在 3 张卡上） | **4** | **10**（时间倒序 1 + 3 张卡 × 3） |

⟹ **写点数、控件数、运行时实例数是三个数**；729 记的 46 是第一个，
它既不等于用户在屏幕上能 Tab 到的数量，也不等于被标记的控件数量。
判断「这个标记管不管用」，得先说清数的是哪一个。

1. **`data-inert` 要不要补 `aria-disabled`** —— 729 已提出；本批把证据从

2. **19 处 `data-inert` 按钮没有 `aria-label`**（27/46 有 ⟹ 19 处没有）——

## 方法论

1. **普查的正则会撞上注释** —— 朴素 `<button\b[^>]*>` 在注释里那个 `<button>` 的
   `>` 上截断，把整枚按钮连同标记一起漏掉。**先抹注释再匹配**，
   并保持字节偏移不变以便报行号。
2. **自己审计里的数字要互相对账** —— `nInert: 46` / `nInertButtons: 45` /
   `TopNavBar: 2` 三者不能同时成立。**口径之间要对得上**，
   一个对不上的数字要么是数错了，要么是口径没写清；**它自己就是线索**。
3. **「可聚焦」有两个不同的问法** —— 程序化 `focus()` 成功（元素属性）
   与在自然 Tab 序列里（文档顺序）是两件事，**两格都要测**，
   而且第二格要比**多重集**而不是去重后的身份数。
4. **先问「Tab 归谁」，再问「Tab 能不能到」** —— 画布把 `Tab` 征用成快捷键之后，
   「按 Tab 能不能到达某个控件」这个问题本身就得先分层。
5. **「不可用」的视觉暗示要逐维查** —— `cursor: default` 骗了鼠标那一维，
   **焦点环把键盘那一维也骗了**；判断一个标记够不够，
   要去测它**挡不住的那几维**上留下什么痕迹。
6. **写点数 / 控件数 / 实例数是三个数** —— `.map()` 会把一个写点撑成多枚控件；
   说「46 处」之前先说清数的是哪一个。
7. **零副作用要分鼠标与键盘两格测** —— 729 只点了鼠标。
8. **一格读不出来就先怀疑探针** —— 本批最贵的两格（键盘 mutation、agent 的 Tab）
   都是先怀疑探针、反复复现、最后才决定「记未取证」而不是「下结论」。
9. **机制未取证就不写成结论** —— 现象复现三次 ≠ 成因已知；
   读数自相矛盾时，正确的动作是**把它排除出判据并记录**，不是挑一个说得通的解释。

## 探针返工四处

1. **朴素正则漏掉一枚按钮**（v1）—— 写成上文「纠正 729」那一节。
   最终产物是验收器里的 `mask_comments()`：抹注释、保持偏移。
2. **Tab walk 的绕回判定返工三次**：
   - v2「指纹第二次出现且首次位置 < 5」—— Tab 会重复经过同一组元素，误判成绕回，
     生成历史报出 `14 > 12` 的重复计数。
   - v3 指纹用「自身 + 两层祖先」—— 同一工具条里多枚 `BUTTON` 折叠成同一个签名
     （`BUTTON<BUTTON<DIV`），误判「焦点卡住」提前收尾（生成历史只走 8 步就停）。
   - v4「前 40 步的指纹序列要在后面完整重现」/「找最小 L 使 `seq[-L:]==seq[-2L:-L]`」
     —— **第一圈的顺序与后续不同**，锚在第一圈永远匹配不上（cap 走完得到
     「同一枚数了 5 遍」的重数）；锚在末尾则 `n` 很小时窗口取到 3 就误触发，
     **一枚都没走到**。
   ⟹ 最终**不猜周期**，改成按「该走够的枚数」截断：一整圈里每枚只经过一次，
   所以 `inertStops` 达到挂载数时计数恰好就是挂载的重数。
3. **agent 视图读数自相矛盾** —— 现象（三次复现都读不到抽屉三枚）稳，
   但正向 Tab 与反向 Tab 给出互不相容的结论；而且其中一版探针**因为假定抽屉已打开
   而拿到空列表**（`querySelectorAll('button[data-inert]')` 只返回 2 枚，
   `focus()` 找不到目标静默失败）—— **那次读数整个作废**。
   ⟹ **每一格都断言状态**；断言不过就作废那一格，不解释。
4. **`key` 模式报了 30 次 mutation**（v2）—— 全部落在 `react-flow__pane`
   与节点名 `INPUT.name` 上，而 store / overlay / status 皆零。
   **成因未取证**，不硬解释；判据改为只断言已证的维度。
