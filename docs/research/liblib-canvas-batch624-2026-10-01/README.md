# Batch 624 —— 把普查从宽度推广到「宽度 × 开启态」，并第三次撞上同一个层叠陷阱

日期：2026-10-01 · 零源站断言

623 把普查从三个离散档拉成了 86 个宽度，但只扫了**基础态**。而普查至今抓到的每一个真缺陷，几乎都在**开启态**里：619 的窄屏导出面板被视口底条压死、620 的资产侧栏页脚收起钮被埋、618 的属性抽屉被顶栏盖住 —— 基础态扫描一个都看不见。所以本批把两个维度乘起来。

## 零源站断言

`probe616` 复跑：源站仍 1600×1000、导演台被他人关闭。

## 一、矩阵：45 格，挖出一个真缺陷

**10 个宽度**（390/620/768/850/898/899/900/1024/1440/1920）× **各宽度下存在的状态**。难点不在跑，在**状态对宽度的适用性**：

- rail 系浮层（全景图/画幅比例/添加角色/AI 识图）挂在资源栏上，而资源栏在 ≤898 是 `display:none` —— 在 500px 点它必然点不到，失败原因是**状态在那里不存在**，不是缺陷；
- 抽屉只在 ≤898 存在，≥899 时打开它们的按钮根本没渲染；
- 场景树右键菜单在窄屏要**先开树抽屉**才有锚点。

每格带适用性判据，不适用就记 `skipped` 而**不是报缺陷** —— 否则矩阵里一大半格子是假红。

结果：**45 格，5 格报缺陷，全部集中在 AI 识图导入模态**，且横跨所有桌面宽度：

```
 899 rail ai-import   2 条    900 rail ai-import   2 条    1024 rail ai-import  2 条
1440 rail ai-import   1 条   1920 rail ai-import   1 条
```

窄屏各态与其它五个状态**全绿**。

## 二、为什么 619 没报：视口高度不同

619 明确记过这个态是干净的（1920×1150，`attributed 36`、`covered 1`）。而矩阵用的是 1920×**900**。第一件事不是去修，而是把**视口高度**这个变量隔离出来（`/tmp/dbg624b.py`，同一宽度扫 844/900/968/1000/1062/1150）：

```
heights WITH defects:    [844, 900]
heights WITHOUT defects: [968, 1000, 1062, 1150]
```

干净利落。算术也对得上：模态**垂直居中**、539 高 → 占 `[(h−539)/2, (h+539)/2]`；时间线贴视口底、182 高 → 占 `[h−182, h]`。重叠条件 `(h+539)/2 > h−182` → **h < 903**。实测阈值与算术分毫不差。

所以这不是随机、不是时序，是**确定性的几何重叠**：视口一矮，模态的脚就伸进时间线地盘。

## 三、根因：模态被关在资源栏的 z-30 里（同一个陷阱第三次）

`/tmp/dbg624c.py` 逐层读祖先链，一眼看到：

```
0: div[data-director-ai-import-backdrop]  fixed  z=290   ← 模态自己的 z
1: div[data-director-icon-rail]           abs   z=30    ← 把它关在这里
2: div[data-director-workspace]           fixed  z=100
```

模态一直由 `DirectorIconRail` 渲染（它在资源栏那一层），而资源栏 `absolute z-30` **创建层叠上下文**。于是工作区这一层真正在比的是「资源栏 30」对「时间线 40」与「属性列 30」：

- 时间线 `z-40 > 30` → 整个资源栏子树（含 backdrop 与模态）被时间线压住；
- 属性列 `z-30` 与之同级、DOM 在后 → 同样压住。

**`z-[290]` 从未生效过**，它被关在了父亲的上下文里。这解释了全部观测：高度方向的缺陷来自时间线，宽度方向的缺陷（模态居中 560 宽，窄到右缘伸进属性列地盘，右上角关闭钮落进去）来自属性列。

这是本项目**第三次**遇到「子元素 z-index 被父级层叠上下文关住」：

| 批次 | 陷阱 | 抬的是 |
| --- | --- | --- |
| 611 | section 的 `backdrop-filter` 造出上下文 | section 自己 |
| 621 | 父级 flex item 的 `z-30` | 父级 |
| **624** | **组件被嵌在资源栏内** | **portal 出去** |

**修法**：照 `DirectorInspector.tsx:685` 的 `viewerLayer` 先例，`createPortal` 到 `document.body`，让 `z-290` 真的在工作区（`z-100`）之上生效。修后 `生成站位参考` 在 900×900 / 1920×900 / 1920×1150 三个视口下都命中自己。

## 四、验收里特意加的一条：结构断言而非几何断言

只断言「重叠处能点到」是不够的 —— 那只覆盖恰好重叠的视口。真正的回归判据是**结构**：「模态的祖先链里不得再出现资源栏」。所以 624 额外断言 `modalInRail === false` / `backdropInRail === false`，外加那枚曾被时间线埋掉的「生成站位参考」必须命中自己，三视口各一组。

## 验收脚本自己踩的坑：把格子数写成魔数

矩阵验收首版断言 `cells >= 50`，实际矩阵是 **45** 格（窄屏 5 宽度 × 3 态 + 桌面 5 宽度 × 6 态），于是唯一一条红是 `45 >= 50` 不成立 —— 缺陷全绿，栽在自己猜的数上。

改成**从 `states_for()` 推导**期望格数（`sum(len(states_for(w)) for w in WIDTHS)`）。这不是把阈值调小去迁就读数，而是让判据在状态或宽度增减时**不可能再漂** —— 魔数阈值在矩阵长大或缩小时总会变成一句谎言。

## 验收

- **矩阵 45 格**：不适用格记 skipped 而非失败；活格 ≥40；每格零 unexpected covered；每个开面板的态必须**被看见是开着的**（否则该格什么也没证明）。
- **陷阱三视口**（900×900 / 1920×900 / 1920×1150）：模态与 backdrop 都不在资源栏内；「生成站位参考」命中自己。

## 不声称
