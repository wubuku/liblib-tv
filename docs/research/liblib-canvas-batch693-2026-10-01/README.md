# batch 693 — **同一个控件，两个输入设备，两个不同的可达集**

> 起点：691/692 收在「位置面」上。几何普查里还有 6 条位置面没量，其中最值得量的
> 是 **FOV 滑块**：它是**原生 `range` 盖在自绘旋钮上** ——
> 浏览器和 clone 各自维护一套「值↔位置」映射。
>
> 验收：`scripts/verify-liblib-batch693.py`（6/6）　读数：`runtime-audit.json`

## 靶子为什么是它

`DirectorInspector.tsx:1638/1644`：

```js
const ratio = (fov - 15) / 75;                    // FOV_MIN=15, FOV_MAX=90
<div style={{ width: `${ratio * 100}%` }} />      // fill
<div style={{ left:  `${ratio * 100}%` }} />      // knob（自绘 12px 圆点）
<input type="range" min={15} max={90} step={1} className="… opacity-0" />
```

跨度 **75 不是 2 的幂** ⟹ 整数 FOV 也给出分数百分比 ——
691 那条「整数入、小数出」的**第三个运算符变体**（先减、后除）。

## ① 鼠标逐 1px 扫 170 档：点击只能得到 **20 个值**

`step="1"` 声明了 **76** 个值（15..90）。实测可达集合：

```
15, 19, 23, 27, 31, 35, 39, 43, 47, 51, 55, 59, 63, 67, 71, 75, 79, 83, 87, 90
```

相邻差恒为 **4**（末段 87→90 是 3）。**中间 56 个值点击永远到不了。**

平台跨度：首平台 **16px**（offset 0..15 全给 15）、中间 **8 或 9px**、末平台 **6px**。

## ② 决定性实验：键盘给出**每一个整数**

**同一个 `input` 元素**，键盘序列：

```
Home→15, ArrowRight×24 → 16, 17, 18, …, 39,  End→90
```

**逐 1 递增，一个不落。**

| 输入方式 | 可达集 |
|---|---|
| 鼠标点击滑杆 | **20 个值**（步长 4） |
| 键盘（同控件） | **全部 76 个整数** |
| 旁边数值框 | 接受 `[15,90]` 内任意值 —— 实测 `44 → 44` ✓ |

**44 落在 43 与 47 两个平台之间，任何点击都给不出它**；而键盘和数值框都能。

⟹ **同一个 FOV 值，三条设置路径给出三个不同的可达集，界面上没有任何地方说明。**

**与 688 的区别（不是复读）**：688 记的是「声明量程 88..420 只在窗高 ≥508 时真的可达」
—— 可达集是**窗口**的函数。本批可达集是**输入设备**的函数，而 170 个样本里
**视口一个像素都没变**。两者不能互相推出。

## ③ 量化在控件不在 store

| 读数 | |
|---|---|
| `input.value` 与 `store.fov` 一致 | **170 / 170** |
| 关键帧数 前 → 后 | **6 → 6** |

⟹ 「store 把 fov 取整了」这个替代解释**被读数排除**，不是被推理排除。
顺带确认这次 170 次改动**没有把项目写脏**：`recordObjectKeyframe` 是
**upsert 到当前播放头**，同一时刻 170 次替换同一个关键帧，轨道不增长。

## ④ 自绘旋钮**追不上指针**，最大 15px

旋钮画在 `ratio × 170`，浏览器自己的 thumb 两端有内缩 ⟹ 画出来的位置在左半边
**落在指针后面**、右半边**跑到指针前面**：

| | |
|---|---|
| 误差区间 | **[−15, +7.19] px** |
| 最差样本 | offset 15、值 15、旋钮画在 offset 0 ⟹ **落后 15px** |
| 该容器边框 | **实测 `borderLeft=0` `borderRight=0`** |

⟹ **691/692 那条 border-box 机制在这里被排除**（这个容器没有边框）。
**长得几乎一样的控件，机制不同，误差大一个数量级**（姿态垫 1px，这里 15px）。

**不声称** thumb 内缩是成因 —— **thumb 宽度没有被量到**，那仍是推断。
本批只主张两个读数：点击可达 20 个值、旋钮错位 ≤15px。

## 自记

- **探针整整扫空了一轮**：第一版没滚进视口。FOV 字段初始在 **y≈1150** 而视口只有
  900 高，`page.mouse.click` **不会自动滚动**（只有 `locator.click` 会）⟹
  170 次点击**全落在视口外**，value 恒为 43，误差区间假到 **[−105, +63]**。
  **一个假到离谱的误差区间本身就是信号** —— 读数大到不合理时先怀疑仪器。
  修法：`scroll_into_view_if_needed()` + **断言中线在视口内**。
- **`node -e` 走的是 TS 解析**：`x.inputValue!cur.v` 里的 `!` 被当成非空断言
  （`Expected ')', got 'cur'`）。`-e` 里避开 `!`，或干脆写文件。
