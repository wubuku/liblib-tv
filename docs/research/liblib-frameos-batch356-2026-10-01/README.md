# Batch 356 — 7 个「呈现为可点、实则毫无反应」的按钮

日期：2026-10-01
范围：`FrameosMaterialLibrary.tsx`、`FrameosPromptEditor.tsx`
性质：**CLONE_DECISION**（克隆侧缺陷；不改几何/尺寸/圆角/位置/文案）

---

## 缺陷

Batch 347 审的是「**缺钩子**」（能不能被测试寻址）。本批审它的行为孪生：
「**点了有没有反应**」。

静态普查 frameos 全部 `<button>` 找**没有任何 `onClick`** 的，逐个人工核实后
确认 **7 个**是真缺陷：

| 位置 | 按钮 | 原样貌 |
|---|---|---|
| FrameosMaterialLibrary | 收藏筛选 / 创建者筛选 / 创建时间排序 | 灰底 + `cursor: pointer` |
| FrameosMaterialLibrary | 批量操作 | 描边 + `cursor: pointer` |
| FrameosMaterialLibrary | **+ 本地上传** | **蓝色主按钮** + `cursor: pointer` |
| FrameosPromptEditor | **生成音频**（¥100） | **实心蓝圆形主按钮** |
| FrameosPromptEditor | **生成视频**（¥300） | **实心蓝圆形主按钮** |

**越像「主行动」的越糟**：两个「生成」按钮是各自面板里最醒目的实心蓝圆钮，
`+ 本地上传` 是素材库那一行里唯一的蓝色按钮 —— 点了全都毫无反应，
连一条提示都没有。

### 普查本身有误报（所以必须人工核实）

普查初版报 8 个，其中 `FrameosGroupToolbar` 的排列菜单项是**误报** ——
它其实有 `onClick`（`arrangeGroup`），只是落在我的正则窗口之外。

> 普查工具的假阳性会把**真按钮**标成「该修的」，进而诱导改动正常代码。
> Batch 352 的死状态普查已经吃过一次（5 类误报），这里再次印证：
> **普查结果必须逐个核实，不能直接照单修**。

## 修复：不是「让它能用」，是「别假装它能用」

两条路可选：① 接线到真实行为；② 让它看起来就不可点。

选 ②，理由是不发明：源站这些交互**未采样**；而「生成」是**付费动作**（¥100/¥300），
按源站纪律**绝不触发**。凭空虚构一套上传/生成流程比留一个诚实的禁用态更糟。

按**本仓库既有的「惰性控件」约定**（见 `FrameosGroupToolbar` 的「整组执行」：
`cursor: default` + 暗色）统一处理：

- 加 `disabled`（语义正确：没有行为的按钮就应该是 disabled）
- 加 `title` 说明原因（「未接入（源站交互未采样）」/「未接入（付费动作…）」）
- 降饱和 + `cursor: default`
- **几何、尺寸、圆角、位置、文案一律不动**

## 变成门禁

`scripts/verify-frameos-batch356.py`（**34 项检查，0 诊断**）在 4 种 UI 态
（默认 / 素材库 / 音频面板 / 视频面板）枚举所有按钮，判据是
**「计算样式 `cursor: pointer`」且「未被 disabled」且「React props 里没有 onClick」**——
即「呈现为可点、实则毫无反应」。

另钉住：7 个目标确实 `disabled`、确实带说明、**付费按钮没有被接线**（回归防护）、
**几何未被动过**（32×32）。

## 写验证器时踩的四个坑（都是探针自己的问题，不是产品问题）

1. **同名按钮张冠李戴**：「本地上传」有两个 —— 素材库里那个是假按钮（本批修），
   工具条上那个是 `onClick={openFilePicker}` 的**真**按钮（不能动）。
   早期版本只用 `aria || text` 匹配，结果把**真按钮**当成目标、报「又变回可点」。
   → 目标识别必须带**所在对话框作用域**。

2. **装饰前缀**：素材库按钮的文本是「**+** 本地上传」，匹配前需归一化。

3. **进不去视频面板**：fixture 的 `video-1` **带 `imageUrl`**，按 Batch 225
   （源站实测）「内容媒体节点无面板」会被 `FrameosPromptEditor` 的早退分支排除。
   必须注入一个**无内容**的视频节点。

4. **自己污染 `diagnostics:zero`**：验证器会多次注入面板节点，固定 id 造成
   React 重复 key 报错。→ 注入 id 必须唯一，且 `selectNode` 要用**同一次
   evaluate 内捕获的**那个 id（我第一次拼成了 `Date.now()` 而 selectNode
   用了 `nodes.length`，两者对不上）。

> 第 4 条是本会话**第六次**因「先看失败在哪一步」而避免误改应用代码。

## 保真度差距

- 素材库的三颗筛选芯片在源站是**真能筛的**（代码注释写「静态展示」是照 2026-09-25
  采样复刻的静态形态）。本批只让它们**看起来不可点**，没有实现筛选。
- 「+ 本地上传」「生成音频」「生成视频」在源站都是真功能，克隆未实现，
  本批同样只处理外观。
- 三者的真实行为都**依赖源站采样或产品决定**，不在本批内发明。
