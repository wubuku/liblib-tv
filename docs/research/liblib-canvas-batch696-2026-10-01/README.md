# batch 696 — 把「成因未定位」的假读数，钉到一个可复现的序列上

> 起点：695 撞到一次**读数是假的**却长得完全像真读数的事故
> （五枚 scene 控件稳定报「96px 轨道鼠标只能到 1 个值」，K 退化成
> **96.0 —— 恰好等于轨道宽度本身**）。695 当时只能确定「差异在『上一阶段做过什么』」，
> **成因未定位**。
>
> 验收：`scripts/verify-liblib-batch696.py`　读数：`runtime-audit.json`

## ① 先看被排除掉的（每一条都留下了读数）

| 怀疑 | 怎么查的 | 结果 |
|---|---|---|
| 控件被 `disabled` / `readOnly` | 读 DOM 属性 | ❌ `false` / `false` |
| 被别的层压住 | `elementsFromPoint` 五点采样 | ❌ 五点全部命中自身 |
| 祖先 `overflow` 裁剪 / `transform` | 逐级祖先链 | ❌ 全 `visible`，无 transform |
| 指针落在视口外（693 的老坑） | 命中校验 | ❌ `inViewport = true` |
| 只露出一部分 | 5 点命中校验 + 找滚动祖先 | ❌ 五点全中 |
| 读数时元素还在动 | 逐字相同的探针稳定给 11 | ❌ |
| dev server 重编译 | `src/` 干净 + 日志无痕迹 | ❌ 稳定复现 |
| 一次瞬态 | 原地重扫一次 | ❌ 第二次照样 1 |
| 焦点没落上去 | 读 `document.activeElement` | ❌ `INPUT/range SELF` |
| 键盘能改、鼠标不行 | 读 Home/End/6×Arrow 八个值 | ❌ 八个全是同一个值 |
| 滚动位置漂了 | 按键后显式滚回控件 | ❌ 无效 |
| Playwright 的鼠标状态坏了 | 改用显式 `move` + `down` + `up` | ❌ 结果一致 |

**十二条排除之后，剩下的唯一变量是「有没有按过键」。**

## ② 第一张表：唯一变量是键盘

同一条代码路径、同一枚 `scene-scale`（96px 轨道）：

| 姿态阶段做了什么 | **scene 鼠标可达** |
|---|---|
| 不测姿态控件 | **11** |
| 3 枚 / 滚动 + 点击 + 键盘 | 1 |
| 3 枚 / **无键盘** | 1 |
| 3 枚 / **无滚动** | 1 |
| 3 枚 / **全无**（无滚动无键盘） | **11** |
| 3 枚 / 每枚只点 20 次 | 1 |
| **1 枚** / 滚动 + 点击 + 键盘 | 1 |
| **1 枚** / **无键盘** | **11** |

最后两行是本批最干净的一对：**唯一的差别就是有没有按键，11 ↔ 1。**

## ③ 第二张表：不是 `focus`，不是某一个键，不是时间

| 变体 | **scene** |
|---|---|
| `focus()` 但**不按任何键** | **11** |
| `focus()` + `End` | 1 |
| `focus()` + `Home` | 1 |
| `focus()` + `ArrowRight`×2 | 1 |
| `focus()` + `ArrowDown` | 1 |
| 按 `End` 后等 **0 / 300 / 1000 / 2000** ms | 1 / 1 / 1 / 1 |

**任意一个键等价，四个等待点全部无效。** 我第一反应是「等一会儿就settle 了」——
**这个反应被自己的读数推翻了**，而且是四个不同等待长度一起推翻的。
如果当时只试了一个等待点，很容易「修好」然后在第五次运行时失效。

## ④ 第三张表（本批最锋利的一张）：恢复手段要分「可靠」和「不可靠」

失效之后，试图恢复它：

| 尝试 | **scene** | 可靠吗 |
|---|---|---|
| 什么都不做 | 1 | — |
| 等 300 / 1000 / 2000 ms | 1 / 1 / 1 | ✅ **稳定无效** |
| **在出事的那个面板**（pose）上点 1 次 | **1 或 11** | ❌ **不可靠** |
| 在出事的那个面板上点 5 次 | **1 或 11** | ❌ **不可靠** |
| **在时间轴的 `timeline-zoom` 上点 5 次** | **11** | ✅ **稳定有效** |
| 重新开一个页面 | **11** | ✅ **稳定有效**（= 695 的修法） |

**「在同一个面板上点」这一格，是我这一批跑出来的最难看的一格。**
上一轮同样的实验（`dbg696h`）里，点 1 次和点 5 次**都是 1**；
这一轮**都是 11**。**同一个操作，两次运行给出相反答案。**

⟹ 所以诚实的说法不是「同一面板救不了自己」，而是
**「在同一面板上点击不是可靠的恢复手段 —— 它有时有效」。**
把这两句混成一句，就把一条**下一位读者会当成定论**的规则写进账本了。

**验收器因此对这一格测了三次**（`repeats`），判据说清楚：
三个样本全相同才算通过 —— **不一致就如实记成不一致**。

**两条稳定有效的恢复才是有承重作用的**：
**另一个面板的 range**，和**重新开页面**（695 用的就是后者）。

**顺带排除了两个很自然但错的猜测**：
- 「多点几下就好了」—— 同一面板点 5 次**时灵时不灵**；
- 「面板里有东西被盖住了」—— 如果是被盖住，在同一面板点任何位置都该有用，
  而**真正稳定有效的是「另一个面板」**。

## ⑤ 结论：一个**行为序列**，不是一个**机制**

> **在右栏的 range 上按过一次键盘键之后，紧接着切换到另一个面板，
> 新面板里的 range 收不到鼠标输入。**

**这仍然没有追到源码的那一行。** 所以 695 的「成因未定位」被替换成
**「已定位到一个具体序列、机制未追」** —— 这两者的区别不丢掉，
因为**序列能指导验收器，机制才能指导修复**。

**而且必须记下这个序列的「可靠边界」**：

| 事实 | 强度 |
|---|---|
| 失效本身（对照 11 / 实验 1） | **每轮都复现** |
| 时间恢复不了它（4 个等待点） | **每轮都复现** |
| 另一个面板的 range 能恢复它 | **每轮都复现** |
| 重新开页面能恢复它（695 的修法） | **每轮都复现** |
| **在同一个面板上点击能恢复它** | **两轮给出相反答案** ⚠️ |

**最后一行是本批最重要的一条「反例」**：一条**在两轮里翻转**的行为，
只能被写成**更弱的事实**（「不可靠」），不能写成「无效」——
否则下一位读者会把一条会翻转的规则当成定论。

> 这里的「两轮」指**两次独立的实验运行**（先前的 `dbg696h` 探针给 1/1，
> 本批验收器给 11/11），
> **不是**验收器内部那三次重复 —— 验收器内部三次是一致的，
> 而「跨轮不一致」是它**测不到**的（要测就得把上一轮的输出当输入），
> 所以只记在 README 与账本里，**不塞进判据名**。

**还有一条必须说清的限制**：695 复现走的是 `selectObject(null)` 这个
**store API**，而真人取消选中是「**点空白处**」。两者是否等价**我没有取证**，
因此 **不声称这是一个用户能撞上的缺陷** —— 只声称「在我的复现路径上存在」。

## ⑥ 对 695 的意义

695 的修法是「**每个阶段开独立页面**」。本批的第 5 条判据专门确认：
**那个修法确实消除了这个条件**（不是把它藏起来了）——
重新开页后读数回到 11，与干净会话逐位一致。

**695 那句「成因未定位，如实记」没有被撤销**；
本批只是把「不知道是什么」换成了「知道是哪一串操作」。

## 自记

- **排除法比猜测贵，但比猜错便宜。** 十二条排除花了七轮跑，
  而每一轮都在缩小范围；反过来，如果我先去猜「可能是 overlay」
  再去证，会浪费同样多的时间却得不到一张可复用的分类表。
- **「等一会儿就好了」是最容易自我说服的错觉。** 四个等待长度一起测，
  才让它站不住 —— 而只测一个长度的话，我几乎必然会「修好」它。
- **对照组和实验组必须只差一个动作。** 第一张表最后两行之所以干净，
  是因为「1 枚 / 全套」和「1 枚 / 无键盘」之间**只差一个按键**。
  695 当时的二分（测不测姿态族）差了太多动作，定位不到这一步。
- **恢复手段的分类比「能不能恢复」信息量大得多。**
  「换个页面能恢复」是废话；「**同一面板救不了自己，另一个面板能**」才是机制线索。
- **测试自身写错要当信号读** —— 696 的探针第一版把 `focus()` 写在了
  切换面板之后，结果 pose 控件已经卸载、`focus()` 等满 30 秒超时。
  **「等满超时」又一次是第三态而不是错误。**
- **判据名必须说它实际断言的东西。** 判据 3 一度叫「同一面板的恢复不可靠」，
  而它实际断言的只是「**本轮**三次重复给同一个数」——
  **跨轮不可靠是元观察，验收器测不到**（要测就得把上一轮的输出当输入）。
  把它塞进判据名，等于宣称一个仪器没有的能力。
- **遇到判据 FAIL，先问「读数打架了还是判据错了」。** 这两种要分开记：
  本批判据 3 第一次 FAIL，而**那个 FAIL 就是发现本身**
  （同一个操作在两轮里给出相反答案），不是需要「修好」的缺陷。

## 不声称

- **不声称** 追到了机制（**这是一个行为序列，不是一行源码**）；
- **不声称** 真实用户路径等价于脚本路径 ⟹ **不声称这是一个用户可见的缺陷**；
- **不声称** 源站有同样行为（**未取证**；源站导演台关着，进入需点击、**需授权**）；
- **不声称** 「另一个面板的 range 能恢复」这条路径是**唯一**的恢复途径
  （本批只测了这几种）；
- **不改 `src/`**。
