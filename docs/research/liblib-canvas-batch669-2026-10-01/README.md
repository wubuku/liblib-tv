# batch 669 —— 把 668 的两条发现做成普查，并问它们**泛不泛**

## 一句话

668 钉下两件事，都**只在一处**量到。本批把各推成一次普查，
外加一句本该早点问的话：**那 1.0px 是普遍现象，还是只在检视器那两枚上？**

**答案是：不泛。** 21 行读数里 `leftGap` 只取三个值 **`0 / 0.48 / 0.98`** ——
668 的 `0.98` 是其中之一，**不是常数**。而**「命中宽度 ≠ rect 宽度」才泛**
（15/21 行差 > 0.9px）。

## 1. 同盒普查：**26 组 / 4 组 pe 混杂**，三视口逐格相同

按盒分组（零尺寸不参与 —— 665 记过的盲区），三个视口
`1280×1150 / 1440×1150 / 1920×1150` 的读数**完全一致**，
连「成员 ident + pe」的多重集合指纹都逐字相同。

**130 枚控件**这个人口与 **617 报的 `total=130`** 逐位吻合（跨批复核）。

26 组里 **4 组同时含 `pe:auto` 与 `pe:none`**：

| 组 | 盒（1280 宽） | 成员 | 谁 |
|---|---|---|---|
| 视口格 | `[281, 88, 718, 880]` | 6：3 auto（`main` / `section` / **`div.absolute.inset-0`**）+ 2 无 class `none` + 1 `none` canvas | **668** |
| **视口右上 gizmo** | `[899, 108, 80, 80]` | 6：**`div.absolute.right-5.top-5.z-20`**（= `data-director-viewport-gizmo`）+ 1 `pe:none` 且**有 class** 的 `pointer-events-none.absolute.inset-0.drop-shadow-…` + 2 无 class `none` + 1 `none` canvas + 1 `div.absolute.inset-0.pointer-events-auto` | **没有 —— 本批新记的一处** |
| 时间轴对象行 ×2 | `[0, 1041/1105, 320, 32]` | 2：`group.relative.grid.h-8` + `pointer-events-none.absolute.inset-x-0.inset-y-0` | **667 已命名** |

所以 **668 的形状在全表里只多出一处未命名的实例，就是那个 gizmo**
（`DirectorViewport.tsx:384-388`，`aria-label="3D视口原生坐标控件"`）。
它里面的 `pe:none` 成员有 **2 枚无 class 的 div + 1 枚 canvas** ——
正是 664 记的「13 个不带任何 `data-director` 属性」那批的成员。

## 2. 半像素中心普查：**60 / 130**（46%），三视口逐格相同

| 量 | 1280 | 1440 | 1920 |
|---|---|---|---|
| 控件总数 | 130 | 130 | 130 |
| 中心**不落在整数**上 | **60** | **60** | **60** |
| 中心正好在 `.5` 上 | 52 | 52 | 52 |

小数部分的分布在三个视口**逐格相同**：`0/0.5` ×21、`0.5/0` ×20、
`0.5/0.5` ×4、`0.16/0.5` ×2、`0.44/0.5` ×2、`0.13/0.5` ×2、
`0/0.25` ×2，其余各 1。**宽度一个都没动** —— 变的只有 x，y 那一项是恒的。

**所以 668 那 1.0px 的修正不是边角情形**：只要拿 rect 边去推可点性，
**接近一半的人口**都可能落在错的一侧。

## 3. 那 1.0px 泛不泛（本批的主要否证机会）

对 4 个混杂组里全部 21 行 `pe:auto` 成员，0.02px 步长扫各自 rect 的左右沿
（`pe:none` 成员不扫 —— 那是原理不是读数）。

| `leftGap` | 行数 | 出自 |
|---|---|---|
| **0** | 9 | 视口格的 3 枚 auto × 3 视口 |
| **0.48** | 6 | 时间轴对象行 ×2 × 3 视口 |
| **0.98** | 6 | **gizmo 的 2 枚 auto × 3 视口** |

`rightGap` 只有两个值：**0.02**（gizmo + 时间轴行）与 **1**（视口格）。
`hitWidth − rectWidth ∈ {−1, +0.46, +0.96}`。

**三条结论，每一条都与 668 的说法有出入，必须写清楚：**

1. **「左沿差 ≈1.0px」不泛。** 它出现在 **gizmo** 上，**不在 668 自己的起点
   （视口格）上** —— 视口格那 3 枚的 `leftGap` 是 **0**，即它们的命中区
   从 rect 左沿就开始。
2. **668 量的那对（检视器 `section` / `column`）根本不在这次普查里** ——
   它们**没有同盒的 `pe:none` 兄弟**，所以按「同盒组」筛是筛不到它们的。
   **668 的 0.98 没有被本推翻，也没能被本推广**：它仍然是那两枚的读数，
   而本批给出的是「同一现象还出现在 gizmo 上、且不是常数」。
3. **真正泛的是「命中宽度 ≠ rect 宽度」**：**15/21 行**差 > 0.9px。
   方向还不统一 —— 视口格是**窄了 1px**，gizmo 和时间轴行是**宽了近 1px**。

**不声称**这三种差值各自的成因；不声称 gizmo 在源站是否有对应物；
不声称「命中宽度差 > 0.9px」就一定改变某个具体控件的判定
（那要逐控件问，本批没问）。

## 4. 本批自己犯的错

1. **第一版把「同盒组」当成普查的全部单位**，差点把 668 那对检视器元素
   判成「不存在」—— 是**它们不属于任何同盒组**，不是差值不存在。
   幸好看的是「1px 行数 < 总行数」而不是「1px 行数 = 2」，否证才没翻车。
2. `fp` 的值是 list 塞进 `set` → `TypeError: unhashable type: 'list'`。
3. 探针与验收器对「半像素」用了**不同的窗口**（探针 `[0.25, 0.75]`、
   验收器「非整数」）⟹ 探针报 58、验收器报 60。**以验收器为准**，
   README 里的数字全部取自验收器载荷。
