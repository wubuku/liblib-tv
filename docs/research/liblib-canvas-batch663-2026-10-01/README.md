# batch 663 —— 竞争面集合的两种口径，以及第三种读法：**仪器必须拒绝作答**

## 一句话

626 判「浮层有没有被谁压住」靠一份**手写的 6 项面板名单**。
用 662 的地面真值把「谁画在这个浮层之上」直接量出来之后：
名单在 27 格上不多报、**漏掉 1 个真竞争面**（但那个洞没有伤亡），
而在另外 3 格上**仪器自己测不了** —— 而它**没有失败，它自信地答了**。

## 1. 两种口径

| 口径 | 做法 |
|---|---|
| **626 手写名单** | 一份全局的 6 项猜测（timeline / inspector / tree / rail / viewport / workspace），**从不量、也从不是逐浮层的** |
| **662 派生集合** | 对每个浮层，在它自己盒子的 5×5 晶格上取命中栈，**凡排在浮层之前（即画在它之上）的元素**，再取反链极小化 |

33 格（11 浮层 × 3 视口）分布：**27 空 / 3 非空 / 3 不可测**。

## 2. 名单不多报 —— 但这是最弱的一致

27 个派生集为空的格上，626 的 `structBad` **也都是空**。

**但必须把话说准**：一份「短到永远不会触发」的名单和一个正确的名单，
**在空集上长得一模一样**。所以这一节只主张「**不多报**」，
**不主张「够用」**。真正的检验是下一节。

## 3. 名单漏掉的那一个 —— 以及它**没有**造成伤亡

`camera-preset-panel` 在 3 个视口上都有一个**真实**的竞争面：

```
div.pointer-events-auto.flex.w-full.overflow-x-auto
  @1280x720  rect [293, 490, 694, 48]   与面板重叠 304 × 48 px
  z-index: auto   position: static   不在 626 的 6 项名单里
  ⟹ 626 的 structBad = 0
```

那个 48px 横滚宿主在 W=1280 时宽 **694** —— 正是 **659/660** 收过闭式的
那条**场景提示条宿主**。同一个容器，隔了三个批次从另一个方向被量到。

**但这不改变 626 的判定**：626 自己的 audit 记着该浮层
**`liveCount=10 / blocked=[]`**（三个视口都是）——
**重叠的 48px 带里没有活控件**，那是面板的留白。

> 所以本批的结论是**归因不全**，**不是**「626 漏报缺陷」。
> 626 在 33 格里**判定全对**，缺的是解释。

## 4. 第 9 个盲区形状：**仪器自信地回答它看不见的问题**

`camera-fov-help-tooltip` 的 className 里明写 `pointer-events-none`
（`src/components/director/DirectorInspector.tsx:1621`）。

**`pointer-events:none` 的元素永远不会被 `elementsFromPoint` 返回**，
无论它画在哪一层。于是：

```
可命中性读数  selfHits = 0/25     （25 个采样点没有一点是它自己）
第一版派生仪器  「栈里在它前面的元素」= 「盖住它的东西」
             ⟹ 凭空造出 2–3 个竞争面
```

**那其实只是「那个位置本来有什么」。** 639 / 641 / 646 都记过
`elementsFromPoint` 在 `pointer-events:none` 上有盲区 ——
**没有人写下它的后果**：建在它上面的仪器**不会失败，它会作答**。

### 独立否证（不靠命中栈）

伪造出来的那两个，在 1920×1150 上是
`section[data-director-shot-inspector]`（重叠 64px）与 `main`（重叠 68px）。
而提示条的**祖先链**是

```
camera-fov-help-tooltip → camera-fov-help → camera-fov-field
  → section[data-director-inspector][data-director-inspector-kind=camera]
  → data-director-mobile-panel-state → data-director-workspace
```

**两个都不在祖先链上**（`containsOverlay: false`）——
它们是同一列的**兄弟 section**，盒与提示条纵向重叠而已。
而提示条 **`z-index: 1700`**，它们是 **`auto`**（`camera-preview` 是 20）——
**提示条画在它们之上**。命中栈只是因为跳过它，才把它们露了出来。

> **z 序在这里不是替代口径，是唯一的否证路径** ——
> 命中栈在这个格上失效了，得由另一条独立的路把结论钉死。

### 于是仪器长出第四种状态

```
missing · zero-sized · not-measurable · measured-empty · measured-nonempty
```

**「测不了」与「量到空集」必须分开。** 把拒绝报成空集，
就是 656 记的「抛错探针被读成否定」的**镜像**：
那次是仪器把「不知道」报成「否定」，这次是把「不知道」报成「知道」。

## 5. 标定

* **阳性**：27 格派生集为空 ⟺ 626 `structBad` 为空（两套独立实现）。
* **拒绝**：3 格 `pointer-events:none` ⟹ `not-measurable`。
* **跨批复现**：本批从零重开 11 个浮层 × 3 视口，读到的 **33 个浮层盒
  与 626 自己 audit 里的 33 个 `box` 逐位相同**。
* **setup 重试**：首跑有 2 格因 4317 共享而超时；照 626 的先例
  **只重试 setup、绝不重试断言**，重跑后 **0 errored** ——
  反过来证明那 2 格是 infra 抖动、不是判据红。

## 7. 本批**不**主张的事

* **零源站断言** —— 源站有没有这些重叠**未取证**，**未改任何 `src/`**。
* **不主张 626 判错了** —— 它的**判定**在 33 格里全对；缺的只是**归因**。
* **不主张该删掉 626 的 `PANELS`** —— **迁移合同而非删除被测行为**：
  本批只**记录**派生集合与那一个洞，**不动那份名单**。
* **不主张**提示条与兄弟 section 的重叠是缺陷 —— 那是**产品决定**。
* **不主张** z 序比较能替代命中栈 —— 本批的结论恰恰是命中栈在
  `pointer-events:none` 上失效，z 比较只用来**否证**伪造出来的集合。
* **第 2 节的一致是弱证据**，本批只据它主张「不多报」。

## 8. 我自己写错的地方

1. **首跑 3/5 红，两处都是我把读数之外的数字写死** ——
   断言 `len(agree) == 30` 和 `len(box_cmp) == 33`，而实测是 28 和 31。
   **与 660/634/638 同一个错误**：把某个 regime 的数当普适值。
   改法是**从读数推**（`not disagree and not errored`），
   并把「实测多少」放进 detail 而不是条件里。
2. **「一致」这件事我第一版主张过头了** ——
   我本来想写「手写名单不多报也不少报」，**那 3 格非空的反例就在数据里**，
   是我把「非空」当成了「不一致」而没看见它正是下一节的主题。
   改成第一节只主张「不多报」，并把「短名单与正确名单在空集上同形」写进 note。
3. **`AUDIT_DIR` 用了字符串的 `.parent`**（当场 `AttributeError` 崩掉），
   同一批里第二次犯**没先读自己写的路径表达式**的错。
4. **第一版仪器没有闸门** —— 它在 `pointer-events:none` 上**作答了**。
   这条不是「我写错了」，是**仪器设计漏了一步**；修正就是加 `not-measurable`。
