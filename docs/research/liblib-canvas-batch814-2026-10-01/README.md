# batch 814 —— 重复产物：能撤干净，但**长得一模一样**

> 813 量到重复产物会真的建出来，并留下三条没测。本批测前两条 + 累积量。
>
> - **能撤干净**：连建 4 份之后，**一次 `Cmd+Z`** 就回到「少一份」的精确状态
>   （节点数 + 边数 + 历史长度三件同时）。
> - ★ **分辨不出**：同一 kind 的多份产物，**DOM 可见文本逐字相同** ——
>   画布上出现几个一模一样的节点，**没有任何线索**告诉用户自己点了几次。
> - **能积几份**：逐帧拉片 4 份、智能续写 3 份、音视频分离 6 份（每次两个）；
>   而被守卫拦住的去字幕**停在 1 份**。

## 一、读数（两轮逐位相同）

| 臂 | 连点次数 | 逐次节点数 | 一共建了几份 | 按 kind 分组（已排除选中） | 撤一次回到少一份 |
| --- | --- | --- | --- | --- | --- |
| 逐帧拉片 | 4 | 10→11→12→13→**14** | **4** | `shot-breakdown`: 1 种 | **是** |
| 智能续写 | 3 | 10→11→12→**13** | **3** | `video`: 1 种 | **是** |
| 音视频分离 | 3 | 10→12→14→**16** | **6** | `audio`: 1 种、`video`: 1 种 | **是** |
| **去字幕（对照组）** | 3 | 10→11→**11→11** | **1** | `video`: 1 种 | — |

★ **对照组是关键**：没有它，「能积 4 份」可能只是「每个动作都这样」，
而不是「那三个没防重」。实测去字幕**停在 1 份**，正是 813 说的指纹去重（`:1970`）。

★ **撤销的读数**（逐帧拉片那一臂）：全部建完 `14 节点 / 15 边 / 历史 4`
⟹ 期望回到少一份 `13 / 14` ⟹ **按一次 `Cmd+Z` 得到 `13 / 14 / 历史 3`**，
**三件同时**。

## 二、★ 最有分量的一条：重复产物**逐字相同**

四份逐帧拉片节点的 **DOM 可见文本**：

```
逐帧拉片 · 分镜视频-#9逐帧拉片SD 2.5视频素材00:30 · 1280×720拆解维度分镜动态音乐开始拉片
```

**四份完全一样**，一个字符都不差。智能续写、音视频分离同样。

⟹ ★ 用户在画布上看到的是**几个一模一样的节点**，**没有任何线索**告诉他
「我刚才点了几次」「这个是不是刚建的那个」。

★ 判据只读 **DOM 可见文本**（808 立的纪律：能读 DOM 就不只读 store）。

## 三、★★ 判据上我踩的两个坑（都是**假红**）

第一次跑，基线直接判红。查下去发现两次都是**判据写错**，不是被测代码错：

| # | 现象 | 真因 |
| --- | --- | --- |
| 序1 | S1 判红：`audio` 一共建了 **6** 份、但只有 **3** 次点击 | ★ 我把「总份数」写成了「点击次数」—— `audio` **一次建两个**（音轨 + 无声）⟹ 正确判据是「总量 == **每次新建数之和**」 |
| 序2 | S3 判红：`audio` 出现 **2** 种文本、`continuation` 出现 **2** 种 | ★ 判据写成「整条臂只应有一种文本」⟹ ① `audio` 一次建**两个 kind**，它们文本**本来就该不同**；② `continuation` 第 3 份多出一大截 —— 真因是**它正被选中**、编辑器面板展开、`textContent` 把面板文字吃了进去，**那不是节点身份的差异** |

⟹ 修法：**按 kind 分组 + 排除选中态**。修完之后每个 kind 都只有一种文本，
「重复产物逐字相同」这条**才真正成立**。

★ 这已经是 808—814 连续第七次「基线红 ⟹ 先怀疑判据」。三次假红全在
**分组口径**和**总量口径**上 —— 这两类错误**不会让判据变松**，
只会让它误报，而**基线会把误报抓出来**。

## 四、探针返工一处

第一版只记 `textContent`，导致上面序2 的两个假红。修法：同一次读数里
**同时**记下每个节点的 `type` 与 `selected`，让判据能按 kind 分组、排除选中态。

## 五、验收结果

主检查 **5/5**，阴性对照 **7/7**，raw 的 sha256 未变（对照全是**纯内存**变异）。

| 阴性对照 | 打在哪个字段上 | 翻红 |
| --- | --- | --- |
| N1 | ★ 伪造「撤销只掉了节点、边还留着」 | S2 |
| N3 | 伪造「可见文本读不到」 | S3 |
| N4 | ★ 伪造「同 kind 的多份产物文本各不相同」 | S3 |
| N5 | ★ 伪造「只有一个 kind 重复出现过」 | S3 |
| N6 | ★ 伪造「对照组也累积了」 | S4 |
| N7 | ★ 伪造「中间某一次没建出来」 | S1 |
| N8 | 反向对照：只动 `secs` 这个无关字段 | 无 |

★ **N5 不可省**：「每个 kind 只有一种文本」在「每个 kind 都只出现过一次」时
是**恒真**的 ⟹ 必须显式要求「至少有一个 kind 出现过两次以上」。

★ **N1 也不可省**：判据要求节点数 + 边数 + 历史**三件同时**，
「只掉了节点、边还留着」这种半截状态必须被抓住。

## 六、不声称

- ★ **「重复产物该不该有」是产品决策**。源站允不允许对同一个视频反复拉片／
  反复续写？**没有源站依据** ⟹ 记为**阻塞在源站对照，不发明**。
  ★ 「重复产物**长得一样**、用户分辨不出」这条读数**不依赖那个决策**，
  它在「允许多份」的前提下**依然是问题**（用户仍然不知道哪份是哪份）。
- ★ **只测了 4 / 3 / 3 次**。**能不能积到几十份**（画布会不会卡、
  历史栈会不会满 `MAX_HISTORY`）**未测**。
- ★ **只测了「撤销一次」**。**连续撤销能不能把四份全部干净撤掉**
  （尤其撤销到 0 份时状态对不对）**未测**。
- ★ **「用户分辨不出」只比了节点卡内的文本**。
  **位置**（四份是不是排成一排等距）、**缩略图**、**连线**、**创建时间**
  有没有区分性，**本批没测** ⟹ 也不能说「完全没有任何线索」。
- ★ **只测了逐帧拉片／智能续写／音视频分离这三个**。
  813 说它们「不防重」，但**第四、第五个**动作（首帧两个芯片、
  `completeShotBreakdown`）的**累积行为本批没测**。
- ★ **`createSubtitleErase` 换区域再提交**（不同指纹）**未测** ⟹
  「停在 1 份」只对**完全相同**的请求成立。
- ★ **撤销后选区**没判（`undo()` 会清空选区）。
- ★ **未与源站对照**（源站需登录）。本批只判 clone 自身的内部一致性。
