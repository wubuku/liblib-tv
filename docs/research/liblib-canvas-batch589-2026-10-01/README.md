## 取证方法补充

rail 的 flyout 条目同样只响应**受信指针事件**（沿用 586 确立的结论）。
另外，定位 flyout 面板不能靠「x 紧邻 rail 且宽 120–360」这种几何启发式——
画布上的节点卡片（`逐帧拉片` @(99,563) 122×148）会误命中。可靠做法是
**从已知选项文案（如 `二头身`）向上找到 `querySelectorAll('button').length >= 11`
的祖先**。

每个 flyout 顶部都有一行 12px / `font-weight: 400` / class `truncate` 的标题
（`添加角色` @(60,66) 48×20），**位于卡片上方**：卡片从 y=100 起，标题在
y=66–86，中间留空。

## 本批修正

1. **`AI 生成` → `AI生成`**（逐字）。batch 538 从截图转录时记成了带空格，
   本批 DOM 复核确认无空格。`verify-liblib-batch538.py` 的对应断言随之迁移。
2. **面板宽度统一 232px**：clone 原为 150（添加角色）/ 130（全景图）/
   210（画幅比例）三个各不相同。
3. **补标题行**，且按源站结构放在卡片之外：外层定位容器（232px）承载
   「标题 + 卡片」，卡片只装选项。
4. **画幅比例卡高 64 → 72px**，使行距落到 78px（源站 ≈81px），
   卡片总高 322px（源站 324px）。

### 过程中被 verifier 抓到的自身缺陷

重构为「标题在卡片外」后自然消失；verifier 保留行分布断言防回归。
