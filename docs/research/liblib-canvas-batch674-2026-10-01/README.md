# batch 674 —— **没有不折叠的身份**，但折叠能压到 4；而「更细的键」会同时把另一维做粗

## 一句话

673 数出 130 枚控件只对应 **102** 个可及名，**28 枚**被按名字的字典吞掉。
本批问那句更根本的话：**换一个身份就不折叠了吗？**

答案是：**换五次都不折叠，但折叠量可以是 28 / 68 / 10 / 11 / 4**，
而且中间那次「换得最细」的尝试**净效果更差** —— 它把一个维度做细、把回退维度做粗。

## 仪器

`scripts/verify-liblib-batch674.py`，三视口 1280 / 1440 / 1920 × 1150，
沿用 617 的开桌序列，普查前移除所有 `nextjs-portal`，指针先挪 (5,5)。
**全部读数三视口逐格相同**（折叠组数、组内控件数、被吞数、残留组名单，全部逐位吻合）。

五套身份，同一批 130 枚控件：

| 身份口径 | 不同身份 | 折叠组 | 组内控件 | **被吞** |
|---|---|---|---|---|
| **可及名**（`aria-label` → placeholder → textContent） | **102** | 8 | 36 | **28** |
| **结构 kS** = tag + class 头 3 段 + 最近 data 的**名** + role | **62** | 19 | 87 | **68** |
| **结构+值 kS2** = kS 但 data 带 `name=value` | **120** | 5 | 15 | **10** |
| **kS3** = 自身**全部** data 属性，**回退祖先只取名** | **119** | 4 | 15 | **11** |
| **kS4** = 自身全部 data 属性，**回退祖先带值** | **126** | 2 | 6 | **4** |

## 1. 结构身份比名字折叠得更狠（68 > 28）

`kS` 吞掉的 68 枚，比可及名吞掉的 28 枚多一倍多。原因是结构上同族、名字各不相同的三族：
9 条拖动说明标签、9 枚关键帧轨道片、6 枚 3D 轴按钮。

**「按名字数控件」不是「按控件数控件」的中性做法** —— 它在这批控件上恰好是**较细**的那一档。

## 2. 两套划分**不互相包含**

- 名字把 `当前帧有关键帧` 那 **11** 枚并成一条（9 枚轨道片 + 2 枚检视器钮），kS/kS2 把它们分开；
- 结构把三条 `左右拖动调整 X/Y/Z 轴` 并成 **9** 枚一条，可及名把 X/Y/Z 分得开。

**所以没有「最好的键」：每套键各对一族最优。** 换一套键不是「逼近真相」，是**换一种失真**。

kS4 也不是 kS2 的细化：kS2 有 **25** 个键不在 kS4 里，kS4 有 **31** 个键不在 kS2 里 ——
两套键集合**互不包含**（尽管 kS4 吞得更少）。**吞得更少 ≠ 更细。**

## 3. kS2 残留的 10 枚 —— **本批第一版把这句写成「不可约」，被读数推翻**

| 族 | 组数 × 每组 | 键里那一维的值 |
|---|---|---|
| 变换输入框 | 3 组 × 3 | `data-director-transform-field=position / rotation / scale` |
| 关键帧导航钮 | 2 组 × 3 | `data-director-track-label=director-track-camera-main` / `…-character-lead-transform` |

第一版 README 在这里写「都是同维度重复而该维度没有逐节点 id」。**这是错的。**

`src/components/director/DirectorInspector.tsx:179-180` 在**同一个** `<input>` 上同时写了
`data-director-transform-field` 与 `data-director-transform-axis`：

```
data-director-transform-field=position & data-director-transform-axis=x
data-director-transform-field=position & data-director-transform-axis=y
…（9 枚的完整 self-data 是 9 个互不相同的元组）
```

**逐节点判别位一直都在 clone 里 —— 是 kS2 只取「第一个」 data 属性把它丢掉了。**
kS3/kS4 取全部自身 data 属性，这一族立刻散成 9 个不同的键。

**历史批次不重写，纠正记在本批。**

## 4. 一条独立的教训：**把一个维度做细，会把回退维度做粗**

kS3 换掉 kS2 之后，净效果**更差**：吞 11 枚 > kS2 的 10 枚。原因写在键定义里：

- kS3 在**自身 data** 维度变细（9 枚变换输入框散开）；
- 但它的**祖先回退**从 `name=value` 退化成只有 `name`；
- 于是两条导演台轨道（`director-track-camera-main` / `…-character-lead-transform`）
  **被并成一条 6 枚的组**（kS2 下是 2 组 × 3），
  5 枚 `隐藏*` 按钮也因为丢了 `object-id` 的值被并成一条 5 枚的组（kS2/kS4 下是 5 个不同的键）。

读数：残留组最大规模 kS2 = **3** → kS3 = **6**。

**一条键不是「整体更细」，它是「逐维更细」，而各维之间会互相换。**
要把两个维度分开量，回退那一维就不能顺手简化。

## 5. kS4 压到 4 —— 残留的是唯一真无处可辨的一族

kS4 = 自身 data 全取 + 祖先回退带值：**126 个身份，2 个折叠组，吞 4 枚**。
残留**正好**是那 6 枚关键帧导航钮（两条轨道各 3 枚）：

```
button|group.relative.flex|data-director-track-label=director-track-camera-main|-
    → ['上一关键帧', '当前帧有关键帧', '下一关键帧']
button|group.relative.flex|data-director-track-label=director-track-character-lead-transform|-
    → ['上一关键帧', '当前帧有关键帧', '下一关键帧']
```

这 6 枚**自身一个 data 属性都没有**（`selfData` 为空数组），判别位在祖先 `div` 上，
而同一轨道的三枚按钮共享那个祖先。**它们彼此只能靠自己的名字区分**
（`上一关键帧` / `当前帧有关键帧` / `下一关键帧`）—— 这正是 673 数出的「同类重复」那一类。

**不声称**这就是最小可折叠量：不声称 4 是下界（本批没试第六套键），
不声称 130 这个控件总体是完备的（纳入过滤本身就是 665 记的盲区）。

## 6. 18 枚控件**自己身上**没有任何 `data-*`

18 枚元素、**14** 个名字：`上一关键帧`、`下一关键帧`、`变换`、`开启九宫格辅助线`、
`当前帧有关键帧`、`搜索场景内容`、`收起属性`、`机位`，以及全部 6 个 `隐藏*`。

它们只能靠**祖先**的属性被认出来 —— kS4 的回退分支正是为它们准备的。

**这与 664 的「22 个 `pointer-events:none` 元素」不是同一人口，是两个口径，不构成冲突**：
664 数的是 `pe:none` 的**元素**，本批数的是**控件里自身无 data 属性的那 18 枚**。

## 7. 顺带更正 670 的一处措辞（以及我本批自己的一处预期错误）

670 的 README 写「**66 枚控件**在每一档宽度上都是假阳性」。**那 66 是名字数**：

| 身份 | 恒真键（逐格交集） |
|---|---|
| 可及名 | **66** |
| kS | **32** |
| kS2 | **71** |
| kS3 | **66** |
| kS4 | **71** |

而真阳性的**控件**数是 **73 / 75 / 76**（1280 / 1440 / 1920），与 670 记的「每档 77 格里 73–76 格」吻合。

**「枚控件」这个措辞不成立** —— 控件层的数字取决于用哪套身份，本批把五套都记下来了。

**一个反直觉的连带读数**：kS2/kS4 折叠得最少（4 / 10），却给出**最多**的恒真键（**71 > 66**）。
键的个数与折叠量**不成单调关系** —— 折得越细，同一批控件散成的键反而越多。
按恒真键数回答「哪套身份最好」，得到的是**折叠最狠**的那套（kS，32 键），
和「折叠最少所以最精确」是**相反**的答案。

**我本批自己的预期也被读数纠正过一次**：动手前我以为 kS2 的恒真键会**最少**（因为它折叠最少），
第一次运行读到 71 > 66，与预期相反。判据已改成断言「三个键数互不相同且 kS2 > 可及名」，
把这个反直觉点写进载荷，而不是写死我的猜测。

## 8. 自记错误：`all()` 收的是可迭代对象，不是布尔值

本批验收器第一版第 196 行写成 `all(len(set(...)) == 1 and ... and ...)`，
第一次运行直接 `TypeError: 'bool' object is not iterable`。

**`and` 链本身已经是布尔值，再包一层 `all()` 就是把一个布尔值当可迭代对象用。**
逐段二分花了四轮才定位（每段单独都过、串起来才炸，这正是「单测全过、组合失败」的形状）。

**教训**：`and` 链**不要**包 `all()`。要断言「三视口读数相同」直接用集合：
`len({d_name[k] for k in keys}) == 1`。已改。

**另两条自记**：
- 第 6 条判据我按记忆写死「kS3 残留有 4 个不同的祖先属性名」，运行读到 3 个
  （第 4 组复用的是 `track-label`，不是新属性）。**改成断言真正承载机制的那一条**：
  `swallowKS3 > swallowKS2` 且「残留组最大规模 kS3 > kS2」（3 → 6）。
- 判据里凡是能钉的钉**这次运行的数**；kS4 的 126 / 2 / 4 是本文件最后一次运行的读数。
