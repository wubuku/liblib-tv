## 一、一句话结论

batch 832 建出了「添加机位」的**面板**（几何逐字相等），但**没有建出「点了会怎样」**。

本批把 15 枚预设的**语义**逐枚实测并实现：
点哪一枚，就按那一枚的**固定值**建一台机位（位置／旋转／注视坐标／FOV）⟹
**15 枚 × 4 组 = 60 组数值与源站逐字相等**（门禁 S3–S6）。

★ 15 枚的 FOV 从 **35**（正面特写）到 **70**（低角度广角）不等 ⟹
**不凭一枚推 15 枚** ⟹ 必须逐枚实测（batch 832 只测了「正面中景」一枚）。

★ 顺带把一处**自拟名**按实测改正：源站新建的机位叫 **「机位N」**（N = 现有机位数 + 1），
clone 原先叫「机位 02 · 新镜头」（batch 89 当时的**自选**名）⟹ 本批改成「机位2」。

## 三、★★ 本批修掉的第二个坑：读数口径必须**按字段标题分组**

★ 上一版（batch 832 的语义探针）用的是「把右栏所有 `input[type=number]` 按 y 升序拼起来，
再切 `[0:3]` 位置／`[3:6]` 旋转／`[6:9]` 注视」。

★ ★ 这条口径**只在源站成立**：

| | 字段标题元素 | number 输入的构成 |
| --- | --- | --- |
| 源站右栏 | `DIV`（「位置」「旋转」「注视坐标」「视野角度 (FOV)」） | 位置 3 ＋ 旋转 3 ＋ 注视 3 ＝ 9 个 |
| clone Inspector | `LEGEND`（「位置」「旋转」「**缩放**」）＋ `SPAN`（「注视坐标」「视野角度 (FOV)」） | 位置 3 ＋ 旋转 3 ＋ **缩放 3** ＋ 注视 3 ＋ FOV 1 ＝ **13 个** |

⟹ ★ clone **多一行「缩放」** ⟹ 索引切片会**整体错位** ⟹ 「位置 3 个」会读成位置+旋转的一部分
⟹ ⟹ 两边**不可比**，而且是**静默**的：两边都读出 9 个数，都不报错。

⟹ ⟹ 改成**规则 R**（`probes/reader833.py`，源站与 clone **跑同一段 JS**）：

- **R2**：按**字段标题文字**分组 —— 取标题下方 60px 内、**同一行**的 3 个 number 输入，按 x 升序；
- **R3**：FOV 取「视野角度 (FOV)」标题下方 60px 内的**第一个 range**。

⟹ ★ 为什么 FOV 必须读 range：源站的 FOV 数值框**没有 `type` 属性** ⟹ `input[type=number]` 选不到它 ⟹ 两边都读 range 才一致。

★ 规则 R 的**自证**（门禁 S10／S11）：在**源站活体**上跑同一段 JS，读出「机位1」的
位置 (3.3, 2.2, 10)／旋转 (5.42, -161.74, 0)／注视 (0, 1.2, 0)／FOV 67，
与**另一次独立采集**（`diag833.py` 的 DOM 顺序切片）**逐字相等**
⟹ ⟹ 证明读数器**确实读到了东西**，不是「两个空集相等」。

## 四、读数器自己翻的三次车（本批的失败记录）

| 序 | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| 序 1 | clone 探针的「机位数」**恒为 0** | 点开预设面板后**左侧栏切成预设视图** ⟹ 场景树**根本不在 DOM 里** ⟹ 读 DOM 文本恒空（假读数） | 改读 **store**：`authoredObjects.filter(kind==='camera').length` |

⟹ 与已存记忆同族：「**跑通了 ≠ 看到了**」——校验器正常返回空/绿灯是最贵的一种失败。
