# batch 646 —— `own` 把**被裁掉**的控件读成「干净的」：普查的第三个盲区

日期 2026-10-02 · 验收器 `scripts/verify-liblib-batch646.py` · **14 checks / 0 failures**

## 一句话

本批原计划是给时间轴控件行收闭式。闭式连红两次之后去挖地面真值，
看见的不是几何问题，是**判据自己的问题**：

> `own` 的定义里有一支 `hit.contains(el)`，它在**命中元素是控件的祖先**时判真。
> 而**裁剪只改变「绘制」，不改变 DOM 树** —— 被自己滚动盒裁掉的控件仍是那个
> 盒子的 DOM 后代，而那个盒子通常就画在采样点上。于是**压根没被绘制**的控件被判成
> 「自己接到了点击」。

这是普查的**第三个盲区**，前两个形状都不同：

| 批次 | 盲区形状 | 出错在哪 |
|---|---|---|
| 640 | 晶格只打中心 → 「中心干净、身体被挡」漏报 | **探针**的采样点 |
| 641 / 642 | `rounded-full` 的四角按设计就在形状外 | **探针**的形状假设 |
| **646** | 被裁掉的控件读成干净的 | **判据自己的命中测试** |

## 1. 实测样例（1020px，时间轴控件行）

```
删除关键帧  rect = [747, 722.5, 28, 28]      行盒 = 8..760
  矩形出界          True        ← 它确实被裁掉了
  普查 own          True        ← 却报「干净」
  命中元素          header[data-director-timeline-controls]   ← 是它的祖先
  elementsFromPoint 里有没有它   没有        ← 地面真值
```

普查的盲区桶 `ownButNotPainted` 在 23 个宽度上量到 **10 处分歧**，
涉及**四枚**控件：`添加关键帧` / `删除关键帧` / `模型库` / `移除角色01 · 陈默 · 变换轨道`
—— **不局限于时间轴那一行**。

三条机制断言全部成立：

* **每一例都是被裁的控件**（若有不裁剪的，就是第二种机制，「祖先命中」就不是全部故事）；
* **每一例都走的 `hit.contains(el)` 那一支**；
* **单向**：普查只可能「过于干净」，不会「过于脏」——
  单向错误可以用加宽探针吸收，双向错误意味着量具不可用。

## 2. 为什么它挡着时间轴那条律

本来以为闭式对不上是几何问题。实际是**我混了两个谓词**：

| 谓词 | 测什么 | 判据 |
|---|---|---|
| `isClipped` | 整个盒子装不装得下 | **矩形**测试（`±0.5` 容差） |
| 是否被绘制 | 采样点那一像素有没有它 | **中心**测试 |

证据在 @754：`添加关键帧` 的矩形只越出 **1px**（747 对行右 746），
普查的 `isClipped` 判它被裁，但它的**中心 703 仍远在行内** ——
所以它**仍被绘制、仍可点**。

**我第二版闭式改用矩形测试，正是在这一格变红的。红是对的，改是错的。**
这与 643 那条（`clipped` 与「被盖」独立）是同一个道理深一层。

## 3. 中心律与四个边界

```
行左沿 = 8（两族）
行宽   = W − 16（窄族） / W − 268（桌面族）    ⇒ 行右沿 = W − 8 / W − 260
cx     = 703（添加关键帧） / 761（删除关键帧）   （两族恒定）

被绘制 ⟺ cx < 行右沿
未被绘制 ∧ 中心在窗口内 ⟺  联合的地面真值
```

| 控件 | 窄族窗口 | 桌面族窗口 |
|---|---|---|
| `添加关键帧` | **[703, 711]** | **[899, 963]** |
| `删除关键帧` | **[761, 769]** | **[899, 1021]** |

四个窗口**全部逐像素夹逼**（网格把每条边放在相邻两个采样宽度上）：

```
添加关键帧/narrow   预测[703,711]  实测未绘制[703,710,711]  其上首个已绘制 712
添加关键帧/desktop  预测[899,963]  实测未绘制[899,962,963]  其上首个已绘制 964
删除关键帧/narrow   预测[761,769]  实测未绘制[761,768,769]  其上首个已绘制 770
删除关键帧/desktop  预测[899,1021] 实测未绘制[…,1020,1021] 其上首个已绘制 1022
```

窄族那两个窗口**各只有 9px 宽**，因为行左沿恒为 8 —— 行溢出到窗口外的那条缝
只有 9 像素，比半枚 32px 按钮还窄，所以它们在窄族里**只可能整枚或半枚被裁**。

## 5. 我自己写错的五处

1. **闭式用中心、判据用矩形**，我把两者混了 —— 第二版改矩形后在 @754 变红，
   而**红是对的、改是错的**（见 §2）。
2. **出屏是第三种状态**：我用「在不在盲区桶里」反推「有没有被绘制」，
   而出屏控件既不绘制、**也不进盲区桶**（普查跳过探针、`own` 保持 false）。
   改为直接用 `elementsFromPoint` 测。
3. **行盒比较用错了索引**：`row[2]` 是**宽**，右沿是 `row[0] + row[2]`。
4. **网格与判据口径脱节**：我把中心律的边界（711/769/963/1021）换成了矩形律的
   （754/782/1006/1034），于是窗口一个都夹不住。
5. **探针里 `at(r)` 传了 DOMRect**（不是元素），一路报
   `getBoundingClientRect is not a function` —— 笔误当成工具故障排查了两轮。

另有一处是**我自己的检查空转**：`the-only-covered-control-is-still-632s-defect`
在第一版网格里拿到 `covered: []` 也判绿，而 `收起` 只在 339 出现、339 不在网格里 ——
**空集让「全部都是收起」平凡成立**。第二版把 339 放进网格，并给这条检查加了
`nonVacuous` 断言。
