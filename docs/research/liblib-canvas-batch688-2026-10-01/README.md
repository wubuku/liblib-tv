# Batch 688 — `88..420` 这条量程是窗口的函数，而拖拽是单向规则的逃逸口

日期：2026-10-01
验收脚本：`scripts/verify-liblib-batch688.py`（**5 项，5/5 通过**）
取证脚本：`/tmp/dbg688a.py`（10 个窗高的拖拽上限 + 逃逸序列 + 收起/展开往返）

本批**零源站断言**（无源站授权、未开源站会话）。拖把手与收起按钮都是操作
**我们自己的 clone**，**不碰源站**；`src/` **一字未改**。

## 起点：687 留的那条未测，第一句就站不住

687 写「`fit()` 只挂在 `resize` 上」。**读源码发现那句话不成立**：

```tsx
useLayoutEffect(() => {
  if (timelineCollapsed) return;
  const fit = () => { ... if (overflow > 0) setTimelineHeight(timelineHeight - overflow); };
  fit();
  window.addEventListener("resize", fit);
  return () => window.removeEventListener("resize", fit);
}, [timelineHeight, timelineCollapsed]);   // ← 依赖里有 timelineHeight
```

依赖数组里有 `timelineHeight` ⟹ **`fit()` 会在任何一次对它的写入后重跑**，
而拖拽写入者（`moveHeightResize`）**不做任何溢出检查**。

**于是一条「未测」变成了两条新的读数。**

## 读数一：可达上限 = `max(88, min(420, vh − 88))`，跨点在 **508**

在 10 个窗高下把把手**死命往上拖**，读落定的值：

| 窗高 | 拖后落定 | `vh − 88` | 到 420？ |
|---|---|---|---|
| 150 | **88** | 62 | 否（且 `overflowBy = 26`，MIN 也救不了） |
| 200 | 112 | 112 | 否 |
| 250 | 162 | 162 | 否 |
| 300 | 212 | 212 | 否 |
| 400 | 312 | 312 | 否 |
| 450 | 362 | 362 | 否 |
| **507** | **419** | 419 | **否（差 1px）** |
| **508** | **420** | 420 | **是** |
| 600 / 720 | 420 | 512 / 632 | 是 |

**607 记的「量程 88..420」只在窗高 ≥ 508 时才真的可达。**
在任何一个更矮的窗口上，**声明的量程与有效的量程不是一回事**，而界面上没有任何地方说明这件事。

## 读数二：跨点是 **508**，两侧都量到了

`88 + 420 = 508` —— 面板顶边被顶到 88，加上 store 的上限 420。
与 622/623 的 898/899、685 的 620 同一种形状：**一个声明值加一个布局常量，两侧各取一个点**。

机制上也能说清：拖拽先写 `min(420, 起点 + 距离)`（在 507 也是 420），
然后 `fit()` 减去那 1px 越界（`88 + 420 − 507 = 1`）⟹ 落定 419。508 时越界为 0，420 站住。

## 读数三：拖拽写入者不做溢出检查，却仍被钳住 —— 靠的是**依赖列表**，不是设计

`moveHeightResize` 直接 `setTimelineHeight(next)`，没有溢出判断；
是包着 `fit()` 的那个 effect 重跑时把越界减掉。

**所以「拖不出界」这件事是靠依赖数组成立的，不是靠写入者自己保证。**
把它当设计保证读会把修法指向错的方向；**而这是一条推断，不是读数** ——
「去掉 `timelineHeight` 依赖会怎样」**本批没有测**。

## 读数四：**拖拽是逃逸口，窗口变高不是** ⟹ 单向性是**写入者**的性质，不是 store 的

| 步骤 | 窗高 | `timelineHeight` |
|---|---|---|
| 打开 | 720 | 182 |
| **拖把手死命往上** | 720 | **420** |
| 缩到 150 | 150 | **88**（`overflowBy = 26`） |
| **回到 720** | 720 | **88**（**什么都不做**） |
| **再拖一次** | 720 | **420** ⟵ 写回来了 |

store 乐意接受 420；**是 `fit()` 拒绝向上写**。

**这收窄了 687 的产品问题**：A（变高时自动恢复）**并不是「能不能恢复」的前提** ——
恢复能力已经存在，只是要用户动手一次。真正的问题变成：
**「自动恢复」值不值得**，而不是「能不能恢复」。

## 读数五：收起/展开往返**不**丢值

| 窗高 | 拖后 | 收起 | 展开 |
|---|---|---|---|
| 720 | 420 | 88（`collapsed=true`） | **420** |
| 250 | 162 | 88（`collapsed=true`） | **162** |

`timelineCollapsed` **也在** `fit()` 的依赖里，但收起期间 `fit()` 直接 return，
展开时又无越界 ⟹ **这条路不触发降档**。**「是依赖」不等于「是写入者」。**

顺带又一次撞上 687 那条：`collapsed=true` 时属性也读 **88** ——
和被钳后的 store 值**读起来一样**。

## 产物状态机（687 那张表的修正版）

| 事件 | `timelineHeight` 变成 |
|---|---|
| 打开 / 重载 | **182**（`DIRECTOR_TIMELINE_DEFAULT_HEIGHT`） |
| 拖把手 | `min(420, 起点 + 拖动量)`，**随后被 `fit()` 减去越界** ⟹ 落定 `max(88, min(420, vh − 88))` |
| 收起 / 展开 | **不变** |
| 窗口 resize 且面板越界（`H < 270`） | **减掉恰好那次溢出**，下限 88 |
| 继续 resize 且仍越界 | 继续减 |
| **窗口变高** | **什么都不做** |
| 重载 | 182 |

## 自记

**这一批的主要价值在「否掉 687 留的那条未测」，而否掉它的方式是先读源码。**
687 写「`fit()` 只挂在 `resize` 上」时我只看了 `addEventListener` 那一行，
没看依赖数组 —— **一个 effect 的两条触发路径，只看了一条**。
与 687 那条「先 grep 注释」同族：**只读一半的代码，结论就会少一半。**

**第二次自记：在 Python 写的 JS 串里落进 Python 语法，本会话第三次。**
685 的 `rec = {vw: …}`（JS 裸键名）、`{x["data"] for x in rows}`（Python 集合推导），
本批的 `(box(vp) or [0,0,0,0])[3]`。三次都是**仪器自己先报错**，才没让错误读数流到结论。

这不是手滑，是**可复现的失败模式**：探针 JS 嵌在 Python 字符串里，而写探针时手在 Python 模式里。
**同一类错误的第三次出现就该上工具** —— 本批已把 JS 串抽出来用 `node --check` 过一遍再跑
（685 的 README 里记过这个做法，**当时只用在那一批，没变成惯例**）。
