# batch 808 —— 「删掉组里最后一个成员」之后，那个**空组**到底会怎样

> 807 留了一条：**臂 2 的空组读数只覆盖「成员被搬进另一个组」这一种变空路径**。
> 「删掉组里最后一个成员」这条路径下的空组行为**未测**。本批去测。
>
> 一句话结论：**空组会永远留着** —— 框一像素不缩、连线 handle 照画、键鼠都能选中，
> 按 `Delete` 删得掉，但按 `Shift+G` 取消分组**完全静默**。

## 一、为什么这条不阻塞在源站对照

807 遗留里大部分都要源站登录才能拍板（嵌套组、提示文案、导演台历史栈）。
这一条**不同**：它是**可本地确定性测**的内部一致性问题 ——
「组空掉之后，UI 上那些属于成员的东西（框、连线把手、组合能力）有没有跟着走」。

而它不只需要「记一条读数」，它同时能给 **793 的待拍板 ②** 一条**此前没有的**输入：
793 问的是「空组要不要收缩／弱化」，而 807 只测到一种变空路径。
**两条路径下空组的读数是否一致**，本身就是要先知道的事实。

## 二、方法：宿主组**通过 UI 造出来**，不注入

沿用 807 的前提：792 的修法是建立在「UI 造得出组」上的，注入组会绕过这个前提。

探针每轮做同一串动作（两轮逐位相同，见第四节）：

| 序 | 动作 | 读数落在哪 |
| --- | --- | --- |
| 序1 | 建 1 个散节点 + 1 张图节点 | 节点数 |
| 序2 | 选中这 2 个、按 `G` | **臂 A** 宿主的成员表 |
| 序3 | 选中组 + 组内 1 个成员、按 `Delete` | 臂 A（连坐 + 撤销） |
| 序4 | 再删掉**剩下那 1 个**成员 | 臂 B（框收缩） |
| 序5 | 删掉**最后 1 个**成员 | ★ 臂 C（空组） |
| 序6 | 选中空组按 `Delete` | 臂 D（删得掉吗） |
| 序7 | 重新造一个空组按 `Shift+G` | 臂 E（静默吗） |
| 序8 | 右键空组 | ★ 臂 F（作废） |

★ 判据只认**绝对几何**与**DOM 可见读数**。空组的框从 store 读、handle 从 DOM 读，
并且**两个来源必须能被同一个 zoom 解释**（见 S4）—— 否则「handle 还在」可能只是
DOM 残留。

## 三、五条臂的读数

### 臂 A：删掉一个**带 1 个成员**的组

| 读数 | 值 |
| --- | --- |
| 删掉的组 | `group-…` |
| 它的成员还在吗 | `{文本: false, 图片: false}` |
| 节点数 Δ | **−3** |
| `Cmd+Z` 之后节点数 | **11**（= 删之前的原数） |
| `Cmd+Z` 之后组回来了 | **true** |
| `Cmd+Z` 之后成员全回来了 | **true** |

⟹ **成员被连坐删除**（`removeNode` 走 `withDescendantIds`），
但**撤销是原子的** —— 一次 `Cmd+Z` 把组和两个成员一起还原。

★ 这条本身是个**好消息**，与 803 撞出的「导演台重载后 `Cmd+Z` 全无效」不同：
画布侧的撤销栈在**同一会话内**是完整的。

### 臂 B ★★：删掉 1 个成员，组还剩 1 个 —— **阳性对照**

| 读数 | 值 |
| --- | --- |
| 原来的框 | `722 × 828` |
| 删之后的框 | `698 × 430` |
| 组还剩几个 | 1 |

⟹ **框真的收缩贴合了剩下的那个**。★ 这条是**阳性对照**，不是可选项：
没有它，「空组框不变」完全可以只是「框从来就不变」的另一种说法
（⟹ 即 `fit` 从来没跑过）。**臂 B 证明 `fit` 对非空组是活的。**

### 臂 C ★★★：删掉**最后一个**成员 —— 空组

| 读数 | 值 |
| --- | --- |
| 空组还在吗 | **true** |
| 一步之前的框 | `698 × 430` |
| 空组的框 | `698 × 430` |
| ★ 框一像素都没变 | **true** |
| 节点里的边数 | 8 |
| DOM rect | `367 × 226` |
| handle 数 | **2** |
| handle 明细 | 1 个 `target`（左）、1 个 `source`（右） |

**三件同时成立**：空组还在 ∧ 框沿用上一个状态 ∧ 框**非零**（没塌成 0）。

★ `367 / 698 = 0.5258`、`226 / 430 = 0.5256` —— **两个方向比值一致**，
证明 store 的框和 DOM 画的框**差且只差一个 zoom（≈0.526）**，
⟹ 「空组还在被渲染」这件事**不是 DOM 残留**，也不是框塌了。

源码侧对应物：`fitStoryboardGroupsToChildren` 里
`if (kids.length === 0) continue;`（`canvasStore.ts:754`）
—— **空组直接被跳过**，所以框保持上一次的值。

### 臂 D：空组**删得掉**

| 读数 | 值 |
| --- | --- |
| 按 `Delete` 之后节点数 | 8 |
| 空组还在吗 | **false** |

⟹ 空组**不是陷阱**。★ 这条是臂 E 的**对照**：正因为用户能删掉它，
「`Shift+G` 没作用」才是「缺一条提示」而不是「清不掉」。

### 臂 E ★★：空组按 `Shift+G`（取消分组）—— **静默**

| 读数 | 值 |
| --- | --- |
| 节点数 Δ | **0** |
| 空组还在吗 | **true** |

源码侧对应物：`ungroupSelectedNodes` 开头
`if (!group || children.length === 0) return state;`（`canvasStore.ts:3582`）
—— 段内**没有任何提示路径**。

★ 这是**同族静默的第三个**（807 记的第二个：选区含组时按 `G`；
792 记的第一个：同一族的更早版本）。

### 臂 F ★★：右键菜单那条臂 —— **显式作废**

探针右键空组后读到的 `menuItems` 是 **空数组**，而 `groupDom.selected = true`
（说明**选中确实生效了**，只是菜单没被打开）。

源码里**确实有** `data-canvas-context-item="删除"`（`CanvasContextMenu.tsx:191`），
所以「空数组」**极容易被写成**「菜单里没有删除项」—— 那是**错的结论**。

⟹ 按 802 起的规矩「**前提不满足的臂显式作废，并做成断言**」，
本批把这条作废写成了 **S7**，让验收器去断言「该臂确实没测到东西」。

## 四、验收结果

主检查 **8/8**，阴性对照 **7/7**。raw 的 sha256 未变（对照全是**纯内存**变异）。

| 阴性对照 | 打在哪个字段上 | 翻红 |
| --- | --- | --- |
| N1 | raw：声称 `Cmd+Z` 后成员没全回来 | S1 |
| N2 | raw：声称删成员后框没收缩（打掉臂 B 阳性对照） | S2 |
| N3 | raw：把空组框改成 `[0,0]` 且声称没变 | S3、S4 |
| N4 | raw：声称空组没有 handle 了 | S4 |
| N5 | raw：声称空组删不掉 | S5 |
| N6 | raw：**伪造**「菜单里有其它项」（即假装那臂测到了东西） | S7 |
| N7 | 反向对照：只动 `note` 这个无关字段 | 无 |

★ **N2 必须成对看 N2 与 S2**：阳性对照的作用就是让「空组框不变」这句话
有个可比较的参照 —— 非空组**会**变，空组**不会**变，这才是结论而不是巧合。

★ **N3 顺带抓出我自己验收器的一个 bug**：S4 原来直接算
`rect["w"] / store_box[0]`，N3 把框改成 `[0,0]` 后**除零崩掉整个验收器**
（`ZeroDivisionError`）—— 崩掉意味着**阴性对照测不出东西**，
「读数没变」会被误当成「没崩」。修法：分母为 0 时显式记为「比值不可用」并判否。

`src/` 未改动，**没跑 build**（789 / 796 / 798 / 801 / 803 / 806 / 807 同样处理）。

## 五、我的验收器**第六次**踩「同名锚点」

802 起的规矩：一律用 `rfind` 或带完整参数类型标注。
本批验收器 S8 又踩了一次 —— `src.find("ungroupSelectedNodes: (")` 抓到的是
`CanvasState` 的**接口声明**（`canvasStore.ts:385`），而
`children.length === 0 → return state` 在**实现**里（`:3582`）。

改成取**最后一次**出现，并在证据里记录**同名出现次数**，让「取的是不是实现」
这件事本身可被审查。

前五次：799 `updateNodeData`、800 `ungroupSelectedNodes`、801
`duplicateGraphSelection`、802 `createImageHdPreset`、807 `groupSelectedNodes`，
第六次：**我自己的验收器**。

## 六、这一批**修不了**，以及为什么

> 「删掉组里最后一个成员」之后，UI 留一个**什么都不装**的组：
> 框不缩、连线把手照画、组合不了（`Shift+G` 静默）。

**为什么本批不改**：该改成什么，是**产品决策**，而且要源站依据：

- 最后一个成员被删时**顺手把组也删掉**？（那 `Delete` 一次删 3 个，用户能不能预期？）
- 或者组**保留但弱化**（框缩成最小、连线 handle 去掉、只留一个细边）？
  ⟹ 但「弱化」长什么样，源站有没有这个东西，都**没有依据**。

⟹ 与 803、806、807 同款结论：记为「**阻塞在源站对照**」，不发明 UI。

★ **但本批把这条从「一条遗留」升级成了「一个有读数的拍板项」** ——
793 待拍板 ② 现在手上有**两条变空路径**的读数：

| 变空路径 | 来源 | 空组读数 |
| --- | --- | --- |
| 成员被搬进**另一个**组 | 807 臂 2 | 框 `1000×1487`，**不变** |
| 成员被**逐个删掉** | 808 臂 C | 框 `698×430`，**不变** |

两条路径**读数一致**（都是「框保持最后状态、不收缩」）⟹
「空组保持原框」是**一条稳定行为**，不是某条路径的巧合。

## 七、不声称

- ★ **右键菜单整条路径未测**（臂 F 已作废）。源码里有
  `data-canvas-context-item="删除"` ⟹ 空组在菜单里**可能有**删除入口，
  本批**没有测到**，不做任何声称。
- ★ 只测了 **`Delete` 与 `Shift+G` 两条键盘路径**。
- ★ 只测了**组内成员从 2 个逐个删到 0**这一种路径。
  「一次多选把两个成员一起删掉」（⟹ 组**同时**变空）**未测**。
- ★ 只测了**两层**结构。嵌套组仍未测（792 决定 UI 造不出嵌套）。
- ★ 「一像素都没变」是**逐位相等**（`698 == 698`），不是「小于 1px」。
- ★ 撤销只验了**一臂**（`Cmd+Z` 一次）。**多次** `Cmd+Z`／`Cmd+Shift+Z` 重做
  **未测**。★ 803 撞出「导演台重载后撤销栈不持久化」，画布侧**跨会话**撤销
  **未测**。
- ★ 框的「不变」只在**成员被删**这条路径上验证过**由谁造成**：
  本批只看到结果（框没变），**没有**单独证明「是 `fit` 的 `continue` 造成的」
  而非「`removeNode` 根本没去改组的 position」。
- ★ **未与源站对照**（源站需登录）。本批只判 clone 自身的内部一致性。
