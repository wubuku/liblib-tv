# batch 657 —— `help` 换探针重测：普通 `click()` 的超时**不是探针故障，是 Playwright 正确地拒绝点击一个被遮挡的控件**；那 4 个 `scene-*` 标记**只存在于源码**

## 一句话

656 留了两笔账，本批各还一笔。
账一是 `help` 记成 `probe-failed`（它背后是**未测**，不是「测了没有」）；
账二是「那 4 个无人引用的 `data-director-scene-*` 标记可能只存在于源码字符串里」这个开口。

**账一还出来的不是「探针故障」，也不是「no-op」，而是一枚真实的遮挡缺陷候选。**
**账二还出来的答案是：4/4 只存在于源码，十个状态里一次都没挂载过。**

## 1. 头条：`help` 被**时间轴轨道列表**盖住了

用 649 的办法——**不点击，用 `elementsFromPoint` 看结构**：

| | |
|---|---|
| 目标中心 | **(24, 1126)**，`rect = [8, 1110, 32, 32]` |
| 该点的元素栈深度 | **21** |
| 目标在栈中的位置 | **第 8 位**（不是栈顶） |
| `targetIsTopmost` | **False** |
| 栈顶 | `button.group.relative.z-[1]` |
| 往下第 2 位 | `div.group.relative.grid [data-director-timeline-object-row, -object-selected]` |
| 第 3 位 | `div [data-director-object-group]` |
| 第 4 位 | **`div.w-[320px].shrink-0.overflow-y-auto [data-director-timeline-track-list]`** |

**盖住它的是时间轴的轨道列表**（320 宽），在 1280 × 1150 的默认导演台态下。

## 2. 我前两批的判断**都反了**

| 探针 | 结果 | 我原来的说法 | 实际含义 |
|---|---|---|---|
| plain `.click()` | `TimeoutError` | 「探针的 actionability 假象」 | **探针是对的** —— 它看见目标坐标上站着别的元素，于是拒绝点击并一直等 |
| `click(force=True)` | `moved`，geo 26，元素 1390→1367 | 「force 落地了，读数是 noop/moved」 | **force 跳过了遮挡检查**，按坐标点下去，点中的是**时间轴轨道行** |
| `dispatch_event('click')` | **noop** | 「也是落地」 | 直接派发到元素上，**它自己的 handler 不改任何 DOM** |

**`force=True` 「发现」的那 24 个元素（`cursor-ew-resize` 拖拽把手、旋转 45° 的菱形关键帧、`chevron-left/right` 折叠箭头）全部属于时间轴** ——
那不是 help 的行为，那是**轨道行被选中**之后长出来的东西。

**这与 649 的「位置不等于层叠」是同一件事的镜像：在坐标上点击 ≠ 点中那个元素。**

## 3. 那 4 个 `scene-*` 标记：4/4 只存在于源码

656 事先预测「点 `scene` 会带出这 4 个」，一个都没出现，并写下「它们可能只存在于源码字符串里」。

**就是这个。** 在默认态 + 7 个 rail 入口的十个状态里：

* `src/` 里**有**这 4 个：`scene-settings-section` / `scene-display-settings` / `scene-camera-actions` / `scene-toggle`
* DOM 里**一次都没有**（0/4）
* 而**真正存在的** `data-director-scene-*` 是另外 7 个：`axis-scrub` / `prompt-bar` / `prompt-file` / `prompt-input` / `prompt-status` / `prompt-submit` / `prompt-upload`

**所以 656 的预测「猜对了嫌疑人、猜错了理由」** —— 不是 `scene` 入口不带它们，是**没有任何状态带它们**。

## 4. 顺带：把「源码里有、DOM 里没观测到」变成一个数

| | 数 |
|---|---|
| `src/` 里的 `data-director-*` | **445** |
| 十个状态里**观测到**的 | **222** |
| **有源码、从未观测到** | **224** |

**这不是死代码名单。** 十个状态是很小的样本，而本项目大部分表面都锁在状态门后面 ——
移动面板、选中相机、画完的运动路径，**都没采**。
在那类状态里挂载的标记当然观测不到。
这个数是「src/ 有多少被观测到过」的**棘轮**，仅此而已。

## 5. 仪器自己的一处盲区

两次 `force` 运行**逐位一致**（`moved/+0/−0/sig+0/sig−0/geo26/1390→1367`），
所以**不是不确定性**。但 657 这一版仪器有一处看不见的东西：

> 元素数从 1390 掉到 1367（**−23**），而**签名集合零变化** —— 这两件事互相矛盾。
> 签名是用 **set** 记的，所以增删 N 个**共享同一签名**的元素完全不可见。

另一次用 **multiset**（按签名记重数）跑同一探针，看到的却**全是新增**（+3 `span.hidden`、+3 关闭按钮、+2 轨道行按钮……）。
**同一个探针，两种签名记法，一个说减 23 一个说加 24 —— 而 set 记法两次都说「零」。**

记录在此：**set 记的签名看不见重数变化**。这是本项目仪器谱系里第 8 个盲区形状
（零尺寸 / 位置≠层叠 / 只打中心 / 祖先命中 / 零尺寸门槛 / 探针副作用 / 只测出现不测消失 / set 看不见重数）。

## 7. 我自己写错的地方

   **却没问那把探针点的是谁**。这是 651 那条教训的**反面**：不是所有不报错的探针都更可信。
