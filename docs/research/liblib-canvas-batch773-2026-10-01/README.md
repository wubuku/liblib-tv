# batch 773 — 「分支到没到」的直接读数：桌内那个 keydown 处理器对浮层一无所知

> 画布 · 导演台 · disclosure 浮层（导出面板 / 运镜预设面板 / 路径菜单 / 本机预演面板 / 群众阵列面板 / 模型库面板）
> 复刻对象：`http://localhost:4317` 的 `canvas-2`，导演台，桌面 1440×1000，chromium（playwright sync_api）
> 本批**没有改动 `src/`**（`git diff --stat HEAD -- src/` 为 0 行）
> 判据 **10 条（10 PASS / 0 FAIL）**；原始读数 51 格 × 2 轮（两个探针合并）；验收器 `scripts/verify-liblib-batch773.py`

## 0. 这一批在做什么

772 有一个缺口。它报的是：**4/6 个浮层**实测按 `Delete`/`Backspace` 会真删对象，而 **preset / 路径菜单的 4 格判为「结构上不可判」** —— 因为这两个浮层必须选中主机位才能开，而对照格实测**相机根本删不掉**，于是「对象没少」既可能是「分支没跑」，也可能是「跑了但目标删不掉」。

772 的读法是**靠副作用反推**。本批换**与副作用无关的直接读数**，把缺口填掉。

**结果：D14 的范围从 4/6 更正为 6/6**（更正 C773-1）。preset 与路径菜单**不是安全的**，只是种子项目里恰好没有可删的目标。

## 1. 机制（静态可查，本批逐行读过）

`DirectorDesk.tsx:473-571` 在 **window、冒泡**阶段注册**一个** keydown 处理器。它**每走到一个分支就调一次 `event.preventDefault()`**：

| 键 | 分支 | `preventDefault()` 在 |
| --- | --- | --- |
| `Escape` + `activeMobilePanel` | 关移动抽屉 | `:483` |
| — | **`if (isEditable) return;` ← 唯一的挡板** | `:487` |
| `Meta/Ctrl+C` | `copyDirectorSelection()` | `:491` |
| `Meta/Ctrl+V` | `pasteDirectorClipboard()` | `:502` |
| `Meta/Ctrl+Z` | `undoDirector()` | `:507` |
| `Meta/Ctrl+Y` | `redoDirector()` | `:513` |
| `Delete` / `Backspace` | 组路径 / 对象路径 | `:526` / `:541` |
| `Escape` | 手势 → 导出面板 → 跟随 → **`closeWorkspace()`** | `:550` |

⟹ **「按键结束时 `event.defaultPrevented === true`」就是「桌内那个处理器真的走到了对应分支」的直接证据。**

**读数不会被别的处理器污染**，三条独立理由：

1. 对话框那个 Tab 处理器（`useDirectorFocusContainment.ts:149-172`）第一句就是 `if (event.key !== "Tab") return;` ⟹ 对本批这五个键**一次都不 preventDefault**；
2. 主画布页那条 Delete 在导演台开着时**整条早退**（`src/app/page.tsx:1306-1310` 的 `if (uiState.activeDirectorNodeId) return;`，772 的 F9）；
3. **中性键对照**：按一个桌内**明确不处理**的键（`F2`），间谍必须读到 `false`。

## 2. 间谍怎么读

同一个节点（`window`）上的监听器按**注册顺序**触发。桌内那个处理器在**挂载时**注册（`DirectorDesk.tsx:570`），而间谍是**开完浮层之后**才装 ⟹ 排在它**之后**，读到的 `defaultPrevented` 已包含桌内那次的调用。间谍是**纯读**（只加一个监听器，不改行为）。

`Meta` 键自己也会发一个 keydown，所以 `press("Meta+z")` 共两个事件，取**最后一个**。

## 5. 守卫的作用域此前只量过一个键，现在量全了

| 落点 | `Delete` | `Backspace` | `Meta+z` | `Meta+c` | `Meta+v` |
| --- | --- | --- | --- | --- | --- |
| 可编辑（3 个浮层） | false | false | false | false | false |
| 非编辑（6 个浮层） | true | true | true | true | true |

**45/45 格上 `defaultPrevented` 恰好等于「落点非可编辑」，与是哪个浮层完全无关。** 772 只验过 `Delete` 被挡（3/3）；本批证明那道 `isEditable` 早退对**五个键一视同仁**。

所以它不是「只挡住一半」，而是「**按控件类别整齐地挡**」—— 修 D14 时可以把判据从「标签名」换成「焦点在不在浮层内」，**行为边界不变**。

## 6. 「分支跑到了」与「东西真被删了」是两个信号

| 信号 | 格数 | 落在哪 |
| --- | --- | --- |
| `dp=true` **且** Δ对象 < 0 | **8** | export / phonevcam / crowd / modellib 的 Delete+Backspace |
| `dp=true` 但 Δ对象 = 0 | **4** | preset / pathmenu 的 Delete+Backspace（目标=主机位，删不掉） |
| `dp=true` 且 Δ对象 = 0（`Meta+C/V/Z`） | 18 | 全部 6 层 —— 本来就不会改对象数（剪贴板 / 撤销栈） |

**8 + 4 = 12** 格都是「分支跑到了」。**只报第一个信号，就会把第二个写成「测不出来」—— 而它其实是可以判的，只要换一个与副作用无关的读数。** 这正是 R94 在同一批里的第二次成立。

## 8. 观察

**O773-1 · 桌内那个处理器对浮层一无所知。** 它唯一的输入是 `event.target` 的标签名。45/45 格上 `defaultPrevented` 恰好等于「落点非可编辑」，**与是哪个浮层完全无关**。「按浮层逐个测」在这里是浪费 —— **机制上不存在按浮层的分支**，一个守卫就能全族覆盖。

**O773-2 · 那道 `isEditable` 早退的作用域此前只量过一个键。** 现在补全：它对 `Delete`/`Backspace`/`Meta+C`/`Meta+V`/`Meta+Z` **五个键一视同仁**。

**O773-3 · 「分支跑到了」与「东西真被删了」必须分别报。** 8 格两个信号同时为真，4 格只有前者。

## 9. 探针教训

**R97 ·「一个读不出来」和「一个没发生」是两回事。** 772 那 4 格是靠**副作用**判的，而副作用只在目标可删时可见。**判别式：读数方法里有没有一个「目标本身可不可观测」的自由变量。** 修法是找一个与副作用无关的直接读数。

**R98 · 读数方法本身要有中性对照。** 本批在断言之前先跑一格：按桌内**明确不处理**的键（`F2`），间谍必须读到 `false`。**顺序型读数（监听器顺序、事件顺序）必须配一个「什么都没发生」的阴性格** —— 监听器顺序是注册顺序决定的，而注册顺序随时可能被一次重挂载改掉，不测就会静默失效。

**R99 · 要读的字段必须在监听器里真的 push 它。** 第一版间谍写成 `{key, meta, shift, atEntry: false, tag, type}` —— `atEntry` 是**硬编码的字面量 false**，而 `e.defaultPrevented` **根本没记**。结果 45 格全部读成 `None`，**探针不报错、汇总照常打印**。★ **识别信号：某一个字段在所有格上取同一个值（尤其是 `None`/`False` 这类「看起来合理」的值），先怀疑它没被记，而不是先怀疑产品。**

**R96（同批复用）· 一批读数失效时不要整套重跑。** 中性臂没跑（for-want 补丁没落进文件），补一个只跑这 6 格的探针、在汇编器里**合并**，773a 的 45 格全部保留。
