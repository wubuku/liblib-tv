## 一、源站事实

### 1.1 车道区根本不是 DOM，是**第二块 canvas**

`document.querySelectorAll('canvas')` 全量列举（probe34），时间轴相关两块：

| canvas | attr 尺寸 | CSS 盒 | 父容器 |
|---|---|---|---|
| 标尺 | 4248×136 | 2124×68 @(322,1021) | `h-full overflow-hidden bg-[#212121]`（被 36px strip 裁切） |
| **车道** | **4248×230** | **2124×115 @(322,1021)** | `relative shrink-0 overflow-hidden rounded-r-md bg-black/15` |

车道 canvas 一次性画出标尺、车道色带、播放头、关键帧菱形。右列
（x ≥ 322、y 1050–1150）用 div/span/button/svg/path/line/rect/polygon 全量扫描，
**没有任何 DOM 覆盖元素**（probe32），所以本批所有数值都是 `getImageData` 读位图得到的。

> 顺带纠正：标尺 canvas 与车道 canvas 都画了标尺，但 strip（`absolute inset-x-0 top-0 z-30`，
> 不透明 `#212121`）盖住车道 canvas 的前 36px，肉眼只看到 68px 那块。车道 canvas 里那份
> 标尺不可见，clone 不必复刻。

### 1.2 车道格节奏：32px = 31px 色带 + 1px `#212121` 底边

canvas 内 CSS y 的纵向色带（`laneCol`，取 x=400 与 x=1200 两处，读数一致）：

```
y 34.0–35.5   #212121        车道区底
y 36.0–36.5   #355359        ← 对象行车道顶边，1px
y 37.0–66.5   #28464c        对象行车道色带，30px
y 67.0–67.5   #212121        车道之间的 1px 间隙
y 68.0–98.5   #243032        属性轨道车道色带，31px
y 99.0–       #212121
```

即每格 32px 节奏 = 31px 色带 + 1px 底边（间隙与底色同色，所以「底边」视觉上等于间隙）。

### 1.3 车道底色是 `#212121` 叠左列同一套 alpha

把两个色值反解回 `#212121` 上的合成：

```
#28464c = #212121 + rgba(60,181,204, 0.25~0.26)   ← 对象行车道（选中）
#243032 = #212121 + rgba(60,181,204, 0.10)        ← 属性轨道车道（选中）
```

与 batch 597 在**左列**实测到的两档 alpha 完全一致（对象行 0.25 / 轨道行 0.1），
说明车道与左列共用同一套「选中 = 青色底」的阶梯，只是画在不同介质上。

### 1.4 对象行车道还有一条 1px `#355359` 顶边 + 4px 圆角

`cssY 36` 那一行沿 x 扫描（probe42）：

```
x 0      #323232     ← 圆角起点
x 2.0    #333a3c
x 2.5    #344346
x 3.0    #344b4f
x 3.5    #355359     ← 平台色
...      #355359     直到 x 2120.5
x 2121.0 #344346
x 2121.5 #323232
```

两端各 3.5px 的渐变 = **4px 圆角**；平台色 `#355359` 比车道底 `#28464c` 亮，是
对象行车道**专有**的顶边（属性轨道车道顶边直接是 `#243032`，没有亮线）。
`#355359` 恰好是 `#28464c` 叠约 6% 白，与「车道色 + 一道极淡高光」一致。

### 1.5 播放头：2px、`#05a3c5`、**只画在对象行车道**

在 0s 主刻度那一列（device x=12，canvas css x=6）纵向取色（probe39）：

```
y 35.0–36.5   #212121        标尺区
y 36.0–36.5   #355359
y 37.0–66.5   #05a3c5        ← 播放头，只在这里
y 67.0–67.5   #212121        间隙
y 68.0–75.0   #243032        属性轨道车道：整段都是车道底色
```

横向在车道中段（device y=90）取色：`x 0–6 #28464c | x 6–8 #05a3c5 | x 8+ #28464c`
——**2 CSS px 宽**。

要点：播放头**不画进标尺**、**不画进属性轨道车道**、没有三角头、没有辉光。
注意这**不是**「被菱形挡住」：菱形只有 11px 宽且竖直方向只占车道中段 11px，
车道道里菱形上下两侧（y 68–78.5 与 89.5–99）实测都是纯车道底色。

### 1.6 关键帧菱形：外接 11×11 的空心菱形

`diamondRow`（菱形竖直中心那一行）与 `diamondCol`（水平中心那一列）互相印证：

```
水平  x 0.5 #167184 | 1.0 #13879f | 1.5 #1c7182 | 2.0–10.0 #2f2f2f | 10.5 #1c7182 | 11.0 #13879f | 11.5 #167184
垂直  y 78.5 #167184 | 79.0 #13879f | 79.5 #1c7182 | 80.0–88.0 #2f2f2f | 88.5 #1c7182 | 89.0 #13879f | 89.5 #167184
```

- 外接 **11×11**，`#167184 / #1c7182` 是 1px 描边的抗锯齿过渡，描边本色 **`#13879f`**
- 内部**不是透明**，是实心 **`#2f2f2f`**（比车道底 `#243032` 亮）
- 11px 外接 ÷ √2 = **7.78px** 见方旋转 45°
- 中心 css y = 84，所属车道 68–99（中心 83.5）→ **垂直居中于车道**

### 1.7 车道区跟随左列的两级行与收起状态

- 车道 1 覆盖 page y 1057–1088，左列对象行实测在 `(0,1057) 320×32`
- 车道 2 覆盖 page y 1089–1120，左列轨道行实测在 `(0,1089) 320×32`
- 点对象行的 chevron（纯 `aria-expanded` 切换，事后已还原）后，canvas 只剩一条
  `[37,67)` 色带（probe42）——**收起时轨道车道整条消失，对象行车道保留**

### 1.8 标尺窗口是 36px，不是 28px

batch 595 实测刻度带在 y 22.5–31.0（主）/ 27.5–31.0（次）。源站标尺窗口 36px，
故刻度底对齐在窗口底往上 **5px** 处，窗口底与刻度底之间留 5px 空隙。

## 二、clone 改动

`src/components/director/DirectorTimeline.tsx`

### 2.1 车道区结构（主要修复）

原先车道区直接 `timeline.tracks.map(...)`：**一条 track 一条道**，共 2 条；而左列是
两级，共 4 行。实测错位 8px（左列对象行 y=1041，车道 y=1033），且完全无视收起状态。

改为按 `timelineTrackGroups` 渲染：每个 group 一条**对象行车道** + 该 group 的轨道车道，
`collapsedObjects[group.key]` 为真时只留对象行车道。现在车道行与左列行**逐行 y 对齐**
（实测 1041 / 1073 / 1105 / 1137，收起后 1041 / 1073 / 1105）。

对象行车道用**新属性** `data-director-timeline-object-lane`，**不占**
`data-director-track-id` —— batch 36 / 93 / 595 都按轨道计数断言，不动这些合同。

### 2.2 配色与几何

| 元素 | 值 |
|---|---|
| 车道区底 | `#212121`（canvas 容器） |
| 对象行车道 | 选中 `rgba(60,181,204,0.25)` / 未选中 `bg-white/10`；`rounded-[4px]`；`border-t` 1px `#355359`；`border-b` 1px `#212121` |
| 轨道车道 | 选中 `rgba(60,181,204,0.1)` / 未选中透明；`border-b` 1px `#212121` |
| 播放头 | `w-[2px]` `#05a3c5`，无 shadow、无子元素 |
| 关键帧菱形 | 7.8px 见方 `rotate-45`，1px `#13879f` 描边，`#2f2f2f` 填充（外接 11.03px） |
| 标尺窗口 | 36px，刻度 `bottom: 5px` |

### 2.3 播放头归属

播放头移入**对象行车道**内部（源站实测只画在那里），并只画在**当前选中轨道所属对象**
的那一条车道上。

## 三、clone-only 决策与未取证项（记录，不臆造）

1. **未选中车道的底色从未在源站出现过。** 源站该项目只有一条轨道且始终是选中态，
   取不到未选中车道。clone 沿用 batch 597 已在左列实测过的同一套 alpha 阶梯
   （对象行车道 `white/10`、轨道车道透明），保证左右两列观感一致。**属推断。**
2. **多对象时播放头落在哪条对象行车道，源站测不出。** 源站只有一个对象。
   clone 选「当前选中轨道所属对象」，无选中时退回第一个。**属 clone-only 决策。**
3. **选中态关键帧菱形未取证。** 源站菱形在 canvas 里，第二次点击可能删关键帧，
   没敢试。clone 把选中态填成实测的播放头色 `#05a3c5`。**属 clone-only 决策。**
4. **4px 圆角**是从 3.5px 的顶边渐变反推的，不是从 DOM 盒读出来的。
5. 车道色带上下端 1px 的 `#253437 / #263d41` 等过渡色是圆角抗锯齿，未单独复刻。

## 四、迁移的既有合同

- **`verify-liblib-batch595.py` 的 `lane:2a2a2a-no-grid`**：batch 595 当时把
  `#2a2a2a` 读成车道填充，本批逐像素复测证明那是**车道之间的间隙色**。车道底实为
  `#212121`，未选中轨道车道是透明的。断言改为
  `lane:212121-base-no-grid`（未选中轨道车道透明 + canvas 底 `#212121` + 无竖向网格线），
  被测意图（车道是平色、无网格）不变。

  自闭合字面量消失），此前一直没人跑到。改为断言挂载本身 + import 路径。
